## Asked

`Scheduler_BatchFailed_LogsAndTagsOnlyTheErrorCode` (`tests/Encina.UnitTests/Messaging/Encryption/ErrorMessageLeakTests.cs`) attached a real, process-global `ActivityListener` to the `"Encina.Messaging.Scheduling"` `ActivitySource`, filtered only by source name, and captured "whichever activity stopped first" into a single `stopped` variable polled with `Task.Delay` — a race whenever another test started or stopped any activity on that same shared source while the listener was attached. A follow-up comment (2026-09-27) reported the mirror failure mode on `ReshardingActivitySourceTests.StartPhaseExecution_WithoutListeners_ReturnsNull` in an unrelated PR's CI run: a "no listener attached, must return null" assertion failing because a *different* test class (also named `ReshardingActivitySourceTests`, in `Sharding/Resharding/Observability`) attaches a real listener to the same `"Encina.Resharding"` source, and xUnit does not serialize different test classes by default. The brief asked for a repository-wide fix covering every test that calls `ActivitySource.AddActivityListener` or asserts "without listeners" behaviour in `tests/Encina.UnitTests` (excluding `Compliance/**`, `Marten/**`, and `*ProcessorTests.cs`, reserved for #1430).

## Outcome

Delivered:

- **`ErrorMessageLeakTests.Scheduler_BatchFailed_LogsAndTagsOnlyTheErrorCode`**: the listener now selects the activity by `OperationName == "encina.scheduling.processor_cycle"` (the name `SchedulingActivitySource.StartProcessingCycle` gives the `ScheduledMessageProcessor`'s own cycle, which only this test drives) via a `TaskCompletionSource` completed from `ActivityStopped`, replacing the racy shared `stopped` variable and `Task.Delay` poll loop. The assertions are unchanged.
- **The `ReshardingActivitySource` duplication**: `tests/Encina.UnitTests/OpenTelemetry/Resharding/ReshardingActivitySourceTests.cs` (asserts null without a listener) and `tests/Encina.UnitTests/Sharding/Resharding/Observability/ReshardingActivitySourceTests.cs` (attaches a real listener to the same `"Encina.Resharding"` source) both now carry `[Collection("ActivityListenerIsolation")]`; the collection is defined once (`[CollectionDefinition("ActivityListenerIsolation", DisableParallelization = true)]`, named `ActivityListenerIsolationTestGroup`) in the Observability file, following the pre-existing `Security-Observability` pattern in `ObservabilityTests.cs`.
- **A second, independent source of the same class of flakiness**: five enricher test classes under `tests/Encina.UnitTests/OpenTelemetry/Enrichers` (`Tenancy`, `Repository`, `ReferenceTable`, `Migration`, `Audit` `ActivityEnricherTests`) used `ShouldListenTo = _ => true`, attaching their listener to *every* `ActivitySource` in the process — including unrelated production sources like `Encina.Security.PII` and `Encina.Resharding` — for the lifetime of each test instance. All five were narrowed to `source => source.Name == _source.Name`, matching only the private, test-only `ActivitySource` each file already owns (`test.tenancy`, `test.repo`, `test.reftable`, `test.migration`, `test.audit`).

A grep sweep confirmed every remaining `AddActivityListener` call in the in-scope files targets either a private per-test `ActivitySource` name (unique, no cross-test risk) or a shared production source with no other in-scope file attaching a competing listener or strict "without listener" assertion to it, and every strict "without listener"/"no listeners" assertion in scope is either on a source no other in-scope file touches, already inside a pre-existing `DisableParallelization` collection (`Security-Observability`), or now inside the new `ActivityListenerIsolation` collection. The full `tests/Encina.UnitTests` project (21,270 tests) ran green 5 consecutive times after the fix.

## Where the knowledge lives

- `tests/Encina.UnitTests/Sharding/Resharding/Observability/ReshardingActivitySourceTests.cs` — the `ActivityListenerIsolation` collection definition (`ActivityListenerIsolationTestGroup`) and its use.
