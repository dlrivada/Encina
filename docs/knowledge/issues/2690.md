## Asked

Bring the unit and guard flags of `Encina.Aspire.Testing` to their manifest targets (unit 55, guard 15) with tests that execute the real package code.

## Outcome

New test classes build a real `DistributedApplication` over a host that is never started, with the real `Encina.Testing.Fakes` stores, and run every assertion, getter, wait helper and `Simulate*` method including timeout, cancellation, not-found and invalid-argument paths. Measured locally, the package reached unit 95% and guard 23% (before: unit 24%, guard 15%). The manifest gained per-file targets with justifications and the package targets were raised to unit 85 and guard 20, while the `WithEncinaTestSupport` registration path stays at a low unit target because Aspire creates a testing builder only from an AppHost assembly.

## Where the knowledge lives

- `tests/Encina.UnitTests/Aspire/Testing/AspireTestApp.cs` — helper that builds a real `DistributedApplication` with the fake stores.
- `tests/Encina.UnitTests/Aspire/Testing/DistributedApplicationExtensionsTests.cs` — assertions, getters and wait helpers.
- `tests/Encina.UnitTests/Aspire/Testing/FailureSimulationExtensionsTests.cs` — failure simulation methods.
- `tests/Encina.GuardTests/Aspire/AspireTestingArgumentGuardTests.cs` — null and invalid argument guards.
- `.github/coverage-manifest/Encina.Aspire.Testing.json` — per-file targets and justifications.
