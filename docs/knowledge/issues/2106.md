## Asked

Replace the three ways packages detected that multi-tenancy is in use (a Messaging marker, a core marker and an `ITenantProvider` probe) with one core marker that every tenant-aware component checks.

## Outcome

Delivered with the Phase 5 change of #751: `DeadLetterManager` takes `MultiTenancyMarker?`, `QueryCacheInterceptor` checks the marker, `TenancyInUse` and its registration are gone, and DI tests build the provider with `ValidateOnBuild` and `ValidateScopes` with and without `AddEncinaTenancy` for the dead letter manager and the ABAC decision audit reader.

## Where the knowledge lives

- `src/Encina/Abstractions/MultiTenancyMarker.cs` — the marker and how a package checks it.
- `src/Encina.Tenancy/ServiceCollectionExtensions.cs` — the single registration.
- `docs/features/dead-letter-queue.md` — how the dead letter manager uses the marker.
