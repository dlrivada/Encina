## Asked

Following #1314 (which removed the data subject id from `Encina.Compliance.Consent`'s log templates, activity tags and metric tags) and #1350/#1415/#1417 (which did the same for `EncinaError.Message`/details across Consent, DataSubjectRights and Marten.GDPR), the diagnostics layers of `Encina.Compliance.DataSubjectRights` (`DSRLogMessages.cs`, `DataSubjectRightsDiagnostics.cs`) and `Encina.Marten.GDPR` (`CryptoShreddingLogMessages.cs`, `CryptoShreddingDiagnostics.cs`) still passed the raw `subjectId` into `[LoggerMessage]`/`LoggerMessage.Define` templates and set it as an OpenTelemetry activity tag (`dsr.subject_id`, `crypto.subject_id`). Found during the adversarial review of PR #1427 (#1415's fix) on 2026-09-27, out of scope for that PR.

## Outcome

Delivered: no DSR or crypto-shredding log message, activity tag, or metric tag carries the raw data subject id. `DSRLogMessages.cs` (11 templates) and `CryptoShreddingLogMessages.cs` (9 templates, including two unused ones kept consistent for completeness) had `subjectId` removed from every template and signature; call sites in `DefaultDSRService.cs`, `DefaultDataErasureExecutor.cs`, `DefaultDataPortabilityExporter.cs`, `ProcessingRestrictionPipelineBehavior.cs`, `CryptoShredderSerializer.cs`, `CryptoShredErasureStrategy.cs`, `PostgreSqlSubjectKeyProvider.cs` and `InMemorySubjectKeyProvider.cs` (including several ad hoc `_logger.LogDebug/LogWarning` calls not routed through the generated `*LogMessages` classes) were updated to match. Both `TagSubjectId` constants and the `Start*`/`Record*` diagnostics helper parameters that only existed to set them were removed. Two new leak test files (one per package) attach a `FakeLogger` and an `AsyncLocal`-scoped `ActivityListener`/`MeterListener` and prove a sentinel subject id never appears in any captured log message, activity tag/status or metric tag, across the DSR request lifecycle, all six `Handle*Async` operations, the erasure executor, the portability exporter, the restriction pipeline behavior (blocked/warned/store-error paths), crypto field encryption/decryption (including the forgotten-subject placeholder path), subject forget and key rotation. Several methods whose pre-existing complexity exceeded the CRAP gate's threshold were incidentally touched and were refactored (extract-method, no behavior change) to bring them back under the gate; see the gotcha above.
