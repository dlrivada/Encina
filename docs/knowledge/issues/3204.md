## Asked

Rename the multi-tenancy option `ThrowOnMissingTenantContext` to `RequireTenantContext` in `Encina.Messaging`, because the option only feeds the EF Core tenancy configuration and the name no longer reflects the underlying behaviour.

## Outcome

Delivered in the rename; there is no changelog fragment here, because the last sub-issue of #3005 writes one for the whole rename.

## Where the knowledge lives

- `src/Encina.Messaging/Tenancy/TenancyMessagingOptions.cs` — the option is renamed to `RequireTenantContext` (default `true`) with XML docs stating it only feeds the EF Core tenancy option.
- `src/Encina.EntityFrameworkCore/ServiceCollectionExtensions.cs` — copies the value from `TenancyMessagingOptions` into `EfCoreTenancyOptions`.
- `docs/features/multi-tenancy.md` — names each provider's option and describes its real behaviour.
