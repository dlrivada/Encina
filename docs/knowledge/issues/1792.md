## Asked

Make `RabbitMQMessagePublisher` read time from `TimeProvider` and keep the outbox message id as the broker `MessageId`, and keep the other transport publishers consistent.

## Outcome

RabbitMQ, Azure Service Bus, Kafka (batch items carry their own id), Redis Pub/Sub, NATS, MQTT and Amazon SQS/SNS publishers take an optional `messageId`; RabbitMQ and Redis Pub/Sub read time from the injected `TimeProvider`. InMemory, gRPC and GraphQL have no publisher with an id or clock read. Not done: the Redis subscriber does not expose the envelope id to typed handlers, and `SendBatchAsync` of Amazon SQS has no per-message id (follow-up file); the outbox relay is #2385.

## Where the knowledge lives

- `src/Encina.RabbitMQ/RabbitMQMessagePublisher.cs` — `CreateProperties` builds the AMQP properties from `TimeProvider` and the supplied id.
- `tests/Encina.UnitTests/RabbitMQ/Publishing/RabbitMQPublisherTimeAndMessageIdTests.cs` — fake time and id preservation.
