## Asked

Remove the project-less `src/Encina.ADO.Sqlite` and `src/Encina.Dapper.Sqlite` leftovers and add a check that fails when a `src/` directory has no `.csproj`, so the drift cannot return.

## Outcome

The two directories held only git-ignored build output and a user file, so they were deleted by hand from the maintainer's disk. `.github/scripts/check-src-projects.cs` exits 1 for any `src/` directory without a direct-child `*.csproj` (and for a missing or empty `src/`), naming the directory and its tracked file count, and exits 0 otherwise. Its `--self-test` builds temporary trees for the passing case, a project-less directory, a bin/obj-only directory and an empty `src/`.

Out of scope and tracked elsewhere: the package manifest drift check (#1362) and the stale `Encina.*.Sqlite` assembly names in `InternalsVisibleTo` and the CLI (#1944, #2527, #1808).

## Where the knowledge lives

- `.github/scripts/check-src-projects.cs` — the rule and its self-test.
