## Asked

Make the hooks recognise a worktree that `git worktree list` registers, wherever it lives. The orchestrator creates worktrees beside the repository (`D:\Proyectos\Encina-w<issue>`); `block-main-checkout-writes` denied a worker's `pwsh -File <abs path>\.claude\hooks\tests\Test-Hooks.ps1` launched from the main checkout because it did not see that folder as a checkout, so the sanctioned-script exemption did not apply.

## Outcome

`Get-RepoLocation` in `.claude/hooks/_repo-paths.ps1` now reads `git -C <MainRoot> worktree list --porcelain` once per process, lazily, and returns the registered worktree that contains a path (Root, forward-slash Relative, `InWorktree = $true`). Regression cases in `.claude/hooks/tests/Test-Hooks.ps1` run against a real `git worktree add` fixture and cover the three affected hooks. `guard-orchestrator-writes` and `enforce-path-ownership` now enforce in such worktrees.

## Where the knowledge lives

- `.claude/hooks/_repo-paths.ps1` — `Get-RegisteredWorktrees` and `Get-RepoLocation`.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#3244` block at the end of the suite.

## Known limits

- `Test-MainCheckout` is unchanged: a registered worktree nested in the main checkout but outside `.claude\worktrees` is a worktree for `Get-RepoLocation` but still counts as the main checkout for `block-main-checkout-writes`.
- A session whose project directory is itself an outside worktree is out of scope (D8): the layout then takes that worktree as the main checkout.
- `git worktree list` runs once per hook process that sees a path outside `.claude\worktrees` (about 70 ms with 41 worktrees).
