## Asked

Fix the persistent policy administration point so policy changes are audited in their own DI scope, fail closed when the audit write fails, take time from `TimeProvider`, and are refused without a principal.

## Outcome

Delivered on branch `fix/abac-pap-audit-1677`: the PAP takes `IServiceScopeFactory` and `TimeProvider`, awaits the audit write before applying the change, and refuses unattributed changes; the seeding hosted service runs in an explicit system-actor scope; error audit entries written on failure carry `writeAheadEntryId` metadata; instances without an audit store log one Warning per instance (EventId 9097); startup seeding fails on any policy change error instead of starting with a partial set (EventIds 9094-9097).

## Where the knowledge lives

- `src/Encina.Security.ABAC/Administration/PersistentPolicyAdministrationPoint.cs` — principal check, write-ahead audit, fail-closed behavior.
- `src/Encina.Security.ABAC/ABACPolicySeedingHostedService.cs` — startup seeding under the built-in service identity `service:encina.abac.policy-seeding`, which replaced the internal system-actor scope (#1705).
- `docs/features/abac/reference/persistent-pap.md` — the documented behavior.

Note: the singleton PAP still captures the scoped `IPolicyStore`, tracked by #1707; the 30 second timeout bounds only token-honouring stores (#1704).
