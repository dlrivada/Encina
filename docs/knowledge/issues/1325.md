## Asked

`Encina.ADO.PostgreSQL` read wall-clock time directly (`DateTime.UtcNow`/`DateTimeOffset.UtcNow`) in four
call sites instead of taking `TimeProvider` by injection (contradicting #543/#667), and called ADO.NET
synchronously in seventeen call sites instead of through async overloads with a propagated
`CancellationToken` (contradicting the rule from #794/#897), found by the SPEC-003 pilot-2 deep quality
audit of the package.

## Outcome

Delivered: `AdoMigrationHistoryStore` and `PostgreSqlSchemaIntrospector` now take an optional `TimeProvider`
(default `TimeProvider.System`) for every timestamp. `UnitOfWorkADO`'s transaction begin/commit/rollback
(the highest-traffic call site), `BulkOperationsPostgreSQL`, `PolicyStoreADO`, `TokenMappingStoreADO`,
`TemporalRepositoryADO`, `ReferenceTableStoreADO`, and the sharding migration helpers (`AdoHelper`,
`AdoMigrationExecutor`) now call the async ADO.NET overloads with the caller's `CancellationToken`, and a
Npgsql-specific type check with a bare synchronous fallback was widened to the ADO.NET base classes
(`DbConnection`/`DbCommand`/`DbDataReader`) so wrapped connections (e.g. `SchemaValidatingConnection` under
module isolation) also take the async path. Two exceptions are documented rather than fixed: the sync
overrides required by the `DbConnection`/`DbCommand` base contract in `SchemaValidatingConnection`/
`SchemaValidatingCommand` (already correct, both sync and async members present), and
`ReferenceTableStoreFactoryADO.CreateForShard`, which stays synchronous because it implements the
synchronous `IReferenceTableStoreFactory` core interface shared by all 7 provider implementations.

## Where the knowledge lives

- `src/Encina.ADO.PostgreSQL/UnitOfWork/UnitOfWorkADO.cs` — async transaction begin/commit/rollback via
  `DbConnection`/`DbTransaction` when available, `Task.Run`-wrapped fallback otherwise.
- `src/Encina.ADO.PostgreSQL/Sharding/Migrations/AdoMigrationHistoryStore.cs`,

  `Sharding/ReferenceTables/ReferenceTableStoreADO.cs` — async ADO.NET calls with `DbConnection`/
  `DbCommand`/`DbDataReader` checks.
