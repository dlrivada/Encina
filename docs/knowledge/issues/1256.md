## Asked

Make `ProhibitedPractice` cover every prohibition of AI Act Art. 5(1) and stop the README, XML comments, log message and feature page from claiming coverage or blocking behaviour the code does not have.

## Outcome

`ProhibitedPractice` now has 11 members. `ProhibitedPracticeExtensions.GetArticlePoint()` maps each to its Art. 5(1) point. The wording in `Encina.Compliance.AIAct` says what the code does: a declared practice is blocked in Block and Warn mode, and Disabled mode skips all checks. Behaviour is unchanged.

Cross-cutting check (AGENTS.md section 6, ADR-018): all 12 functions are Not applicable. The change adds enum members, a pure mapping and wording; it adds no entity, store, behaviour, background service or integration. The existing log message keeps its EventId and placeholders. The issue's tenant-aware and instrumented acceptance items are Not applicable for the same reason: no record is added or changed and no new operation exists.

## Where the knowledge lives

- `src/Encina.Compliance.AIAct/Model/ProhibitedPractice.cs`: the 11 members and their points.
- `src/Encina.Compliance.AIAct/Model/ProhibitedPracticeExtensions.cs`: the point mapping.
- `docs/features/aiact-compliance.md`: the practice table with the dates each point applies from.
