## Asked

Remove the per-type `Enabled = false` of `[EncryptedMessage]`, and any other per-type or per-member negative encryption value in `Encina.Messaging.Encryption`, so that a type marked for encryption or covered by `EncryptAllMessages` can never be left unencrypted (maintainer gate G5 = b of #3111, "compliance controls are never optional").

## Outcome

`EncryptedMessageAttribute.Enabled` is gone, the attribute cache no longer carries it, and `EncryptingMessageSerializer` encrypts every marked type (declared or inherited) and, with `EncryptAllMessages`, every other type. XML docs, the package README, `PublicAPI.Unshipped.txt` and a `removed` changelog fragment follow.

## Where the knowledge lives

- `src/Encina.Messaging.Encryption/Serialization/EncryptingMessageSerializer.cs` - the `ShouldEncrypt` predicate (marked or `EncryptAllMessages`).
- `tests/Encina.UnitTests/Messaging/Encryption/EncryptingMessageSerializerTests.cs` - marked, derived-from-marked, unmarked with and without `EncryptAllMessages`.
- `tests/Encina.ContractTests/Messaging/Encryption/MessageEncryptionContractTests.cs` - the attribute exposes only `KeyId` and `UseTenantKey`.
