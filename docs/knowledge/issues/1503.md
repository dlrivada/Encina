## Asked

The adversarial review of #1499 (the DPIAHealthCheck result fix) found that `EncinaError.Message` still
reached the **logging** sink in `Encina.Compliance.DPIA` — a different sink from the health-check result
(#1499) and the activity tags (#1454, #1488). `AGENTS.md` §3 forbids `EncinaError.Message` reaching logs,
activity tags, health-check results or plaintext storage; only the error code or exception type may be
recorded (why: #1168, #1173, #1259, #1274). Four call sites were named: the Block/Warn store-error paths in
`DPIARequiredPipelineBehavior.cs`, the draft-creation failure in `DPIAAutoRegistrationHostedService.cs`, and
the review-cycle failure in `DPIAReviewReminderService.cs` — the latter two wrapping `error.Message` in a
new `InvalidOperationException` only to satisfy a logger overload that requires an exception.

## Outcome

Delivered: all four call sites now log `error.GetCode().IfNone("encina.unknown")`. `DPIAPipelineBlocked` and
`DPIAPipelineWarned` kept their EventIds and had their shared parameter renamed to `errorCode`.
`AutoRegistrationFailed` and `ReviewReminderCycleFailed` each gained a new string-`errorCode` overload
(new EventIds 8825/8848, since reusing their existing EventId for a same-name overload with a different
parameter shape was rejected by `EncinaEventIdAllocationTests` as a within-assembly duplicate) instead of
wrapping the code in an exception. A grep of the whole package confirmed no other `error.Message`/`ex.Message`
reaches a logger call outside the four fixed sites and the excluded `DPIAErrors.StoreError(..., ex.Message, ex)`
error-construction calls and `DPIAHealthCheck.cs` (out of scope, PR #1504).

Two findings were scoped out and written up as follow-up issues: the CRAP gate's known line-attribution
limitation (#1355, #1360) flagging two large pre-existing async methods that merely contain the touched
lines inside a nested closure, verified via the raw coverage XML to not actually need any change; and the
same error-message-reaches-logger pattern found widespread across
`Encina.Compliance.DataSubjectRights` and `Encina.Compliance.Retention` during the mandated sweep of those
two packages.
