## Decisions
- **Deprecate `Encina.EventStoreDB`**: the team decided to remove EventStoreDB support and keep only Marten for event sourcing. Source: closing comment by dlrivada, 2025-12-23. Implemented the same day in commit `87d92a394cccbcb4445e2ac349123f290548742d` ("refactor: deprecate EventStoreDB, Wolverine, NServiceBus, MassTransit, Dapr", `Closes #17`), which deleted `src/Encina.EventStoreDB/` from the repository (the commit message says it was "moved to `.backup/deprecated-packages/`", but `.backup/` is gitignored and absent from this checkout — verify code claims against the filesystem, not the commit prose).
- **Retain `Encina.Marten`**: Marten remains the sole event-sourcing backend. Source: same comment. Verified current: `src/Encina.Marten/` still has `IAggregateRepository.cs`, `MartenAggregateRepository.cs`, `Snapshots/SnapshotAwareAggregateRepository.cs`.
- **Do not create an `Encina.EventSourcing` abstractions package**: rejected because with a single provider (Marten) there is nothing to abstract. Source: comment ("Answer: No"). Verified: no such directory exists under `src/`.
- **Projection API differences are not a concern**: moot with a single provider. Source: same comment.
- **Snapshotting is a native Marten feature, no separate strategy needed**: source: same comment; consistent with `src/Encina.Marten/Snapshots/SnapshotAwareAggregateRepository.cs` existing as the one snapshot path.
- **Package count reduction**: active packages went from 40 to 39 (EventStoreDB removed, no replacement added). Source: comment; the commit that implemented this also deprecated four other packages (Wolverine, NServiceBus, MassTransit, Dapr) in the same pass, so the "40 to 39" step recorded here was one of several package removals in that commit, not the only one.
- **ADR recorded later, not at close time**: ADR-027 ("Marten Is the Event-Sourcing Provider; EventStoreDB Is Deprecated") was written on 2026-09-22, nine months after the issue closed, as part of a historian pass (PR #1113, "docs: promote nine rules into CLAUDE.md and record ADR-027..030 from the project history") that mined `docs/engineering/PROJECT-HISTORY.md` for undocumented decisions. It is Accepted and cites #17 and #321.

## Rejected alternatives
- **Option A: Strategy + Orchestrator Pattern (both EventStoreDB and Marten as strategies)**: rejected — once EventStoreDB was dropped, there was only one strategy left, making the abstraction unnecessary. Source: issue body (Option A) + closing comment.
- **Option B: Keep both packages independent**: rejected because `Encina.EventStoreDB` was deprecated outright. Source: issue body (Option B) + closing comment.
- **Option C: Shared abstractions only (`Encina.EventSourcing`)**: rejected — a single provider makes shared interfaces redundant. Source: issue body (Option C) + closing comment.

## Rules and lessons
- **Prefer single-vendor simplicity over premature abstraction**: when only one implementation is supported, do not add an abstraction layer over it. Source: closing comment.
- **Infrastructure choice drives architecture**: choosing Marten (PostgreSQL-based) over EventStoreDB (dedicated server) avoided a second piece of operational infrastructure. Source: closing comment; ADR-027 rationale.
- **Deprecation as physical removal, not an in-repo marker**: this deprecation was executed by deleting the package's files from `src/` and `Encina.slnx` in one commit, not by leaving an `[Obsolete]`-marked package in place (consistent with AGENTS.md §3's ban on compatibility layers). The commit's claim that the files were "moved to `.backup/`" should not be read as "still present in the repo" — `.backup/` is gitignored.
