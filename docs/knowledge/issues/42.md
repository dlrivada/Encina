## Asked

Enhanced dead letter queue handling across all messaging providers: a unified abstraction, message inspection and replay, DLQ monitoring, automatic poison message detection, manual and automatic replay. Proposed API `AddEncinaDeadLetterQueue(config => { MaxRetries, RetentionPeriod, EnableAutoReplay, OnDeadLetter })` and `IDeadLetterManager.ReplayAsync/ReplayAllAsync`. Eight unticked implementation tasks, including `IDeadLetterStore`, an inspection API, replay, monitoring metrics and integration with all transport providers. Created 2025-12-24T13:25:23Z as the re-creation of #26 (closed in error 2 hours earlier).

## Outcome

Closed 2025-12-26T18:31:20Z, state_reason COMPLETED, by commit `d5c60cab` (Fixes #42; no PR, no comments on the issue). The commit added 14 source files under `src/Encina.Messaging/DeadLetter` and `Health`, two edits to `MessagingConfiguration` and `MessagingServiceCollectionExtensions`, and unit, property, contract and integration tests.

Delivered: store, factory and manager abstractions, filter, options with retention, cleanup and integration flags, orchestrator, replay and statistics, health check, cleanup processor. Not delivered by #42 and not so today: poison detection (no `poison` symbol in `src/` outside an unrelated Marten file), `MaxRetries` and `EnableAutoReplay` options (`DeadLetterOptions` has `RetentionPeriod` and `OnDeadLetter` only) and DLQ integration with the transports. Metrics came later (#2082). Recorded as `partial`.
