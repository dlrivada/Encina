## Asked

Close the guardrail gap found in the #2234 self-review: the transcript the per-audit binding reads lives outside the project, where every path was allowed, so the agent it binds could alter it.

## Outcome

`Test-PathOwnership` in `enforce-path-ownership.ps1` denies the six audit-stage agents any path under `~/.claude/projects` (home resolved from the user profile, case-insensitive) before the "outside the project" allow, with a message naming #2244 and #2234. Write/Edit and shell writes share that check. Beyond the issue's Proposed Fix, the same check fails closed for these agents on a path that cannot be resolved or normalised and on the `\\?\`, `\\.\` and UNC forms, which `GetFullPath` leaves unchanged and would otherwise evade the prefix test (found by the self-review). Other callers, the orchestrator included, are unchanged. `Test-Hooks.ps1` covers Write, `Set-Content`, case-insensitivity and the unchanged callers.

## Where the knowledge lives

- `.claude/hooks/enforce-path-ownership.ps1` — the transcript-folder deny in `Test-PathOwnership`.
- `.claude/hooks/tests/Test-Hooks.ps1` — the #2244 cases.
