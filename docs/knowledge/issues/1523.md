## Asked

`test-auditor.md`'s Method step 1 tells test-auditor to run coverage with `--results-directory
<wt>\artifacts\audit\coverage\<flag>`, but `enforce-path-ownership.ps1` allowed test-auditor to write only its
own stage artifact (`artifacts\knowledge\stages\tests.md`), blocking that instructed path outright. During
audit #18 this forced test-auditor to write coverage to its session scratch directory instead of the location
`audit-verifier` needed to read from -- an internal contradiction between the agent definition and the
enforcement hook.

## Outcome

Delivered: `enforce-path-ownership.ps1` now allows both `test-auditor` and `audit-verifier` -- and only these
two of the five single-owner SPEC-003 audit-stage agents -- to write under `artifacts/audit/coverage/**`. The
new check sits inside the shared `Test-PathOwnership` function both the Write/Edit tool path and the
Bash/PowerShell shell-write-scan path call, so a shell redirection into that prefix behaves the same as a
direct Write. `audit-verifier.md`'s Method step 5 was extended to instruct it to actually re-run coverage into
its own `verify-<flag>` subdirectory and compare against `tests.md`'s reported numbers; `test-auditor.md`
needed no change, since its instructed path was already correct -- only the hook was wrong. `artifacts/` was
already gitignored wholesale, so this stays ephemeral scratch, never a stage artifact.

## Where the knowledge lives

- `.claude/hooks/enforce-path-ownership.ps1` -- the `artifacts/audit/coverage/**` allowance, scoped to
  `test-auditor`/`audit-verifier` inside the single-owner `elseif` branch.
- `.claude/agents/audit-verifier.md` -- Method step 5, now instructing an actual re-measurement into
  `verify-<flag>`.
- `.claude/hooks/tests/Test-Hooks.ps1` -- the `#1523` ownership and shell-vector cases (allow/deny, both tool
  and shell paths).
