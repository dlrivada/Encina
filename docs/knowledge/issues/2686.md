## Asked

Stop Encina.AspNetCore and the core inbound path from letting a client-supplied tenant header choose the tenant without a trust decision, deny a header that disagrees with the verified claim, and route the DPIA endpoints through the request context.

## Outcome

Delivered: `TrustTenantIdHeader` (default off, logged opt-out), the `TenantHeaderTrusted` flag on `InboundRequestInfo`, the claim-wins rule with a 403 refusal for a disagreeing header or conflicting claims, and DPIA endpoints that read the tenant from the request context. The `X-Module-Id` header and a DPIA assessment created with no tenant are tracked as follow-ups.

## Where the knowledge lives

- `src/Encina.AspNetCore/EncinaAspNetCoreOptions.cs` — the trust option and why there is no address list.
- `src/Encina/Identity/RequestContextScopeFactory.cs` — the claim-wins rule and the refusal.
- `src/Encina.AspNetCore/README.md` — the "Tenant resolution" section.
