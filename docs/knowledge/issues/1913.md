## Asked

With multi-tenancy enabled and no resolved tenant (a connection flow, a job), the default cache key had no tenant segment, so every tenant-less caller of every tenant shared one cached response. The EF Core query cache interceptor was already fixed (#1905); the Encina.Caching pipeline behaviors were not.

## Outcome

`QueryCachingPipelineBehavior` bypasses the cache (no read, no write) and `CacheInvalidationPipelineBehavior` skips the invalidation when `MultiTenancyMarker` is registered and the context has no tenant. A request with `VaryByTenant = false` is unchanged. The `VaryByUser` rule was already in place (#1892).
