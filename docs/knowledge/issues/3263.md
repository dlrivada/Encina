## Asked

Make registering Recoverability more than once an error instead of a silent acceptance: `AddEncinaRecoverability` together with `UseRecoverability`, the same path twice, or a `RecoverabilityOptions` instance next to either. The sibling #3262 made the options a single value; #3263 delivers the errors and the documentation that the pair fails by design.

## Outcome

Delivered: the registration methods count the existing descriptors and throw `InvalidOperationException` on a duplicate before they add anything. A `RecoverabilityRegistrationCheck` hosted service fails the host start (Critical log, EventId 5458) for a duplicate added directly to the service collection after every Encina call. `TryAddEnumerable` is not used for Recoverability, because its duplicate is an error. The idempotence guard in `RegisterErrorClassifier` was removed as unreachable. The README states the failure by design and its samples now compile.
