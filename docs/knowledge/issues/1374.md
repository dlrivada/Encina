## Asked

Two concurrent instances of `enforce-path-ownership.ps1` (the hook is deliberately wired twice for the same tool call) raced a non-atomic read-modify-write on `artifacts/knowledge/stages/.authors.json`, occasionally leaving it as two concatenated JSON objects. Both the hook and `audit-commit-stage.ps1` swallowed the resulting parse exception silently, misreporting it as "no recorded author" and leaving an open SPEC-003 audit stuck with no repair path.

## Outcome

Delivered: the sidecar write is now serialized with a named `System.Threading.Mutex` and written atomically (temp file + `File.Move`); an unreadable sidecar denies the write and names the repair command instead of being masked; `audit-commit-stage.ps1` distinguishes "unreadable" from "no recorded author" from "wrong agent"; `tools/ai/audit/audit-stage.ps1` gained `-RepairAuthors`, the one sanctioned repair, which only ever restores already-committed content; `Test-Hooks.ps1` gained a delimited block covering the real concurrent-process race and the repair path.

## Where the knowledge lives

- `.claude/hooks/enforce-path-ownership.ps1` — the mutex-serialized, atomically-written, fail-closed authorship sidecar write (`Set-StageAuthor`).
- `tools/ai/audit/audit-commit-stage.ps1` — the three-way distinction between an unreadable sidecar, a missing entry and a mismatched agent.
- `tools/ai/audit/audit-stage.ps1` — the `-RepairAuthors` repair path.
- `.claude/hooks/tests/Test-Hooks.ps1` — the concurrency and repair regression cases.

## Audit

Conforms: reviewed by `adversarial-reviewer` against the issue's acceptance criteria; the one major (a temp-file leak on a failed `File.Move`) and two minors (a Mutex-construction fail-open edge, an untimed `WaitForExit` in the new test) it found were fixed in the same branch before merge. No remediation issues opened.
