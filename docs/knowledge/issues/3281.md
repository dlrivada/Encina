## Asked

Stop `.claude/hooks/guard-orchestrator-writes.ps1` from denying read-only commands in two shapes: a script path held in a variable assigned in an earlier tool call (case a) and a relative script path when the payload has no `cwd` and the hook process runs from a directory such as `C:\` (case b, seen on 2026-11-10 as `pwsh -File .claude/hooks/tests/Test-Hooks.ps1` denied to a read-only reviewer).

## Outcome

Case (b) fixed: with no payload `cwd` the base is the process directory when it is inside a checkout, else `CLAUDE_PROJECT_DIR`. Case (a) stays fail-closed by design; the message now states that a variable from an earlier tool call is invisible to the hook, and the same-command literal workaround keeps passing. Regression cases for both are in `.claude/hooks/tests/Test-Hooks.ps1` (the no-cwd cases run the hook from a process directory outside any checkout).

## Where the knowledge lives

- `.claude/hooks/guard-orchestrator-writes.ps1` — the `$cwd` fallback and the unresolved-variable message.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#3281` cases after the `#2009` block.
