## Asked

Evaluate whether Stryker.NET 5.0.0, whose MTP runner claims `perTest` coverage support, can replace Encina's Stryker 4.14.0 setup (VsTest runner, `coverage-analysis: off`, one `test-case-filter` per shard), by measuring options A (5.0.0 + MTP + `perTest`), B (5.0.0 + VsTest + `off`) and C (stay on 4.14.0) on one mutation shard against the five decision criteria of the issue.

## Outcome

Delivered as a measured spike on the pilot shard `**/Dispatchers/Strategies/*.cs`. The baseline measurement showed that the question behind the spike was the wrong one: the VsTest runner kills no mutant under xUnit v3 in either Stryker version, so options B and C both publish 0 % scores. Option A fails two criteria (the filter is ignored and per-test coverage capture is far slower than the whole run it replaces) and never tested a mutant. The only configuration that activated mutants was 5.0.0 with the MTP runner and coverage off in project mode, which is 3.8 times slower and has its score inflated by Verify snapshot tests. None of A, B or C yields a valid mutation measurement; the follow-up issues carry the runner switch and the Verify test fix.
