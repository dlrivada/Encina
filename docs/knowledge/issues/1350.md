## Asked

`ConsentErrors.MissingConsent`, `ConsentExpired`, `ConsentWithdrawn`, `RequiresReconsent` and `VersionMismatch` built `EncinaError.Message` with the raw data subject id interpolated into the text. #1314 had removed the subject id from log templates, activity tags and metric tags, but left the error message itself untouched, and that message reaches `Encina.AspNetCore.ProblemDetailsExtensions.ToProblemDetails`'s `ProblemDetails.Detail = error.Message` unfiltered, so the subject id could reach an HTTP response body. `IConsentValidator`'s own XML doc example also logged `error.Message` directly.

## Outcome

Delivered: the five factories now build their message with the non-identifying description "the specified data subject" (a `SubjectDescription` constant) instead of the interpolated `subjectId`, keeping purpose, consent version ids and timestamps in the text. `IConsentValidator`'s XML doc example now logs `error.Code` instead of `error.Message`. Factory signatures and error codes are unchanged. Regression tests: the five factories' existing unit tests were flipped from asserting the subject id was present to asserting it is absent, plus a new FsCheck property test file (`ConsentErrorsPropertyTests.cs`) proving the invariant holds for arbitrary non-empty subject ids.

## Where the knowledge lives

- `src/Encina.Compliance.Consent/ConsentErrors.cs` — the `SubjectDescription` constant and the five factories that use it instead of interpolating `subjectId` into `Message`.
- `src/Encina.Compliance.Consent/Abstractions/IConsentValidator.cs` — the XML doc example now logs `error.Code`.
- `tests/Encina.UnitTests/Compliance/Consent/ConsentErrorsTests.cs`, `ConsentRequiredPipelineBehaviorTests.cs` — updated assertions.
- `tests/Encina.PropertyTests/Compliance/Consent/ConsentErrorsPropertyTests.cs` — new property tests, with the GUID-suffix gotcha above.
