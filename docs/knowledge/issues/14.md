## Asked

Apply the Orchestrator pattern to the three validation packages (FluentValidation, DataAnnotations, MiniValidator) so the pipeline behavior exists once in the core package.

## Outcome

Delivered the same day by commit `fc36f4df` ("refactor: apply Orchestrator pattern to validation packages (#14)"); the maintainer closed the issue with a summary comment. No pull request. All code described exists in `src/` today and matches the description.

## Where the knowledge lives

- The orchestrator pattern for validation is in `AGENTS.md` section 3 ("Validation uses the orchestrator pattern") and in `src/Encina/Validation/`; each package has its `PublicAPI.Unshipped.txt` and README.
- The regression suites under `tests/Encina.{UnitTests,PropertyTests,ContractTests}/{FluentValidation,DataAnnotations,MiniValidator}` guard the behavior, with gaps tracked below.

## Audit

Verdict: `findings-tracked`. One new remediation issue, #1339 (no `ValidateOnBuild` DI proof test for FluentValidation and MiniValidator). Three gaps were already tracked and not duplicated: the README/`Exception` mismatch (#1330), DataAnnotations context, DI and cancellation tests (#1337), and the missing guard tests for all three providers (#1338). The `EncinaError.Message` logging finding is covered by #1319 (closed). See [docs/knowledge/audits/issue-14.md](../audits/issue-14.md).
