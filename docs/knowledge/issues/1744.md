## Asked

The prompt-text rule of `audit-stage-guard.ps1` blocked any `issue-worker` or `general-purpose` spawn whose prompt contained "SPEC-003 audit", including briefs that only change the audit tooling. It had to block only a spawn that runs an audit.

## Outcome

Delivered: the rule now matches an audit worktree (`wia-<n>`), an `audit/<n>` branch or the `artifacts/knowledge/stages/` folder, and the denial message names the matched marker and tells a tooling brief to name the files it changes instead; an empty `subagent_type` is covered too. `Test-Hooks.ps1` covers eight denials and the allowed tooling brief.

## Where the knowledge lives

- `.claude/hooks/audit-stage-guard.ps1` — the run-marker rule and its header comment.
- `.claude/hooks/tests/Test-Hooks.ps1` — the nine cases for the rule (eight denials, one allowed tooling brief).
