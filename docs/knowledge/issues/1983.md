## Asked

Make XACML target matches and condition attribute designators select values by (Category, AttributeId, DataType), as XACML 3.0 requires, because the evaluation context dropped attribute names and any value of a category satisfied any designator of that category (a user whose `subject-id` is `service` matched a target on `identity-kind == "service"`).

## Outcome

Delivered: `PolicyEvaluationContext` keeps one `AttributeBag` per attribute id, `AttributeContextBuilder.ToAttributeBags` replaces `ToBag`, and `TargetEvaluator` and `ConditionEvaluator` resolve designators through `Evaluation/AttributeDesignatorResolver.cs`. EEL conditions (`[RequireCondition]`) already read attributes by name and are unchanged; a test checks that both paths read the same values.

## Where the knowledge lives

- `src/Encina.Security.ABAC/Evaluation/AttributeDesignatorResolver.cs` — the one place a designator's values are selected.
- `tests/Encina.UnitTests/Security/ABAC/Evaluation/AttributeDesignatorSelectionTests.cs` — the issue's scenario, presence and data-type rules, XACML/EEL agreement.
- `tests/Encina.PropertyTests/Security/ABAC/AttributeDesignatorSelectionPropertyTests.cs` — a designator returns exactly its attribute's values of its data type.
