## Asked

Decide how to keep issues on user project 1 once the personal access token behind the hygiene workflow expires: renew it, replace it with a GitHub App, or drop it.

## Outcome

The maintainer chose to drop the token (2026-10-07); renewing it and a GitHub App were rejected. The workflow no longer writes to the project, and `open-remediation.ps1` adds its issues to project 1 itself.

## Where the knowledge lives

- `tools/ai/audit/open-remediation.ps1` — project add right after each issue is created, warning on failure.
- `tools/ai/issues/check-project-membership.ps1` — local, read-only by default: lists open issues not on project 1 (`-Add` adds them); self-test beside it.
- `.github/workflows/issue-hygiene.yml` — labels, comment and weekly summary with the default token.
- `.claude/skills/open-issue/SKILL.md` — step 4 is the caller's; revoke the old token and delete the secret after merge.
