## Asked

Make no singleton consume a scoped audit store: `ReadAuditRetentionService` must resolve `IReadAuditStore` per purge run through `IServiceScopeFactory`, with a DI test that builds the provider with `ValidateOnBuild` and `ValidateScopes`.

## Outcome

`ReadAuditRetentionService` takes `IServiceScopeFactory` and creates one async scope per purge run. Unit tests prove one scope per run with the store disposed with it; DI tests build the provider with `ValidateOnBuild` and `ValidateScopes`, `EnableAutoPurge = true` and the scoped ADO and Dapper stores. The Secrets hosted services take no audit store.

## Where the knowledge lives

- `src/Encina.Security.Audit/ReadAuditRetentionService.cs` — the scope per purge run.
- `tests/Encina.UnitTests/Security/Audit/ReadAudit/ReadAuditRetentionServiceRegistrationTests.cs` — the DI proof.
