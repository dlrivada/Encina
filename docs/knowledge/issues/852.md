## Asked

Validate the URL, endpoint and connection options found by the #849 self-audit so that a misconfigured or malicious endpoint (wrong scheme, plain http, loopback, link-local, metadata) cannot reach a client.

## Outcome

Delivered on branch `fix/endpoint-validation-852`: the public core helper `EndpointValidator` (with `EndpointPolicy` and `EndpointHostKind`), validators for HashiCorp Vault, both Azure Key Vault packages, AmazonSQS, NATS, MySQL CDC and Debezium, the attestation validator moved onto the helper, opt-out warnings with registered EventIds (new range `CdcMySql` 5400-5449), tests in four test projects and updated docs.

## Where the knowledge lives

- `src/Encina/Validation/EndpointValidator.cs` — host normalisation and classification, the strict policy.
- `src/Encina.*/*OptionsValidator.cs` — one validator per options class, registered for `ValidateOnStart` and run eagerly by each `Add*` method.
- `changelog.d/852-endpoint-validation.security.md` — the breaking changes.

Not audited yet (the issue is closed by this branch's PR).
