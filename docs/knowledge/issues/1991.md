## Asked

Make the five `DeadLetterOptions.IntegrateWith*` flags do what their documentation promises: a terminal failure of recoverability, outbox, inbox, scheduling or a saga is captured once into the dead letter queue, and a flag set to false captures nothing from its source.

## Outcome

Partly delivered through PR #2202 (`Refs #1991`): `DeadLetterSourceCapture`, `DeadLetterOrchestrator.AddSerializedAsync`, the capture points in the five sources, notification replay in `DeadLetterManager`, and unit, guard, DI and ten-provider integration tests. A capture the queue rejects (`dlq.capture_rejected`) records the source's terminal state instead of looping. The "saga not found" path (`SagaNotFoundContext.MoveToDeadLetterAsync`) is not wired: the identity of a not-found message waits for the decision in #2203.

## Where the knowledge lives

- `src/Encina.Messaging/DeadLetter/DeadLetterSourceCapture.cs` — the flag per source, the own-scope capture and failure reporting.
- `src/Encina.Messaging/DeadLetter/DeadLetterOptions.cs` — when each source captures (XML documentation of the five flags).
- `docs/features/dead-letter-queue.md` — "What each source captures".
- `docs/architecture/adr/046-persistent-dead-letter-queue.md` — decisions added with the source capture.
