## Asked

PR #1465 (#1457) added `artifacts/knowledge/stages/.rerun-archivist`, written by `tools/ai/audit/audit-done.ps1`
when the knowledge record fails validation, so `audit-stage-guard.ps1` can allow re-spawning `issue-archivist`
out of the pipeline's fixed order. A pr-reviewer review of that PR found two gaps: `enforce-path-ownership.ps1`
did not protect the marker, so any caller without a recognised agent could create it with a direct `Set-Content`
and force an out-of-order archivist re-spawn; and `audit-commit-stage.ps1 -Stage archivist` removed the marker
as soon as `knowledge-records --check` passed, before attempting `git add -f`/`git commit`, so a commit that
then failed with "nothing to commit" (a byte-identical record) silently lost the marker.

## Outcome

Delivered: `enforce-path-ownership.ps1` denies every direct Write/Edit/shell-write to `.rerun-archivist` for
every caller, mirroring the existing `.authors.json` rule exactly -- the marker's two sanctioned writers
(`audit-done.ps1`, `audit-commit-stage.ps1`) act from inside their own script text, which this hook's
shell-write analysis never inspects, so the deny never blocks either of them. `audit-commit-stage.ps1` now
holds the marker's original content in memory across the `git add -f`/`git commit` attempt and restores it
verbatim if either step fails (including "nothing to commit"), instead of deleting it unconditionally the
moment the record check passes; a successful commit still leaves it deleted permanently.

## Where the knowledge lives

- `.claude/hooks/enforce-path-ownership.ps1` -- the unconditional `.rerun-archivist` deny, next to
  `.authors.json`.
- `tools/ai/audit/audit-commit-stage.ps1` -- the marker's hold-and-restore logic around the archivist stage's
  `git add -f`/`git commit` attempt.
- `.claude/hooks/tests/Test-Hooks.ps1` -- the `#1466` ownership, shell-vector and "nothing to commit" cases.
