## Asked

#1454 fixed every call site in `Encina.Compliance.DataSubjectRights`, `Encina.Compliance.DPIA` and
`Encina.Compliance.Retention` that tagged an `EncinaError`'s raw `Message` on an OpenTelemetry
activity, but deliberately left a related, out-of-scope pattern: a **caught `System.Exception`'s
own `.Message`** (not `EncinaError.Message`) was still tagged on the same
`RecordFailed`/`RecordFailure`/`RecordAssessmentFailed` diagnostics helpers at five call sites,
listed in #1488's issue body. `AGENTS.md`'s rule itself reads "record only the error code **or the
exception type**", so this is the same defect class the rule already names, not a different rule.

## Outcome

Delivered: all five listed call sites now pass `ex.GetType().Name` instead of `ex.Message` —
`DefaultDSRService.HandleRestrictionAsync` in `Encina.Compliance.DataSubjectRights`;
`DPIAReviewReminderService.ExecuteReminderCycleAsync` and
`DefaultDPIAAssessmentEngine.AssessAsync` in `Encina.Compliance.DPIA`;
`RetentionValidationPipelineBehavior.Handle` and
`RetentionEnforcementService.ExecuteEnforcementCycleAsync` in `Encina.Compliance.Retention`. A
grep of every remaining `ex.Message` occurrence in the three packages confirmed no other
`RecordFailed`-style diagnostics helper call site was missed — the rest feed structured logging
methods or `*Errors.*` constructors, not an activity tag, and are out of this issue's scope.

New regression tests, one file per package, reuse #1454's `ActivityListener`/`MeterListener`
scoped-capture pattern with a sentinel exception message that must never appear in an activity tag
or status description, proving the leak is closed for each of the five call sites.

Two of the five touched methods (`DefaultDPIAAssessmentEngine.AssessAsync`,
`RetentionValidationPipelineBehavior.Handle`) failed the AGENTS.md CRAP gate on pre-existing
complexity the diff's one-line change triggered under diff attribution but did not introduce — see
the gotcha below. Both were refactored (extraction, not test-only) to clear the gate, following
#1454's precedent.
