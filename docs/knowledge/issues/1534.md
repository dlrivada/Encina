## Asked

`tools/ai/audit/audit-draft-remediation.ps1` (the SPEC-003 audit pipeline's remediation stage) had no way to
record a finding as a duplicate of a real open issue when `Test-DuplicateEvidence` (`_remediation-checks.ps1`,
#1393) could never accept it by design. Audit #18's docs finding 12 (`docs/messaging/index.md:45` referencing
the removed package `Encina.Dapper.Oracle`) is the exact case: open issue #1177 already reports this drift, but
only as item 6 of a numbered list inside its own Description section, which #1393 deliberately excludes from
evidence (a Description commonly just mentions a file/symbol without being about it). Every remediation run
therefore drafted a new duplicate issue for finding 12, and audit-verifier's own dedup pass then failed the
audit against the real duplicate #1177 -- a loop with no way to converge short of dropping a valid finding or
manually opening and closing a throwaway issue.

## Outcome

Delivered: `audit-draft-remediation.ps1` gains a repeatable `-DuplicateOf "<stage> <n>=<issue>"` parameter that
records the named finding as a duplicate of the given issue by explicit, logged override, confirmed by
`audit-verifier` or the orchestrator rather than guessed by the script or the local model. It format-validates
every entry up front, verifies (unless `-NoGh`) that each target is a real `OPEN` issue via `gh issue view`, and
errors when a key does not match a finding parsed from the stage artifacts -- all before touching any file. The
overridden finding's own line in `stages/remediation.md` reads exactly like an automatically detected
duplicate's line, plus `" (manual override)"`; when the overridden finding is the primary of a same-location
group (#1491), the whole group is recorded as that duplicate. Every override is logged under `## Lessons for
the pipeline`. `.claude/skills/issue-audit/SKILL.md` documents the rule, including the acceptance command for
audit #18's own case: `pwsh -NoProfile -File tools/ai/audit/audit-draft-remediation.ps1 -Only 'docs 12'
-DuplicateOf 'docs 12=1177'`. `Test-DuplicateEvidence`'s own evidence rules were left unchanged (the
list-item-evidence idea from the issue's Proposed Solution point 2 is a follow-up, not part of this fix).
