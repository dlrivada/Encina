## Asked

Register read/write separation on `Encina.ADO.PostgreSQL`, `Encina.ADO.MySQL`, `Encina.Dapper.PostgreSQL` and `Encina.Dapper.MySQL` when `MessagingConfiguration.UseReadWriteSeparation` is on, as the SQL Server, EF Core and MongoDB packages already do.

## Outcome

Each of the four `ServiceCollectionExtensions.cs` files now has a `RegisterReadWriteSeparation` method mirroring the SQL Server one, called from the `AddEncinaADO` or `AddEncinaDapper` entry point. DI tests build the provider with `ValidateOnBuild` and `ValidateScopes` for the enabled, no-replica and disabled cases, and integration tests on real PostgreSQL and MySQL containers show a query reaching the read database and a command the write database.

## Where the knowledge lives

- `src/Encina.ADO.PostgreSQL/ServiceCollectionExtensions.cs` and its three siblings: `RegisterReadWriteSeparation`.
- `tests/Encina.UnitTests/*/ReadWriteSeparation/ReadWriteRegistrationTests.cs`: registration completeness per provider.
- `tests/Encina.IntegrationTests/*/*/ReadWriteSeparation/ReadWriteRoutingRegistration*IntegrationTests.cs`: routing on real databases.
