## Asked

Stop `XacmlXmlPolicySerializer` from putting `XmlException` and parse-failure messages into the activity status (`ABACDiagnostics.RecordPapFailure`) and into the `ABACErrors.DeserializationFailed` errors it returns, as AGENTS.md section 3 requires.

## Outcome

Fixed together with #1700. The four catch blocks and the two wrong-root-element branches of `DeserializePolicySet` and `DeserializePolicy` pass the exception type name or a fixed reason to the activity and the log, and build the error reason from the exception type.

## Where the knowledge lives

- `src/Encina.Security.ABAC/Persistence/Xacml/XacmlXmlPolicySerializer.cs` — the redacted catch blocks.
- `tests/Encina.UnitTests/Security/ABAC/ExceptionMessageRedactionTests.cs` — sentinel tests for the error, the activity and the log output.
