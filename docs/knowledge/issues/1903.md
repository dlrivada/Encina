## Asked

Fix `ProblemDetailsExtensions.MapErrorCodeToStatusCode` (and its Azure Functions and AWS Lambda siblings) so the `encina.authorization.*` codes map to 401 and 403 instead of 500.

## Outcome

The three mappers compare against `EncinaErrorCodes.AuthorizationUnauthenticated` and the new `EncinaErrorCodes.AuthorizationPrefix`. The unit tests cover every authorization code per adapter and an unknown `encina.authorization.*` code, which fails closed to 403.

## Where the knowledge lives

- `src/Encina/Errors/EncinaErrorCodes.cs` — the code constants and the shared prefix.
- `src/Encina.AspNetCore/ProblemDetailsExtensions.cs`, `src/Encina.AzureFunctions/HttpResponseDataExtensions.cs`, `src/Encina.AwsLambda/ApiGatewayResponseExtensions.cs` — the three mappers.
- `tests/Encina.UnitTests/AspNetCore/ProblemDetailsExtensionsTests.cs`, `tests/Encina.UnitTests/AzureFunctions/HttpResponseDataExtensionsTests.cs`, `tests/Encina.UnitTests/AwsLambda/ApiGatewayResponseExtensionsTests.cs` — the status proofs.
