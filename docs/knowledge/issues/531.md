## Asked

Find why the `Encina.UnitTests.DistributedLock` tests hung, fix them so they run reliably, and put them back in CI.

## Outcome

Delivered on branch `fix/531-distributed-lock-tests-hang`: the InMemory and Redis lock providers wait between retries on the injected `TimeProvider`, try at least once, and (InMemory) remove entries with compare-and-remove; the unit tests drive a `FakeTimeProvider` with no wall-clock waits, and the duplicate `Base/` copy of the InMemory tests is gone. CI already ran the tests again.

- `src/Encina.DistributedLock.InMemory/InMemoryDistributedLockProvider.cs` — retry loop on the injected clock, compare-and-remove.
- `src/Encina.DistributedLock.Redis/RedisDistributedLockProvider.cs` — retry loop on the injected clock.
- `tests/Encina.UnitTests/DistributedLock/InMemoryDistributedLockProviderTests.cs` — fake-clock tests of wait, retry, expiry and takeover.
- `tests/Encina.UnitTests/DistributedLock/Redis/RedisDistributedLockProviderTests.cs` — fake-clock retry tests with a mocked `IDatabase`.
