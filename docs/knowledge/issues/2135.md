## Asked

Make operation audit store queries and exports return a total, stable order so paged reads never repeat or drop entries, and check the read audit and entity-change audit stores for the same single-key sort.

## Outcome

Every operation audit, read audit and entity-change audit store (ADO.NET, Dapper and EF Core on SQL Server, PostgreSQL and MySQL; MongoDB; Marten; the in-memory stores) now orders by the timestamp and then by the entry id. Integration tests on real databases page through entries sharing one timestamp. EF Core on MySQL stays skipped until Pomelo supports EF Core 10.

## Where the knowledge lives

- `tests/Encina.IntegrationTests/Security/Audit/OperationAuditStableOrderCheck.cs` — the shared paged-walk check every operation audit store runs.
- `tests/Encina.IntegrationTests/Security/Audit/ReadAuditStableOrderCheck.cs` — the same check for the read audit stores.
