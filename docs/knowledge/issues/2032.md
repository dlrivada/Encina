## Asked

Make the shadow sharding behaviors (`ShadowWritePipelineBehavior`, `ShadowReadPipelineBehavior`) run when shadow sharding is enabled, after they were registered only under the CQRS-specific service types that the pipeline never resolves.

## Outcome

`AddShadowSharding` registers both behaviors as `IPipelineBehavior<,>` open generics with `TryAddEnumerable`. A unit DI test (`ValidateOnBuild`, `ValidateScopes`) shows each behavior in the right pipeline and absent when shadow sharding is off, and sending a command and a query through `IEncina` triggers the shadow routing. An integration test on sharded SQL Server shows the shadow write and the shadow read comparison happening against real databases.

## Where the knowledge lives

- `src/Encina/Sharding/Shadow/ShadowShardingServiceCollectionExtensions.cs` — the registration under `IPipelineBehavior<,>`.
- `tests/Encina.UnitTests/Core/Sharding/Shadow/ShadowShardingPipelineRegistrationTests.cs` — pipeline membership and end-to-end Send.
- `tests/Encina.IntegrationTests/Sharding/ADO/SqlServer/ShadowShardingPipelineTests.cs` — shadow write and read comparison on real shards.
