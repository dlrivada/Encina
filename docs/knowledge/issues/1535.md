## Asked

`Limit-RelatedIssues` (`tools/ai/audit/_remediation-checks.ps1`) strips an unverified `#n` reference from a
remediation draft, but when that reference was the leading or sole number of a Related Issues list item (e.g.
`- #910 - [TEST] Increase coverage ...`), it removed only the `#n` token and left the rest of the bullet behind.
This produced three broken Markdown shapes, all found in audit #18's live drafts under
`artifacts/knowledge/remediation/`: a doubled list marker with no link (`- - [TEST] title`, 18-tests-1 through
18-tests-4), a dangling colon (`-: [DEBT] title`, 18-docs-13 and 18-docs-14), and a bare `-` line with no content
(18-docs-5). Published as-is, these lines would be broken Markdown with related-issue titles carrying no link to
their issue number.

## Outcome

Delivered: `Limit-RelatedIssues` now drops the whole bullet line when the stripped reference is the bullet's own
leading token (with or without bold wrapping, followed by `-`, `:`, or nothing at all) AND the line falls inside
an actual Related Issues region (the `## Related Issues` H2, the `- **Related Issues**:` bold-bullet field, or the
plain `Related Issues:` line -- the same three conventions `Add-RelatedIssuesLine` already recognizes); a reference
elsewhere in the draft's own prose still gets only the token removed, unchanged from before. The region scoping was
added after `pr-reviewer` on PR #1550 found the first version dropped ANY disallowed-leading-token bullet anywhere
in the draft, which would have deleted real prose bullets in Additional Context/Root Cause/Proposed Fix. A second
adversarial-review round of that fix then found the two field conventions' own region was still bounded too
loosely (any contiguous bullet/blank run, not distinguishing a genuine sibling bullet of the field from an
unrelated one written afterward with no separating heading); the region is now bounded by indentation instead,
established by the field's own first sub-bullet, which still covers both the real indented-sub-bullet shape and
#1400's unindented-sibling shape while excluding a genuinely less-indented, unrelated bullet. A `## Related Issues`
section left with no bullets at all after this gets the line `None.` under its still-present header. Each of the
three broken shapes and both rounds of the region-scoping fix's own in-region/out-of-region cases were confirmed
against origin/main's unmodified script, or against the pre-fix commit, before landing. A companion case in the
existing `#1534` block proves naming a non-primary member of a same-location group records the whole group as
duplicate, the same as naming the primary -- confirming existing behavior rather than changing it.

## Where the knowledge lives

- `tools/ai/audit/_remediation-checks.ps1` -- `Limit-RelatedIssues`'s Related Issues region detection (reusing
  `Add-RelatedIssuesLine`'s three conventions, the two field forms' region bounded by the first sub-bullet's own
  indentation), the bullet-leading-reference regex gated by that region, and the empty-section `None.` insertion,
  all added at the end of its per-line loop.
- `.claude/hooks/tests/Test-Hooks.ps1` -- the `#1535` block (the three broken shapes, the bold-bullet variant, the
  empty-section case, the two out-of-region prose cases, the in-region bold-bullet/plain-line cases, and the
  indentation-boundary over-extension case) and the new non-primary-member case in the existing `#1534` block.
