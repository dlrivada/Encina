## Asked

Two of the project's own PreToolUse hooks, `guard-orchestrator-writes.ps1` (for the orchestrator) and `block-main-checkout-writes.ps1` (for a writing worker), blocked running the hook regression suite itself, `.claude/hooks/tests/Test-Hooks.ps1`, from the very sessions `.claude/agents/README.md` tells to run it after changing a hook. Both hooks decide "does this script write into the repository?" with a text heuristic that only checks whether the launched script's own text contains a write-API call and a `src/`/`tests/` substring, never where the write actually lands; `Test-Hooks.ps1` legitimately contains both, but every write it performs resolves under `$env:TEMP`, never the repository.

## Outcome

Delivered: `_write-targets.ps1` gained `Test-ScriptIsSanctioned`, a narrow repository-relative path allowlist for the pipeline's own tooling (`.claude/hooks/tests/Test-Hooks.ps1`, `tools/ai/audit/*.ps1`, `tools/ai/*.ps1`, `.github/scripts/*.cs`); both hooks skip the write-API/reference check for a script that matches it, while an unreadable or unresolved script, or a script whose repository-relative path does not match, still goes through the existing heuristic. `Test-Hooks.ps1` gained a delimited `#1368/#1380` block covering the allowlist's positive and negative cases directly against the real hooks.

## Where the knowledge lives

- `.claude/hooks/_write-targets.ps1` — `Test-ScriptIsSanctioned` and `$SanctionedScriptPatterns`, the allowlist itself.
- `.claude/hooks/guard-orchestrator-writes.ps1`, `.claude/hooks/block-main-checkout-writes.ps1` — the exemption wired into each hook's `Scripts` loop, and the updated header comments.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#1368/#1380` regression block (cases a-e) and `Get-FlatOutput` (shared with #1380).
