## Asked

Nine stream-request/pipeline-behavior tests failed with "No handler registered for StreamNumbersQuery -> IAsyncEnumerable<Int32>". The issue's own diagnosis: `IStreamRequestHandler<,>` was not scanned/registered by `AddEncina`, unlike `IRequestHandler<,>`.

## Outcome

Delivered same-day by a direct commit (c993620085f2077c81b6e1b176bf7a3b20396aaa, 2025-12-22), no PR: added `IStreamRequestHandler<,>`/`IStreamPipelineBehavior<,>` branches to the assembly scanner and matching `RegisterStreamHandlers`/`RegisterStreamPipelineBehaviors` calls in `AddEncina`, and fixed `StreamPipelineBehaviorTests` to stop scanning the test assembly (avoiding double registration).

## Where the knowledge lives

- The decision is encoded as executable code: `src/Encina/Dispatchers/MediatorAssemblyScanner.cs` (the stream handler and stream pipeline branches) and `src/Encina/Core/ServiceCollectionExtensions.cs` (`RegisterStreamHandlers`/`RegisterStreamPipelineBehaviors`), present today.
- The regression test the audit found missing (AUD-06) was added by #1317 (closed by PR #1598): `tests/Encina.UnitTests/Core/AddEncinaServiceGraphTests.cs` drives the scan to discover a stream handler and a stream pipeline behavior.

## Audit

Verdict: `findings-tracked`. One Major finding (AUD-06: no regression test for the scanned-discovery path) was added to the existing issue #1317, since closed. The pre-existing legacy alias in the same file (`AddApplicationMessaging`) is tracked by #1318; no new issue was needed. Full detail: [docs/knowledge/audits/issue-1.md](../audits/issue-1.md).
