## Asked

The repository holds hundreds of open issues with no ordered, quantitative view of what to do
first, and a newly opened issue had no defined position relative to the existing backlog. Issue
#1552 asked for a repeatable pipeline scoring every open pre-1.0 issue against 8 weighted
criteria (Unblocking, Importance, Regulatory/reference-app risk, Transversality, Method
acceleration, inverse Effort, Fit with 1.0, Age), with per-criterion justifications, maintainer
overrides, and a single-issue mode so a freshly opened issue is placed immediately.

## Outcome

Partial: `tools/ai/priority/` (`_priority-lib.ps1`, `collect-issues.ps1`, `score-issues.ps1`,
`rubric.md`, `overrides.json`, `Test-Priority.ps1`) implements the full scoring model exactly as
specified — deterministic scores in pure, unit-tested PowerShell functions, one local-model call
per issue for the judged criteria, overrides applied last, ranking with the specified tie-break,
and both `-All` (full recompute) and `-Issue <n>` (single new issue) modes. The 56-case
`Test-Priority.ps1` self-test passes with no `gh` or model dependency, and `-Issue 1552` was run
live end to end (real `gh issue view`, a real local-model call, ranking, and a ledger line at
`artifacts/local-ai/ledger.csv`). What is NOT delivered by this record: the acceptance criterion's
`-All -Limit 15` live sample run across the real backlog, because `collect-issues.ps1`'s
`gh api graphql` call is blocked for an issue-worker by `block-worker-publish.ps1` (decision 1's
GraphQL choice is always a POST, which that hook cannot distinguish from a mutation). The
orchestrator runs that verification; see the pending-work item above for the exact command.

## Where the knowledge lives

- `tools/ai/priority/_priority-lib.ps1` — the deterministic scoring functions, the dependency-
  keyword regex, the effort-checkbox parser, `Get-PriorityRankedList`/`Get-PriorityTotal`, override
  merging, and the model-JSON parsing/validation helpers used by both scripts and the self-test.
- `tools/ai/priority/collect-issues.ps1` — the paged `gh api graphql` collection and the reverse
  dependents map.
- `tools/ai/priority/score-issues.ps1` — the `-All`/`-Issue` orchestration, the local-model call
  per issue (with retry-once-then-unscored), `scores.json`/`board.json` generation.
- `tools/ai/priority/rubric.md` — the fixed 0/25/50/75/100 anchors the local model scores against.
- `tools/ai/priority/Test-Priority.ps1` — the 56-case self-test (age cap, every milestone mapping,
  the three effort-checkbox shapes, dependency parsing including the "see #n" exclusion, total/rank/
  tie ordering, class assignment, override application, invalid-model-JSON handling).
- `.claude/skills/open-issue/SKILL.md` §4 — the new step scoring a freshly created issue and
  reporting its rank, plus the weekly `-All` re-run note.
- `.claude/agents/README.md` and `docs/engineering/ai-task-routing.md` — the pipeline's routing
  entry (local model for the judged criteria, deterministic PowerShell for the rest, `-All` from
  the orchestrator only).
