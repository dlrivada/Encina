## Asked

The OpenTelemetry decorators set the activity status description from `EncinaError.Message` or `Exception.Message` when the wrapped call fails, so SQL fragments, key values or personal data could reach the trace exporter. The status must carry the error code or the exception type name.

## Outcome

Fixed on branch fix/2134-otel-status-no-messages. New public helper `ActivityStatusDescriptions` in `Encina.Diagnostics`; all decorators (audit, repository, bulk operations, unit of work, query cache, outbox, saga, scheduled message stores, inbox, dead letter) and the activity sources they call use it. The same defect in the ProcessingActivity registries, the read-audit repositories, the CDC cache handler, and the encryption, sanitization and secret-injection pipeline behaviors is fixed too.

## Where the knowledge lives

- `src/Encina/Diagnostics/ActivityStatusDescriptions.cs` - the helper.
- `src/Encina.OpenTelemetry/` `Instrumented*.cs` - the decorators.
- `tests/Encina.UnitTests/OpenTelemetry/ActivityStatusNeverCarriesMessagesTests.cs` - per-family listener tests.
