## Asked

Make `IRequestContextScopeFactory.RunAsPrincipalAsync` refuse a principal with conflicting tenant claims, as the inbound path already does, instead of opening an anonymous scope with the option tenant.

## Outcome

`RunAsPrincipalAsync` resolves the tenant with `TryResolveTenantId` and returns `encina.identity.conflicting_tenant_claims` before opening the scope. The work delegate never runs. The README and changelog warn that differing values across the configured claim types are refused.

## Where the knowledge lives

- `src/Encina/Identity/RequestContextScopeFactory.cs` — the conflict check in `CheckPrincipalTenant`.
- `src/Encina/Identity/RequestIdentityErrors.cs` — `ConflictingTenantClaims()`.
- `src/Encina.AspNetCore/README.md` — the claim-types warning.

## Audit

Not audited yet. Conflicting or missing subject claims still map to Anonymous on both paths; a follow-up issue was drafted.
