## Asked

Stop the ADO.NET audit and anonymization stores from interpolating raw exception messages into the `EncinaError` they return, because a driver message can carry constraint names, column names or values.

## Outcome

Fixed together with #2445 for every provider of the four compliance store families. The error factories now take the exception and write only its type name into the message; the exception stays on `EncinaError.Exception`. The repository-wide sweep stays with #2130 and the older umbrella #1134.

## Where the knowledge lives

- `src/Encina.Security.Audit/OperationAuditErrors.cs` and `ReadAuditErrors.cs` — the shared audit store error factories.
- `src/Encina.Compliance.Anonymization/AnonymizationErrors.cs` and `src/Encina.Compliance.GDPR/GDPRErrors.cs` — the token mapping and processing activity factories.
- `tests/Encina.UnitTests/Compliance/StoreFailures/` — the per-provider proof that a failing store never leaks the exception message.
