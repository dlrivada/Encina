## Asked

Since #2827 the published coverage summary marks a package with no coverage data as `measured: false` and lists it in `unmeasuredPackages`. The release-readiness `CoverageFlags` reader ignored both: an unmeasured package with manifest targets was reported as below target on every flag with coverage "n/a", and one without targets was skipped silently.

## Outcome

Delivered: the collector lists unmeasured packages as their own fact and the evaluator fails with a distinct "not measured" message, with or without targets, while per-flag failures stay for measured packages only. The self-test gained an evaluator case and a collector case fed with a summary that has an unmeasured package with targets, one without, and a measured package below target.

## Where the knowledge lives

- `.github/scripts/release-readiness.cs` — `CoverageFlags` (collector and evaluator) and the self-test case "coverage flags: an unmeasured package is its own failing fact".
- `.github/scripts/fixtures/release-readiness/evaluator-cases.json` — the evaluator case for a not-measured package.
