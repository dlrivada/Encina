## Asked

Two FluentValidation property tests failed because the error structure changed during the Mediator-to-Encina rename: they cast `error.Exception` directly although it is an `Option<Exception>`.

## Outcome

Delivered exactly as scoped by direct commit `3f20fec8f4ebbe98317be9ec02e8b9755ed19dc2` (2025-12-23, also `Fixes #7`); the maintainer closed the issue manually with a comment. No pull request exists. The fixed test file no longer exists: it was deleted on 2025-12-29 by `d7b7b8ac`, and the behavior it protected drifted with the #14 refactor (`ValidationOrchestrator.cs` now leaves `Exception` as `None`).

## Where the knowledge lives

- Regression test for the `error.Exception` invariant: missing, and moot until #1330 decides what shape the structured errors reach callers in.
- `src/Encina.FluentValidation/README.md` still documents the pre-#14 behavior; tracked by #1330 (open).
- The manifest `.github/coverage-manifest/Encina.FluentValidation.json` requires only `unit` and `guard` flags, so the missing property assertion is not a manifest violation.

## Audit

Verdict: `findings-tracked`. The regression-test and README findings are not net-new: they are the defect already tracked by #1330, so no new remediation issue was opened. See [docs/knowledge/audits/issue-11.md](../audits/issue-11.md).
