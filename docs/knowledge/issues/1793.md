## Asked

Make Encina.Security.PII fail closed: no code path returns or emits personal data unmasked because masking failed.

## Outcome

Invalid or slow regex patterns mask the whole value, every regex has a timeout option, the response pipeline returns an error instead of the unmasked response, object and audit masking rethrow instead of returning the original, and get-only PII properties are no longer skipped. Catch sites judged safe: `PIILoggerExtensions.LogMasked` (logs a placeholder and the exception type only), `PIIMasker.MaskObject` (rethrows) and both `PIIHealthCheck` catches (only the exception type reaches the result).

## Where the knowledge lives

- `src/Encina.Security.PII/PIIMasker.cs` — fail-closed pattern masking, rethrow on failure, post-deserialization check.
- `src/Encina.Security.PII/PIIMaskingPipelineBehavior.cs` — `pii.masking_failed` error instead of the unmasked response.
- `src/Encina.Security.PII/PIIOptionsValidator.cs` — `RegexTimeout` validation.
- `src/Encina.Security.PII/Internal/PIIPropertyScanner.cs` — get-only PII properties kept.
