## Asked

Verify whether `[CryptoShredded]` ignores subject ids that are not `string`, as #1149 found for the data-subject-rights stores, and fix it.

## Outcome

Confirmed and fixed: a `Guid`, integer or strongly-typed subject id made the serializer read `null` and persist the personal-data field unencrypted. The subject id is now resolved with the shared `SubjectIdConversion`, and the startup scan rejects unsupported types.

## Where the knowledge lives

- `src/Encina.Marten.GDPR/Metadata/CryptoShreddedField.cs` — `ResolveSubjectId`, the single place that reads the subject id (since #1698).
- `src/Encina.Marten.GDPR/CryptoShreddingStartupValidationHostedService.cs` — the startup validation (since #1698).
- `docs/features/crypto-shredding.md` — supported subject-id types and the erase-key spelling.
