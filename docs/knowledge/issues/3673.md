## Asked

Part of #3617: give `Encina.Tenancy` a coded tenant-not-found error and make `TenantConnectionFactoryBase<TConnection>` fail closed, so the provider factories (#3674, #3675, #3676) can reuse the error; remove the dead `ThrowOnMissingConnectionString` option.

## Outcome

`src/Encina.Tenancy/TenancyErrors.cs` adds `tenancy.tenant_not_found` (`NotFound`) and `tenancy.tenant_required` (`InvalidRequest`). `TenantConnectionFactoryBase` returns the first for an unknown tenant id, explicit or current, without creating a connection, and the second for no tenant while `TenancyOptions.RequireTenant` is true. `TenantConnectionOptions.ThrowOnMissingConnectionString` is gone, and the `ITenantConnectionFactory` documentation describes the fail-closed order.

## Where the knowledge lives

- `src/Encina.Tenancy/TenancyErrors.cs` — the codes and their categories.
- `src/Encina.Tenancy/Data/TenantConnectionFactoryBase.cs` — the fail-closed resolution.
- `tests/Encina.UnitTests/Tenancy/TenantConnectionFactoryBaseTests.cs` — the behavior, pinned.

## Known limits

- A known tenant without a connection string still gets the default database (separate issue of #3617).
- The base class does not log the denial; it has no logger.
