## Asked

Event-sourced systems accumulate events and their schemas evolve. The issue asked for event upcasting (v1 to v2 to v3), schema evolution strategies, version metadata on events and migration tooling, with an `IEventUpcaster<TFrom, TTo>` interface, an upcasting pipeline and integration with Marten's existing versioning, in `Encina.Marten`, later `Encina.EventStoreDB`, and core `Encina` abstractions.

## Outcome

Delivered by commit 957093c2 (2025-12-26, `Fixes #37`, no PR): the `Versioning` folder of `Encina.Marten` (interfaces, `EventUpcasterBase`, `LambdaEventUpcaster`, `EventUpcasterRegistry`, `EventVersioningOptions`, `ConfigureMartenEventVersioning`, error codes, `VersioningLog`), plus options and DI registration hooks, a CHANGELOG entry and tests. The issue was opened 2025-12-24T13:23:48Z and closed 2025-12-26T21:37:39Z. Not delivered: core `Encina` abstractions, `Encina.EventStoreDB` (the package does not exist), dedicated migration tooling. Property tests named in the commit message no longer exist in `tests/Encina.PropertyTests`. The open bug #1914 reports dead code in the failure policy.
