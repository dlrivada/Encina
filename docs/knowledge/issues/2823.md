## Asked

Make the issue-creation hook apply the same local-draft evidence, template and metadata checks to issue creation through the REST API (`gh api ... -X POST`) as to `gh issue create`, and deny a GraphQL `createIssue` mutation, after issue #2822 was created over REST when the hook had blocked the equivalent `gh issue create`.

## Outcome

Implemented in `.claude/hooks/check-issue-template.ps1` with cases in `.claude/hooks/tests/Test-Hooks.ps1`; documented in the open-issue skill and the agents README. `gh issue create` and `gh issue edit` behave as before.

## Where the knowledge lives

- `.claude/hooks/check-issue-template.ps1` - the REST and GraphQL detection, the shared template and label functions, the three-column milestone cache.
- `.claude/hooks/tests/Test-Hooks.ps1` - the REST, GraphQL and milestone-cache cases.
- `.claude/skills/open-issue/SKILL.md` - the sanctioned REST route when the GraphQL quota is exhausted.

## Audit

Not audited. Known gaps recorded as follow-ups: an inline `-f body=` passes like `gh issue create --body`; a splatted or variable `gh` program and direct HTTP (`Invoke-RestMethod`) are invisible to the hook; unquoted `{owner}` braces in Bash split the statement.
