## Asked

Execute everything in `PostgresCdcConnector` that a unit test can reach without a PostgreSQL server, justify in the coverage manifest what only a live server reaches, and cover that part with the integration flag.

## Outcome

Unit tests now run the constructor guards, `ConnectorId`, the failure paths against a refused local port (returning `Left` without the exception message), cancellation, the saved-position restore branches and the health check. Real integration tests run the connector against a PostgreSQL 17 container started with `wal_level=logical` through the shared `CDC-PostgreSQL` collection fixture, replacing the old `PostgreSql.md` justification file. The connector is measured mostly by the integration flag and the server-free paths by the unit flag (figures on the coverage dashboard); the manifest carries per-file targets and justifications for both flags. The tests also exposed four connector defects, recorded above and opened as follow-up bugs (#2776, #2777, #2778, #2779) because this change is tests-only.

## Where the knowledge lives

- `.github/coverage-manifest/Encina.Cdc.PostgreSql.json` - the unit and integration targets and what each flag really runs.
- `tests/Encina.UnitTests/Cdc/PostgreSql/PostgresCdcConnectorTests.cs` and `PostgresCdcHealthCheckTests.cs` - the server-free paths.
- `tests/Encina.IntegrationTests/Cdc/PostgreSql/` - the collection fixture and the live-server tests.
