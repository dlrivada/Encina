## Asked

Make the contract, guard and property flags of Encina.Compliance.Consent reach their manifest targets with tests that execute the real package code, or establish and fix the cause of the 0 readings.

## Outcome

The cause was that coverage-report.cs computes a flag's package row only over the files whose manifest entry lists that flag, so the existing tests executed files that were not assigned to those flags. New tests were added: ConsentRequiredPipelineBehaviorContractTests for the contract flag, ConsentValidationPropertyTests for the property flag (covering the two validators), and ConsentFailClosedGuardTests for the guard flag. The package row figures are on the coverage dashboard.
