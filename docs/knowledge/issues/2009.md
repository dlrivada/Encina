## Asked

Stop four reported hook false positives from blocking valid read-only commands: `git checkout main 2>&1` read as a write, a `Select-String` regex read as a `Remove-Item` path, `pwsh -File "$wt\script.ps1"` denied for the orchestrator and read-only reviewers, and `git archive` denied for `pr-reviewer`, while every real block stays.

## Outcome

Three of the four were caused by hooks of this repository and are fixed in `_write-targets.ps1`, `guard-orchestrator-writes.ps1` and `block-worker-publish.ps1`, each with regression cases in `Test-Hooks.ps1`. The second is caused by Claude Code's own permission check; the cause and the workaround are documented in `.claude/agents/README.md`.

## Where the knowledge lives

- `.claude/hooks/_write-targets.ps1` — redirection tokens are not pathspecs; stream merges versus `>&file`; `git archive --output` as a write target.
- `.claude/hooks/guard-orchestrator-writes.ps1` — the narrow literal-assignment rule for variable script paths.
- `.claude/hooks/block-worker-publish.ps1` — `git archive` allowed, `--remote`, `--exec` and `tar.*` denied.
- `.claude/agents/README.md` — the hook table and the Limits entries, including the built-in check and its workaround.
