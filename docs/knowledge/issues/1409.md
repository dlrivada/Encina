## Asked

`tools/ai/audit/audit-draft-remediation.ps1` could not produce a clean `[BUG]` draft for a code-stage finding:
`bug_report.md`'s `## Environment` section asks for facts (Encina version, .NET version, OS) the local model
has no way to know, so the model leaves the template's own placeholders, the one re-ask does not change that,
and the run exits 1 with `PLACEHOLDERS LEFT`. Observed on 2026-09-27 during the remediation re-run of audit #16
(after #1405 merged): 22 findings, 21 clean drafts, and one draft kept with the Encina/.NET Version and OS
placeholders untouched.

## Outcome

Delivered: a new `Set-BugEnvironment` function (in `tools/ai/audit/_remediation-checks.ps1`) overwrites the
whole `## Environment` section body of a `bug_report.md`-routed draft with four deterministic facts, called
from `audit-draft-remediation.ps1`'s `Repair-Draft` after the model replies and the outer-fence strip, but
before `Find-TemplatePlaceholders` runs -- so the model's own guess at these facts is never what decides
whether the draft is clean. `Build-DraftBrief` also now tells the model the same facts for a bug-routed
finding, so its own prose stays consistent with the section the script keeps. Routing, duplicate detection,
`Limit-RelatedIssues` and the re-ask logic are unchanged.

## Where the knowledge lives

- `tools/ai/audit/_remediation-checks.ps1` -- `Set-BugEnvironment`, `Get-EncinaVersion`,
  `Get-PackageFromFindingText`, `Test-PlaceholderEnvironmentValue`.
- `tools/ai/audit/audit-draft-remediation.ps1` -- `Repair-Draft` calls `Set-BugEnvironment` for every
  `bug_report.md`-routed draft, before `Find-TemplatePlaceholders`; `Build-DraftBrief` adds the matching
  Environment guidance note for a bug-routed finding.
- `.claude/hooks/tests/Test-Hooks.ps1` -- the `#1409` block exercising `Set-BugEnvironment` and
  `Get-EncinaVersion` directly with plain strings and a throwaway `Directory.Build.props` fixture, no `gh` and
  no local model.
