## Asked

Issue #12's SPEC-003 audit found that `Encina.EntityFrameworkCore` and `Encina.MongoDB` never called the shared `AddMessagingServices<...>` helper in `Encina.Messaging.MessagingServiceCollectionExtensions` that the six ADO.NET/Dapper packages use; each hand-rolled its own `UseOutbox`/`UseInbox`/`UseSagas`/`UseScheduling` registration blocks, which had drifted: MongoDB never registered `InboxPipelineBehavior<,>` against `IPipelineBehavior<,>` (Inbox idempotency silently never ran), and neither EF Core nor MongoDB registered `ISagaRunner` or `ISagaNotFoundDispatcher` (both throw `InvalidOperationException` on first resolution). No DI test caught either gap.

## Outcome

Delivered: `Encina.Messaging.MessagingServiceCollectionExtensions` gained `AddOutboxInboxSagaSchedulingServices<...>`, a granular overload of the Outbox/Inbox/Saga/Scheduling registration logic that takes individual flags and options instead of a `MessagingConfiguration`. `AddMessagingServices<...>` (used by ADO.NET and Dapper) now delegates to it internally with no behavior change. `Encina.EntityFrameworkCore.ServiceCollectionExtensions` and both `Encina.MongoDB.ServiceCollectionExtensions.AddEncinaMongoDB` overloads now call the new method directly, closing the Inbox and Saga gaps. EF Core's own DbContext-bound `TransactionPipelineBehavior` stays registered separately, since it is not interchangeable with the generic `Encina.Messaging.TransactionPipelineBehavior` ADO.NET and Dapper share — discovered by a failing test during the first (too-broad) migration attempt. New `ValidateOnBuild`/`ValidateScopes` DI tests per provider resolve `ISagaRunner`, `ISagaNotFoundDispatcher` and the `InboxPipelineBehavior<,>` registration, verified to fail against the pre-fix code and pass against the fix.

## Where the knowledge lives

- `src/Encina.Messaging/MessagingServiceCollectionExtensions.cs` — `AddOutboxInboxSagaSchedulingServices<...>`, the granular Outbox/Inbox/Saga/Scheduling helper shared by every provider.
- `src/Encina.EntityFrameworkCore/ServiceCollectionExtensions.cs` — calls the shared helper for Outbox/Inbox/Saga/Scheduling; keeps its own `TransactionPipelineBehavior` registration.
- `src/Encina.MongoDB/ServiceCollectionExtensions.cs` — both `AddEncinaMongoDB` overloads call the shared helper.
- `tests/Encina.UnitTests/EntityFrameworkCore/ServiceCollectionExtensionsTests.cs`, `tests/Encina.UnitTests/MongoDB/ServiceCollectionExtensionsExtendedTests.cs` — the registration-completeness regression tests.
