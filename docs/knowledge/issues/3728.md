## Asked

Make every error the ADO.NET provider packages create declare its `ErrorCategory`, so the three ADO lines of the completeness scan's pending file can be deleted.

## Outcome

All 64 calls in 26 files carry `ErrorCategory.Internal` and the three pending lines are deleted. Nothing changes for callers: each call answered HTTP 500 before and still does. Eleven calls (`MissingColumnMappings` in the four mapping builders of each provider) cannot be reached through the public API, because `HasId` always adds a column mapping; the static scan is their check. The three code-less `EncinaError.New` calls of `TenantConnectionFactory` stay `Internal` by the 500 fallback (ADR-062 "Known limit").

## Where the knowledge lives

- `src/Encina.ADO.SqlServer/`, `src/Encina.ADO.PostgreSQL/`, `src/Encina.ADO.MySQL/` - the categorized calls.
- `tests/Encina.UnitTests/ADO/AdoErrorCategoryTests.cs` - the category of each reachable producer, in all three providers.
- `docs/architecture/adr/062-error-category-contract.md` - the contract.
