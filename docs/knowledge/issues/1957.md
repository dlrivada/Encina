## Asked

Make `SagaHealthCheck` report Unhealthy, with only the error code in its message and data, when `GetStuckSagasAsync` or `GetExpiredSagasAsync` returns `Left`, instead of counting the failure as zero problematic sagas and reporting Healthy.

## Outcome

Delivered: `SagaHealthCheck` returns Unhealthy on either `Left` through a `StoreFailure` helper that mirrors `OutboxHealthCheck`. The test that asserted Healthy was rewritten, and a "saga" row joined the leak theory. The sibling health checks of `Encina.Messaging` (Outbox, Inbox, Scheduling, DeadLetter) already failed closed. A CDC position-store `Left` deliberately reports Degraded in `Encina.Cdc`; this PR leaves that unchanged.

## Where the knowledge lives

- `src/Encina.Messaging/Health/SagaHealthCheck.cs` — the fail-closed store-failure path.
- `tests/Encina.UnitTests/Messaging/Health/SagaHealthCheckTests.cs` — Unhealthy on each `Left`, no message leak.
- `tests/Encina.UnitTests/Messaging/Encryption/ErrorMessageLeakTests.cs` — the health-check leak theory, now with the saga row.
