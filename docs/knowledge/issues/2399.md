## Asked

Make the verified tenant claim win in the three request-facing tenancy integrations, deny a client-supplied tenant that disagrees with it, and make a tenant header an explicit, logged, trusted-source-only fallback, with `RequireTenant` failing closed by default.

## Outcome

Delivered in the ASP.NET Core resolver chain and middleware, the AWS Lambda and Azure Functions `ResolveTenantId` extensions, the options and their startup validation, tests for each rule, the corrected feature pages and package READMEs, and a security changelog fragment.

## Where the knowledge lives

- `src/Encina.Tenancy.AspNetCore/Resolution/TenantResolverChain.cs` — authoritative-first resolution and mismatch detection.
- `src/Encina.Tenancy.AspNetCore/Configuration/TenancyAspNetCoreOptionsValidator.cs` — startup failure for an untrusted header resolver.
- `src/Encina.AwsLambda/LambdaContextExtensions.cs` and `src/Encina.AzureFunctions/FunctionContextExtensions.cs` — the cloud tenant rules.
- `docs/features/multi-tenancy.md` — user-facing resolution order and trust settings.

## Audit

Not audited. Encina.GoogleCloudFunctions is post-1.0 (SPEC-000 DEC-003), so the GCP side of the cloud triangle has no equivalent yet; `Encina.AspNetCore` still reads the tenant header without a trust decision (follow-up issue file drafted by the docs-writer).
