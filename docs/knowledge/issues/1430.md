## Asked

`ExecuteAsync_WithUnknownNotificationType_MarksAsFailed` in the PostgreSQL ADO.NET outbox suite (and the same pattern repeated across every provider's `OutboxProcessorTests`) started a real `OutboxProcessor` hosted service, waited a fixed `Task.Delay(500)`, cancelled, then asserted `store.Received().MarkAsFailedAsync(...)`. On a loaded CI runner the fixed wait can expire before the processor's first cycle ran, producing a flaky failure that violates AGENTS.md §9 (no `Thread.Sleep`-style synchronisation, deterministic tests). The issue also flagged `DateTime.UtcNow` in test message data as non-deterministic, and asked for the same fix across every `OutboxProcessorTests` and `InboxProcessorTests` for all providers.

## Outcome

Delivered for every processor test class that exists. Across `tests/Encina.UnitTests/ADO/{SqlServer,PostgreSQL,MySQL}/Outbox/OutboxProcessorTests.cs`, the three `Dapper/*/Outbox/OutboxProcessorTests.cs` (plus their extra `ExecuteAsync_WithExhaustedRetries_DoesNotScheduleNextRetry` test), `EntityFrameworkCore/Outbox/OutboxProcessorTests.cs`, `Messaging/Processors/DeadLetterCleanupProcessorTests.cs` and `Messaging/Processors/DelayedRetryProcessorTests.cs`:

- Every `start; Task.Delay(n); cancel; assert` is replaced by a `TaskCompletionSource` completed from the substitute call the test asserts on (or the last expected call in a chain: e.g. `SaveChangesAsync` for the "processes and marks processed" test), awaited with `.WaitAsync(TimeSpan.FromSeconds(10))` before cancelling.
- Negative/loop assertions (`callCount.ShouldBeGreaterThan(1)`) wait for a positive signal that a second cycle ran (`callCount >= 2`) instead of a fixed delay.
- Tests whose processor returns immediately (`EnableProcessor = false`, no `RetentionPeriod`, or a processing interval far longer than the test, as in the EF Core `StartAsync_CompletesSuccessfully` test) drop the wait: `StartAsync` completing means the loop was never entered, so there is nothing to wait for.
- `DateTime.UtcNow` in outbox message and delayed-retry message test data was replaced with a fixed `DateTime` (`FixedCreatedAtUtc` per file, or an inline fixed timestamp for `DelayedRetryProcessorTests`' `CreateMockMessage`).
- No shared cross-file helper was extracted: the transformation is a few lines per test and each provider file already differs enough (constructor argument order, notification type names, `Either<...>` construction style) that a shared helper would add indirection without removing real duplication; `DelayedRetryProcessorTests.cs` already had two tests using this exact TCS pattern from an earlier fix, which this issue's changes now match consistently across the whole file.

Out of scope, found and reported as follow-ups rather than fixed:

- `tests/Encina.UnitTests/Cdc/Sharding/ShardedCdcProcessorTests.cs` has the identical `Task.Delay` pattern six times, but CDC processors are not outbox/inbox/scheduled-message processors and the brief's scope named only those plus core Messaging processor tests.
- MongoDB has no `OutboxProcessorTests.cs`, and no provider has an `InboxProcessorTests.cs` or `ScheduledMessageProcessorTests.cs` — only outbox has a dedicated hosted-processor unit test today, so the fix is complete for every class that exists.

Verification: `dotnet build` clean (0 warnings); the 97 tests across all nine changed classes passed 10 consecutive `dotnet test --no-build` runs and again under two parallel `dotnet test` processes running concurrently (CPU contention simulation); `dotnet format --verify-no-changes` reported no changes for the changed files.

## Where the knowledge lives

- `tests/Encina.UnitTests/ADO/{SqlServer,PostgreSQL,MySQL}/Outbox/OutboxProcessorTests.cs` — TCS-based synchronisation, fixed timestamps.
- `tests/Encina.UnitTests/Dapper/{SqlServer,PostgreSQL,MySQL}/Outbox/OutboxProcessorTests.cs` — same, including the exhausted-retries test unique to Dapper.
- `tests/Encina.UnitTests/EntityFrameworkCore/Outbox/OutboxProcessorTests.cs` — delay removed (processor never enters its loop in that test).
- `tests/Encina.UnitTests/Messaging/Processors/DeadLetterCleanupProcessorTests.cs` — TCS on `DeleteExpiredAsync`, delays removed for the disabled/no-retention-period tests.
- `tests/Encina.UnitTests/Messaging/Processors/DelayedRetryProcessorTests.cs` — TCS on the scope/service lookup or `GetPendingMessagesAsync`, fixed message timestamps.
