## Asked

Stop the hooks from denying read-only commands run through the Bash tool when they contain Windows paths with backslashes, because the shared Bash tokenizer rewrote `"C:\Users\a\b.ps1"` to `C:Usersab.ps1`.

## Outcome

The Bash double-quoted branch of `Split-CommandStatements` now follows Bash (D1), so a quoted Windows path survives and the same mangling no longer hides write targets. Of the six reported symptoms, S1 (double-quoted path) is fixed here; S2 (unquoted path) matches Bash and is unchanged (D2); S3 (variable path) stays denied (D4); S4 (scratchpad script naming repository paths) was fixed by #2892 and S6 (relative script path with an empty base) by #3281. S5 (`gh pr comment --body-file`) was not confirmed as a tokenizer bug: `orchestrator-delegation-guard.ps1:141-142` denies it by design in a marked orchestrator session.

## Where the knowledge lives

- `.claude/hooks/_command-text.ps1` — the Bash double-quoted branch of `Split-CommandStatements`.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#3229` block after the `#1854` block, and the unchanged variable-path pins of `#1854`/`#2009`.
