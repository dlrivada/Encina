## Asked

Rename the multi-tenancy option `ThrowOnMissingTenantContext` to `RequireTenantContext` in `Encina.MongoDB` and `Encina.Messaging`, because MongoDB returns a `Left` with `Repository.TenantRequired` instead of throwing.

## Outcome

Delivered in the rename; there is no changelog fragment here, because one fragment for all of #3005 is written by the last sub-issue.

## Where the knowledge lives

- `src/Encina.MongoDB/Tenancy/MongoDbTenancyOptions.cs` — the option is renamed to `RequireTenantContext` (default `true`) with XML docs that describe the refusal as a `Left`.
- `src/Encina.Messaging/Tenancy/TenancyMessagingOptions.cs` — the same rename; the messaging package reads no behaviour from it, and `AddEncinaEntityFrameworkCore` copies it into the EF Core options.
- `docs/features/multi-tenancy.md` — names each provider's option and describes its real behaviour.
