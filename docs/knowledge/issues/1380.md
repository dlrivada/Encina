## Asked

A `Test-Hooks.ps1` case added by PR #1378 for #1375 (the missing `## Findings` header case) passed for the issue-worker (619 cases, 0 failed, run from the worktree) and failed for the maintainer from a plain terminal on the same commit, just before the merge. The case asserted a literal multi-word phrase against captured child-process stderr; PowerShell wraps a rendered `ErrorRecord` at the host's console width even when stderr is redirected, so the phrase split across two lines in a narrow terminal and the regex no longer matched, with no code difference between the two runs.

## Outcome

Delivered: `Get-FlatOutput` (join captured lines with a space, collapse whitespace) was added to `Test-Hooks.ps1` and every `-match` over captured child-process output in the `#1374` and `#1375` blocks now compares against `Get-FlatOutput`'s result, so the assertions no longer depend on console width. A dedicated case proves `Get-FlatOutput` reconstructs a phrase deliberately wrapped across two lines. A narrow-width run of the full suite (`$Host.UI.RawUI.BufferSize` narrowed before invoking the script) was attempted as part of the companion fix (#1368) verification; in the non-interactive host used, the buffer size could not be narrowed below its minimum, so the narrow-width reproduction itself could not be exercised end to end, but the suite still passed at 631 cases, 0 failed with the new width-insensitive assertions in place.

## Where the knowledge lives

- `.claude/hooks/tests/Test-Hooks.ps1` — `Get-FlatOutput` and its use across the `#1374`/`#1375` blocks' `-match` assertions, plus its own regression case.
