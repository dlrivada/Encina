## Context

Created 2025-12-24T13:24:09Z, closed 2025-12-25T08:29:03Z (completed) with the single comment "Implemented saga timeout support in commit 3cc4d57. See CHANGELOG.md for details." The issue asked for a NServiceBus-style `RequestTimeout<T>()` on the saga context, per-step timeouts, timeout handlers, configurable retry and scheduler integration.

## Outcome

Partial. Commit 3cc4d57b (authored 2025-12-25T09:28:43+01:00 = 08:28:43Z, 20 seconds before the close at 08:29:03Z) delivered the persistence and orchestrator primitives for all supported providers (EF Core, Dapper, ADO.NET, MongoDB; the Oracle and SQLite copies it also touched were removed later under ADR-009 and ADR-024), with unit tests for the EF store and the state factories. The message-style `RequestTimeout<T>()` API, handlers, dispatch and scheduler integration were not built.

## Where the knowledge lives

- `src/Encina.Messaging/Sagas/ISagaState.cs`, `ISagaStore.cs`, `SagaOrchestrator.cs` (timeout API, options, `SagaStatus.TimedOut`); `SagaErrorCodes.cs` (`saga.timeout`).
- Provider stores: `SagaStoreEF`, `SagaStoreDapper` (SqlServer, PostgreSQL, MySQL), `SagaStoreADO` (same three), `SagaStoreMongoDB`.
- `CHANGELOG.md`, entry "Saga timeout support (Issue #38)".

## Audit

Verdict: `findings-tracked`. Twenty-two remediation issues were opened (#2206-#2227): seven bugs (among them the SQL Server saga DDL scripts that cannot hold a saga, #2206, and timeouts that are recorded but never enforced, #2208), four debt items (one code, three documentation), eleven test items. Docs 4 is held by #1885 and tests 11 by #1887, with comments posted there and on #1470. Full detail: [docs/knowledge/audits/issue-38.md](../audits/issue-38.md).
