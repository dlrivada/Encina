## Asked

Make the scheduler persist each cycle's outcomes on EF Core, where `ScheduledMessageStoreEF` records processed, failed and rescheduled messages only on the tracked `DbContext`, so a due message no longer runs again on every cycle.

## Outcome

`SchedulerOrchestrator` saves the batch outcomes after the batch and returns a failed save as the cycle's `Left`. Regression tests run three cycles per EF Core provider (SQL Server, PostgreSQL; MySQL is skipped until Pomelo supports EF Core 10).

## Where the knowledge lives

- `src/Encina.Messaging/Scheduling/SchedulerOrchestrator.cs` — the save after the batch and its error handling.
- `tests/Encina.IntegrationTests/Infrastructure/EntityFrameworkCore/Scheduling/SchedulerCycleScenarios.cs` — the per-cycle regression scenarios.
- `tests/Encina.UnitTests/Messaging/Scheduling/SchedulerOrchestratorTests.cs` — save once per cycle, Left propagation, no save when nothing is due.
