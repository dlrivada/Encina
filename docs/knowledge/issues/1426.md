## Asked

`GDPRErrors.ConsentNotFound` (`Encina.Compliance.GDPR`) wrote the raw data subject id straight into
its `EncinaError`'s structured `details` dictionary (`["subjectId"] = subjectId`). Same defect class
as #1350 (`Encina.Compliance.Consent`, fixed by PR #1417) and #1415
(`Encina.Compliance.DataSubjectRights`, `Encina.Marten.GDPR`, fixed by PR #1427), this time in a
third package that neither earlier sweep had covered. `details` reaches anything that serializes
`EncinaError` metadata; `ConsentNotFound`'s `Message` text never embedded the subject id (unlike the
DSR/crypto-shredding factories #1415 fixed), so only `details` needed the fix.

## Outcome

Delivered: the `["subjectId"] = subjectId` entry is removed from `ConsentNotFound`'s `details`
dictionary. Factory signature and error code (`gdpr.consent_not_found`) are unchanged. A grep of every
`GDPRErrors` factory confirmed `ConsentNotFound` was the only one with a subject-id-shaped parameter,
and a grep of `src/` and `tests/` confirmed no caller reads the removed `details["subjectId"]` key.
Regression tests: `GDPRErrorsSubjectIdLeakTests.cs` (per-factory unit assertions, with and without the
optional `subjectId` argument) and `GDPRErrorsSubjectIdLeakPropertyTests.cs` (one FsCheck property
test proving the invariant for 100 arbitrary GUID-suffixed subject ids). An adversarial review of the
fix found a related but out-of-scope fourth sibling — `LawfulBasisValidationPipelineBehavior` logs the
raw subject id and `EncinaError.Message` on every consent check — written up as a follow-up issue
rather than folded into this fix, since it is a different leak channel (logging, not `EncinaError`
metadata) in a different package.

## Where the knowledge lives

- `src/Encina.Compliance.GDPR/GDPRErrors.cs` — `ConsentNotFound` no longer writes `subjectId` into
  `details`; its XML doc for the `subjectId` parameter now states the identifier is never surfaced.
- `tests/Encina.UnitTests/Compliance/GDPR/GDPRErrorsSubjectIdLeakTests.cs` (new) — per-factory leak
  assertions.
- `tests/Encina.PropertyTests/Compliance/GDPR/GDPRErrorsSubjectIdLeakPropertyTests.cs` (new) — FsCheck
  property test with the GUID-suffix technique from #1350/#1415.
- `changelog.d/1426-gdpr-errors-subject-id.security.md` — user-visible changelog fragment.
- `artifacts/issues/lawfulbasis-subjectid-log-leak.md` (in the issue's worktree, not yet opened) —
  follow-up issue for the `LawfulBasisValidationPipelineBehavior` logging leak found during review.
