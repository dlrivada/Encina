## Asked

Make the fast CI run the test jobs for every change that can alter a test result, not only for `src/` and a suite's own folder, and fix the comment on the `build` condition so it describes the real rule.

## Outcome

Delivered: the `changes` job of `ci.yml` exposes a `shared` filter, and the `build` job and all six test jobs also run when it is true. `ci-result` still treats a skipped job as success, so a docs-only PR stays green without running tests.

## Where the knowledge lives

- `.github/workflows/ci.yml` — the `shared` filter and the `if:` of `build` and of each test job.
- `docs/releases/RELEASE-PROCESS.md` — the release-page items #1747 and #1748, written in the same change.
