## Asked

Create fluent assertion extensions for `Either<EncinaError, T>` results (`ShouldBeSuccess`, `ShouldBeError`, value extraction, error code and message assertions, chaining) in `Encina.Testing`, with 100% unit coverage, contract tests and FluentAssertions compatibility.

## Outcome

Closed 2025-12-24 (created 13:26Z, closed 18:11Z) by commit 8ebf437b with no PR. The commit delivered the success/error, error-code, validation and authorization assertions with async variants. The surface grew in the Encina.Testing package (AndConstraint, collections, streaming, NotFound and property variants) and in Encina.Testing.Shouldly. Partial against the issue text: three proposed names, FluentAssertions support and contract tests were not delivered as written.
