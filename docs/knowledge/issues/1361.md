## Asked

Make the dashboard publishers fail loudly instead of concluding `skipped` when their source run did not succeed, add a scheduled check that flags any GitHub Pages dashboard whose `latest.json` is older than a threshold, and settle the fate of the stale data copies tracked under `docs/*/data`.

## Outcome

Delivered together with #1381 in one pull request: the job-level `if` is gone from the four publishers, whose first step now fails with a named error when the source run did not succeed; `dashboard-freshness.cs` and the daily `dashboard-freshness.yml` flag any dashboard older than 8 days; the "persist to main" steps are removed. The tracked `docs/*/data` copies stay for now because scripts and fallbacks still read them; their removal is a follow-up.

## Where the knowledge lives

- `.github/workflows/publish-coverage.yml`, `publish-mutations.yml`, `publish-benchmarks.yml`, `publish-load-tests.yml` — the fail-loud first step of each data job.
- `.github/scripts/dashboard-freshness.cs` and `.github/workflows/dashboard-freshness.yml` — the freshness check.
- `docs/testing/coverage-measurement-methodology.md` — publishing flow and the note that the live Pages data is authoritative.
