## Asked

Stop the AI Act compliance validator from classifying a request whose resolved AI system id is not registered as minimal risk with no violations, which let unclassifiable systems through the pipeline in every mode.

## Outcome

`DefaultAIActComplianceValidator` now returns a high-risk result with one violation for an unregistered resolved system id. The existing pipeline denies it in Block (the default) and logs a warning in Warn; Disabled never reaches the validator. Unit tests cover the validator and the pipeline with the real validator in all three modes.

## Where the knowledge lives

- `src/Encina.Compliance.AIAct/DefaultAIActComplianceValidator.cs` — the unregistered-system branch and the unchanged no-system-id branch.
- `src/Encina.Compliance.AIAct/Abstractions/IAIActComplianceValidator.cs` — contract: direct callers get the Right result, only the pipeline enforces.
- `tests/Encina.UnitTests/Compliance/AIAct/AIActCompliancePipelineBehaviorTests.cs` — Block, Warn and Disabled with the real validator.
