## Asked

Let the read-only reviewer subagents (`adversarial-reviewer`, `pr-reviewer`) run the gate self-test `dotnet run --file .github/scripts/release-readiness.cs -- --self-test`, which `guard-orchestrator-writes.ps1` denied as a script that references `src/` or `tests/` and writes files, while a write to `src/` or `tests/` and a variable script path stay denied.

## Outcome

The root cause was `Get-RepoLocation` not recognising a registered worktree outside `.claude\worktrees`; the fix itself landed in #3244 (PR #3473). This issue adds the regression cases in `.claude/hooks/tests/Test-Hooks.ps1` that prove a reviewer is allowed in the main checkout, in a worktree under `.claude\worktrees` and in a registered worktree outside it, and that a `src/` or `tests/` write, a variable script path and a lookalike script in an unregistered folder stay denied. The hook code is unchanged.

## Where the knowledge lives

- `.claude/hooks/_write-targets.ps1` — `SanctionedScriptPatterns` and `Test-ScriptIsSanctioned`, the allowlist by path.
- `.claude/hooks/guard-orchestrator-writes.ps1` — resolves the script with `Get-RepoLocation` and skips the text heuristic when it is sanctioned.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#3115` block with the regression cases.
