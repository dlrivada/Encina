## Asked

Two issue-workers on 2026-09-27 reported that `tools/ai/local-ai-ask.cs` (and, for one, `.github/scripts/knowledge-records.cs`)
did not exist in their worktrees, so they skipped the mandatory local-model first draft for follow-up issue files
and, for one, the `knowledge-records --check` step. The orchestrator verified with PowerShell `Test-Path` that
both files exist in both worktrees and are tracked by git. A third worker (#1426) had already identified that
the Bash tool in this environment is Git Bash, which silently mangles Windows backslash paths passed to `git -C`
and quoted arguments, and mis-parses `$_` and here-docs -- the likely cause of the false "missing" reports.

## Outcome

Delivered: removed `Bash` from the `tools:` front matter of all 13 agent definitions in `.claude/agents/*.md`,
leaving `PowerShell` and every other tool unchanged, so no subagent can invoke the Bash tool at all and the
Git Bash path-mangling failure mode is structurally impossible for workers. Added one sentence to the
worker-brief skill's fixed part instructing every worker to use the PowerShell tool for every command because
its definition has no Bash tool. Left the `"Bash|PowerShell"` PreToolUse hook matchers in each agent's
`hooks:` front matter and the hook-behavior table in `.claude/agents/README.md` unchanged, since those still
guard the main orchestrator session (which keeps Bash) and a matcher naming an absent tool is inert.
