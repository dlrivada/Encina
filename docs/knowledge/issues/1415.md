## Asked

`DSRErrors` (`Encina.Compliance.DataSubjectRights`) and `CryptoShreddingErrors` (`Encina.Marten.GDPR`) built `EncinaError.Message` with the raw data subject id interpolated into the text, and — worse than the sibling `ConsentErrors` defect fixed by #1350/#1417 — also put the subject id straight into the error's structured `details` dictionary. Both channels reach a consumer: `Message` reaches `Encina.AspNetCore.ProblemDetailsExtensions.ToProblemDetails`'s `ProblemDetails.Detail` unfiltered, and `details` reaches anything that serializes `EncinaError` metadata. Eight `DSRErrors` factories (`RestrictionActive`, `ErasureFailed`, `ExportFailed`, `ExemptionApplies`, `SubjectNotFound`, `LocatorFailed`, `RectificationFailed`, `ObjectionRejected`) and six `CryptoShreddingErrors` factories (`SubjectForgotten`, `EncryptionFailed`, `DecryptionFailed`, `KeyRotationFailed`, `InvalidSubjectId`, `KeyAlreadyExists`) were affected. The packages' own XML doc examples (`IDataPortabilityExporter`, `IDataErasureExecutor`) and the `Encina.Marten.GDPR` README also modeled logging `error.Message` directly.

## Outcome

Delivered: all 14 factories now build their message with the non-identifying description "the specified data subject" (a `SubjectDescription` constant in each file) instead of the interpolated `subjectId`, preserving reason/field/purpose/format context that was already present, and the subject id was removed entirely from `details` (no `subjectId` key remains in any of the 14). Factory signatures and error codes are unchanged. `IDataPortabilityExporter`'s and `IDataErasureExecutor`'s XML doc examples, and the `Encina.Marten.GDPR` README's two affected examples, now read `GetCode()` instead of `Message`. Regression tests: existing unit tests were flipped from asserting the subject id was present to asserting it is absent; two new leak-focused unit test files assert per-factory that neither `Message` nor any `details` value contains a sentinel subject id; two new FsCheck property test files (`DSRErrorsPropertyTests.cs`, `CryptoShreddingErrorsPropertyTests.cs`) prove the invariant holds for arbitrary non-empty subject ids, using the GUID-suffix technique from #1417 to avoid shrinker collisions.

## Where the knowledge lives

- `src/Encina.Compliance.DataSubjectRights/DSRErrors.cs` — the `SubjectDescription` constant and the eight factories that use it instead of interpolating `subjectId` into `Message`, and no longer write it into `details`.
- `src/Encina.Marten.GDPR/CryptoShreddingErrors.cs` — the same treatment for the six crypto-shredding factories; `InvalidSubjectId`'s message no longer echoes the caller-supplied value at all (not even for the null case).
- `src/Encina.Compliance.DataSubjectRights/Abstractions/IDataPortabilityExporter.cs`, `IDataErasureExecutor.cs` — XML doc examples now log `error.GetCode()`.
- `src/Encina.Marten.GDPR/README.md` — the "Forget a Subject" and "Key Rotation" examples now log `e.GetCode().IfNone("encina.unknown")`.
- `tests/Encina.UnitTests/Compliance/DataSubjectRights/DSRErrorsTests.cs`, `DSRErrorsExtendedTests.cs`, `DSRErrorsSubjectIdLeakTests.cs` (new) — updated and new assertions.
- `tests/Encina.UnitTests/Marten/GDPR/CryptoShreddingErrorsTests.cs`, `CryptoShreddingErrorsSubjectIdLeakTests.cs` (new) — updated and new assertions.
- `tests/Encina.GuardTests/Marten/GDPR/CryptoShreddingHappyPathGuardTests.cs` — two guard tests updated (`InvalidSubjectId_NullAllowed` no longer expects `"(null)"`; `KeyAlreadyExists` no longer expects the raw one-letter subject id back in the message).
- `tests/Encina.PropertyTests/Compliance/DataSubjectRights/DSRErrorsPropertyTests.cs`, `tests/Encina.PropertyTests/Marten/GDPR/CryptoShreddingErrorsPropertyTests.cs` — new property tests, with the GUID-suffix gotcha above.
