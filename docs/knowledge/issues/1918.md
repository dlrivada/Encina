## Asked

`Encina.Security` returned `security.*` error codes that `ProblemDetails`, the Azure Functions and the AWS Lambda adapters did not recognise, so a denied or unauthenticated request answered 500 instead of 401 or 403.

## Outcome

Maintainer option B (2026-10-06): `Encina.Security` emits the `encina.authorization.*` family. The four denial codes are 403 through the prefix rule, `unauthenticated` and the missing security context are 401, and `EncinaErrors.Unauthorized()` is a denial while `EncinaErrors.Unauthenticated()` is new. The ABAC enforcement point adopts the same unauthenticated code in #1705 Phase 4 (decision of 2026-10-07).

## Where the knowledge lives

- `src/Encina/Errors/EncinaErrorCodes.cs` — the `Authorization*` constants.
- `src/Encina.Security/SecurityErrors.cs` — the factories that emit them.
- `src/Encina/Results/EncinaErrors.cs` — `Unauthorized()` (403) and `Unauthenticated()` (401).
- `src/Encina.Security/README.md` — the error code table.
