## Asked

The ABAC PEP evaluated a request as user `""` when there was no security context, and the PDP's whole-store `EvaluateAsync` decided on the policy sets alone when the standalone policies could not be read. Both violate "compliance and security gates fail closed" (AGENTS.md section 3; SPEC-002 DEC-006). Make both deny, log by code only, and keep exception messages out of logs and errors.

## Outcome

Delivered on branch fix/abac-pep-pdp-fail-closed-1676; closed is the expected merge date and the orchestrator corrects it if the PR merges later. The PEP returns `abac.missing_context` in every enforcement mode before collecting attributes (EventId 9091); `EvaluateAsync` is Indeterminate on any failed retrieval (9092) or unexpected error (9093). `ABACErrors.EvaluationFailed` and the PEP's activity tag no longer carry the exception message. The docs pages and the package README were updated.

- `src/Encina.Security.ABAC/Evaluation/XACMLPolicyDecisionPoint.cs` - `EvaluateAsync` and `EvaluateWholeStoreAsync`.
