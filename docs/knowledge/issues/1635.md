## Asked

Make every `AddEncina*` method that registers a pipeline behavior leave that behavior in the pipeline whichever package registered a behavior first, and warn at startup when a known security behavior is missing.

## Outcome

All 22 `TryAddTransient(typeof(IPipelineBehavior<,>), ...)` sites in `src/` now use `TryAddEnumerable(ServiceDescriptor.Transient(...))`. A unit test proves both behaviors are present in both registration orders for every ordered pair of the 23 registrations, that repeated calls add each behavior once, and that Security with ABAC, Audit with Security, and Validation with Transaction resolve from a scope of a provider built with `ValidateOnBuild` and `ValidateScopes`. The startup warning is left to a follow-up.

## Where the knowledge lives

- `tests/Encina.UnitTests/Core/PipelineBehaviorRegistrationTests.cs` — the order-independence proof.
- `src/Encina.Security/ServiceCollectionExtensions.cs` — the registration pattern every package follows.
