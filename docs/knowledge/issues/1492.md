## Asked

The verifier for Audit #17 failed four passes on 2026-09-27, each pass costing about 130k tokens, because
regenerating every remediation draft to fix ONE detail re-rolled every OTHER draft's own already-correct model
choices: a `[DEBT]` draft's `## Type` checkbox flipped between "Documentation gap", "Refactoring needed" and
"Incorrect implementation" across re-runs for findings whose stage/kind never changed, and a draft cited `#1372`
(an unrelated package-count issue) in its own Description prose, which `Limit-RelatedIssues` -- scoped only to a
labelled Related Issues section, or (for `bug_report.md`) the whole `Additional Context` section -- never
looked at. Regenerating all drafts on every verifier `FAIL` made the loop fail to converge.

## Outcome

Delivered: (1) the `## Type` checkbox of a `technical_debt.md`-routed draft is now decided deterministically by
the script (`Get-DeterministicDebtType`/`Set-DebtType` in `_remediation-checks.ps1`, wired into
`Repair-Draft` the same way `Set-BugEnvironment` already handles bug_report.md's `## Environment`), from the
finding's stage and, for a code-stage finding, the classifier's own kind, with a keyword override in each
branch for the two exact audit #17 failures. (2) `Limit-RelatedIssues`' allowed-set rule now scans the WHOLE
draft body for every `#n` reference (skipping a fenced code block and the header HTML comment), not only a
labelled section, removing just the disallowed token (and a bare enclosing parenthetical) rather than the whole
line, so the rest of the sentence stays readable. (3) `audit-draft-remediation.ps1` takes a new, repeatable
`-Only "<stage> <n>"` parameter that regenerates only the named finding(s), leaving every other finding's own
draft, input, brief and `stages/remediation.md` line completely untouched -- proven end to end with a fixture
that backdates an untouched file's mtime and shows it survives an `-Only` run unchanged. `Test-Hooks.ps1` covers
all three fixes directly (no `gh`, no local model), and the one pre-existing `#1428` test that asserted the
narrower, now-superseded `Limit-RelatedIssues` scope was updated to assert the new global scope in the same
commit.
