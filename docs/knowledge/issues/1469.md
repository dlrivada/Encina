## Asked

Stop a saga step's raw `ex.Message` from reaching the returned `EncinaError.Message`, the logs, the persisted `ISagaState.ErrorMessage` column (and through it the saga activity tag and `SagaStateSnapshot.ErrorMessage`), as AGENTS.md section 3 requires.

## Outcome

Delivered in `SagaRunner` and `SagaOrchestrator`: the exception path persists the error code, returns a generic message with the inner exception, and logs only the exception type plus the exception object; cancellation persists `saga.handler.cancelled`; the orchestrator's `errorMessage` parameters became `errorCode`. The same pattern still exists in other runners of `Encina.Messaging` and is tracked by a separate umbrella debt issue.

## Where the knowledge lives

- `src/Encina.Messaging/Sagas/LowCeremony/SagaRunner.cs` — the exception, cancellation and compensation paths.
- `src/Encina.Messaging/Sagas/SagaOrchestrator.cs` — `FailAsync` and `StartCompensationAsync` with the `errorCode` parameter and its documentation.
- `tests/Encina.UnitTests/Messaging/Encryption/ErrorMessageLeakTests.cs` — sentinel regression tests (see #1483).
