## Asked

`tools/ai/audit/audit-draft-remediation.ps1` (#1375) wrote remediation drafts the audit verifier rejected on audit #16, blocking its FAIL loop: 3 of 4 "duplicate-of" claims named a real candidate issue that covered a different defect (only `Test-ValidDuplicate` checked the number was among the candidates offered, never that it was the same problem), one draft was wrapped in an outer ` ```markdown ` fence, and one draft kept five of `test_implementation.md`'s own placeholder markers verbatim.

## Outcome

Delivered: a new `tools/ai/audit/_remediation-checks.ps1` adds `Get-FindingAnchors`, `Test-DuplicateEvidence` (file anchor + symbol anchor, both matched against the candidate's real `gh issue view` title/body, exact-token symbol equality, generic `UseXxx` toggles excluded), `Remove-OuterFence` (strips one outer fence) and `Find-TemplatePlaceholders` (built from the templates themselves). `audit-draft-remediation.ps1` applies all three before writing a draft, passes each candidate's body excerpt to the classifier, appends a "possibly related" note when a duplicate claim is rejected, re-asks once on leftover placeholders, and exits 1 naming any draft that still has placeholders after the re-ask. `Test-Hooks.ps1` gained a delimited `#1388` block replaying audit #16's own four duplicate claims and two real drafts as fixtures.

## Where the knowledge lives

- `tools/ai/audit/_remediation-checks.ps1` — the four pure checks (anchors, duplicate evidence, fence stripping, placeholder detection).
- `tools/ai/audit/audit-draft-remediation.ps1` — where the checks are wired into the drafting flow (candidate body fetch and cache, evidence gate, fence/placeholder repair with one re-ask, the "possibly related" note, the final non-zero exit).
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#1388` regression block, with fixtures under `.claude/hooks/tests/fixtures/1388/` (the real `gh issue view` output for #1333/#1328/#1170/#1177 and the real audit #16 finding paragraphs and drafts).

## Audit

Not yet audited under SPEC-003 (`audit.verdict: not-audited`); reviewed by `adversarial-reviewer` against this issue's acceptance criteria during implementation. That review caught one blocker (`gh issue view $Number --json title, body` had a stray space, splitting into two argv tokens and making `gh` reject the call — so the whole candidate-fetch/evidence-check path would have failed on the first real run) and one major (bare file names with no path prefix, e.g. `` `MessagingConfiguration.cs` ``, were left in the symbol-anchor pool instead of being excluded like a bare `UseXxx` toggle); both were fixed in this same change before merge. A further hardening idea the review raised but left as a follow-up — excluding or de-weighting a verbatim AGENTS.md/CLAUDE.md rule quote (e.g. `` `EncinaError.Message` ``) from symbol evidence, since several unrelated findings quote the same house rule verbatim — is tracked separately rather than folded into this fix.
