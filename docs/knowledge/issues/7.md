## Asked

Issue #7 requested fixing 57 failing tests across 15 packages that were causing SonarCloud CI failures, initially addressed by temporarily excluding test suites from the CI workflow.

## Outcome

The issue was resolved by directly committing a temporary CI filter to exclude failing tests, followed by specific code fixes for test compatibility issues in SQLite, DataAnnotations, and FluentValidation packages (no pull request; closed by commit 3f20fec8, "Fixes #7"). A later commit re-enabled the tests, and the temporary filter mechanism was subsequently replaced by a matrix-sharded CI system.

## Where the knowledge lives

- CustomValidationAttribute public-type gotcha: routine .NET behaviour, not a project rule; the resulting coverage gap (no test exercises the scenario today) is tracked by #1330 (open).
- EncinaError.Exception is Option<Exception> gotcha: already the standard LanguageExt Option-access convention; the coverage gap (no test asserts on `Exception` for a validation failure) is tracked by #1330.
- SQLite datetime gotcha: none (code removed, ADR-024).
- Temporary CI exclusion filter: none (superseded by the matrix-sharded CI in `.github/workflows/ci.yml`).
- README/code mismatch found during this audit (new, not from issue #7 itself): `src/Encina.DataAnnotations/README.md` and `src/Encina.FluentValidation/README.md`, tracked by #1330.

## Audit

Verdict: findings-tracked. One major finding (the DataAnnotations and FluentValidation READMEs document `EncinaError.Exception = Some(ValidationException)` for a validation failure, but `ValidationOrchestrator.ValidateAsync` always leaves `Exception` as `None`) and two minor coverage-gap findings (no test exercises `CustomValidationAttribute`/`ValidationContext`; no test locks in the `Exception`-stays-`None` invariant). All three are grouped in [docs/knowledge/audits/issue-7.md](../audits/issue-7.md) and the remediation issue #1330.
