## Asked

Encina publishes several sites and data feeds (documentation, DocFX API reference, coverage/mutation/benchmark/load-test dashboards, the maintainer's private control board) with no single list and nothing watching them as a whole; three failures went unnoticed for weeks until the maintainer found them by hand (#1361, #1381). This issue adds a versioned registry, a `site-health` skill and a read-only `site-steward` agent on top of the CI checks already landed in #1361/#1381.

## Outcome

Delivered, all three parts of #1382 on this branch: `tools/ai/sites.json` (schema 1) lists all seven published sites and feeds; `dashboard-freshness.cs` reads it, keeps its old flags and exit codes, adds `--registry`/`--check-registry`, and reports the tracking issue next to a stale/error entry; the `docs.yml` post-deploy smoke check builds its URL and content-type-assertion list from the same registry instead of a second hard-coded copy. `tools/ai/board/session-stats.cs` and `tools/ai/board/build-board-stats.ps1` version the maintainer's private prototype scripts that feed the control board's Week tab, with the same arguments and output shape. The `site-health` skill runs the freshness and smoke checks over every registry entry, prepares the board's snapshot inputs, and routes each failure to a tracking-issue comment or a new issue draft; the `site-steward` agent (Haiku, read-only except its own `artifacts/site-health/**`) runs it, hooks (`enforce-path-ownership`, `block-worker-spawn`) were extended for it with Test-Hooks cases, and the agent tables (`.claude/agents/README.md`, `docs/engineering/ai-task-routing.md`, `docs/engineering/AI-DEVELOPMENT-MODEL.md`) were updated to match.

## Where the knowledge lives

- `tools/ai/sites.json` — the registry schema (id, name, kind, path, expectHtml, dataPath, timestampField, publisher, maxAgeDays, trackingIssue).
- `.github/scripts/dashboard-freshness.cs` — registry-driven freshness judging, `--check-registry`, `--registry`, tracking-issue annotation.
- `.github/workflows/docs.yml` — the registry-driven smoke check and its sparse checkout.
- `tools/ai/board/session-stats.cs` — per-session/per-day transcript summary (active time, prompts, reply latency, tokens per model, agents).
- `tools/ai/board/build-board-stats.ps1` — merges the transcript summary, GitHub activity, local-model ledgers and the optional private session-meta/plan inputs into the board's `db-*.json` files.
- `.claude/skills/site-health/SKILL.md` — the checks, snapshot prep and failure-routing procedure.
- `.claude/agents/site-steward.md` — the read-only agent that runs the skill; `.claude/hooks/enforce-path-ownership.ps1` and `.claude/hooks/block-worker-spawn.ps1` — its write and spawn restrictions.
