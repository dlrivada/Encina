## Asked

Encina publishes several sites and data feeds (documentation, DocFX API reference, coverage/mutation/benchmark/load-test dashboards, the maintainer's private control board) with no single list and nothing watching them as a whole; three failures went unnoticed for weeks until the maintainer found them by hand (#1361, #1381). This issue adds a versioned registry, a `site-health` skill and a read-only `site-steward` agent on top of the CI checks already landed in #1361/#1381.

## Outcome

Partial (parts 1 and 3 of 3, this branch): `tools/ai/sites.json` (schema 1) lists all seven published sites and feeds; `dashboard-freshness.cs` reads it, keeps its old flags and exit codes, adds `--registry`/`--check-registry`, and reports the tracking issue next to a stale/error entry; the `docs.yml` post-deploy smoke check builds its URL and content-type-assertion list from the same registry instead of a second hard-coded copy. `tools/ai/board/session-stats.cs` and `tools/ai/board/build-board-stats.ps1` version the maintainer's private prototype scripts that feed the control board's Week tab, with the same arguments and output shape. Part 2 (skill, agent, hooks) is a separate worker on the same branch.

## Where the knowledge lives

- `tools/ai/sites.json` — the registry schema (id, name, kind, path, expectHtml, dataPath, timestampField, publisher, maxAgeDays, trackingIssue).
- `.github/scripts/dashboard-freshness.cs` — registry-driven freshness judging, `--check-registry`, `--registry`, tracking-issue annotation.
- `.github/workflows/docs.yml` — the registry-driven smoke check and its sparse checkout.
- `tools/ai/board/session-stats.cs` — per-session/per-day transcript summary (active time, prompts, reply latency, tokens per model, agents).
- `tools/ai/board/build-board-stats.ps1` — merges the transcript summary, GitHub activity, local-model ledgers and the optional private session-meta/plan inputs into the board's `db-*.json` files.
