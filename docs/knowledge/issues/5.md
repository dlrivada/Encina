## Asked

Eight stream load tests (`StreamRequestLoadTests.cs`) crashed the CLR with `AccessViolationException` on .NET 10 Release builds under NBomber concurrency, inside `LanguageExt.Either.Map` / `StreamDispatcher.StreamRequestHandlerWrapper.MoveNext`. The issue asked to investigate whether this was a LanguageExt or NBomber problem and decide a fix.

## Outcome

Closed as `rejected-reasoned`: no merged PR references or closes #5 directly. Commit `e5732baa` (2025-12-22) added `[Trait("Category","Load")]` skips to the 8 tests (bundled with an unrelated dedup fix). Commit `c137e40d` (2025-12-23) recorded a root cause (dotnet/runtime#121736/PR#121771) in `ROADMAP.md` that CodeRabbit could not find on request. The maintainer closed the issue manually on 2025-12-30, accepting the citation as given. The affected test file was later deleted with no replacement in the Jan 2026 test consolidation (commit `65826302`).

## Where the knowledge lives

- Workaround env var: [docs/testing/load-tests-known-issues.md](../../testing/load-tests-known-issues.md), present, but it never mentions the Stream case and lists unrelated projects only.
- CI exclusion rationale: `AGENTS.md` section 8 ("why: #5, #496"); the audit found the older `CLAUDE.md` wording overgeneralized (AUD-01, AUD-11), and that text has since moved to `AGENTS.md`.
- Stream/StreamDispatcher load-test justification: **missing**, no `.cs` or `.md` under `tests/Encina.LoadTests/` for this feature today; tracked by #1327 (open).
