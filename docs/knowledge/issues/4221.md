## Asked

Make `EncryptThenDecrypt_EmptyPayload_RoundTripsSuccessfully` pass on SDK 10 and on SDK 11 / net11.0, where decrypting an empty payload returned `Left`.

## Outcome

The root cause is in ASP.NET Core 11.0.0, not in Encina: `EphemeralDataProtectionProvider` cannot unprotect the ciphertext of an empty plaintext. The round-trip tests now run on a persisted keyring (`DataProtectionProvider.Create` over a per-class temporary directory deleted on `Dispose`), and two new real-keyring tests check that a tampered and an empty ciphertext give `Left`. No production code changed.

## Where the knowledge lives

- `tests/Encina.UnitTests/Messaging/Encryption/DataProtection/DataProtectionMessageEncryptionProviderTests.cs` - the persisted-keyring round-trip tests and the comment explaining why they avoid the ephemeral provider.
