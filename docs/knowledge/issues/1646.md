## Asked

`CryptoShredderSerializer` stored `[CryptoShredded]` personal data in plaintext in the append-only Marten event store when the subject id was missing or the key could not be obtained, guessed key version 1 when the subject-info lookup failed, and dropped getter-only `[CryptoShredded]` properties from encryption without a warning.

## Outcome

Delivered: every path that cannot encrypt a non-null value throws `CryptoShreddingEncryptionException`, so the append fails and nothing is stored; the key provider returns the key and its version together; the startup scan rejects getter-only properties. Decryption is unchanged.

## Where the knowledge lives

- `src/Encina.Marten.GDPR/Serialization/CryptoShredderSerializer.cs` — the fail-closed encryption path.
- `src/Encina.Marten.GDPR/CryptoShreddingEncryptionException.cs` — the exception and its reasons.
- `src/Encina.Marten.GDPR/Model/SubjectEncryptionKey.cs` — key material and version from one read.
- `src/Encina.Marten.GDPR/Metadata/CryptoShreddedPropertyCache.cs` — unencryptable properties are recorded, not dropped.
- `docs/features/crypto-shredding.md` — the fail-closed behaviour for users.
