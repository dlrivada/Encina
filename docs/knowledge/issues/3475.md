## Asked

Make `Test-MainCheckout` and the local-draft ledger search of `check-issue-template.ps1` use the definition of a worktree that `Get-RepoLocation` has had since #3244 (every worktree `git worktree list` registers), with a regression case for each in `.claude/hooks/tests/Test-Hooks.ps1` on the real git fixture of the `#3244` block.

## Outcome

`Test-MainCheckout` in `.claude/hooks/_repo-paths.ps1` now asks `Get-RepoLocation` and returns true only for a location in the main checkout, so `block-main-checkout-writes` and the hooks that use `Get-RepoLocation` agree about a registered worktree nested in the main checkout outside `.claude\worktrees`. `Get-CandidateRoots` in `.claude/hooks/check-issue-template.ps1` adds the worktrees `Get-RegisteredWorktrees` reports, so a ledger row recorded in a registered worktree outside `.claude/worktrees` is local-draft evidence. The `#3475` block of `Test-Hooks.ps1` covers both, the main checkout still being recognised, the git-unavailable fallback and the missing-helper denial.

## Where the knowledge lives

- `.claude/hooks/_repo-paths.ps1` — `Test-MainCheckout`.
- `.claude/hooks/check-issue-template.ps1` — `Get-CandidateRoots` and the load of `_repo-paths.ps1`.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#3475` block at the end of the suite.
- `.claude/skills/local-ai-task/SKILL.md` — where a ledger row counts as evidence.

## Known limits

- A repository root that is itself a worktree outside `.claude\worktrees` is out of scope, as in #3244 (D8): `Get-RepoLayout` then takes that worktree as the main checkout, so the ledger search does not reach the real main checkout's ledger (it did not before either).
