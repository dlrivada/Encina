## Asked

`SanitizeForSql` removed semicolons but could still return SQL comment markers formed by the removal itself (`*;/` became `*/`), and the skipped property `SanitizeForSql_NeverContainsCommentMarkers` documented it as a known bug.

## Outcome

Delivered: the faulty logic was in `SqlSanitizer`, not `DefaultSanitizer`. The sanitizer now scans the input once in linear time, removing each dangerous token from the output tail as it forms, so it never returns `--`, `/*`, `*/` or `xp_`, and the bare `xp_` and `axp_b` gaps of the extended-procedure pattern are closed. The property is unskipped with a generator that reaches the re-forming cases, and deterministic unit tests cover each one.

## Where the knowledge lives

- `src/Encina.Security.Sanitization/Sanitizers/SqlSanitizer.cs` — the linear tail scanner that removes each dangerous token as it forms.
- `tests/Encina.UnitTests/Security/Sanitization/DefaultSanitizerTests.cs` — deterministic regressions for each re-forming input.
- `tests/Encina.PropertyTests/Security/Sanitization/SanitizationPropertyTests.cs` — the two properties over the marker alphabet.
