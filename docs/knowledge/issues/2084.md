## Asked

Make a message's handler run exactly `InboxOptions.MaxRetries` times before the inbox rejects it, identically on all 10 providers, and make every store `Left` inside `InboxOrchestrator` fail the operation.

## Outcome

`MarkAsFailedAsync` is the only increment, `IncrementRetryCountAsync` is gone, store `Left`s are returned, and the EF Core store sees tracked messages. Unit tests cover the boundary for `MaxRetries` 1 and 3 and every store call; integration tests run the same scenario against each real provider (EF MySQL keeps its fixture skip, tracked in #2086).

## Where the knowledge lives

- `src/Encina.Messaging/Inbox/InboxOrchestrator.cs` — retry check and store error propagation.
- `src/Encina.Messaging/Inbox/InboxOptions.cs` — the `MaxRetries` attempt semantics.
- `docs/messaging/inbox.md` — the user-facing description.
