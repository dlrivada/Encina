## Asked

Make the EventId registry documentation internally consistent (free-gap total, one statement on where free space is read) and make the agreement test refuse new ranges below 10000.

## Outcome

The ADR now lists the six gaps below 10000 that are in no registry table (230 ids, 200 once the 7470-7499 claim of #827 is set aside) and says they are not allocatable. ADR-021, AGENTS.md section 7, the registry page and the allocation skill agree that the registry is the place to read free space only for the 10000+ zone. `EventIdRegistryAgreementTests` checks every code range below 10000 against an allow-list of the 91 historical names.
