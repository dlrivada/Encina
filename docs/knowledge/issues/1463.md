## Asked

`src/Encina.Compliance.GDPR/Diagnostics/LawfulBasisLogMessages.cs` declared the same
`[LoggerMessage]`-generated methods (`ConsentCheckStarted`, `ConsentCheckPassed`, `ConsentCheckFailed`,
and 10 others) as `src/Encina.Compliance.LawfulBasis/Diagnostics/LawfulBasisLogMessages.cs`, using a
different EventId range (8120-8133 vs. 8350-8399) but nothing in `src/` ever called the GDPR-package
copy — `LawfulBasisValidationPipelineBehavior` only imports the LawfulBasis-package one. The duplicate
was discovered dead code during #1435/PR #1462, which had to patch both files to remove a subject-id
leak even though only one was reachable. This issue asked for the dead file to be deleted.

## Outcome

Delivered: `src/Encina.Compliance.GDPR/Diagnostics/LawfulBasisLogMessages.cs` is gone. A repo-wide
grep (class name and all 13 method names, across `src/` and `tests/`) confirmed no caller anywhere
before deletion. The `ComplianceGDPR` EventId range in `EventIdRanges.cs` was left registered unchanged
(other GDPR log messages still use it); EventIds 8120-8133 simply become free slots within that range.
`EncinaEventIdAllocationTests`'s `AssemblyRanges` map needed no change. A stale comment in the sibling
`GDPRLogMessages.cs` that pointed at the now-deleted file by bare class name (ambiguous with the real
LawfulBasis-package class of the same name) was corrected to name the actual file and its EventId
range. Full Release build: 0 warnings, 0 errors. `EncinaEventIdAllocationTests` (9/9) passes, and every
unit test matching the substring filters `GDPR` (324/324) and `LawfulBasis` (249/249) in
`Encina.UnitTests` passes.

## Where the knowledge lives

- `src/Encina.Compliance.GDPR/Diagnostics/LawfulBasisLogMessages.cs` — deleted; the dead duplicate.
- `src/Encina.Compliance.GDPR/Diagnostics/GDPRLogMessages.cs` — comment above the 8113-8115 region
  corrected to point at the real `Encina.Compliance.LawfulBasis.Diagnostics.LawfulBasisLogMessages`.
- `src/Encina/Diagnostics/EventIdRanges.cs` — `ComplianceGDPR` range left registered unchanged.
- `docs/knowledge/issues/1435.md` — the record that first identified this file as dead code and
  named the cleanup that became this issue.
