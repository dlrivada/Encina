## Asked

Make `AesGcmFieldEncryptor` return `Left(EncryptionErrors.InvalidCiphertext())` for a stored value with a wrong-sized nonce or tag, instead of letting `AesGcm` throw `ArgumentException` through the `Either` API.

## Outcome

`ValidateEncryptedValue` now calls a private `HasValidNonceAndTagLength` helper that requires a 12-byte nonce and a 16-byte tag (default and empty still invalid). Unit tests cover nonce lengths 5, 11 and 13 and tag lengths 15 and 17 through both `DecryptStringAsync` and `DecryptBytesAsync`.

## Where the knowledge lives

- `src/Encina.Security.Encryption/Algorithms/AesGcmFieldEncryptor.cs` — the length check before `AesGcm.Decrypt`.
- `tests/Encina.UnitTests/Security/Encryption/AesGcmFieldEncryptorTests.cs` — the regression tests.
