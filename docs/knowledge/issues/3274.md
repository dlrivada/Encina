## Asked

Make `.claude/hooks/check-issue-template.ps1` judge the REST equivalents of `gh issue edit` (`gh api repos/dlrivada/Encina/issues/<n> -X PATCH` and the `issues/<n>/labels` writes) as it judges `gh issue edit`, reusing the endpoint normalisation and field parsing of the #2823 creation block, with tests for each new branch.

## Outcome

Delivered: the hook normalises `issues/<n>` and `issues/<n>/labels` endpoints, parses the call's body, title and labels (fields or `--input` JSON), reads the existing issue once when it needs its title, body or pull request flag, and applies the template, local-draft and Dilemma checks. `Test-Hooks.ps1` has cases for every branch and `.claude/agents/README.md` describes the behaviour.

## Where the knowledge lives

- `.claude/hooks/check-issue-template.ps1` — the REST edit route (`Get-ApiIssueTarget`, `Get-RestEdit`, `Get-RestEditViolation`).
- `.claude/hooks/tests/Test-Hooks.ps1` — the `edit:` cases.
- `.claude/agents/README.md` — the hook description.

## Audit

Not audited yet. A PATCH of the title only is not judged (the issue asks for body and needs-decision only).
