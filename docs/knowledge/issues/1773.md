## Asked

Make the crypto-shredding startup check fail closed when an application `IPersonalDataLocator` would be silently left out of access and erasure, document a working composite registration, and let the metadata readers read events without decrypting them.

## Outcome

`CheckLocator` now requires the resolved locator to reach every registered locator type (nested composites included) and names the missing types; `MartenEventMetadataQuery` reads under `EventReadScope.SuppressDecryption()`, which `CryptoShreddingFrame` honours. The composite factory snippet is in `docs/features/crypto-shredding.md`. `MartenProjectionManager` is unchanged: its only `QueryAllRawEvents` use that needs no data is a count, and the rebuild batches need decrypted events.

## Where the knowledge lives

- `src/Encina.Marten.GDPR/CryptoShreddingStartupValidationHostedService.cs` — the fail-closed locator rule.
- `src/Encina.Marten/EventReadScope.cs` — the no-decrypt read scope.
- `docs/features/crypto-shredding.md` — the registration-order section and the composite factory.
