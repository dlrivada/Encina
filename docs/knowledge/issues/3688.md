## Asked

Make `Encina.AspNetCore` read the `ErrorCategory` and the core HTTP table (`ErrorCategoryHttp`) instead of parsing error codes, and stop the DPIA endpoints from recording a telemetry status that differs from the response status.

## Outcome

`ToProblemDetails` takes the status, title and headers from the category; 429, 499, 502, 503 and 504 get real titles; `Retry-After` and `WWW-Authenticate` are written at execution; the authorization producers are categorized; the DPIA endpoints share one status for telemetry and response. An error without a code no longer throws.

## Where the knowledge lives

- `src/Encina.AspNetCore/ProblemDetailsExtensions.cs` - the mapping and the header-writing result.
- `src/Encina.AspNetCore/DPIAEndpointExtensions.cs` - one status for telemetry and response.
- `docs/architecture/adr/062-error-category-contract.md` - the contract and the staged migration.
