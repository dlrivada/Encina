## Asked

Under Stryker.NET 5.0.0 with the MTP runner and `coverage-analysis: off`, 36 Verify snapshot tests of `Encina.UnitTests` passed in the initial test run but failed in later mutant runs of the same test server, so they were reported as killers of unrelated mutants and inflated the mutation score (spike #1087). They must pass on every run in the same process.

## Outcome

Fixed on branch fix/verify-tests-mtp-rerun-1442. The cause is Verify's process-wide prefix uniqueness check, not state in `Encina.Testing.Verify`. The test project's module initializer disables that check, and a regression test verifies the same prefix twice in one process. A local Stryker 5.0.0 MTP run on `SequentialDispatchStrategy.cs` reports the same 4 killed and 0 survived before and after, but before the fix the 36 Verify tests were in `killedBy` of 3 of the 4 mutants, and after it of none.

## Where the knowledge lives

- `tests/Encina.UnitTests/Testing/Verify/ModuleInitializer.cs` - the `DisableRequireUniquePrefix()` call and the reason.
- `tests/Encina.UnitTests/Testing/Verify/VerifyRerunTests.cs` - the regression test (fails with the prefix error when the call is removed).
