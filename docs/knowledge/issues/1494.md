## Asked

Five unrelated pull requests failed Link Check on 2026-09-27 (and two more on 2026-09-28) because the full external scan hit transient third-party failures (503, 500, connection failures, a timeout) in files they did not touch, each costing a manual re-run. The check had to fail a PR only for links it introduces, and the full external scan had to stop blocking anything.

## Outcome

Delivered: `link-check.yml` has a `check-links` job for pull requests and pushes (offline scan of the whole site plus an online scan of the changed Markdown files) and a `full-external-scan` job for the daily schedule and dispatch, with permissions declared per job. `link-health-report.ps1` turns the lychee JSON report into one tracking issue and fails only for 404/410; its `-SelfTest` runs against fixtures under `.github/scripts/fixtures/link-health/`.

## Where the knowledge lives

- `.github/workflows/link-check.yml` — the event matrix (header comment), the changed-files step and the per-job permissions.
- `.github/scripts/link-health-report.ps1` — classification, tracking-issue handling and exit code.
- `docs/contributing/README.md` — what CI runs where.
