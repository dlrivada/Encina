## Asked

A worker running `tests/Encina.UnitTests` five times on 2026-09-27 saw one run fail with `Failed: 1` while the other four were green; the tail of the failure log showed an exception stack passing through `HttpConnection.SendAsync`, `HttpConnectionPool.SendWithVersionDetectionAndRetryAsync`, `RedirectHandler.SendAsync`, `Socket.AwaitableSocketAsyncEventArgs.ThrowException` and `HttpConnection.InitialFillAsync` — evidence that some unit test opens a real network connection through the default `HttpClient` handler chain (redirects included). The worker recalled the failing test was "a cloud-secrets test" but had not captured its name. The issue asked to grep `tests/Encina.UnitTests` for `new HttpClient(` without a custom handler, SDK clients built with real endpoints/credentials, and `Uri("https://`, replace real calls with stubs or move genuinely HTTP-dependent tests to `Encina.IntegrationTests` with WireMock, and re-verify with network disabled.

## Outcome

Delivered. Discovery combined a targeted grep (`new HttpClient(`, `Uri("https://` / `Uri("http://`, SDK client construction) across `tests/Encina.UnitTests` with the network-disabled reproduction the brief asked for: `dotnet test` with `HTTP_PROXY`/`HTTPS_PROXY` set to the unroutable `http://127.0.0.1:9` for the test process only. The grep surfaced many `Uri(...)` literals (Azure Key Vault, HashiCorp Vault, Google Cloud Secret Manager, Refit, Compliance/Attestation options tests), but reading each one showed every cloud-secrets/attestation test mocks its SDK client or DI-registered client with NSubstitute — no outbound call is ever made. The reproduction run was the ground truth: it failed with exactly **71** tests, every one of them inside `tests/Encina.UnitTests/Testing/WireMock/`, five classes:

- `EncinaWireMockFixtureTests.cs` — drives a real `WireMockServer` through a real `HttpClient` from `EncinaWireMockFixture.CreateClient()`.
- `EncinaRefitMockFixtureTests.cs` — same, through a real Refit-generated client (`ITestApi`).
- `FaultSimulationTests.cs` — fault/timeout/error-code scenarios over the same real `HttpClient`.
- `SequenceTests.cs` — request ordering/history assertions over the same real `HttpClient`.
- `WebhookTestingExtensionsTests.cs` — webhook stub scenarios over the same real `HttpClient`.

These five classes (plus their `Fixtures/TestPayloads.cs` helper, used only by `WebhookTestingExtensionsTests`) were moved to `tests/Encina.IntegrationTests/Testing/WireMock/` under `[Trait("Category", "Integration")]`, matching the existing `Testing/{Pact,Respawn,Testcontainers}` layout in that project and the pre-existing `Web/Refit/RefitClientIntegrationTests.cs` pattern (WireMock + Refit already integration-tested there). `Encina.IntegrationTests` already references `Encina.Testing.WireMock` and `Refit`, so no project file changed.

Three sibling classes in the same original folder — `GuardClauseTests.cs`, `FaultTypeTests.cs`, `ReceivedRequestTests.cs` — start the same fixtures (a local WireMock server bound to localhost) but never issue an outbound `HttpClient` request; they only call a fixture's synchronous guard-clause validation or exercise the plain `ReceivedRequest` data type. They passed cleanly in the network-disabled run and stayed in `Encina.UnitTests`. `GuardClauseTests.cs` used the `ITestApi` interface that lived inside the now-moved `EncinaRefitMockFixtureTests.cs`; it now declares its own minimal `IGuardClauseTestApi` (one unused `[Get]` method) so it no longer depends on a type from a different project/namespace.

No runtime network guard was added, per the brief's explicit decision.

Verification: `dotnet build` clean for both `Encina.UnitTests` and `Encina.IntegrationTests` (0 warnings). The moved 102 tests (`--filter "FullyQualifiedName~Testing.WireMock"` inside `Encina.IntegrationTests`) all passed. The full `Encina.UnitTests` project run with `HTTP_PROXY`/`HTTPS_PROXY` pointed at `127.0.0.1:9` for the test process: **21250 passed, 1 skipped, 0 failed** (previously 71 failed under the same condition). `dotnet format --verify-no-changes` reported no changes for the touched files.

## Where the knowledge lives

- `tests/Encina.IntegrationTests/Testing/WireMock/EncinaWireMockFixtureTests.cs`, `EncinaRefitMockFixtureTests.cs`, `FaultSimulationTests.cs`, `SequenceTests.cs`, `WebhookTestingExtensionsTests.cs`, `Fixtures/TestPayloads.cs` — relocated real-network WireMock/Refit tests, `[Trait("Category", "Integration")]`.
- `tests/Encina.UnitTests/Testing/WireMock/GuardClauseTests.cs` — stayed in place; now declares its own `IGuardClauseTestApi` instead of the moved `ITestApi`.
