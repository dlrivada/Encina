## Asked

Make every error the EF Core sharding code creates declare its `ErrorCategory`, so the EF2 line of the completeness scan's pending file can be deleted.

## Outcome

All 11 calls in 5 files carry a category and the EF2 pending line is deleted. 10 calls are `ErrorCategory.Internal` and keep answering HTTP 500. The `encina.sharding.all_replicas_unhealthy` call is `ErrorCategory.Unavailable` and now answers 503 instead of 500 (D11). The two reference table errors and the seven migration errors sit inside `catch (Exception ex) when (ex is not OperationCanceledException)`, so a caller cancellation never becomes one of them.

## Where the knowledge lives

- `src/Encina.EntityFrameworkCore/Sharding/` - the categorized calls.
- `tests/Encina.UnitTests/EntityFrameworkCore/Sharding/EfCoreShardingErrorCategoryTests.cs` - the category of each reachable producer.
- `docs/architecture/adr/062-error-category-contract.md` - the contract.
