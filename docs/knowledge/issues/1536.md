## Asked

Coverage obligations are per flag and read from `.github/coverage-manifest/{Package}.json` (AGENTS.md §9). A source
file with no manifest entry carries no obligation at all, so it can sit at 0% coverage forever without CI noticing.
Issue #1497 added `coverage-report.cs --check-stale-manifest`, catching the opposite case (a manifest key naming a
deleted file); its review found this reverse gap. No CI step or script checked that every `src/<Package>/**/*.cs`
file (excluding `obj/`, `bin/`) has a manifest entry. 38 files across 12 packages had no entry at the time the issue
was filed.

## Outcome

Delivered: `.github/scripts/coverage-report.cs` gained a `--check-missing-manifest` mode that, for every package with
both a `src/<Package>/` directory and a manifest, scans `src/<Package>/**/*.cs` (excluding `obj/`, `bin/`, and
generated `*.g.cs`) and exits 1 listing every file with no key in that package's manifest, in the
`"<Package>: <relPath>"` format matching `--check-stale-manifest`'s output style. It reuses that mode's
manifest-dir-derived repo root, its parse-failure-is-fatal handling, and its "no manifest loaded" guard so a
misconfigured `--manifest` path cannot pass vacuously. The 38 missing entries were added to the 12 affected
manifests (`Encina.Compliance.Consent`, `.DataResidency`, `.DataSubjectRights`, `.Retention`, `Encina.Hangfire`,
`Encina.Marten`, `Encina.Messaging` (13 files), `Encina.MongoDB`, `Encina.Quartz`, `Encina.Security.AntiTampering`,
`.PII`, `.Secrets`) by hand rather than by running `generate-coverage-manifest.cs` over them, because that script
would have silently dropped each file's `targets` block (it has no `Targets` field on its output record) and
reclassified every existing entry from today's `defaults.json` rules. The `defaultTests`/`defaultRule`/`reason` for
each of the 38 new entries were still computed deterministically by running the generator into a scratch directory
and reading its output, not invented by hand. `--check-missing-manifest` now exits 0 for the whole repository;
`--check-stale-manifest` and the default report mode were re-verified to still behave correctly, and a corrupted
manifest file was confirmed to still make the new mode exit 1. Whether the new obligations push any package below
its target was not fully measured (needs a real coverage run); a static reference-count check flagged the files
most likely to be at risk as a starting point for a follow-up measurement.

The PR #1545 review of the gate itself (adversarial-reviewer) found one MAJOR and four MINOR gaps, all fixed in the
same PR: an explicit `--manifest <dir>` that did not exist silently fell back to the ancestor-directory search
instead of failing, defeating the "cannot pass vacuously" guarantee for a misspelled path in every mode; a
`src/Encina.*` package directory with `.cs` files but no `<Package>.json` at all was invisible to
`--check-missing-manifest` (now reported as `"<Package>: no coverage manifest"`); the two check flags silently ran
only the first one and ignored the second when passed together (now both run, and the process exits 1 if either
fails); a manifest naming a `src/` directory that does not exist was silently skipped rather than reported (now
`"<Package>: manifest has no src/<Package>/ directory (check the name and its case)"`); and the missing-entry
listing gained a remediation line pointing at `defaults.json`'s rules and warning against regenerating an existing
manifest with `generate-coverage-manifest.cs`. Neither of the two new detection gaps (no manifest at all; manifest
naming a nonexistent `src/` dir) flagged any package in today's repository — verified by running the fixed check
against the real manifest directory (all 106 manifests match an existing `src/` directory, and every `src/Encina.*`
directory with source files has a manifest). Every fix was reproduced directly (misspelled `--manifest` in all three
modes; a scratch `src/`+manifest tree exercising both new listings; both flags together with only one of the two
checks failing, to prove the exit code is not masked by whichever check ran first).
