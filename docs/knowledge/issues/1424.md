## Asked

Audit #16's remediation stage (`tools/ai/audit/audit-draft-remediation.ps1` and `_remediation-checks.ps1`) had
two tooling defects, both surfaced by the same 2026-09-27 verification pass 4: (A) `Limit-RelatedIssues` kept a
Related Issues reference just because it appeared in the duplicate search's own candidate list, not because
anything about the finding actually related to it -- 5 drafts cited real, open, but unrelated issues the
verifier confirmed unrelated with `gh issue view`; and (B) duplicate-vs-new classification was unstable across
re-runs for the same finding and the same unchanged open issues (16-code-4 vs #1170: duplicate in one run, new
in the next), because the deterministic anchor check (`Test-DuplicateEvidence`) only ever ran on the one
candidate the local model happened to name that run.

## Outcome

Delivered: `Limit-RelatedIssues` dropped its `$CandidateText` parameter entirely -- a search candidate is no
longer, on its own, evidence of a relation; only the audited issue itself, the finding's own text, and the
script's own anchor-checked note lines keep a reference alive. A new `Find-DuplicateAmongCandidates` function
runs `Test-DuplicateEvidence` against every candidate a finding's duplicate search returned (not only the one
the model named), and accepts the lowest-numbered passing candidate as the duplicate whatever the model
answered, making the decision deterministic for the same finding and the same open issues. The model's own
classification now only decides the drafted template kind for a non-duplicate finding.

## Where the knowledge lives

- `tools/ai/audit/_remediation-checks.ps1` -- `Limit-RelatedIssues` (narrowed allowed-number set, no
  `$CandidateText`), `Find-DuplicateAmongCandidates` (new).
- `tools/ai/audit/audit-draft-remediation.ps1` -- the duplicate-decision block runs
  `Find-DuplicateAmongCandidates` over every fetched candidate before falling back to the model-named-candidate
  evidence check; the `Limit-RelatedIssues` call site no longer passes a candidate-text argument.
- `.claude/hooks/tests/Test-Hooks.ps1` -- the `#1424` block exercising both functions directly with plain
  strings and the real `#1388` fixtures (`finding-code-4.md`, `issue-1170.json`, `issue-1333.json`,
  `issue-1328.json`), no `gh` and no local model.
- `.claude/skills/issue-audit/SKILL.md` -- the remediation stage description updated to describe the
  deterministic, all-candidates duplicate check and the narrowed `Limit-RelatedIssues` rule.
