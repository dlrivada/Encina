## Asked

`DataSubjectRightsDiagnostics.RecordFailed(activity, reason)` and its siblings in
`Encina.Compliance.DPIA` and `Encina.Compliance.Retention` set `reason` both as an OpenTelemetry
activity tag (`*.failure_reason`) and as the `ActivityStatusCode.Error` status description. Every
call site that reported a business-level failure passed `error.Message` directly, so the
human-readable `EncinaError.Message` reached an OpenTelemetry activity tag and status description —
a channel `AGENTS.md` explicitly forbids for `EncinaError.Message` (why: #1168, #1173, #1259,
#1274). Found during the adversarial review of PR #1429/#1456 (out of that PR's scope).

## Outcome

Delivered: the seven call sites across the three packages that tagged `error.Message` on an
activity now tag `error.GetCode().IfNone("encina.unknown")` instead —
`ProcessingRestrictionPipelineBehavior`, `DefaultDataErasureExecutor`,
`DefaultDataPortabilityExporter` and `DefaultDSRService` (four call sites) in
`Encina.Compliance.DataSubjectRights`; `DPIAReviewReminderService` in `Encina.Compliance.DPIA`;
`RetentionEnforcementService` in `Encina.Compliance.Retention`. The `Diagnostics.RecordFailed`
helper signatures were left unchanged (`string reason`), since most other call sites in these
packages already pass a fixed code string, not `error.Message`. Logs at the same call sites were
left as-is (already fixed by #1429/#1456 for DataSubjectRights; DPIA/Retention logs pass
`ex.Message`/error objects to structured logging methods, a different rule).

Three findings were scoped out and written up as follow-up issues rather than folded into this fix:
`System.Exception.Message` (not `EncinaError.Message`) reaching the same `RecordFailed` helpers in
these same three packages; the identical `error.Message`-not-`EncinaError`-leak pattern search
found no further `EncinaError.Message` instances outside these three packages (only
`ex.Message` ones, in NIS2 and Marten.GDPR); and a pre-existing CRAP-gate violation on
`RetentionEnforcementService.ExecuteEnforcementCycleAsync` (complexity 16, already above the
gate's ceiling regardless of coverage) that this fix's one-line change inside that method
triggered under diff attribution but did not cause.
