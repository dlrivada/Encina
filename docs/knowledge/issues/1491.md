## Asked

`tools/ai/audit/audit-draft-remediation.ps1` (the SPEC-003 audit pipeline's remediation stage) drafted one
remediation GitHub issue per numbered finding under each stage artifact's `## Findings` section
(`code.md`/`tests.md`/`docs.md`), deduplicating only against OPEN GitHub issues -- never against the audit's OWN
findings. Audit #17 verification pass 2 (2026-09-27) failed because docs finding 7 and code finding 4 both
described the same one-line defect (`src/Encina.DomainModeling/AggregateBase.cs:20`, a stale XML doc comment):
the script drafted two remediation issues for it, even though the docs stage's own text said not to open a
second issue, and the docs stage had to be re-run to remove the duplicate finding before verification could
pass.

## Outcome

Delivered: the audit's own findings are now grouped by their leading location anchor
(`Get-FindingLeadingAnchor`/`Test-SameLocationAnchor`/`Group-FindingsByLocation` in `_remediation-checks.ps1`)
before any drafting happens -- same file and an overlapping or equal line (or line range) is one group;
different lines of the same file are different groups; a finding with no `file:line` anchor is never grouped.
One issue is drafted per group, from the group's highest-severity finding (`Get-GroupPrimary`: Blocker > Major
> Minor > Unknown, ties broken by stage order code/tests/docs); its Description names every stage and finding
id in the group with a deterministic `Reported by: ...` line (`Add-ReportedByLine`), and every other member's
own line in `stages/remediation.md` reads `merged into <stage> <id> (same location)` instead of getting a
second draft. `-Only "<stage> <n>"` on a merged (non-primary) finding now regenerates its group's one draft
(the primary's) instead of trying to draft the merged finding on its own. `.claude/skills/issue-audit/SKILL.md`
documents the rule. Two defects were found and fixed by adversarial review before commit: a PowerShell
single-element-array constructor call that threw on every real run, and a duplicated `Reported by:` line when
the model complied with the brief's own guidance note asking it to write one itself. Three narrower, safe-
direction gaps (a multi-citation leading clause, non-transitive three-way overlap, and a stale primary draft
file surviving a cross-run primary reassignment under repeated `-Only`) were left as a follow-up, not blocking.
