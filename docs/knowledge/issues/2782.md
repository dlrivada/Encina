## Asked

Make an AES-GCM failure while encrypting return an encryption error instead of `EncryptionErrors.DecryptionFailed`, remove `DecryptionFailed` and `DecryptionFailedCode`, and prove the catch with a test.

## Outcome

`EncryptionErrors.EncryptionFailed(string keyId, Exception? exception = null)` and `EncryptionFailedCode = "encryption.encryption_failed"` replace the decryption pair; `PublicAPI.Unshipped.txt` is updated. `AesGcmFieldEncryptor` gained an internal constructor with a replaceable nonce source; unit and guard tests use it to make the primitive fail and assert the code, the `keyId` detail, the kept exception and that the exception message is absent from the error message. Unit, contract and property tests that built `DecryptionFailed` were rewritten, the field-level encryption page and the inventory name the new code, and the coverage manifest justifications describe the now covered catch. Two changelog fragments record the removal and the fix.

Out of scope and tracked elsewhere: the fail-open path of `EncryptionOrchestrator` when `FailOnError` is false (#2824), and a `PlatformNotSupportedException` from `new AesGcm` on unsupported platforms, which is not caught.

## Where the knowledge lives

- `src/Encina.Security.Encryption/EncryptionErrors.cs` — the new factory and code.
- `src/Encina.Security.Encryption/Algorithms/AesGcmFieldEncryptor.cs` — the catch and the internal constructor.
