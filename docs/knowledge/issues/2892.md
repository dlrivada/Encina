## Asked

Stop `.claude/hooks/guard-orchestrator-writes.ps1` from denying `pwsh -File <script>` merely because the script contains a file-write API and its text mentions `src/` or `tests/` (an issue-draft generator whose here-strings name source paths while it writes only under `artifacts/`). Judge the resolved write targets, deny when one resolves under the checkout's `src/` or `tests/` or cannot be resolved.

## Outcome

Fixed for PowerShell scripts. `Test-ScriptWritesAreSafe` (`.claude/hooks/_write-targets.ps1`) classifies a script as Guarded (a target under `src/` or `tests/`), Safe (every write site understood and resolved elsewhere) or Unknown (anything else). An Unknown script is denied only when its text names `src/` or `tests/` (for an unresolved target also when the launching command, script path removed, names them or the launching cwd is under them); an Unknown script with no such mention is allowed. Other scripts (`dotnet run <file>.cs`) keep the text rule. Regression cases are in `.claude/hooks/tests/Test-Hooks.ps1`, including 26-level doubling chains through `-f`, `Join-Path`, `[IO.Path]::Combine` and `.Replace` (every resolved value over 8192 characters is unresolved; each case must finish within 10 s and report an unresolved path; measured before the cap 17.9, 83.8, 97.9 and 21.4 s, after it about 1 s each) and a case that pins the cap itself: a target over 8192 characters built from `'s'+'rc'`, with no src/tests word in the script or the launch, is unresolved and ALLOWED, a known B1 limit (the cap extends to `-f`, `Join-Path`, `Combine` and `.Replace` the exposure `SwCross` already had).

Target analysis details (PR #3236 review threads): `New-Object` parameters `-TypeName`, `-ArgumentList` and `-ComObject` are bound as values, so a wordless `New-Object StreamWriter ('s'+'rc/X.cs')` is judged, not opaque; `[IO.File]::Move` and `[IO.Directory]::Move` check the source as well as the destination (a move removes its source), also in the command-level analysis; `[IO.File]::Open(path, mode, FileAccess.Read[, share])` is read-only and every other `Open` shape is a write; `pwsh -co 'text.ps1'` (any prefix of `-Command`, `-CommandWithArgs`, `-EncodedCommand`) is not a script launch; the environment-change check also covers `[Environment]::GetEnvironmentVariable`. Known limit (not changed, it only over-blocks): a function parameter's default value is always kept as a possible value of the parameter, even when every call passes its own argument.

Evasions that remain open under follow-up B1 (reproduced by the delta reviews, none caused by this change): a wildcard in a parent segment (`[s]rc\Encina\Foo.cs`; `Set-Content -Path '.\wcdir\[s]rx\a.txt'` overwrote an existing file), a target over 8192 characters built without a src/tests word (unresolved and allowed), targets built in the launching command from `'s'+'rc'`, splatting, an environment variable, and a cwd that is a junction to `src` (`GetFullPath` does not resolve reparse points); plus Invoke-Expression, computed command names, nested launches and native copiers. The seven real parameter-driven repository scripts below are exercised against the real hook by seven cases of `Test-Hooks.ps1` (all allowed; brittle by design: they flip to deny if a later edit adds the word `src` or `tests` to one of these scripts): tools/ai/priority/collect-issues.ps1, tools/ai/board/build-board-stats.ps1, tools/ai/board/reconcile-board.ps1, .github/scripts/link-health-report.ps1, .github/scripts/sonar-issues.ps1, .github/scripts/crap-gate-selftest.ps1, tools/ai/priority/Test-Priority.ps1 (all allowed).

Two other symptoms in the issue comments are not fixed here and have their own follow-up issues: running an existing repository script in a read-only check mode is blocked, and `block-main-checkout-writes` does not recognise worktrees outside `.claude\worktrees`.
