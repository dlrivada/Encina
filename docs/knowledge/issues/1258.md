## Asked

`QuartzRequestJob` copied the handler's response to `IJobExecutionContext.Result` after every successful run. Quartz does not persist that value itself, but job listeners, trigger listeners and plugins can, so personal data could leave Encina's retention and erasure controls. The default must not expose the response, and exposing it must be an explicit, documented opt-in, as in the Hangfire integration (#1173).

## Outcome

Fixed on branch fix/quartz-job-result-1258. By default the job leaves `context.Result` unset; `EncinaQuartzOptions.ExposeResponseInJobContext = true` restores the old behaviour. The failure path is unchanged.
