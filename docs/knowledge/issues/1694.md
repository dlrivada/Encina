    statement: "A stage's '## Findings' section whose first non-empty line is '- none' (or a bare 'None'; case-insensitive, optional trailing period) has no findings, and any text after it is ignored with a printed note ('trailing text after '- none' in <stage> ignored'), instead of becoming one Unknown finding. A section that does not start with that marker keeps the earlier behaviour: numbered findings, or one Unknown finding for an unnumbered paragraph, so real findings are never dropped by a formatting drift. The rule fails closed and is implemented as a guard: after a leading '- none', the section is parsed normally when any following line is finding-shaped, meaning a numbered or lettered item in any style ('1.', '1)', '1:', '#1', 'a.'), or a line that starts with a severity word (Blocker, Critical, Major, Minor, Nit, High, Medium, Low, Warning, Severity), optionally after bullet, quote, bracket or emphasis characters. Prose that starts with a severity word is therefore parsed as an Unknown finding (a re-run, by design: fail closed). Shapes outside these rules (table rows, headings, a severity word mid-sentence) are treated as prose, which the stage templates forbid under Findings. ## Asked

`audit-draft-remediation.ps1 -Prepare` treated a Findings section written as `- none` followed by explanatory prose as a single Unknown finding, so the remediation stage drafted an issue for a nonexistent finding and `audit-verifier` failed the audit.

## Outcome

Delivered: `Split-Findings` in `tools/ai/audit/_audit-lib.ps1` treats the marker alone (`- none` or `None`, optional period, any case) as zero findings; same-line text is one Unknown finding; trailing plain prose is ignored with a printed note and recorded as a pipeline lesson in the remediation manifest (so `remediation-drafter`, `audit-lessons` and `audit-verifier` see it); trailing finding-shaped text falls through to the normal parser. The `test-auditor`, `issue-auditor` and `docs-reviewer` output templates gained an `## Informational (not findings)` section for such prose. `Test-Hooks.ps1` covers `- none` alone, with prose, with a period, upper case, a numbered list and an unnumbered paragraph.

## Where the knowledge lives

- `tools/ai/audit/_audit-lib.ps1` — `Split-Findings`, the none-marker rule.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#1694` cases next to the other `Split-Findings` cases.
- `.claude/agents/test-auditor.md`, `.claude/agents/issue-auditor.md`, `.claude/agents/docs-reviewer.md` — the Informational section in the output templates.
