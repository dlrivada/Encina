## Asked

`audit-draft-remediation.ps1 -Prepare` treated a Findings section written as `- none` followed by explanatory prose as a single Unknown finding, so the remediation stage drafted an issue for a nonexistent finding and `audit-verifier` failed the audit.

## Outcome

Delivered: `Split-Findings` in `tools/ai/audit/_audit-lib.ps1` recognizes `- none` as the first line and returns no findings, printing a note when text follows. The `test-auditor`, `issue-auditor` and `docs-reviewer` output templates gained an `## Informational (not findings)` section for such prose. `Test-Hooks.ps1` covers `- none` alone, with prose, with a period, upper case, a numbered list and an unnumbered paragraph.

## Where the knowledge lives

- `tools/ai/audit/_audit-lib.ps1` — `Split-Findings`, the none-marker rule.
- `.claude/hooks/tests/Test-Hooks.ps1` — the `#1694` cases next to the other `Split-Findings` cases.
- `.claude/agents/test-auditor.md`, `.claude/agents/issue-auditor.md`, `.claude/agents/docs-reviewer.md` — the Informational section in the output templates.
