## Asked

Stop the `api` template of `encina new` and the Problem Details helpers of `Encina.AspNetCore` from returning `EncinaError.Message` (and exception text) to HTTP clients, which breaks information minimisation (GDPR Art. 5(1)(f)/32, ENS) and the fail-closed rule of AGENTS.md section 3.

## Outcome

The `api` template maps errors with `error.ToProblemDetails(httpContext)`. `ToProblemDetails` and `ToActionResult` omit `detail` and the `exception` extension unless `EncinaAspNetCoreOptions.IncludeErrorMessageInProblemDetails` is true and the host is Development. A startup hosted service logs the two warnings, and the README documents the behaviour.

## Where the knowledge lives

- `src/Encina.AspNetCore/ProblemDetailsExtensions.cs` - the message and exception guard (`ShouldExposeErrorMessage`).
- `src/Encina.AspNetCore/ProblemDetailsStartupWarningService.cs` - the startup warnings.
- `src/Encina.AspNetCore/README.md` - the documented response shape and option.
