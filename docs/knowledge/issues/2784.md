## Asked

Raise the guard coverage flag of the `Encina.AzureFunctions` package to its manifest target with tests that execute real package code.

## Outcome

The gap came from a single guard test file that checked only the null arguments of a handful of entry points, leaving the whole Durable Functions area and most HTTP, context and middleware entry points without a guard test. Two new classes, `DurableGuardTests` and `FunctionsGuardTests`, call the real implementations with invalid arguments and assert the exception type and parameter name, plus the minimum valid call that reaches each check. Behaviour verification stays in the unit flag. The coverage manifest now has a per-file guard target and a verifiable justification for every file. The guard target of `HttpResponseDataExtensions.cs` was lowered because a response needs a full `HttpResponseData` double. The unit flag of the Durable orchestration helpers and of `HttpResponseDataExtensions.cs` is still far below its target and is tracked as #2787.

## Where the knowledge lives

- `.github/coverage-manifest/Encina.AzureFunctions.json` - the per-file guard and unit targets and what each flag really runs.
- `tests/Encina.GuardTests/Cloud/AzureFunctions/` - `DurableGuardTests.cs`, `FunctionsGuardTests.cs` and the original `GuardClauseTests.cs`.
