## Asked

Apply the Orchestrator/Store/Factory pattern used for `Encina.Validation` to the 8 `Encina.Caching` packages, on the stated assumption that providers duplicated about 300-400 lines of behavior code.

## Outcome

Rejected with a reason on 2025-12-23 by the maintainer's own closing comment, before any pull request was opened. The timeline shows no PR, only unrelated cross-references from #15, #16, #18, #280 and #650.

## Where the knowledge lives

- The decision is encoded in the code: the three behaviors in `src/Encina.Caching/Behaviors/` and provider packages that only implement `ICacheProvider`.
- Before the SPEC-003 migration the reasoning lived only in the issue's closing comment; this record is now its durable home. A one-line note in `AGENTS.md` would be a nice-to-have, not a gap worth an issue.

## Audit

No code was delivered, so the full AUD checklist does not apply (SPEC-003 REQ-010). The audit re-verified against today's tree that the premise the maintainer refuted in 2025-12-23 is still refuted: the three behaviors are still centralized and no provider duplicates behavior. One minor finding (documentation durability) is resolved by this record; no remediation issue. See [docs/knowledge/audits/issue-13.md](../audits/issue-13.md).
