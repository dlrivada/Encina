## Asked

Stop the audit entry factory from swallowing PII masking failures and from storing the raw payload when no redactor is registered.

## Outcome

Fixed on branch `fix/1835-audit-pii-masking-fail-closed`: the factory and `DefaultSensitiveDataRedactor` fail closed, `AuditPipelineBehavior` maps a masking failure to `audit.masking_failed`, the payload path masks through any registered `IPiiMasker`, and the audit module requires a masker at startup unless the application opts out explicitly.

## Where the knowledge lives

- `src/Encina.Security.Audit/OperationAuditMaskingStartupValidator.cs` - the startup requirement and the logged opt-out.
- `src/Encina.Security.Audit/DefaultOperationAuditEntryFactory.cs` - masking failures are a Left with `audit.masking_failed`.
- `docs/features/audit-tracking.md` - the user-facing description and troubleshooting.

## Audit

Not audited yet. Siblings checked: the read audit entries carry no payload; the EF Core entity-change audit (`AuditInterceptor`) stores raw old and new values with no masking, tracked in a follow-up issue.
