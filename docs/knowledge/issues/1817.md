## Asked

Make the audit publisher, in its normal and delta plans, never publish a relative Markdown link that does not resolve from the file's published location.

## Outcome

`Publish-AuditKnowledge` now runs `Update-PlanLinks` on every Markdown file of the plan after it is written to the publication checkout and before validation: inline links, images and reference definitions are resolved against the source folder (`LinkBase` of the plan item: the stage's folder, `docs/knowledge/issues/` for the delta scope, the destination for generated files) and rewritten relative to the destination; anchors, absolute URLs, site-root links, fenced code and inline code are untouched; a link that resolves from neither location fails the publish before anything is pushed. Reference definitions are recognised only when nothing but an optional title follows the target (footnotes and prose such as `[HIGH]: text` are left alone); a target that changes is re-encoded (`%`, `#`, `?`, parentheses, space) and one that does not keeps its original text; the delta scope turns relative links in the copied stage excerpts into plain text `text (path)`. The guarantee covers those link forms only. Not covered: fences inside indented or blockquote blocks, link text spanning several lines, backslash escapes, raw HTML links, `#heading` fragments (the file is checked, not the heading) and directory targets written without a trailing slash. Covered by `audit-delta-selftest.ps1` and `audit-done-selftest.ps1`.

## Where the knowledge lives

- `tools/ai/audit/_audit-lib.ps1` — `Update-PublishedLinks`, `Update-PlanLinks` and the `LinkBase` of the publish plans.
- `tools/ai/audit/audit-delta-selftest.ps1` — unit and end-to-end cases for the rewrite and the failure.
