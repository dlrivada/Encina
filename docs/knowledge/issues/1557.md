## Asked

Stop `EncinaError.Message` and exception messages reaching logger calls across the libraries.

## Outcome

Every logger call under `src/` now receives `ForLogging()` exceptions and error codes or exception types when the exception or error is passed directly; the NIS2 measure results and the secret audit entries are built from error codes too. Activity tags, `EncinaError` messages built from exception messages and values routed through local variables are not covered yet and are tracked in #1591; #1604 (partial SQS batch failure visibility) is a separate behaviour bug. A scan test over `src/` keeps it that way; it fails on origin/main and passes after the change. XML and markdown examples teach the same rule.

## Where the knowledge lives

- `tests/Encina.UnitTests/Core/LoggerExceptionLeakStaticScanTests.cs` — the executable guard, with an allowlist whose entries are checked for staleness.
- `AGENTS.md` section 3 — the rule.
