## Asked

After #1388 (PR #1394, merged), audit #16's remediation stage still failed the audit verifier on re-run, with
three corrections against drafts written by `tools/ai/audit/audit-draft-remediation.ps1`: code finding 3 was
wrongly marked "duplicate of #1343" even though #1343 does not cover the finding's second location
(`SagaOrchestrator.cs`); the 16-docs-1 draft kept `technical_debt.md`'s own "Link any related issues here."
placeholder sentence verbatim; and the 16-code-5 draft listed three real but wholly unrelated issues (#699,
#696, #181) under Related Issues with no supporting evidence, invented by the local model.

## Outcome

Delivered: `Test-DuplicateEvidence` now requires every file anchor of a finding's own leading location clause
to match a candidate, not just one, narrowing `Get-FindingAnchors`'s file-anchor extraction to that leading,
colon-terminated clause (`Get-LeadingLocationText`); a rejected candidate that still matched at least one
anchor is worded "partially related" (`Test-PartialDuplicateEvidence`) rather than "possibly related".
`Find-TemplatePlaceholders` now takes the one routed template's own text and derives placeholder markers from
every non-structural line of the template body, catching instruction sentences #1388's hand-written list did
not know about. A new `Limit-RelatedIssues` sanitizes a finished draft's Related Issues section (both the H2
header and `bug_report.md`'s own bold-bullet convention), keeping only a reference that is the audited issue
itself or is backed by the finding text, the candidates offered to the classifier, or the script's own
duplicate/partially-related/possibly-related note, logging every other removal.

## Where the knowledge lives

- `tools/ai/audit/_remediation-checks.ps1` -- `Get-LeadingLocationText`, the stricter `Test-DuplicateEvidence`,
  the new `Test-PartialDuplicateEvidence`, the template-driven `Find-TemplatePlaceholders`, and the new
  `Limit-RelatedIssues`.
- `tools/ai/audit/audit-draft-remediation.ps1` -- wires the partial-duplicate note wording, passes the routed
  template's own text to `Find-TemplatePlaceholders`, and calls `Limit-RelatedIssues` after a draft is
  repaired, logging removed references as pipeline lessons and against the finding's own
  `stages/remediation.md` line.
- `.claude/hooks/tests/Test-Hooks.ps1` -- the `#1400` regression block, with fixtures under
  `.claude/hooks/tests/fixtures/1400/` (the real code finding 3 vs `#1343`, the real 16-docs-1 and 16-code-5
  drafts, and the real code finding 5 text) alongside the pre-existing `#1388` fixtures it re-asserts.
- `.claude/skills/issue-audit/SKILL.md` -- documents the coverage rule, the Related Issues sanitizer, and that
  remediation drafts live in the main checkout's `artifacts/knowledge/remediation/`, not the audit worktree.
