## Asked

Give outbound (Refit) errors a code and `http.status`, `http.retry_after` and `transient` metadata without the response body, move the error classifier to core, and make the retry layers (Polly retry, the recoverability pipeline, the delayed-retry processor) classify through it, honour `Retry-After` (the outbox processor only honours `http.retry_after` as the minimum delay of `NextRetryAtUtc`; its classification and non-idempotent rule are tracked in #2587), never retry a permanent error and never retry an ambiguous failure of a non-idempotent send without an opt-in.

## Outcome

Delivered in the PR that closes #1223: `src/Encina/Recoverability` (classifier, outbound codes and metadata keys, `RetryAfterParser`, `OutboundRetryRules`, `RetryMetrics`), the Refit handler, the Polly retry behavior, the recoverability pipeline, the delayed-retry processor and the outbox processor (which only honours `http.retry_after`; classification there is tracked in #2587).

- `src/Encina/Recoverability/IErrorClassifier.cs` — classification order and the pool-exhaustion rule.
- `src/Encina/Recoverability/OutboundRetryRules.cs` — the non-idempotent and Retry-After rules every retry layer shares.
- `src/Encina.Refit/Handlers/RestApiRequestHandler.cs` — the outbound taxonomy.
- `tests/Encina.IntegrationTests/Web/Refit/OutboundErrorTaxonomyIntegrationTests.cs` — the WireMock scenarios.
