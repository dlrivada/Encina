## Findings

1. **Blocker** — Three pages say the README carries a mutation-score badge that a script updates, and the README has none. Evidence: `docs/en/guides/TESTING.md:100` ("The README badge is updated automatically by `.github/scripts/update-mutation-summary.cs`, which is invoked by the publish workflow after each Stryker run"), `docs/en/guides/REQUIREMENTS.md:35` ("refresh the badge with `.github/scripts/update-mutation-summary.cs`") and `docs/testing/mutation-measurement-methodology.md:26` ("The score reported by the dashboard, the README badge, and ..."). The script looks for `![Mutation](https://img.shields.io/badge/mutation-NN%25-RRGGBB.svg)` (`update-mutation-summary.cs:219`); `README.md` has no such badge (the mutation lines are `:26`, a static "dashboard" link badge, and `:35`, a "guide" link badge), so the script takes the `!badgeRegex.IsMatch` branch (`:224-228`), prints a suggestion and returns without writing. It is invoked from `mutation-tests.yml:579`, which only captures the output. Check that fails: Real API / facts (a described behavior that does not occur). Open issues: none cover it (#1385 mentions badges only for `perf-badge.cs`; searched "mutation badge", "update-mutation-summary"). Fix: state that the README links the dashboard and has no score badge, or restore the badge and the script's target together.
2. **Blocker** — `docs/en/guides/REQUIREMENTS.md:35` says "CI enforces the 93.74% baseline" for mutation testing: a hand-typed figure (house rule 2) with no gate behind it. Evidence: a search for `93\.7` over `.github/workflows/*.yml` and `.github/scripts/*.cs` returns 0 hits, and the mutation dashboard data the code stage read (`mutations/data/latest.json`, 2026-10-02) shows an overall score of 0.44. The figure must be a `mutref` citation or be removed, and the enforcement sentence must name the job that fails or go. Open issues: #2003 covers `REQUIREMENTS.md:27`, `:34` and `:54` (the benchmark thresholds) and not `:35`; #1440 and #1026 own the 0 score, not this sentence. Extend #2003's location list with `:35`, or open a new item.
3. **Major** — ADR-023 tells the reader that the failing SonarCloud Quality Gate is cosmetic and caused only by coverage, which the live gate contradicts. Evidence: `docs/architecture/adr/023-coverage-strategy-codecov-sonarcloud.md:100` ("This is cosmetic ... the QG will always fail on that condition") and `:106` ("SonarCloud QG FAIL badge is expected and should be ignored for coverage"); the code stage's finding 1 shows the gate of `main` failing on four conditions (`new_reliability_rating`, `new_security_rating`, `new_coverage`, `new_security_hotspots_reviewed`), two of which are not coverage, and that no job fails on it. A reader following the ADR learns to ignore a gate that is also reporting security and reliability regressions. Decisions check: the ADR must be superseded, not edited. Open issues: #1665 already asks for a superseding ADR and notes the `:43-45` versus `:100` inconsistency, but does not mention that the gate fails on non-coverage conditions; add that to #1665's Proposed Fix. No `README.md` text explains what the SonarCloud badges measure or that a gate exists.
4. **Minor** — No page explains the badge block, although `CONTRIBUTING.md:92` tells contributors to "Update documentation and badges when your changes affect capabilities, coverage, or quality". Evidence: a case-insensitive search for `badge` over `docs/contributing/README.md` returns 0 hits; the pages that mention badges are the five listed above and none says which badge measures what (workflow status versus SonarCloud measure versus dashboard link), where each value comes from, or how to change one. Rule (a) point 5 (adequate docs): there is no concept or reference page for the quality signals the README advertises. Open issues: #1103 (contributor onboarding guide) is the nearest and does not list badges; no issue covers it (searched "README badges", "badge", "quality signals"). Fix: a short reference table (badge, source, refreshed by, what it does not see) in the contributor guide of #1103, with the code stage's findings 3 and 5 (SBOM tag runs, CodeRabbit link) as its first rows.

## Lessons for the pipeline
- A "the badge is updated automatically" sentence is checkable by reading the updater: its regex has to match something in the README. Search the script for the pattern it rewrites, then the README for that pattern.
- When the code stage proves a gate hollow (Quality Gate fails, nothing enforces it), search the ADRs for sentences that tell the reader to ignore that gate; here ADR-023 did.
- Count a badge block with a regex over the line range and say what is counted (images versus linked images); "N badge links" was wrong here (26 images, 21 linked; audit #32 verifier correction 2).
