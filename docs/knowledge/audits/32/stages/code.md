## Lessons for the pipeline
- The archivist said "whether each badge resolves live was not fetched"; the code stage must do it, and a 200 is the weakest of three checks: also read the badge text (the GitHub badge SVG carries the status in `<title>`), compare it with the source (SonarCloud and Codecov APIs, `gh run list`) and test `?branch=` for tag-triggered workflows.
- For a badge or status scope, ask "what does this badge not see" before "does it resolve": a green workflow badge on a scanner (SonarCloud) does not carry the gate, and a green badge on a tag-triggered workflow (SBOM) does not carry tag runs.
- SonarCloud's public API (`qualitygates/project_status`, `issues/search`, `hotspots/search`, `measures/component`) needs no token for this public project and turns "the Security rating is C" into file:line findings.
