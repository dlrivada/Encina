## Lessons for the pipeline

- A manifest default rule that copies a reason ("no constructor null guards") onto every behavior entry hides a guard obligation that tests already satisfy; read the constructor of each scoped file before accepting the reason, and check the guard report for the file.
- For a windowed or adaptive component, the useful test-stage question is whether any existing test advances the clock between consecutive calls after the first window; here none does, which is why a Blocker in the code went unseen for the life of the issue.
- A feature-name filter and a namespace filter can disagree on a shared registration file (`ServiceCollectionExtensions.cs` 8/28 against 16/28); the namespace filter is the one that finds all the tests of the file, and both figures should be printed.
- A consolidation commit that deletes per-flag test projects leaves no `.md` trail; the test stage should run `git log --diff-filter=D -- <path>` per deleted test path named by the archivist and check the manifest for the matching flag key.
