## Lessons for the pipeline

- A SPIKE issue whose only code change is a deletion commit still has a code stage worth running: the check shifts from "is the new code correct" to "is the deletion complete," and the right method is a repository-wide grep for the deleted package's name/namespace across `src/`, `tests/`, `.github/`, `.vscode/`, centralized-package-management files and solution files — not just the files the archivist listed as touched by the original commit. Three of this audit's four findings were leftover references the archivist's `docs/`-focused destination sweep did not check because they live in `.vscode/`, `.github/ISSUE_TEMPLATE/` and `Directory.Packages.props`, none of which are "docs."
- When a deletion-only issue's scope tempts a full re-audit of the sibling package the decision "kept" (here, `Encina.Marten`'s 48 files), stop at reading the two-to-three files the archivist actually scoped for design-smell leftovers and do not expand into a full implementation audit of code written under different issues — that duplicates work the pipeline will do anyway when those issues are audited, and blows the "as if it were issue #17's PR" framing since #17's real diff never touched `Encina.Marten`.
