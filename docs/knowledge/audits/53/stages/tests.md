The real-manager concurrency tests (`BulkheadPipelineBehaviorTests.cs:281`, `PolicyCombinationTests.cs:98`, `EndToEndIntegrationTests.cs:187`) start their callers one after another (`BulkheadPipelineBehaviorTests.cs:315-317` and `EndToEndIntegrationTests.cs:215-217` from a `Select(...).ToList()`, `PolicyCombinationTests.cs:127-130` from a `for` loop), so each `Handle` runs synchronously up to its first await and the arrivals are serialised; they use `MaxQueuedActions` 5 or 10 with fewer waiters than the bound, and they assert concurrency (`maxConcurrent <= 2`), not queue size.    Tests needed: (a) deterministic, passes today and pins the sequential contract: `MaxConcurrency = 1, MaxQueuedActions = 1`, hold the permit, start waiter A and wait (bounded `WaitAsync`) until `GetMetrics(key)!.Value.CurrentQueuedCount == 1`, then B must return `BulkheadFull`; (b) the racing case that fails today: first acquire and release one permit so the bucket exists, then 64 callers released together by a start barrier with `MaxQueuedActions = 1`; require at most one still pending and the rest `BulkheadFull` (code finding 1 reproduction, parts (a) and (b)); (c) `CurrentQueuedCount` never exceeds `MaxQueuedActions`.
