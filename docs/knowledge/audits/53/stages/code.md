## Findings

1. **Major** — The queue bound is not enforced under concurrency, so the documented "requests are rejected when both limits are reached" is soft (unexecuted, static reading). `src/Encina.Polly/Bulkhead/BulkheadManager.cs:125-139` does a check-then-act on two independent reads: `_semaphore.CurrentCount` at `:125` and `_currentQueuedCount` at `:126`, then increments the queue count at `:138` only if `currentCount == 0`.
   (a) When many callers arrive together while one permit is free, all of them read `currentCount > 0`, skip the queue accounting and all block in `WaitAsync` at `:152`. None is counted as queued and none is rejected for the full queue, so the number of waiters is unbounded (each leaves only by timeout, `QueueTimeoutMs` default 30000) and `BulkheadMetrics.CurrentQueuedCount` reads 0.
   (b) When two callers both see `queued == MaxQueuedActions - 1`, both pass the test at `:129` and both increment at `:138`, so the queue exceeds its maximum by the number of racers.
   Fails: the documented contract at `src/Encina.Polly/Attributes/BulkheadAttribute.cs:14` and `:56`, and metrics honesty (known pattern: non-atomic check-then-act). No open issue covers it (open-issue search over `BulkheadManager|MaxQueuedActions|QueueTimeoutMs` found only #2274, #565 and #139, which are other subjects).
   Fix direction (not decided here): reserve a queue slot with an `Interlocked.Increment` compared against the maximum, or take the fast path with `_semaphore.Wait(0)` first and count only callers that actually wait.
   Reproduction for the verifier: copy `BulkheadAttribute.cs`, `IBulkheadManager.cs` and `BulkheadManager.cs` into one file-based app (no `#:project` to `src/`). (a) `MaxConcurrency=1, MaxQueuedActions=1, QueueTimeoutMs=3000`; first acquire and release one permit so the bucket exists and the count is 1; then start 64 `Task.Factory.StartNew(LongRunning)` tasks behind a `Barrier(64)` that each call `TryAcquireAsync("k", cfg)`; after 500 ms count completed tasks. Contract: 1 acquired, at most 1 waiting, the rest `BulkheadFull`. Expect more than 1 task still pending and `GetMetrics("k").CurrentQueuedCount` below the pending count. (b) Hold the only permit, then fire 32 callers behind a barrier with `MaxQueuedActions=1`; count how many stay pending (contract: 1).

2. **Major** — The injected `TimeProvider` is accepted and then discarded, and the queue timeout runs on the wall clock. `src/Encina.Polly/Bulkhead/BulkheadManager.cs:32-35` takes a `timeProvider` documented as "Time provider for timeout calculations" (`:31`). It is passed to the bucket, where `:111-112` says "timeProvider reserved for future use" and runs `_ = timeProvider;`. The only time-driven logic, the queue timeout, uses `new CancellationTokenSource(timeout)` at `:145` and `_semaphore.WaitAsync(timeout, linkedCts.Token)` at `:152`.
   Fails: AGENTS.md section 3 "Time comes from `TimeProvider`... Every store and repository supports it" (why: #543, #667), plus a false XML doc on a public constructor (`src/Encina.Polly/PublicAPI.Unshipped.txt:148`).
   Consequence: `tests/Encina.UnitTests/Polly/BulkheadManagerTests.cs:18-19` builds the manager with a `FakeTimeProvider` but the timeout tests use real milliseconds (`:70` `QueueTimeoutMs = 100`), so queue-timeout behavior cannot be tested without waiting; the same class of defect as #531 and #2561 (both fixed).
   Fix direction: `timeProvider.CreateCancellationTokenSource(timeout)` and `WaitAsync(Timeout.InfiniteTimeSpan, linkedToken)`, or remove the parameter. The sibling `src/Encina.Polly/Behaviors/CircuitBreakerPipelineBehavior.cs:19-37, :108` does use its `TimeProvider`.

3. **Major** — `BulkheadAttribute` validates nothing, so a plausible value silently rejects every request and an invalid one throws a raw exception on every request (unexecuted, derived from .NET semantics). `src/Encina.Polly/Attributes/BulkheadAttribute.cs:49, :59, :68` are plain `{ get; init; }` auto-properties, while the sibling `src/Encina.Polly/Attributes/CircuitBreakerAttribute.cs:36-106` throws `ArgumentOutOfRangeException` for out-of-range values.
   `QueueTimeoutMs = 0` (the natural reading of "do not wait", by analogy with `MaxQueuedActions = 0` documented as "disable queueing" at `BulkheadAttribute.cs:57`): `new CancellationTokenSource(TimeSpan.Zero)` at `BulkheadManager.cs:145` is cancelled at once, so the linked token is already cancelled; `WaitAsync` then throws before taking a free permit, and `:154-158` returns `RejectedQueueTimeout` for every request even when every permit is free.
   `MaxConcurrency <= 0`: `new SemaphoreSlim(config.MaxConcurrency, config.MaxConcurrency)` at `BulkheadManager.cs:115` throws `ArgumentOutOfRangeException` inside `GetOrAdd` (`:47`) on every request. `QueueTimeoutMs < -1` makes the `CancellationTokenSource` constructor at `:145` throw. The exception escapes `src/Encina.Polly/Behaviors/BulkheadPipelineBehavior.cs:61` (no handler around `TryAcquireAsync`), not a `Left`.
   Fails: AGENTS.md section 3 "validation returns Either with detailed errors" and consistency of the attribute set.
   Verifier: three calls to `TryAcquireAsync` with `QueueTimeoutMs=0`, `MaxConcurrency=0`, `QueueTimeoutMs=-5`; expect `IsAcquired == false` with reason `QueueTimeout` for the first and a thrown `ArgumentOutOfRangeException` for the other two.

4. **Minor** — `AddEncinaPolly` registers the bulkhead behavior with `AddTransient`, so a second call doubles it, and a doubled bulkhead waits on its own permit (static reading, derived from the registration and the manager; unexecuted). `src/Encina.Polly/ServiceCollectionExtensions.cs:56` uses `services.AddTransient(typeof(IPipelineBehavior<,>), typeof(BulkheadPipelineBehavior<,>))`. The test at `tests/Encina.UnitTests/Polly/ServiceCollectionExtensionsTests.cs:207-221` asserts 8 behavior descriptors after two calls and pins that on purpose ("AddTransient allows duplicates (not Try)").
   With two copies in the pipeline, both build the same key `typeof(TRequest).Name` (`src/Encina.Polly/Behaviors/BulkheadPipelineBehavior.cs:57-58`). The inner copy acquires a second permit from the same semaphore while the outer copy holds the first, so effective concurrency halves; when `MaxConcurrency` requests are in flight, every one waits for a permit that only another waiting request holds, until `QueueTimeoutMs`.
   Other packages use `TryAddEnumerable` for their behaviors (single-line pattern `TryAddEnumerable.*IPipelineBehavior` over `src/**/*.cs`: 25 occurrences in 23 files; a multi-line reading gives more, so 23 is a floor).
   Fails: AGENTS.md section 3 registration completeness (a registration must be safe in any order or count).
   Owner: this duplicates open #1784 ("[DEBT] Use TryAddEnumerable for idempotent behavior registrations", read with `gh issue view 1784`): its Location lists "Polly" and its Proposed Fix item 1 is to migrate the Polly behavior registrations to `TryAddEnumerable(ServiceDescriptor...)`; item 2 extends the repeat-call idempotency test, which is the pinned `AddEncinaPolly_MultipleCalls_ShouldAddDuplicates` (`tests/Encina.UnitTests/Polly/ServiceCollectionExtensionsTests.cs:207-221`). #2286 (open, TEST) is the owner of the Polly DI proof (`ValidateOnBuild`/`ValidateScopes`) and mentions the pinned test only as a test to rewrite. The duplicate registration also doubles retry attempts and rate limit counting in the siblings, which #1784 covers by its package list.
   What is new and not in #1784 (derived, unrun): the bulkhead-specific consequence described above, the self-wait on one non-reentrant semaphore keyed by `typeof(TRequest).Name` (`BulkheadPipelineBehavior.cs:57-58`, `BulkheadManager.cs:125-152`), for the owner's comment. Registration lines: `ServiceCollectionExtensions.cs:56, :59, :62, :65` and `:144-146` (audit base; on main after PR #2591 the bulkhead `AddTransient` is `:61`).

6. **Minor** — The bulkhead behavior reflects over the request type on every request, including requests with no `[Bulkhead]` attribute (unexecuted, static reading). `src/Encina.Polly/Behaviors/BulkheadPipelineBehavior.cs:50-51` calls `typeof(TRequest).GetCustomAttributes(typeof(BulkheadAttribute), true).FirstOrDefault()` on every call. The behavior is an open-generic registration (`src/Encina.Polly/ServiceCollectionExtensions.cs:56`), so every request in an application that calls `AddEncinaPolly()` pays this lookup (an array allocation plus attribute materialization) just to pass through. Because `TRequest` is a generic argument, a `static readonly` field in the closed generic class would resolve it once per request type.
   The same shape is in the sibling behaviors: `RateLimitingPipelineBehavior.cs:50`, `CircuitBreakerPipelineBehavior.cs:49`, `RetryPipelineBehavior.cs:38`, so the pass-through cost is four lookups per request.
   Open-issue search: #2575 covers this exact pattern for `ReadWriteRoutingPipelineBehavior` only; no issue covers the Polly behaviors.
   Fails: AGENTS.md "pay-for-what-you-use" and the same defect class as #49 (per-request reflection in a dispatcher path).

7. **Minor** — The fast path allocates two `CancellationTokenSource` objects and a timer on every acquire, even when a permit is free (unexecuted, static reading). `src/Encina.Polly/Bulkhead/BulkheadManager.cs:144-147` creates `timeoutCts = new CancellationTokenSource(timeout)` (registers a timer for `QueueTimeoutMs`, default 30 s) and a linked source before acquiring (`CurrentCount` is read first at `:125`, but its result does not skip the creation). When `CurrentCount > 0` the wait completes synchronously and both objects are disposed unused. A `_semaphore.Wait(0)` first attempt would skip both; `BulkheadReleaser` (`:172`) adds one more allocation per acquire.
   #565 (open) lists the target "Bulkhead acquire (uncontended) < 500ns" but does not claim this; the benchmark file is `tests/Encina.BenchmarkTests/Encina.Polly.Benchmarks/BulkheadBenchmarks.cs`. Not measured; the test stage or verifier can run that benchmark.

8. **Minor** — `Reset` and `Dispose` break callers that are mid-acquire or hold a permit, and the failure is an exception, not a rejection (unexecuted, static reading). `src/Encina.Polly/Bulkhead/BulkheadManager.cs:66-74` removes and disposes the bucket while permits are outstanding. The next call for the same key creates a fresh bucket with full capacity (`:47`), so the old holders and the new ones run together and the limit is exceeded. A caller that already obtained the old bucket hits `ObjectDisposedException.ThrowIf(_disposed, this)` at `:122` or, past that check, a `WaitAsync` on the disposed semaphore at `:152`. The `catch` blocks at `:154-163` handle only `OperationCanceledException`, and the behavior has no handler, so the exception escapes the `Either` pipeline.
   `Reset` and `GetMetrics` are on the public `IBulkheadManager` (`src/Encina.Polly/Bulkhead/IBulkheadManager.cs:35, :41`) but have no caller in `src` (grep `IBulkheadManager|\.Reset\(|GetMetrics\(` over `src/**/*.cs`: the only uses are the declarations and the manager's own `GetMetrics` calls), so `Reset` is a test hook on a public interface. Fix direction: drain instead of dispose, or make it internal/test-only.

## Lessons for the pipeline

- A file-based replica of a self-contained class (copy three source files into one `Program.cs` in the scratchpad) is the right tool for a concurrency claim, but writing it with `Set-Content` is blocked by `block-main-checkout-writes` for an `issue-auditor`. The stage text should say whether the auditor writes the replica with Write, or sends concurrency replicas to the verifier; finding 1 carries the reproduction for the verifier.
- For a pattern issue whose family was audited earlier (rate limiting: #40, #2273-#2278), read the open issues' bodies for lines that say "the same applies to the bulkhead": #2273 and #2275 both do, which turned two archivist-planned items (error code, key) into Informational and moved the effort to the manager's concurrency and validation.
- Search open issues for the fix as well as the defect words: #1784 (`TryAddEnumerable`, "idempotent behavior registrations") owns finding 4 but shares no identifier with `AddTransient`/bulkhead; an umbrella issue whose Location lists the package ("Polly") is the owner even when the defect search misses it. A "N files" count states its grep pattern next to the number.
- A test that pins a defect on purpose (`AddEncinaPolly_MultipleCalls_ShouldAddDuplicates`, comment "AddTransient allows duplicates (not Try)") is a pointer to a production-shape defect; read what the duplicated component does with shared state (here a non-reentrant semaphore keyed by name) before treating it as a test-only gap.
- For a `SemaphoreSlim`-based limiter, read the order of the check, the queue accounting and the wait as one unit: every individual line looked right, and the soft bound only shows when the three are read together.
