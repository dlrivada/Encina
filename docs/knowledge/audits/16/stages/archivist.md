## Lessons for the pipeline
- The audit worktree (`wia-16`) did not have `artifacts/knowledge/predraft/16.md` or `artifacts/knowledge/predraft/raw/16.txt` — `artifacts/` is entirely gitignored, so a fresh worktree checkout has none of the local-model pre-draft output that only exists in the main checkout's working directory. I read the pre-draft and raw input from the main checkout (read-only, per AGENTS.md) rather than copying them into the worktree, since `enforce-path-ownership.ps1` correctly blocks issue-archivist from writing anything under `artifacts/knowledge/predraft/`. Future runs of `audit-next.ps1` (or whatever seeds a new `wia-<n>` worktree) should either copy the relevant pre-draft/raw files into the new worktree before handing off to the archivist, or the archivist's brief should explicitly say "read the pre-draft from the main checkout path, not the worktree" so the next agent doesn't waste a step looking for it inside the worktree first.
- The pre-draft's "Open questions for the auditor" were all real and worth verifying — the ADR-does-not-exist question and the DI-extension-name question both turned out to point at genuine gaps (no ADR; `AddEncinaChoreography` referenced in docs does not exist in code). Verifying pre-draft open questions against `src/` directly (grep for the named symbols) rather than trusting the doc's prose caught a real doc/code drift the pre-draft could not have found on its own (it only had issue/comment text, not repo access).
