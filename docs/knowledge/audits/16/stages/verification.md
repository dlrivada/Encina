## Lessons for the pipeline

- The `git merge-base --is-ancestor <commit> HEAD` check introduced by the tests-stage's pass-7 re-run is now confirmed to work as intended from the verifier's side too: running the exact same `Grep` this pass, inside the worktree, reproduced the stage's corrected "zero references" claim exactly. This is worth keeping as the standing verifier discipline for every future "I searched and found nothing" claim in a long-running audit worktree that has not been rebased: check the branch first, then reproduce the search inside that branch's own checkout, never the main checkout.
- A parenthetical line count in a finding's prose (e.g., "`SagaNotFoundDispatcher.cs` (28 lines)") can silently mean "coverable lines per the coverage tool" rather than "total lines in the file" when the same document's coverage table uses the same number for a 0/N coverage cell. This is not a file:line citation error (no specific line is misquoted) and should not be flagged as a correction on its own, but a stage should say "28 coverable lines (per the cobertura report)" rather than the bare "(28 lines)" so a reader — or a future verifier — does not have to infer which count is meant from a different section of the document.
