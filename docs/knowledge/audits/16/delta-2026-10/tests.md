## Lessons for the pipeline
- A guard ceiling must come from the report's valid-line list, not from the source: the first version of this stage assumed the two `ThrowIfNull` lines of `SagaNotFoundDispatcher.DispatchAsync` (38, 39) were not coverable lines in an async method; they are, and the ceiling is 8/28, not 6/28. Print the valid lines of the file for the flag before writing a reachable-line count.
- A `FullyQualifiedName~ServiceCollectionExtensions` filter matches the registration tests of every package, so the figure for a shared registration file (`MessagingServiceCollectionExtensions.cs`) is not isolated to its own namespace; run the file's own namespace alone as a second measurement, and keep the log path literal because the hook cannot resolve a variable log target.
- `gh issue view N --json body --jq .body` returns an array of lines in PowerShell; join it with a newline before calling `.Substring` or `.IndexOf`, or searching a long umbrella body by position fails with an index error.
- Open test issues written from an earlier audit carry stale numbers once the worktree is rebuilt from `origin/main`: #1480 states 0% unit for the dispatcher, the measured figure is 21.43% since the DI smoke checks landed, and it also lists an interface (`IHandleSagaNotFound`) as having 0% coverage; a delta stage should compare each cited issue's numbers with the new measurement and name the stale ones for the orchestrator.
- A manifest entry that lists `unit` and `guard` for an interface with no coverable line (`IHandleSagaNotFound.cs`, `IEventReaction.cs`) is a classification defect that generates impossible test requests; the delta brief for rule (b) should say that such entries are Minor classification findings, not missing targets.
- When one remediation theme repeats across sibling providers (ADO x3, Dapper x3), the sibling comparison found a real gap only by opening each guard class: the MySQL Dapper guard class has 4 tests against 9 in its siblings, and no Dapper integration test calls `GetExpiredSagasAsync` in any provider; the unrounded per-provider table should be a standard part of the stage output for provider stores.
- (Re-run, correction 1) A unit ceiling for a provider store must be derived from what its constructor types let a test substitute, not from the word "database": `SagaStoreADO` takes `IDbConnection`/`IDbCommand`/`IDataReader`, so only the three provider-typed returns (`SqlCommand`, `SqlDataReader` branches) are out of reach and the unit ceiling is 98.5%, not 4.4%. Before writing "needs a real connection", grep `tests\Encina.UnitTests` for the sibling store's mocks (`Substitute.For<IDbCommand>` found `OutboxStoreADORequeueTransactionTests.cs:63-88` in one call) and list, line by line from the uncovered list, which lines are provider-typed branches.
