## Lessons for the pipeline

- A configuration block can fail on the very first call before any option name matters: `AddEncina(config => config.UseSagas = true)` compiles only if `EncinaConfiguration` has the property, and the real members live on `MessagingConfiguration`, reached through the persistence-provider registration. When a page sets a flag, find the class that declares the flag and the registration method whose parameter is that class, instead of searching for the flag name alone (which hits `UseSagas` and passes).
- A method name that appears in `src/` only in XML doc comments (`AddEncinaMessaging`) passes a plain search for the identifier. Search for the declaration shape (`public static .* Name\(`) or classify each hit as code or comment before calling an identifier real.
- A knowledge record can point at a hand-written API surface that existing issues already attack from several sides (here #1467-#1479); the new work in a delta audit is usually the lines those issues do not name, so compare by file path and line range before writing, and say which neighbouring issue each finding sits next to.
- Rule (a) point 1 needs a reading of each diagram, not only a count of diagrams: the flowchart here had both branches of each decision leading to the same node, which no search finds.
- (Re-run after verifier FAIL) Cite a file only after `Test-Path`: `src/Encina/ServiceCollectionExtensions.cs` was invented from the namespace; the overloads are in `src/Encina/Core/ServiceCollectionExtensions.cs:31` and `:41`. When claiming a flag lives only on one class, search the whole `src/` for the flag name (`UseSagas` is also on `EncinaMongoDbOptions.cs:60`) and limit the claim to the class actually compared.
- A range at the end of a file is checked against the line count: `docs/messaging/index.md` has 70 lines, and the placeholder bullets are at :69-70, not :70-71.
- A "0 hits" claim names the exact paths searched and is reproduced over the broader scope the sentence implies: the saga search over `docs/guides/*.md` has 4 hits, all in `health-checks.md`, and the inbound links include `docs/introduction.md:15`. Check optional front-matter fields against the SKILL before listing them as a gap (`nav_order` is optional, `SKILL.md:33`).
- Describe a sample defect from the code as written: the choreography reactions have no constructor at all, so the defect is unassigned fields (a `NullReferenceException` for `_inventory`) plus one dead field, not an injected-but-unused dependency.
- (Re-run 2 after verifier pass 2 FAIL) Verify every line number cited in a re-run, not only the corrected ones: the first re-run wrote `:342` and `:348` (a comment and a blank line; the calls are at :343 and :350) in new text, and ended two block ranges one line late (`index.md:53-60`, `README.md:23-31`). Print each cited range with a line counter and end a block range at its closing token.
