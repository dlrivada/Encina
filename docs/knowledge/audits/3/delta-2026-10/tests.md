## Lessons for the pipeline

- A package's tests may sit in a different namespace than the package name: Redis.PubSub unit and guard tests are under `Messaging.RedisPubSub`, and EF Core, Marten and MongoDB guard tests under `Infrastructure.<Package>` as well as `<Package>`. A filter by package namespace reported 0% for `RedisPubSubMessagePublisher.cs` and 0% for the EF Core guard flag; locate the tests first with one `Select-String -List` over `tests\` for the file's type name, then build the filter from the namespaces found.
- For a pure logging refactor the declaration-only `Log.cs` files have no coverable line (the lines are in `obj\...\LoggerMessage.g.cs`), so rule (b) is satisfied by the manifest's empty `defaultTests` plus reason; the useful rule (b) work is on the call-site files the issue edited, which keep package-aggregate targets.
