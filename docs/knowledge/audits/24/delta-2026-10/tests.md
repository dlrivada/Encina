## Lessons for the pipeline

- A delta rule (b) stage on a closed-in-error issue whose duplicate delivered the code should be told up front that the scope is the duplicate's files and that "the original stage was not-audited", so the stage does not look for original figures; the brief here did, and the stage re-measured everything.
- A `Match(Right: ..., Left: _ => 0)` over a store result is the exact shape of the ROP-migration regression (`5496b46a`, #690) that turns a failure into "healthy"; the test that pins it (`SagaHealthCheckTests.cs:96`, named `..._CountsAsZero`) is a pattern worth a repository-wide search (`Left: _ =>` in `src\`), and the test stage should read every "StoreReturnsError" test for what it asserts, not only that it exists.
- When a manifest entry's `reason` says a file has a constructor guard, check the guard flag's report for that file: the adapter's reason names a `ThrowIfNull` that no guard test reaches (0/25), and three files list `guard` while having no argument check; the delta brief for rule (b) can ask the stage to print the `ThrowIfNull` lines of each scoped file before proposing a guard target (as lesson #23 asks).
- A feature-name filter (`~Health`) is needed for the unit flag because the scope's tests sit in four namespaces, and a namespace-only filter under-reports (`InboxHealthCheck.cs` 15/20 against 20/20); the stage should always run both and say which one the proposals use.
- (Re-run, verifier corrections) A "the line is dead" justification and a "this fake needs an override" claim must each be checked against the code before they set a target: line 93 of `CompositeEncinaHealthCheck.cs` is reachable with `(EncinaHealthStatus)(-1)` (the twin arm of the adapter is covered with `999` at `EncinaHealthCheckAdapterTests.cs:183`), and `FakeDbCommand` already overrides `ExecuteScalar`/`ExecuteScalarAsync` (`DatabaseHealthMonitorBaseDbConnectionTests.cs:142-148`). Also list the whole guard-missed set from the report before writing "the remaining lines are X" (lines 123, 125, 128 were omitted), and when a constructor merges an options value with defaults, trace what the container passes (non-null options) before accepting a test that passes null (finding 16: the provider tag is lost on the production path and kept on the tested one).
- The test-auditor cannot settle an end-to-end defect hypothesis that needs a scratch app referencing `src\` (`guard-orchestrator-writes`); findings 2 and 3 are labelled derived and unrun and name an `issue-worker` test, as lessons #22 and #23 recommend; the delta brief could hand such hypotheses to a worker up front.
