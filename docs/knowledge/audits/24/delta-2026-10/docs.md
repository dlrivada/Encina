## Lessons for the pipeline

- A guide that pairs a core call with a builder extension must be checked against the extension's full parameter list: `AddEncinaHealthChecks(sp)` reads naturally and passes any "the method exists" search, but the first parameter is `tags`.
- A claim that a library "provides" checks for patterns needs the registration call that creates each one; search `src/` for who constructs the class (here only the four `AddEncina<Pattern>` builder extensions), not only for the class name.
- A README that says "automatically registered" for an abstraction (`IEncinaHealthCheck`) distinct from the host framework's (`IHealthCheck`) needs the bridging call checked; the constraint on `AddCheck<T>` makes the sample fail, and the bridge (`AddEncinaHealthChecks`) is absent.
