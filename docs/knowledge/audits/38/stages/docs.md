## Findings

1. **Major** — `docs/engineering/PROJECT-HISTORY.md:96` ("Saga timeouts are implemented via a RequestTimeout<T>() pattern to handle hanging business processes. (#38)") states as delivered an API that does not exist. `RequestTimeout<T>` appears in no `*.cs` file of `src/` and in no page except this line (the repository-wide search above returns only `PROJECT-HISTORY.md:96` for `RequestTimeout` outside `docs/knowledge/`). The code stage proves the shipped scope stops at detection: `SagaOrchestrator.TimeoutAsync` has no caller in `src/` and no hosted service enforces `TimeoutAtUtc` (code.md findings 2 and 3). The page header presents itself as the consolidated, cited record of what closed issues decided, so a reader takes this line as the behavior of the library. Fails encina-docs SKILL section 6 (real API; the page claims an identifier that is not in `src/`). The archivist's `gotcha` item already plans this correction ("SPEC-003 audit of #38 remediation batch"), so no open issue carries it yet. Fix: rewrite the bullet to what #38 delivered (persisted `TimeoutAtUtc`, `TimeoutAsync` marks a saga `TimedOut`, `GetExpiredSagasAsync` finds expired sagas; no message-style `RequestTimeout<T>()`, no handler, no scheduler integration, nothing calls `TimeoutAsync` automatically) and add an entry under the page's "Editorial corrections" section as the page's own header prescribes.

2. **Major** — Six package READMEs tell the reader to run scripts under `.github/scripts/` (`000_CreateAllTables.sql`, `003_CreateSagaStatesTable.sql`), a path that does not exist. Search `Select-String '\.github/scripts/'` over `src/**/README.md` returns 36 lines in six files: `src/Encina.ADO.SqlServer/README.md` 5 lines (`:67, :70-73`), `src/Encina.ADO.PostgreSQL/README.md` 5 (`:67, :70-73`), `src/Encina.ADO.MySQL/README.md` 5 (`:67, :70-73`), `src/Encina.Dapper.SqlServer/README.md` 7 (`:61, :68-71, :190, :212`), `src/Encina.Dapper.PostgreSQL/README.md` 7 (`:62, :69-72, :191, :213`) and `src/Encina.Dapper.MySQL/README.md` 7 (`:61, :68-71, :190, :212`). `Test-Path .github/scripts/003_CreateSagaStatesTable.sql` is `False`; the script lives at `src/Encina.ADO.SqlServer/Scripts/003_CreateSagaStatesTable.sql` (`Test-Path` is `True`), and `src/Encina.Dapper.SqlServer/README.md:212` itself links `./Scripts/` under the text ".github/scripts/", so the page contradicts itself. ## Lessons for the pipeline

- For a persistence-feature issue, read the READMEs that tell the user how to create the table (`Scripts/` path references) together with the code stage's schema finding: here the path was wrong and the script behind it was also broken, which neither stage alone shows.
- A project-history bullet that repeats the issue title as if delivered is checked by searching `src/` for the title's identifier (`RequestTimeout`), not by reading the code stage; the archivist's `gotcha` items name these lines and the docs stage should confirm each one by command.
- When an umbrella issue (#1886) holds a diagram item for the feature's new state, the docs stage should still check the options and FAQ sections of the same page, because the umbrella item stops at the diagram.
