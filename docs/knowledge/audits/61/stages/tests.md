## Lessons for the pipeline

- A substitute-based unit test of Durable orchestration helpers hands the object back without serialization, so a boundary defect (a persisted message, a JSON shape read as the wrong type) can never be seen by it; for a type meant to cross a persisted boundary, ask the test stage for a host-free serializer round trip test as a separate item from the host run.
- The comment "needs an orchestration context double" in a manifest justification was wrong and kept the unit targets low: check by reflection on the built dependency (`IsAbstract`, public constructors) whether the double exists before accepting a "cannot be unit tested" claim, which is hook-safe and takes one call.
- `& "$s\script.ps1"` through a variable worked once and was blocked by `guard-orchestrator-writes` on a later call of the same stage ("whose script path the hook cannot resolve"); the literal absolute path worked every time, as the lessons of #19 say. Use the literal path from the first call.
- Coverage of a file with only constants (`DurableSagaErrorCodes.cs`) is absent from the report rather than 0%; a manifest entry with `defaultTests: ["unit"]` and no targets for such a file is a classification finding, not a missing-test finding.
