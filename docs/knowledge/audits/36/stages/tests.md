- When the scope's package manifest has no per-file `targets` at all (Encina.Marten, fifth audit in a row), open the umbrella issues of the earlier audits of the same package first (#1908, #2024, #1975): this unit's measurements reproduced their numbers exactly, so the useful work was the files and the test-quality problems no tracker holds (`EncinaMartenOptions.cs`, the factory's headers branch, the reflection contract tests).
- A test named for an exception path can be built from a stub that throws earlier than the real collaborator would (`InlineProjectionRelayTests.cs:253`); for every test the code stage's defect list touches, read what is substituted before counting the test as proof.
- A test fixture whose literal value equals the thing under test (`TestProjection.ProjectionName` is the string `"TestProjection"` and the assertion is `nameof(TestProjection)`) cannot distinguish the two code paths; check the test double's values when a code-stage finding says a property is ignored.
- (Re-run, verifier correction 1) Before telling the orchestrator to close an open issue because one item is fixed, read every item of that issue: #1348 had two (the relay log, fixed; a `ValidateOnBuild` DI test, open), and the open item was the same gap as Finding 3. A tracker row says which items are done and which remain, and a finding that overlaps an item cites the issue and narrows itself to what the issue does not hold.
- Run the unit flag with both a namespace filter and a feature-name filter and compare per-file figures; here they were identical, which is the cheap proof that no extra test class sits outside the namespace.
