## Lessons for the pipeline

- Test method names that end in `_Throws` for a business-failure option (`RunAsync_CompensationThrows_WithoutContinueOnFailure_Throws`) pin the defect instead of covering it; the tests stage should read the assertions of every test that the code stage names and say whether the test would fail after the fix.
- A guard class can reach 76% of a runner (95/125) while holding only five `ThrowIfNull` lines of guard-reachable code, because behaviour tests live in the guard project; always list the `ThrowIf*` lines per file before proposing a guard target (lessons #23, #24 again).
- The Glob tool returned nothing for the worktree (as the code stage noted); `Get-ChildItem` and `Select-String` over `tests\<project>` were reliable for locating tests and the other flags.
- A single name filter (`~RoutingSlip`) was enough for a large package (Encina.Messaging) because the report was read per file; the wall time of the unit run exceeded 3 minutes (build), so give the foreground run an explicit 10-minute timeout.
