## Lessons for the pipeline

- When the original audit's remediation (the NATS method names, #1611) has already been applied by a later commit, the delta docs stage should re-read the neighbouring lines of the same section: the fix was complete for the registration but the call two lines below (`PublishAsync` with an "acknowledgment" comment) still contradicted the interface.
- A docs-only spike's sample defects are usually already tracked one-per-sample (#1611-#1624); the delta stage should list the open issues for the page first, map each finding to one, and spend its time on what they do not name (emojis, diagram edges, README coverage, tutorial entry, the `SubscribeAsync` call at line 449).
- Before calling a finding new, search the bodies (not only titles) of every open issue, including the same-day Delta re-audit umbrella issues (here #1886 for the #16 index.md items, #1847 for the package READMEs), for the file path, the line range and the identifier; the first pass pointed finding 10 at #1887 and treated finding 7 as untracked (verifier pass 1 FAIL). Count diagrams and tables with a command before writing the number.
