## Lessons for the pipeline

- A helper whose generic constraint excludes every aggregate in the repository passes all of its own tests because the tests define their own conforming aggregates; the test stage should grep `tests\` for the production types the helper is meant for (here `DSRRequestAggregate` is tested without it) before treating the 97.52% as evidence the helper works.
- A parameterless `[Property]` (here four, 250 executions) is a constant test; a scan for `[Property]` methods with no parameters is a one-call check for property files.
- Counts of "the aggregates under a folder" and of "justification files" must come from a command whose pattern is named in the finding (here `class\s+\w+\s*:\s*AggregateBase\b` gave 16, not 15, and `^## Status: Not Implemented` gave 31, 25 and 9, not 31, 33 and 15); a raw `.md` count includes READMEs (audit #46 verifier correction 4).
- Reading `defaultTests` and the package `targets` keys together exposed the contract and property gap: the package has tests of both kinds (in the unit project) and no key for either flag.
