## Findings

1. **Major** — `src/Encina.Testing/EventSourcing/AggregateTestBase.cs:45` and `:481` constrain `TAggregate` to `AggregateBase<TId>` / `AggregateBase<Guid>`, but no production aggregate in the repository derives from the generic type. Search `AggregateBase<` over `src/*.cs` matches only this file and `AggregateBase.cs:137` (the definition) plus two doc comments; all 16 aggregates under `src/Encina.Compliance.*/Aggregates/` (for example `src/Encina.Compliance.Consent/Aggregates/ConsentAggregate.cs:34`, `BreachAggregate.cs:31`, `DPIAAggregate.cs:30`) derive from the non-generic `AggregateBase`. The class the issue shipped to remove aggregate-test boilerplate therefore cannot be used for any aggregate Encina itself ships, and no test outside its own four test files uses it (search `AggregateTestBase` over `tests/*.cs` returns only `tests/Encina.UnitTests/Testing/{EventSourcing,Base/EventSourcing}/` and the guard tests). The constraint is also unnecessary: the class only uses `UncommittedEvents`, `ClearUncommittedEvents`, `Version` and the protected `Apply`, all of which live on `AggregateBase` (`AggregateBase.cs:76-84,128`), and `AggregateShouldlyExtensions.cs:40` and `EncinaVerify.cs:139` already accept `IAggregate`. A second mismatch compounds it: the production aggregates are created through static factories (`ConsentAggregate.Grant`, `ConsentAggregate.cs:157-180`, which does `new ConsentAggregate()` then `RaiseEvent`), while `When(Action<TAggregate>)` (`AggregateTestBase.cs:125`) can only call instance methods on a pre-built instance, so the "GivenEmpty then create" scenario documented at `:100-105` cannot express them either. Fails: the issue's own purpose (Given/When/Then for Encina event-sourced aggregates), AGENTS.md section 1 "every line serves a current purpose", and the adversarial-reviewer pattern "feature shipped but unusable by its own consumers". Fix direction for the drafter: constrain to `AggregateBase` (id type optional), and give `When` a way to capture a static-factory result.

2. **Minor** — `src/Encina.Testing/EventSourcing/AggregateTestBase.cs:413-441` re-implements event replay with two reflection lookups per event (`typeof(AggregateBase).GetMethod("Apply", NonPublic|Instance)` at `:418`, `GetProperty("Version")` at `:432`) and suppresses Sonar S3011 for it, although `AggregateBase.LoadFromHistory` (`AggregateBase.cs:87-102`, also on the `IAggregate` contract and used by `MartenAggregateRepository.cs:340`) is public and does exactly this (apply without tracking, increment `Version`). Concrete divergences from production replay: (a) an exception thrown by the aggregate's `Apply` during `Given` surfaces as `TargetInvocationException` from `applyMethod.Invoke` (`:429`), hiding the real exception, while production raises it directly; (b) a null element is passed to `Apply` (`:429`) whereas `LoadFromHistory` rejects it with `ArgumentException` (`AggregateBase.cs:93-96`); (c) the `versionProperty?.CanWrite is true` branch (`:436`) is a defensive path that cannot be false because `Version` has a public setter (`AggregateBase.cs:76`), and the version increment at `:438-439` is the only one per replayed event (`AggregateBase.Apply` is abstract, `AggregateBase.cs:128`, and does not touch `Version`), giving the same net `Version` as `LoadFromHistory` (`AggregateBase.cs:100`); the divergence is that the test helper, not the aggregate, owns the counting, which is another copy of the replay logic that can drift. Fails: duplicated logic that can drift from the production replay (AGENTS.md section 3 "errors never swallowed" in spirit: the wrapped exception hides the cause) and the S3011 suppression disappears if `Given` simply calls `_aggregate.LoadFromHistory(events)`. Related open issue: #1923 lists "replace the reflection in `ApplyEventToAggregate` with `AggregateBase.LoadFromHistory`" as an optional checklist item tied to a coverage target (the dead branch at `:424-426`); it does not mention the three behavioral divergences (a)-(c), which are why the replacement is a correction and not only a coverage convenience.

Fails: AGENTS.md section 8 "Public API is tracked by PublicAPI.Shipped.txt and PublicAPI.Unshipped.txt" and "CI enforces public API compatibility". Package-wide (covers every public type in `Encina.Testing`), found while auditing this class.

## Lessons for the pipeline

- A test-infrastructure class is only as good as its constraints: for any base class or helper the code stage should grep the repository's own consumers of the abstraction it constrains to (here `AggregateBase<TId>` versus the 16 aggregates on non-generic `AggregateBase`), because a shipped helper nobody in the repo can use passes every one of its own tests.
- When a helper reflects over a protected member of a public base type, check whether the base type already exposes a public equivalent (`LoadFromHistory`); the reflection and its Sonar suppression are the visible symptom.
