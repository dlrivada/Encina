## Lessons for the pipeline
- Rule (b) in a package whose manifest has no per-file `targets` at all (here every entry of `Encina.Marten.json`) needs the brief to say so: the finding is then "every file is gated only by the package aggregate", and the useful work is the flags that have tests but no key (integration here, contract for `ProjectionRegistry.cs`) and the per-file classification (a reason copied from the `^I[A-Z].*\.cs$` rule on a file that also declares a class, `IProjectionManager.cs`).
- A reflection-based call such as `typeof(IInterface).GetMethod(...)` can be checked in seconds without running the product: `[Reflection.Assembly]::LoadFrom` of the built `Marten.dll` from a test `bin\Release\net10.0` folder, then the same lookup (it returned null for `LoadAsync` and `Store` on `IDocumentSession`). When one class of a package documents and fixes such a defect (`InlineProjectionDispatcher.cs:57-60`), grep the sibling classes for the same call shape before accepting that they work.
- A coverage-gap finding for a file that no test of a flag reaches (0/283 integration) should look for the bug the gap hides before proposing a target: the missing rebuild test is why `MartenProjectionManager` kept broken reflection lookups that the dispatcher had already fixed. A defect found that way is its own numbered finding (finding 6 here), never a paragraph inside the coverage finding: the remediation drafter files one issue per finding, so a bug buried in a target finding is drafted as a `[TEST]` and loses its `[BUG]` shape (verifier pass 1 correction 2).
- Attribute a fix to a commit with `git log --oneline -- <file>` on the file itself, never from the topic of a similarly named commit: the relay's logging fix was `a806ab65` (#1328/#1397), and the first version cited `da52fcd6` (#1606), which never touched `InlineProjectionRelay.cs` (verifier pass 1 correction 1).
- A name-based tracker claim ("no test reference", #1544) and a measured claim (82.35% unit) can both be true; state both and narrow the issue instead of closing it.
- Per-file proposals that mix "today" and "after the new tests" targets (unit 37 now, 55 after the stub tests; relay guard 26 now, 31 after the guard test) keep the manifest honest against `--check-justifications` and the measured table; print `ceil(target x coverable / 100)` and the slack next to each, as lesson #18 asks.
