## Lessons for the pipeline
- The tests stage of a CI-wiring audit still has a measurable flag: run the project the workflow job runs and compare the flag with the manifest. Here that exposed six property-flag FAIL rows (four packages at 0%) that no CI job reports as a failure, because `ci-full.yml:475` ends in `|| true`. The stage definition could say "for a CI-wiring scope, run the wired project and the coverage report for its flag".
- `coverage-report.cs` only reads result folders whose name contains `UnitTests`, `GuardTests`, `ContractTests`, `PropertyTests` or `IntegrationTests`; a stage that names its folder after the flag (`...\coverage\property`) gets an empty report. Name the folders `<Flag>Tests` from the start and write the report output to the session scratchpad.
- A manifest default rule (`*Validator.cs` assigns `property`) hands out obligations that no test was ever written for; a per-flag run of the whole project plus the report's per-package figures finds them all in one pass, far faster than reading test names. Running the report before reading test files avoids the file-name inference that lesson 13 warns about.
