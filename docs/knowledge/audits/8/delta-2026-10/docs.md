## Lessons for the pipeline

- For a test-only issue whose provider was removed, the delta docs stage still has a worthwhile target: the README of the surviving test infrastructure project the issue worked in. Read its samples against the real store class names and the interface members (`OutboxStoreSqlServer` and `GetMessageAsync` exist nowhere), and against AGENTS.md section 9 (a sample using `IClassFixture` for a database fixture contradicts the rule the page claims to follow).
- When a knowledge item has destination `none` with "enforced in code and guard tests", check that a reader-facing page states the contract; here the one scheduling page never mentions the `ArgumentException` on a past reschedule.
- Count emojis with a Unicode range that includes U+23F3 and U+2B50 as well as U+2600-U+27BF; the first pass counted 21 lines and missed the two hourglass lines, which gave 23.
- Before writing "no open issue targets this gap", read the bodies of every open `Delta re-audit` umbrella issue opened the same day (#1847, #1850, #1856) and search them for "tutorial", "learning path" and the feature name, not only the package name; the first pass missed that #1856 already asks for a scheduled-jobs tutorial linked from `docs/tutorials/index.md` (verifier FAIL, correction 1). A page shared with an umbrella issue is a "related issue", stated per finding.
- `docs/features/*.md` front matter is a one-command check (first line not `---`); run it for every feature page a delta audit touches, since one page was the only exception among 62.
