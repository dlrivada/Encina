## Lessons for the pipeline

- When every file a unit touched is deleted, the delta brief should name the surviving files to judge (here the three `ScheduledMessageStoreDapper.cs` files from the record's own destination reason); the tests stage then reports the deleted files in a "does not exist" table and spends rule (b) on the survivors, with the siblings under Informational.
- Per-file targets must be derived from the reachable lines of each flag, not from the package aggregate: for a raw-SQL Dapper store the unit and guard flags can reach only the constructor and the validation throws (about 20% of the coverable lines), integration reaches everything else, and contract and property reach nothing today; targets of 20, 19, 90, 0 and 0 with those justifications are honest, and the zeros need an explicit "provisional" note against `AGENTS.md` section 9.
- A guard target proposed from one provider's measurement can fail on a sibling (SqlServer 20.16%, PostgreSQL 19.84% for the same code, a two-line difference in the async state machine); compare the unrounded value for every sibling before proposing a whole-number target, since the report compares unrounded percentages.
- A knowledge record that says "covered by their guard tests" for three providers needs each provider's test class opened: the MySQL guard class has 4 tests against 14 and 15 for its siblings, and the past-date guard is covered there only by the unit class.
- A test named `..._ResetsFields` can assert something that was already true before the act; check that the assertion would fail if the mutated SQL line were removed before counting its lines as "covered and asserted". The integration run's executed-line figure does not show it.
- The coverage output folder names `unit`, `guard`, ... are skipped by `coverage-report.cs` (it classifies `UnitTests`, `GuardTests`, ...); the role definition's `--results-directory <wt>\artifacts\audit\coverage\<flag>` and the report's folder convention disagree, so the stage had to parse Cobertura by hand. Either the role should name the folders `UnitTests` and siblings, or the report should accept the short names.
- The hook `guard-orchestrator-writes` blocks a `pwsh -File` call whose script path uses a variable (`$sp\parse.ps1`); a literal absolute path (written with the Write tool under the scratchpad) is accepted, as lesson 20 says.
