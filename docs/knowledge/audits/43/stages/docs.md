## Findings
1. **Major** — The saga-not-found handler has no concept in the saga guide, no inbound link from the saga, messaging or package pages and no tutorial or learning-path entry; its only description is a nested bullet inside a how-to about another feature. Reachability by search of `docs/` and `src/Encina.Messaging/README.md` for `SagaNotFound|IHandleSagaNotFound` (case-insensitive): the only reader-facing hits are `docs/features/dead-letter-queue.md` (7 lines: `:239, :249, :263, :264, :266, :275, :278`), ADR-046 (2 lines), `docs/engineering/PROJECT-HISTORY.md:100` and the two release-history records; `docs/messaging/sagas.md` (557 lines) has 0 hits (no "not found" or "late message" section), `docs/messaging/index.md` has none (its "Saga Patterns" link is `:68`), `src/Encina.Messaging/README.md` has none, `docs/features/index.md:56` lists the dead letter queue but not the handler, and `docs/tutorials/` (`index.md`, `quickstart.md`) has no saga or dead letter content. A reader who has a saga and wants to know what happens to a late message cannot find it from the saga guide. Not part of this finding because open issues already hold it: the quadrant leak of the saga-not-found bullet (`dead-letter-queue.md:249-288`, an indented bullet under `### What each source captures` inside `## Behavior to know`) and the move or link of its result table with the error codes (`:251-256`) are named in #2350 (Description, "the saga-not-found result table with its error codes (`:251-256`)"; Proposed Fix steps 1 and 2: move or link the reference content of `:202-331`); the missing reference of the dead letter queue options and error codes (`dlq.not_configured`, `dlq.source_message_id_required` are among the codes) and the missing tutorial entry for the queue are partly held by #1990 (its page now exists as `dead-letter-queue.md`, so only its reference and tutorial parts remain). Related open issues: #2350 and #1990 (partially related, see above) and #1885 (saga tutorial, learning-path entry and API reference; its body does not name saga-not-found or the dead letter queue, so extend it with the handler).
2. **Major** — The page and ADR-046 present the saga-not-found path as a wired built-in source, while the code stage proved nothing calls the dispatcher (code finding 1). `dead-letter-queue.md:230` says "the registration also adds `DeadLetterSourceCapture`, which the built-in sources use" and the table row `:239` sits beside the four sources that do fire on their own (recoverability, outbox, inbox, scheduling) with "Captures when: a handler of `IHandleSagaNotFound<TMessage>` calls `MoveToDeadLetterAsync`"; `:249` says "`ISagaNotFoundDispatcher.DispatchAsync` connects `SagaNotFoundContext.MoveToDeadLetterAsync` to the capture while `IntegrateWithSagas` is on". The sample at `:263-267` shows the application calling `DispatchAsync` by hand but no sentence says that Encina never does (no code in `SagaOrchestrator`, `SagaRunner`, a transport or the inbox calls `DispatchAsync`; the code stage searched `src/`), so a reader who registers the handler and enables the flag will get no dead letters. `docs/architecture/adr/046-persistent-dead-letter-queue.md:68` repeats it as fact ("The five sources are wired, including the saga not found path"), and `docs/engineering/PROJECT-HISTORY.md:100` says "Saga not found scenarios are handled via a dedicated IHandleSagaNotFound interface" with no caveat. Fix: state in the page (and in the ADR as an amendment, never an edit of the decision) that the caller must detect the failed correlation and call the dispatcher, until the wiring issue exists. The wiring itself is the code stage's finding; this finding is the false documentation. Related open issue: #1480 (tests only; does not mention the docs claims).

## Lessons for the pipeline
- When the code stage proves a registered abstraction has no caller, search the docs for sentences that say the infrastructure "connects", "wires" or "uses" it (here the page, ADR-046 decision 10 and a PROJECT-HISTORY bullet); the false claim is repeated in a how-to, an ADR and a history page.
- A feature whose only reader-facing text is a nested bullet inside another feature's how-to counts as undocumented for rule (a) point 5; check section depth (`####`/indented bullets) and the section indexes, not only whether the type name appears somewhere.
- Before stating a quadrant leak of a page as new, search the open issues for the page name and the quoted line ranges (`gh issue list --search "dead-letter-queue.md"`), read their Proposed Fix, and narrow the finding to what they do not hold (#2350 already owned the saga-not-found result table and the move of `:202-331`; verifier correction 2 of audit #43).
