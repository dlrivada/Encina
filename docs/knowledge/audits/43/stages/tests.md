## Lessons for the pipeline
- When the archivist says "no `<Type>Tests` file exists", search `tests\` for the type name across all files before treating the type as untested: here 13 dispatcher tests sat in `DeadLetterRuntimeCaptureTests.cs`, and three open issues (#1480, #1481, #1886) still describe the type as 0% covered after the reshaping of #2202.
- A manifest justification that quotes "measured N%" goes stale as soon as the file changes; `--check-justifications` verifies that a justification exists, not that its figure is current. A check that re-derives the figure (or drops it from the sentence) would remove this class of finding.
- Exception filters (`catch (...) when (...)`) are not reported as branches by Cobertura (`condition-coverage` is absent on `SagaNotFoundDispatcher.cs:103`), so a 100% line figure can hide an untested filter side; read each `when` clause of a scoped file against the test list.
- A negative claim about justification files must come from a plain-path listing per directory (`Get-ChildItem <dir> -Recurse -File`), never from a brace glob (`{LoadTests,BenchmarkTests}`): the brace Glob returned nothing for folders that hold four `.md` justifications and the first version of this stage built a "package-wide gap" on it (audit #43 verifier correction 1). Name the folders listed next to the claim.
- A scoped file with a guard target of 0 because the type is internal can be confirmed in one call: the `InternalsVisibleTo` list of the package project (`Encina.Messaging.csproj:21-63`) names the test assemblies that can reach internal types.
