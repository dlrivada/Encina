## Findings
1. **Major** — A failed replay consumes the dead letter: it is recorded as "replayed", so it can never be replayed again and drops out of every pending view. `DeadLetterManager.cs:395-399` (a `Left` from the handler) and `:405-409` (a thrown exception) build a failed `ReplayResult` and `FinishReplayAsync` (`:295-310`) still calls `RecordReplayOutcomeAsync` (`:269-283`) → `IDeadLetterStore.MarkAsReplayedAsync`, which sets `ReplayedAtUtc` whatever the outcome (`DeadLetterStoreEF.cs:158-176`; contract `IDeadLetterStore.cs:116-120`). The same happens when the message is never dispatched: `PrepareReplayCore` returns "IEncina service not available" (`DeadLetterManager.cs:367-371`) or an unresolvable type name (`:354-358`), and `ReplayStoredMessageAsync` records that code as the final outcome (`:318-326`). After that `TryClaimForReplayAsync` requires `ReplayedAtUtc IS NULL` (`DeadLetterStoreEF.cs:146-149`), `IsNotReplayable` answers `dlq.already_replayed` (`DeadLetterManager.cs:251-255`), `ReplayAllAsync` filters `ExcludeReplayed = true` (`:439`), and the message leaves `DeadLetterHealthCheck` (`DeadLetterHealthCheck.cs:47-49`, `ExcludeReplayed = true`), `DeadLetterStatistics.PendingCount` and `OldestPendingAtUtc` (`DeadLetterOrchestrator.cs:487, :557-558`); `ReplayedCount = total - pending` (`:471`) then counts the failed replays as replayed. There is no operation that re-opens a message (`IDeadLetterStore.cs` has no such method). Effect: one transient downstream failure, or a rolling deploy where the request type is not loaded yet, permanently ends the only retry path of a message that is dead precisely because something failed, and the operator's health signal says the queue is clean. This contradicts the stated purpose "Replay the message when the issue is resolved" (`IDeadLetterMessage.cs:15`) and #42's own ask (manual replay). It is written in `docs/features/dead-letter-queue.md:200` ("After that the message cannot be replayed again") but ADR-046 records no decision for it (decisions 1-15 never mention failed replays). Not covered by an open issue: #2013 is about the tenant/correlation context and auditing of a replay, #2229 is an admin API over the existing semantics, #2080 is the by-id tenant opt-out; the dump search for "failed replay", "cannot be replayed again" and `ReplayedAtUtc` returns none of them. Checks failed: AGENTS.md §3 "errors are never swallowed in background infrastructure ... retry or dead-letter per its semantics" (a failed replay ends the message), and the `IDeadLetterMessage` contract. Options for the remediation, not pre-decided: (a) record only a successful outcome as `ReplayedAtUtc` and keep the failure outcome in a separate column or attempt counter; (b) keep it final but expose "replayed with a failure" as its own state in the filter, the health check and the statistics; (c) keep the behavior and write the decision into ADR-046. Static reading of the code; not run.

Open issue #1602 covers only that the dead-letter entry holds a placeholder event (`CdcProcessor.cs:211`); fixing it as proposed (assign the return value) still never dead-letters a `Left`, because nothing counts a `Left` as an error. Checks failed: AGENTS.md §3 "a `Left` ... inside a processor ... fails that operation (retry, dead-letter or exception per its semantics), never reports success". Derived from reading; not run (a unit test with a dispatcher returning `Left` for the first of two events and asserting the dead-letter store and the saved position would show it).

5. **Minor** — The statistics are derived from non-atomic queries and from a fixed source list. `DeadLetterOrchestrator.GetStatisticsAsync` (`:447-477`) runs 11 separate store calls in sequence (total, pending, expired, six per-source counts, two single-row reads; `:483-492`, `:528-549`, `:557-562`). `ReplayedCount = total - pending` (`:471`) is computed from two counts taken at different instants: a message captured between them gives a negative `ReplayedCount` (empty queue, total read as 0, one capture, pending read as 1). `CountBySource` iterates `SourcePatternsCounted` (`:60-68`), which omits any other source pattern although `AddAsync` accepts any non-empty pattern (`:140`), and includes `Choreography` although nothing produces it: no `IntegrateWith*` flag exists for it, `DeadLetterSourceCapture` rejects it as `CaptureRejected` (`DeadLetterSourceCapture.cs:84-92, :167-168`), and a search of `src/` for `DeadLetterSourcePatterns.Choreography` finds only the constant and this list (the unit tests pin that rejection, `DeadLetterSourceCaptureTests.cs:49, :175`). ## Lessons for the pipeline
- When an issue was closed by a commit that every later issue rewrote, the useful code-stage effort is not the file list but the lifecycle of the entity the feature introduced (here: captured, claimed, replayed, deleted, expired); reading each state transition next to the filters that select by state exposed finding 1, which no per-method review of the manager would show.
- A "documented limitation" in a feature guide (`docs/features/dead-letter-queue.md:200`) is not the same as a recorded decision: check whether the ADR carries the decision before treating the documented behavior as intended.
- Walking one hop to the other packages that implement a "dead letter" under a different name (grep `(interface|class|record|enum) \w*DeadLetter\w*` over `src/`) found a parallel queue in `Encina.Cdc` that the archivist's destination sweep did not list; do this grep for any abstraction whose issue promised a "unified" mechanism.
- An open issue about a defect (here #1602, the placeholder event) can sit next to a larger defect in the same function (a `Left` is never counted); read the issue body against the whole function before sizing the finding, and say in the finding what the open issue's proposed fix would leave unfixed.
- (pass 2) Attribute "throws" to the code or the page, not to an ADR, unless the ADR contains the verb: ADR-046 decision 6 says "rejected, not converted" and the throw is `DeadLetterInputs.cs:74-76`; grep the ADR for the verb before citing a decision for it (code 7).
- (pass 2) State the regex of a negative grep over a common token: `\.Result\b` over the DeadLetter folder has one match (`DeadLetterManager.cs:331`, a record property), so "0 matches" was false until the pattern list excluded it.
