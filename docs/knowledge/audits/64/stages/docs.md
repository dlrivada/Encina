This assignment is new: open #1886 does not name it. 2. **Major** — The `IContentRouter` XML example does not compile (code stage finding 9, confirmed from the docs side). `src/Encina.Messaging/ContentRouter/IContentRouter.cs:23`, `:25` and `:26` use `.RouteTo<HighValueOrderHandler>()`, `.RouteTo<InternationalOrderHandler>()` and `.Default<StandardOrderHandler>()`. `src/Encina.Messaging/ContentRouter/ContentRouterBuilder.cs` declares only non-generic overloads: `RouteTo` at `:219`, `:241`, `:254`, `:271` (parameters `Func<TMessage, CancellationToken, ValueTask<Either<EncinaError, TResult>>>`, `Func<TMessage, Either<EncinaError, TResult>>`, `Func<TMessage, CancellationToken, ValueTask<TResult>>`, `Func<TMessage, TResult>`) and `Default` at `:94` and `:114`; none takes a handler type argument or resolves a handler from DI. ## Lessons for the pipeline

- A fenced sample can fail on a member kind rather than a name: `config.ContentRouterOptions = new ContentRouterOptions {...}` passes every "does the identifier exist" search and fails only because the property is get-only (`MessagingConfiguration.cs:780`). For configuration samples read the property declaration (`{ get; }` versus `{ get; set; }`).
- `AddEncinaMessaging` exists in `src/` only in `///` comments yet appears in five README samples; the docs stage should classify each hit of a registration name as a declaration or a comment before accepting a sample (the earlier #16 lesson, still not applied to this README).
- A code-stage finding about an XML `<example>` (code finding 9) is also a docs finding: the XML example is the first documentation of the type, so the docs stage should read every `<example>` of the audited public interfaces, not only pages under `docs/`.
- For a family of patterns audited in sequence (#62, #63, #64), reuse the sibling docs stage's findings for the shared files (INVENTORY Spanish rows, tutorials index, messaging index) and say in each finding which part is a duplicate of the sibling, so the drafter opens one issue per file rather than three.
- Print every line a finding quotes from a page before describing what it says: the first pass called `transactional-outbox.md:241` and `037:141-142` "content-based deduplication" mentions, when both are registration-limit sentences and `037:142` is wrong against `EntityFrameworkCore/ServiceCollectionExtensions.cs:209` (verification Correction 1).
- Settle every "may overlap, not re-read" pointer with `gh api repos/dlrivada/Encina/issues/<n>` inside the stage: #1850 was an unrelated audit and #1886 and #3314 already owned the `AddEncinaMessaging` calls and the missing diagram (verification Correction 2). Search the open issues for the README path first, then write only the residue.
