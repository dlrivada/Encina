## Lessons for the pipeline
- A guard run filtered to `Encina.GuardTests.Testing` gave 0/89 for `EitherShouldlyExtensions.cs` while the whole guard project (13 seconds) gives 13/89: other packages' guard classes call these extensions through a global using. The dashboard figure is the whole-project one; run both and print both, and treat a guard figure of a file with no argument check as incidental.
- The session scratchpad is shared by parallel stages: a helper script named `cov.ps1` was overwritten on disk by another stage's version between two of my calls. Name helper scripts with the issue number (`a45cov.ps1`) and write each with the Write tool before the first run.
- A consolidation commit can migrate a test project's files and drop another one in the same diff: `65826302` moved the four Shouldly test files into `Encina.UnitTests` and deleted the three TUnit test files (a TUnit/Microsoft.Testing.Platform executable) without trace, so the package's manifest gate (unit 60, guard 15) has no report to color against. For every package a scoped file shares a family with, run `git show --stat --diff-filter=D <commit> -- tests/<Package>.Tests` and grep the consolidated projects for the package's type names.
- A copied manifest `reason` ("ServiceCollection extensions with conditional registration") sits on all four entries of `Encina.Testing.Shouldly.json`, and the same default-reason pattern covers `Encina.Testing.json`; a manifest check that flags a reason naming a feature the file does not contain (`ServiceCollection` in a file without `IServiceCollection`) would catch it.
