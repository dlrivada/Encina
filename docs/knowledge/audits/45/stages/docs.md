## Lessons for the pipeline
- When the only page that names an issue's headline API is a snapshot inventory, compare each identifier with the declarations (one `Select-String '^\s*public static'` per class) and then look for a sample elsewhere in the same file that uses the API; the defect here was a sample 3,200 lines away from the entry (`INVENTORY.md:6390`), in a section about another package.
- Check the README of every package in the issue's `packages:` list, not only the package the open README issue names: `Encina.Testing.Shouldly` was absent from #1689 and its comments although it is in the knowledge record's package list.
- A section's physical end is the next same-level heading, not the last line an earlier audit cited: section 12 of INVENTORY ends at `:3864`, not `:3441`, so a count taken to `:3441` understates the emoji lines (53 against 66).
- A negative claim about an open issue ("no open issue covers X") must be checked against the issue's comments as well as its bodies: #1299's audit #44 comment already held the INVENTORY emoji finding (audit #45 verifier correction 5).
