## Lessons for the pipeline

- For a feature whose only description is a CHANGELOG entry, read the entry's sample as the page: a sample whose symbols exist can still describe behavior the code stage proved false (lambda alias, chaining); run the sample against the code stage's findings, not only against `src/` names.
- When an issue's package already has an open "no page" item in an umbrella (#1894 for `Encina.Marten`), read the umbrella's comments as well as its body (`gh issue view N --json comments`) and record the finding as a duplicate when a comment already extends the item with the feature, as #1894's 2026-10-06 comment did.
- A CHANGELOG entry is repeated in `docs/releases/*/` pages with the same sample and figures; search the release pages for the sample and the literal figures before citing line ranges, and cite each page's own lines.
- Print the line a cited row or cell lives on (`docs/index.md:69` versus `docs/features/index.md:69`) and say whether it holds a status word before writing "repeat the status".
