## Findings
1. **Minor** — `tests/Encina.PropertyTests/ConfigurationProperties.cs:301-302`, `Send_ComposesPipelineAcrossOutcomes`: `[Property(MaxTest = 150, Skip = "Pure ROP: exceptions now propagate (fail-fast)")]` is the only skipped test in the two projects and breaks AGENTS.md §9 "NEVER skip a test without justification" (and "ignore a flaky test (fix or delete it)"): the Skip text says the behavior changed but no issue is referenced, and the test body still asserts the old contract. The body (`:316-330`) expects a handler exception to come back as `Left` with an `InvalidOperationException` in `err.Exception` and a handler cancellation as `Left` with an `OperationCanceledException`, plus the full pre/pipeline/post event timeline in both cases. Only the `Success` outcome stays checked (by the sibling property ending at `:298`), so composition of pre-processors, pipeline behaviors and post-processors under a throwing or cancelled handler has no property coverage; `ThrowAsFault` and `ThrowAsCancellation` (`:429-430`) and the `Exception`/`Cancellation` arms of `MapExecution` (`:227-228`) are reachable only from this skipped test. It has been skipped since the project rename (`git log -S"Pure ROP: exceptions now propagate"` returns only `cab5e04a`). Fix direction: rewrite the Exception and Cancellation arms to the current fail-fast contract (state what actually propagates, and the event timeline up to the failure) and remove the Skip, or delete the test and the dead helpers and record where exception propagation is covered; either way no Skip without an issue.
2. **Minor** — duplicated theory rows that xUnit silently discards (31 cases, "Skipping test case with duplicate ID" at discovery in both `dotnet test` runs): `tests/Encina.ContractTests/Database/ReadWriteSeparation/ReadWriteSeparationContractTests.cs` (16 dropped; for example `:118-119` and `:122-123` list `ADOSqlServerRW.IReadWriteConnectionFactory` and `DapperSqlServerRW.IReadWriteConnectionFactory` twice, and the other `[Theory]` blocks repeat the pattern, e.g. `:138-139`), `tests/Encina.ContractTests/Database/ModuleIsolation/ModuleIsolationContractTests.cs` (9 dropped; `:105-106`, `:125-126`, `:141-142`, `:161-162`, `:165-166`, `:207-208`, `:211-212`, `:265-266`, `:269-270` repeat the SqlServer ADO and Dapper rows) and `tests/Encina.ContractTests/Security/Audit/ReadAudit/ReadAuditContractTests.cs` (6 dropped; `AllProviderTypes` at `:30-31` and `:34-35` lists `ADOSqlServerStore` and `DapperSqlServerStore` twice, feeding the three `[MemberData(nameof(ProviderTypes))]` theories at `:227`, `:240` and `:249`). The doubled row sits where another provider presumably was before a provider removal (`6121713c`, "Remove Oracle provider support", deleted doubled Oracle rows from the first file), so the repeated line stands in for a provider the test no longer exercises; the run still reports green because nothing flags the dropped rows. Fix: delete the duplicate rows (or, if a provider is missing from a matrix, add it) and add a check that discovery reports no duplicate IDs.

## Lessons for the pipeline
- For an audit whose subject is "do these test projects run and pass", run the whole projects once and also grep every skip mechanism over `*.cs`, `*.csproj`, `*.props` and `*.targets`; the run's own "skipped" count (1 here) is a cheap cross-check of that grep.
- xUnit prints "Skipping test case with duplicate ID" at discovery and still reports green, so a `Select-String -Pattern 'duplicate ID'` over the `dotnet test` log should be part of every whole-project test run; the 31 dropped rows here were invisible in the pass/fail totals. Run the project to a log file (`| Out-File`) instead of `Select-Object -Last N`, which cut them off in the first run.
