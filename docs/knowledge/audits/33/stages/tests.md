## Lessons for the pipeline
- A guard-flag figure measured on a Left-returning guard class (100% for `EncinaRequestGuards.cs`) comes from direct behaviour tests, not argument checks; separate "guard lines that are `ThrowIfNull`" from "guard-project behaviour tests" before proposing a guard target, and list `guard` in a file's `defaultTests` only if the file has an argument check (here four dispatcher and strategy files list `guard` with 0 or no reachable null-check line).
- When two sibling strategies handle the same input (an already-cancelled token) differently, read every strategy's tests for what they assert before accepting that "the tests pass": three tests of one strategy assert `Right` and one of another asserts a thrown `TaskCanceledException`; a cancellation decision in the code stage needs the test stage to list those pins so the decision's worker rewrites them.
- A private member kept alive for tests with a suppression pragma (`InvokeNotificationHandler`) is a stable signal of reflection-based tests; one Grep for `BindingFlags.NonPublic` in the scoped test file finds them all.
- Open-issue search for the whole stage was done once into the session scratchpad (`gh issue list --state open --limit 3000 --json number,title,body,comments`, 1054 issues, 7.5 MB) and queried per finding with `-match`; per-finding `gh issue list --search` would have missed comment-only mentions.
