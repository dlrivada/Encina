## Lessons for the pipeline
- The overload binding of an existing test call site can be settled without a scratch app: load the built test assembly with `[Reflection.Assembly]::LoadFrom`, take the IL of the async state machine's `MoveNext` (`GetMethodBody().GetILAsByteArray()`), scan for `call`/`callvirt` tokens and `Module.ResolveMethod` them; the resolved signature shows which overload the compiler picked (here the two-parameter message overload, confirming the code finding on the real types for the Shouldly sibling). The test-auditor definition could name this as the hook-safe alternative to the blocked `#:project` experiment.
- When an open consolidated delta issue (#1923) already holds both rule (b) proposals with the numbers this run reproduces, the stage's useful output is the tracker table plus the test-side counterparts no tracker holds; the delta brief could name the umbrella issue up front, as lesson #138 and #152 ask.
- A rule (b) target in an umbrella issue is derived from the file as it is today: when the code stage's findings add lines to the same file (new overloads, `IAsyncDisposable`, `ThrowIfNull`), recompute the coverable-line count and the "need" before the manifest entry is written. The tracker table states which code findings invalidate which number.
- A test named for a clock (`Constructor_WithTimeProvider_UsesProvidedProvider`) can only construct the store with a `FakeTimeProvider` and assert `ShouldNotBeNull()`; before writing "a fake-clock test exists", Grep for `\.Advance\(`/`SetUtcNow` in the test folder and read the assertion, and cite test methods by their declaration line, not the `[Fact]` line or the statement inside (audit #44 verifier correction 3).
- A negative claim ("no test advances a clock through a fake store") names the folder or tree it searched and the Grep pattern; a Grep of the type name over all of `tests\` (`FakeInboxStore`, 35+ hits) found three test files that build the fake stores with an advancing clock and one test (`InboxTestHelperTests.cs:281`) that advances a clock beside a fake store that does not read it, which a folder-scoped Grep of `Testing\Fakes` could not show (audit #44 verifier pass 2, correction 2). Check also that a test which advances a clock hands that clock to the object whose result it asserts.
- A plain `dotnet test` restore fails with NU1902/NU1903 for `System.Security.Cryptography.Pkcs` 9.0.13; `-p:NuGetAudit=false` was needed on the first run, and `--no-restore` on later runs of the same project.
