## Lessons for the pipeline
- (2026-10-06, #23) A test helper whose public assertions look for an error-code prefix needs one test that feeds it an error produced by the real pipeline, not a hand-built one: all seven tests of `ShouldBeValidationError` build `encina.validation.*` by hand while `ValidationOrchestrator` returns an uncoded `EncinaError.New(message)`, so the prefix check can never pass in use. When a rule (b) stage reads a helper's tests, grep `src\` for the literals the helper asserts on before accepting the tests as proof. (check the literals a helper asserts on against what src\ emits)
- (2026-10-06, #23) The guard flag of a package can be filled by behavior tests that live in the guard project (failing-assertion tests of `EitherAssertionsGuards`: 24.24% guard coverage with zero argument checks in the file); derive the guard ceiling from the `ThrowIfNull` lines (here 0, and 7 of 121 for `AggregateTestBase`) and report the rest as behavior coverage, otherwise a proposed guard target either asks for impossible tests or blesses behavior tests as guards. (derive a guard ceiling from the ThrowIfNull lines, not from the guard project's measured percentage)
- (2026-10-06, #23) A manifest classification of `guard` for a class with no argument checks (`EncinaFixture`) is a Minor-or-Major classification finding like the interface case of lesson #91; the delta brief for rule (b) could ask the stage to count `ThrowIfNull` lines per scoped file before proposing a guard target. (count ThrowIfNull lines per scoped file before proposing a guard target)
- (2026-10-06, #23) A throwaway console app that references `src\` cannot be run by the test stage (guard hook), so a defect found by reading (finding 4) is recorded as "derived, unrun"; the delta brief could hand such hypotheses to an issue-worker test up front. (a defect derived from source and not run is labelled derived, unrun, and the brief names an issue-worker test for it)
