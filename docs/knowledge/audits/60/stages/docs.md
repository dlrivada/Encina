## Findings

1. **Major** — `src/Encina.AwsLambda/README.md:11`, `:119-122`, `:132`, `:138-140` (Features, "Dependency Injection Setup", "Configuration Options"): the README presents features and options that do nothing. `:11` promises "Context Enrichment: Extract correlation ID and user ID from Lambda context", `:132` documents `EnableRequestContextEnrichment` as "Auto-enrich context with correlation ID and user ID", and the DI sample sets `EnableRequestContextEnrichment`, `EnableSqsBatchItemFailures` and `UseApiGatewayV2Format` (`:119`, `:121`, `:122`) as if they changed behaviour; `:138-140` documents `IncludeExceptionDetailsInResponse`, `UseApiGatewayV2Format` and `EnableSqsBatchItemFailures` the same way. The code stage (findings 1 and 2) shows that none of the five options has a reader except the health check (`EncinaAwsLambdaOptions.cs:34`, `:98`, `:106`, `:115`, `:128`) and that nothing in the package opens the identity scope, so `IEncina.Send` from a handler runs anonymous. Check failed: rule (a) point 2 (a sample compiles but its promised behaviour does not exist) and the encina-docs rule that a page states only what `src/` does. The page-side fix is to list only the options that are read (`CorrelationIdHeader`, `TenantIdHeader`, `TrustTenantIdHeader`, `UserIdClaimType`, `TenantIdClaimType`) and to describe `GetCorrelationId`, `GetUserId` and `ResolveTenantId` as helpers the function calls itself. No open issue holds the README side (#2913 holds the response `detail` leak and says to apply its fix to `IncludeExceptionDetailsInResponse` without noting it is unread).

2. **Major** — `src/Encina.AwsLambda/README.md:59-81` and `:216-232` ("SQS Handler with Batch Processing", "Process with Partial Failures"): the page presents `SqsMessageHandler.ProcessBatchAsync` as "automatic partial failure reporting" (`:74`) for any queue and states no precondition. A search of the README for `FIFO|ReportBatchItemFailures` returns 0 matches. Code stage finding 3 shows the helper keeps processing after a failure (`SqsMessageHandler.cs:64-97`), which breaks ordering on FIFO queues, and a partial batch response is only honoured when the event source mapping enables batch item failure reporting (AWS behaviour, not fetched in this audit; the code stage records the function-side `ReportBatchItemFailures` setting as undocumented). Check failed: rule (a) point 2 (the sample's guarantee is narrower than the page states). The page needs a prerequisites sentence (event source mapping setting) and the FIFO limit, stated after the code fix decides whether the helper stops at the first failure.

3. **Major** — `src/Encina.AwsLambda/README.md:97-103` ("EventBridge Handler") and `:236-245` ("Process All or Fail"): both samples teach the pattern AGENTS.md section 3 forbids. ## Lessons for the pipeline

- A README for a package that mirrors an audited sibling (AwsLambda after AzureFunctions) has most of its docs gaps already owned by the sibling's open issues (#2951 names the shared page, #2280 lists the empty Performance marker for nine READMEs, #2958 the missing links); read those bodies first and spend the time on what the code stage proved false in the text (dead options, cold-start advice, swallowed `Left`).
- The strongest README defects here came from reading each documented option and each "automatic" claim against the code stage's dead-option list, not from symbol checks: every identifier in the samples exists, while the behaviour the page promises does not.
- `markdownlint-cli2` reports MD060 (compact table style) on separator rows of READMEs written before the rule existed; run it on every README in scope and count by rule.
