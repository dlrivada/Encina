## Lessons for the pipeline
- (verifier FAIL, re-run) A list of declaration lines must be produced by one Grep of the declaration pattern over the file and pasted, never typed from reading: the first version listed `:1732`, an explicit interface implementation, and dropped `:1806`, so the count of twelve was right and the members wrong. Say which declarations are explicit interface implementations (not public overloads) when the point is overload selection.
- (verifier FAIL, re-run) Before writing "the accessor X already exists", Grep the declaring type for the member and read its access modifier: `InternalsVisibleTo` only helps for `internal` members, and both caches here are `private static` (`RequestDispatcher` itself is a private nested class), so the remediation must add an accessor or delete the reflection test.
- When an earlier audit of the sibling issue (here #33) already filed an open `[TEST]` issue per file with measured proposals (#2100, #2101), the useful tests-stage output is a tracker table that reproduces each number and corrections to what the tracker states, plus findings only for what no tracker holds; this run found a stale statement in #2100 (contract 61.64% vs measured 63.01%; "all four flags miss the same 21 lines" is true only for unit) and a stale #2099 against a manifest entry that landed later.
- A manifest entry added after an umbrella issue was written (`Core/Encina.cs`, `#2380`) can fail the per-file gate the day it lands: the justification said "measured 44%" and the whole-project guard figure is 40.79%; for every scope-adjacent file, read the report's "below/met" column, not only the files the archivist lists.
- A test named for a catch block ("WhenDispatcherCatchesCancellation") is proven not to run it by the missed-line list (`:146-161` at 0 hits), not by reading the test: the lesson of audit #33 about `PipelineBuilder` converting handler exceptions, confirmed here for two more tests that carry the same claim.
