## Findings

1. **Major** — `docs/architecture/patterns-guide.md`, section "Factory Pattern" (`:587-641`) and the audit result `docs/knowledge/audits/issue-12.md:38` fail rule (a) point 5 (adequate docs for a delivered feature). The audit marked "Diataxis docs / README accuracy" as Pass because the page "documents the factory/orchestrator pattern (grep-confirmed)". Read in full, the section describes only the request-handler wrapper of the core dispatcher; a search of the page for `MessageFactory|ISagaStateFactory|Orchestrator|AddMessagingServices|Outbox|Inbox|Saga` returns 0 hits. The factory seam that #12 delivered (`IOutboxMessageFactory`, `IInboxMessageFactory`, `ISagaStateFactory`, `IScheduledMessageFactory` implemented once per provider and registered by `AddMessagingServices<...>` in `src/Encina.Messaging/MessagingServiceCollectionExtensions.cs`) has no concept page, no reference and no mention in `docs/messaging/index.md`, `docs/architecture/index.md`, `docs/tutorials/` or `src/Encina.Messaging/README.md` (0 hits for "Factory" in that README). The knowledge record itself says "No documentation page describes the factory seam yet." Related open issue: #1336 plans the destination for the rule, but its Expected Behavior covers only a new ADR and one bullet in `CLAUDE.md` (its body has no hit for `patterns-guide`, `docs/messaging` or `README`); the record lists `docs` with target #1336, which the issue does not deliver. Extend #1336 with a page (a section in `docs/messaging/index.md` or an architecture page) that explains what is centralized, what each provider implements and the registration entry point, with a diagram of the shared orchestrator, the factory and the per-provider store, and link it from the section indexes. Informational: #1336 names `CLAUDE.md` "Provider Coherence", which today lives in `AGENTS.md` section 3 ("Provider coherence").
