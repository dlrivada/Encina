## Lessons for the pipeline

- For a test-only issue whose audit skipped the docs stage, the delta docs stage still finds defects by reading the package README against the registration signatures (the `AddEncinaQuartz` parameter order alone produced one compile error that symbol-existence checks pass); name the signature file and line in the finding.
- When the delivered knowledge is a testing pattern, search `docs/en/guides/TESTING.md` for it in addition to `CLAUDE.md`; an existing open issue (#1331) can cover only one destination, so state that the finding is a duplicate and that the issue should be retargeted to the missing destination.
- State every count with the command that produced it and measure it before writing (audit #6 verifier FAIL: "67 docs files" was not reproducible; the measure is 16 files and 36 lines under `docs/`, 71 `.cs` files). Say what the files are (here one feature page, the rest knowledge records, plans and release notes), since a bare count overstates adoption.
- Check third-party API claims in samples against the dependency's own XML docs in the local NuGet cache (`~/.nuget/packages/<pkg>/<ver>/lib/**/<pkg>.xml`) instead of leaving them as "could not verify".
