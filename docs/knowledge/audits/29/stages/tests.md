## Lessons for the pipeline
- The path-ownership hook for test-auditor rejects creating the bare directory `artifacts/audit` or `artifacts/audit/coverage` (for example `New-Item -ItemType Directory`) and a file written directly under it before the folder exists, even though its message lists `artifacts/audit/coverage/` as allowed; paths with something after the slash are accepted. The test-auditor definition should say: pass `--results-directory <wt>\artifacts\audit\coverage\<flag>` (dotnet creates the folders) and write the log to `artifacts\audit\coverage\<name>.log` only after that folder exists, and never use `New-Item` for it.
- The test-auditor may not run a command with `run_in_background: true` (hook `no-background-specialists.ps1`); a whole-project run must be foreground with an explicit timeout.
- A marker regex must not contain bare type-name fragments such as `ServiceCollection`: it matched `ShardingServiceCollectionExtensions` in a class name and hid a reflection-only file (audit-verifier FAIL, 28 vs 29 files). Anchor markers on constructions or calls (`new ServiceCollection(`), re-run the documented scan before handing back, and list every file it returns.
- The SQLite-removal leftover also exists as array-literal entries (`"Encina.ADO.SqlServer.Sharding"` twice, `typeof(...)` twice): compare adjacent identical lines, not only adjacent `var` declarations.
- A heuristic "no instantiation marker" scan over contract tests gives false positives for target-typed `new(...)` and helper factories (`CreateSut`); read the sampled files before stating a count, and name the heuristic in the finding.
- When a test project survives a provider removal (SQLite, ADR-024), compare adjacent `typeof(...)` declarations for identical expressions: the variable names keep the old provider while both point at SqlServer, and the comparison can no longer fail. xUnit's duplicate-ID discard (#1725) only exposes the `[Theory]` form of the same leftover.
- A completeness claim ("N files, M pairs in all") needs a whole-tree scan whose command, file count and full hit list are in the finding; an earlier version scoped finding 2 from three files that were read plus an unverified side scan, and the whole-tree scan found 16 files and 105 pairs. When a scan hit looks like repetition, read it before counting it: seven hits (equality and idempotency tests that build two equal objects or call a registration twice on purpose) were legitimate and were excluded with their file:line.
