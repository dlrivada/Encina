- **Breaking: `Encina.Marten.GDPR` never stores a `[CryptoShredded]` value in plaintext** (#1646). When a non-null value cannot be encrypted, because its subject id is missing (`null`, `Guid.Empty`, or an empty or whitespace string), the `ISubjectKeyProvider` returns an error (including a forgotten subject), throws or returns an unusable key, or the property is misconfigured (getter-only, declared on a struct or record struct event, not a string, without `[PersonalData]`, or with a missing subject-id property), `CryptoShredderSerializer` throws the new `CryptoShreddingEncryptionException` before serializing, so Marten's append fails and nothing is stored. The exception names the event type, the property, a `CryptoShreddingEncryptionFailureReason` and the key-provider error code, never the subject id or the value. The startup scan also rejects getter-only `[CryptoShredded]` properties and struct events. `[CryptoShredded]` is discovered only on the appended event type itself; a property on a nested type is not encrypted (known limitation, tracked separately).
- **Breaking: `ISubjectKeyProvider.GetOrCreateSubjectKeyAsync` returns `SubjectEncryptionKey`** (key material and version read together) instead of `byte[]` (#1646). The serializer writes that version into the encrypted value's key id instead of looking it up separately and guessing version 1 when the lookup failed, which made values undecryptable after a key rotation. Custom key providers must return the key and its version from one read.
