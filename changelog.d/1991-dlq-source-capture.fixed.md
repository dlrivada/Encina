- The dead letter queue now captures terminal failures from the five sources its `DeadLetterOptions.IntegrateWith*` flags name, each once per source message (idempotent on `(SourcePattern, SourceMessageId)`) and only while its flag is on: recoverability permanent failures (keyed by the retry chain id), outbox messages that use up `OutboxOptions.MaxRetries`, inbox messages whose failed attempt uses up `InboxOptions.MaxRetries`, scheduled messages the retry policy dead-letters, and sagas that `SagaOrchestrator.FailAsync` ends `Failed` (#1991).
- A failed capture is never reported as success: on a retryable failure (store down, capture threw: `dlq.capture_failed`) the outbox, scheduling and delayed retries leave the message for a later cycle, the inbox attempt and `SagaOrchestrator.FailAsync` return the error, and recoverability logs it. A capture the queue rejects (`dlq.capture_rejected`: an identity value it cannot store, or a source pattern with no `IntegrateWith*` flag; see `DeadLetterSourceCapture.IsRetryable`) is not retried: the source records its terminal state and the inbox answers as without a dead letter queue. Failures are logged (EventIds 2996-2998) and counted in `encina.dlq.store_failures_total`. Each capture runs in its own DI scope, so on EF Core it never saves the source's tracked changes (#1991).
- `IDeadLetterManager` replays an outbox dead letter by publishing the notification again (`IEncina.Publish`) instead of failing to send it as a request (#1991).
- A message whose saga is not found moves to the dead letter queue when its `IHandleSagaNotFound` handler calls `SagaNotFoundContext.MoveToDeadLetterAsync` (wired by `ISagaNotFoundDispatcher` while `DeadLetterOptions.IntegrateWithSagas` is on), keyed by the message identity the caller supplies; without it the call returns `dlq.source_message_id_required`, and with the queue or the flag off `dlq.not_configured` (#2203).
