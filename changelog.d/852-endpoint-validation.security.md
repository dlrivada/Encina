- **Endpoint options are validated against SSRF at registration and at startup** (#852). A new public `Encina.Validation.EndpointValidator` (with `EndpointPolicy` and `EndpointHostKind`) rejects loopback hosts unless `AllowLocalEndpoints` is set, plain `http` unless `AllowInsecureHttp` is set, and link-local, cloud metadata (including AWS/Azure/GCP 169.254.169.254, AWS fd00:ec2::254, Alibaba 100.100.100.200, Azure WireServer 168.63.129.16 and Oracle 192.0.0.192) and unspecified addresses with no opt-out, including IPv4 carried in mapped, compatible, translated, NAT64, 6to4 and Teredo IPv6 addresses and decimal/octal IPv4, trailing-dot and IDN forms; carrier-grade NAT (100.64.0.0/10) and site-local (fec0::/10) count as private and are allowed. The one remaining limit is DNS rebinding, which configuration-time checks cannot catch. It now guards `HashiCorpVaultOptions.VaultAddress`, both `AzureKeyVaultOptions.VaultUri` (secrets and message encryption), `EncinaAmazonSQSOptions.DefaultQueueUrl`, `EncinaNATSOptions.Url`, and `MySqlCdcOptions.Hostname` plus every server in its `ConnectionString`; each `Add*` method throws `OptionsValidationException` and `ValidateOnStart` re-checks, and every opt-out logs one warning. `HttpAttestationOptionsValidator` uses the same helper, which fixes its fe80/ff80 over-match and the IPv4-mapped bypass, link-local and metadata endpoints are now rejected even with `AllowInsecureHttp`, `AllowInsecureHttp` accepts only `http` and `https` (it no longer skips the scheme check), relative URIs are reported as "must be an absolute URI", and its messages no longer carry the `HttpAttestationOptions.` prefix. **Breaking:** the localhost defaults of `EncinaNATSOptions.Url` (so `AddEncinaNATS()` without arguments) and `MySqlCdcOptions.Hostname` now fail unless `AllowLocalEndpoints = true`, `MySqlCdcOptions.ConnectionString` is required, and `DebeziumCdcOptions.DebeziumServerUrl` (never read) is removed; `DebeziumCdcOptions.ListenUrl` is checked for format and an `http`/`https` scheme only.
