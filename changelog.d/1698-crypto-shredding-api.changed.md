- **`Encina.Marten.GDPR` crypto-shredding runs through the System.Text.Json contract** (#1698). `CryptoShredderSerializer` takes Marten's `SystemTextJsonSerializer` and an `IServiceScopeFactory` (keys are resolved per call), and `CryptoShredderSerializerFactory.Apply` changes accordingly; any other serializer, including Newtonsoft, fails with `CryptoShreddingConfigurationException`. Stored values use the v2 token `cs2:{version}:{payload}`, which no longer carries the subject id. `CryptoShreddingOptions.AutoRegisterFromAttributes` becomes `ValidateOnStartup`; the startup validator replaces the auto-registration scan and also checks the erasure strategy, the personal data locator and the async daemon settings. `CryptoShreddingEncryptionException` names the root document type and the declaring type, and its reasons are `SubjectIdMissing`, `SubjectIdInvalid` and `KeyUnavailable`; misconfiguration is reported by the new `CryptoShreddingConfigurationException` with `CryptoShreddedPropertyIssue` and `CryptoShreddedPropertyProblems`. `IForgottenSubjectHandler.HandleForgottenSubjectAsync` receives `fieldPath` and `documentType`. `PersonalDataLocation.FieldName` is a path for nested fields (`Contact.Email`, `Items[].Note`, `Notes{}.Text`). Marten locations always reach crypto-shredding through an internal routing erasure strategy; a custom `IDataErasureStrategy` must be registered before `AddEncinaMartenGdpr`.
