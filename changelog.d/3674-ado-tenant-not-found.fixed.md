- The ADO.NET `TenantConnectionFactory` of `Encina.ADO.SqlServer`, `Encina.ADO.PostgreSQL` and `Encina.ADO.MySQL` no longer falls back to the default database for a tenant id the tenant store does not know: `CreateConnectionAsync` and `GetConnectionStringAsync` return `TenancyErrors.TenantNotFound()` (`tenancy.tenant_not_found`) and open no connection. With no tenant id (null, empty or whitespace) they return `TenancyErrors.TenantRequired()` (`tenancy.tenant_required`) while `TenancyOptions.RequireTenant` is `true` (the default); the default connection string is used for a missing tenant only when `RequireTenant` is `false`. `CreateConnectionForTenantAsync` returns the same `tenancy.tenant_not_found` error, whose message no longer carries the tenant id, and throws `ArgumentException` for a whitespace id. Breaking: the scoped `IDbConnection` registered by `AddEncinaADOWithTenancy` now throws when it is resolved without a tenant while `RequireTenant` is `true`; set `RequireTenant = false` for work that runs without a tenant (#3674).
