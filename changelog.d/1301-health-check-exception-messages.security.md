- Health checks and database health monitors no longer put an exception message, an `EncinaError.Message`, an exception object or a replica host name into a health result: only the exception type name or the error code is reported (#1301). This covers the transport, cache, distributed-lock, scheduler, database read/write-separation, MongoDB, Marten, schema-drift and resharding health checks and the `DatabaseHealthMonitorBase`, `MongoDbDatabaseHealthMonitor` and `ShardedMongoDbDatabaseHealthMonitor` monitors.
- The ASP.NET health adapters (`EncinaHealthCheckAdapter`, the composite check and the tenancy bridge) no longer forward the exception object of an Encina health result to the endpoint result.
- The CDC health checks report the error code instead of `EncinaError.ToString()` in their result data, and `KafkaHealthCheck` reports the Kafka error code instead of its free-text reason.
- Health checks that implement Microsoft's `IHealthCheck` directly (schema drift, resharding, GDPR, data subject rights, anonymization, consent, cross-border transfer, data residency, privacy by design, retention and security) now catch an exception themselves and report only its type name, so `DefaultHealthCheckService` no longer copies the exception message and object onto the report entry (#1301).
