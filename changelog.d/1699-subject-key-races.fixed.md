- `PostgreSqlSubjectKeyProvider` no longer loses or leaves behind crypto-shredding keys under concurrency (#1699): key creation, rotation and erasure for one subject run in one transaction under a PostgreSQL transaction-scoped advisory lock keyed by tenant and subject; key documents are written with insert semantics and, on a conflict with a writer that bypassed the lock, the stored key is returned to every caller; no key can be created after an erasure commits; a repeated `DeleteSubjectKeysAsync` deletes any key document left behind and still returns `crypto.subject_forgotten`. Each operation opens its own Marten session for the injected session's store and tenant instead of using the caller's unit of work.
- `InMemorySubjectKeyProvider` returns copies of key material, so an erasure that zeroes the stored keys can no longer turn a key a concurrent writer still holds into an all-zero key; `Clear()` removes each subject before zeroing its keys (#1699).
