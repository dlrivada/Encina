- `IConsentService.GrantConsentAsync` (`Encina.Compliance.Consent`) keeps at most one consent record per (tenant, data subject, purpose): the consent id is now derived deterministically from the effective tenant, the data subject and the purpose (an RFC 9562 version 8 UUID), so a repeated or concurrent grant no longer creates a second active record that a withdrawal would leave behind (GDPR Art. 7(3)) (#3769).
- `MartenAggregateRepository.CreateAsync` and `SnapshotAwareAggregateRepository.CreateAsync` (`Encina.Marten`) now recognise the loser of a truly concurrent creation of one stream, which Marten reports as a command exception wrapping the PostgreSQL unique violation on `pkey_mt_streams_id`, and return `MartenErrorCodes.StreamAlreadyExists` instead of the generic create-failed error (#3769).
