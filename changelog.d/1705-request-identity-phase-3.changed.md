- `app.UseEncinaContext()` runs every HTTP request inside one inbound identity scope built from `HttpContext.User` through `RequestIdentityOptions`, so handlers, gates, audit and the EF Core interceptors see the caller's `RequestIdentity`; the scope ends with the request, so work that outlives it reads the anonymous identity. Document the pipeline order `UseRouting`, then `UseRewriter`/`UseStatusCodePagesWithReExecute`/`UseExceptionHandler`, then `UseAuthentication`, then `UseEncinaContext` (#1705).
- Connection requests carry no request identity: WebSocket upgrades, every extended CONNECT request, GET requests whose `Accept` lists `text/event-stream` and SignalR hub endpoints (including Blazor's `/_blazor`) run under an anonymous connection marker, over which `RunAsServiceAsync`/`RunAsPrincipalAsync` need `AllowOverInbound`; a POST that streams its response keeps its request identity. `TenantResolutionMiddleware` writes no request context on such requests (resolution, validation and the `RequireTenant` 400 still run) and takes `TimeProvider` by method injection (#1705).
- `[Authorize]` (`AuthorizationPipelineBehavior`) evaluates `IRequestContext.Identity` (its principal holds only the caller's authenticated identities) and denies an unauthenticated identity with `encina.authorization.unauthenticated`; Blazor Server circuits get their identity per circuit activity from `AddEncinaBlazorAuthorization()` (#1705).
