- **`Encina.Hangfire` job adapters now fail the job on a handler `Left` result, separating cancellation, permanent and transient failures** (#1152). `HangfireRequestJobAdapter.ExecuteAsync` and `HangfireNotificationJobAdapter.PublishAsync` used to log a handler failure and return normally, so Hangfire recorded the job as succeeded and never retried it. They now throw: `OperationCanceledException` when the error is an Encina `*.cancelled` code and the job's token is cancelled (Hangfire treats the job as interrupted, not failed); the new `EncinaJobPermanentFailureException` when `Encina.Messaging.Recoverability.IErrorClassifier` (the registered one, or `DefaultErrorClassifier`) classifies the error as permanent (the classifier receives the error and its causing exception, `EncinaErrorExtensions.GetCause`) — for `DefaultErrorClassifier`, a permanent exception type, one of its explicit permanent error codes such as a missing handler, missing or withdrawn consent or an active processing restriction, or a permanent message pattern; and the new `EncinaJobFailedException` for transient or unclassified failures. Both exceptions carry only the error code in their `Message` and `Data` (never `EncinaError.Message`, which may contain data-subject ids that Hangfire persists), and the causing exception as `InnerException`. The new `EncinaAutomaticRetry.Create` / `JobFilterCollection.UseEncinaAutomaticRetry` configure Hangfire's `AutomaticRetryAttribute` with `ExceptOn = [EncinaJobPermanentFailureException]`, so permanent failures go straight to Failed while transient ones are retried. Breaking: `ExecuteAsync` now returns `Task<TResponse>` instead of `Task<Either<EncinaError, TResponse>>`, and both adapters take an optional `IErrorClassifier`.

- **`Encina.Quartz.QuartzNotificationJob` no longer discards a failed publish** (#1152). It ignored the `Either` returned by `IEncina.Publish`, so a failed notification was recorded as a successful run. Both Quartz jobs now throw `OperationCanceledException` for a cancelled job and otherwise a `JobExecutionException` with `RefireImmediately = false`, whose message carries only the error code and whose `Data` carries the error code and the `IErrorClassifier` classification under the new `EncinaJobFailureData.ErrorCodeKey` / `ErrorClassificationKey` keys, for job listeners that reschedule transient failures. `QuartzRequestJob` no longer copies `EncinaError.Message` into the exception message.

- **`DefaultErrorClassifier` now classifies by an explicit list of error codes, and ignores message patterns when the error has a causing exception** (#1152, #1159). After the exception type and before the message, the error code is compared exactly (case-insensitively) with a fixed list of permanent codes — `encina.handler.missing`, `encina.request.handler_missing`, `encina.request.handler_type_mismatch`, `encina.notification.missing_handle`, the four `encina.authorization.*` codes, `Encina.guard.validation_failed`, `Repository.ValidationFailed`, `processor.validation_failed`, `gdpr.compliance_validation_failed`, `aiact.compliance_validation_failed`, `consent.missing`, `consent.expired`, `consent.withdrawn`, `consent.requires_reconsent`, `consent.version_mismatch`, `dsr.restriction_active`, `dsr.subject_id_missing`, `dsr.identity_not_verified` — and of transient codes — `encina.timeout`, `encina.ratelimit.exceeded`. Codes are never matched by substring, so `saga.not_found`, `choreography.saga.not_found`, `routingslip.not_found`, `marten.aggregate_not_found`, `saga.invalid_status` or `choreography.saga.invalid_state` (out-of-order events, saga state races) still fall through to the message and are retried rather than dead-lettered. Behaviour change: message patterns ("invalid", "not_found", "timeout", ...) are no longer applied when the error carries a causing exception (`EncinaErrorExtensions.GetCause`), because such messages are built around the exception — the dispatcher's `encina.notification.exception` message names the handler type, so a `CacheInvalidationHandler` throwing an unrecognised exception used to be classified as permanent. The Hangfire and Quartz job adapters now pass that cause to `IErrorClassifier.Classify`, so custom classifiers keyed on exception types work. The new `EncinaErrorExtensions.GetCause` returns the exception that caused an error without the internal carrier whose message is the error message itself.
