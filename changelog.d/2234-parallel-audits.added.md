- **Several SPEC-003 audits run in parallel, each one individually (#2234).** `tools/ai/audit/pipeline.json` `maxParallelAudits` (2 to 5, default 2) sets how many audits may be open at once; each keeps its own `wia-<n>` worktree, stage agents, verifier loop and knowledge pull request. Every open audit has its own state file `artifacts/knowledge/open-audits/<n>.json` (the old `current-audit.json` is converted on the first run); scripts take `-Issue <n>` or resolve the audit from the worktree they run from, and the hooks enforce stage order and path ownership per audit. `audit-next.ps1` never opens an issue whose `src/` packages overlap an open audit, and `audit-draft-remediation.ps1 -Prepare` and `open-remediation.ps1` check each draft against the drafts of the concurrent audits.
- **No audit is forgotten half-way (#2234).** `audit-stage.ps1 -List` shows every open audit with its next stage and days open and flags one open more than 2 days as stale; `audit-next.ps1` refuses to start another audit while one is stale unless `-Force`.
