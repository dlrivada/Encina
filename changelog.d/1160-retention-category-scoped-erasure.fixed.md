- **Retention enforcement erases only the expired data category** (#1160). When one retention record of an entity expired, the enforcement cycle called the data subject rights `IDataErasureExecutor` with the entity id as a subject id and no category, which erased every category of the entity (for example a clinical record that must be kept five years, when only the one-year contact data had expired). Enforcement now erases through a new port, `IRetentionDataEraser`, called with a `RetentionErasureTarget` (record id, entity id, data category, expiry, tenant id, module id); the application implements it and erases only that category of that entity. **Breaking:** `Encina.Compliance.Retention` no longer references `Encina.Compliance.DataSubjectRights` and no longer uses `IDataErasureExecutor`; register an `IRetentionDataEraser` to erase expired data (until one is registered, expired records stay `Expired` and EventId 8519 is logged once per cycle). EventId 8557 now logs the data category, and EventId 8588 (erasure with failed fields) was reassigned. Decision recorded in ADR-031.
- **Retention enforcement keeps a category while another record of it is retained** (#1160). One entity can have several records in the same category (one per tracking call, for example one per clinical episode). An expired record is no longer erased while another record of the same entity, category, tenant and module is still `Active` and within its period, or `UnderLegalHold`: it stays `Expired`, no `DataDeleted` event is raised, and the cycle reports it as deferred (EventId 8591, `retention.records.deferred.total`, `RecordsDeferred` in EventId 8512). When the last of them expires the category is erased once and all of them are marked `Deleted`. If the sibling records cannot be read, nothing is erased (EventId 8592).
- **Retention records carry the request's tenant and module** (#1160). `RetentionValidationPipelineBehavior` now passes `IRequestContext.TenantId` and the request's module name to `TrackEntityAsync`, so the `RetentionErasureTarget` carries them. `IRetentionDataEraser` implementations must scope the erasure by `TenantId` explicitly (the enforcement service has no ambient tenant) and return `Left` when they cannot.
- **The retention health check reports a missing eraser** (#1160). With `EnableAutomaticEnforcement` on and no `IRetentionDataEraser` registered, `RetentionHealthCheck` returns `Degraded`, because expired data would never be erased.
