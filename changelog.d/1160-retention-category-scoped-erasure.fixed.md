- **Retention enforcement erases only the expired data category** (#1160). When one retention record of an entity expired, the enforcement cycle called the data subject rights `IDataErasureExecutor` with the entity id as a subject id and no category, which erased every category of the entity (for example a clinical record that must be kept five years, when only the one-year contact data had expired). Enforcement now erases through a new port, `IRetentionDataEraser`, called with a `RetentionErasureTarget` (record id, entity id, data category, expiry, tenant id, module id); the application implements it and erases only that category of that entity. **Breaking:** `Encina.Compliance.Retention` no longer references `Encina.Compliance.DataSubjectRights` and no longer uses `IDataErasureExecutor`; register an `IRetentionDataEraser` to erase expired data (until one is registered, expired records stay `Expired` and EventId 8519 is logged once per cycle). EventId 8557 now logs the data category, and EventId 8588 (erasure with failed fields) was reassigned. Decision recorded in ADR-031.
