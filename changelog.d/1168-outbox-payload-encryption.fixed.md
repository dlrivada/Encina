- **Outbox, dead letter, delayed retry, saga and scheduled-message payloads now go through `IMessageSerializer`** (#1168). `OutboxPostProcessor`, `DeadLetterOrchestrator`, `DeadLetterManager`, `DelayedRetryScheduler`, `DelayedRetryProcessor`, `SagaOrchestrator` and `SchedulerOrchestrator` used to serialize request/notification payloads with a private `JsonSerializer` call, bypassing the `EncryptingMessageSerializer` decorator from `Encina.Messaging.Encryption`. A message marked `[EncryptedMessage]` is now encrypted at rest in every one of these stores, not only when read back by the outbox processing loop.
- **`IMessageSerializer` is registered by every provider** (#1168, #1259). `MessagingServiceCollectionExtensions.TryAddDefaultMessageSerializer` registers `JsonMessageSerializer` unless a serializer is already registered; ADO.NET, Dapper, EF Core, MongoDB, the dead letter queue, recoverability and CDC call it, so `AddEncinaMessageEncryption` works whether it is registered before or after the provider.
- **The CDC outbox handler decrypts encrypted outbox rows** (#1168, #1259). `OutboxCdcHandler` reads `Content` through `IMessageSerializer` instead of raw `JsonSerializer`.
- **`OutboxPostProcessor` logs the error code only** (#1259). EventId 2844 no longer includes `EncinaError.Message`.
- **Outbox, scheduler and delayed-retry failures store and log the error code only** (#1259). The outbox processing loop and `SchedulerOrchestrator` record the `EncinaError` code (or the exception type for a thrown exception) in `ErrorMessage` instead of `EncinaError.Message`, and their log events carry only the code; `DelayedRetryScheduler` stores `lastErrorCode` in the retry context instead of the error message.
