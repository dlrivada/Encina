- Processor Agreements: `IProcessorService` reads and mutations are now tenant-scoped (#3679, part of #3517). Every query filters on the ambient tenant of `IRequestContextAccessor` (the null-tenant scope when there is none, never an unfiltered query); a processor of another tenant read, updated or removed by id is reported as not found and nothing is saved, and a sub-processor can no longer be registered under a parent of another tenant. The new `ProcessorAgreementOptions.RequireTenantContext` (default `null`: fail closed when `Encina.Tenancy` is registered; an explicit `false` is logged) makes a missing tenant return `processor.tenant_required` (`ProcessorAgreementErrors.TenantRequired`). Processor cache keys are now `pa:tenant:{tenant|-}:processor:{id}`, and `GetFullSubProcessorChainAsync` returns the store error instead of a partial chain. Processors stored with a null tenant are not visible to tenanted callers; there is no migration.
