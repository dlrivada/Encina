- Tenant resolution: the verified tenant claim now always wins in Encina.Tenancy.AspNetCore, Encina.AwsLambda and Encina.AzureFunctions. A client-supplied tenant (header, route value, subdomain) that disagrees with the claim is denied (403 Forbidden in ASP.NET Core, a Left with the error code `tenancy.tenant_mismatch` in AWS Lambda and Azure Functions), so an authenticated caller can no longer act as another tenant by sending a header (#2399).
- Encina.Tenancy.AspNetCore: the tenant header resolver is disabled by default and is honored only when no claim exists and the request comes from a trusted source (`HeaderResolver.TrustedProxies` or the logged opt-out `HeaderResolver.TrustAnyPeer`); enabling it without either fails startup. `ITenantResolver` gains `IsAuthoritative`, and `TenantResolutionMiddleware` answers 403 on a tenant mismatch (#2399).
- Encina.AwsLambda and Encina.AzureFunctions: `GetTenantId` is replaced by `ResolveTenantId(context, request, options, logger)` returning `Either<EncinaError, Option<string>>`; the header is read only with the new `TrustTenantIdHeader` option (default `false`) and each use is logged. The never-written `EncinaFunctionMiddleware.TenantIdKey` and the context-only `GetTenantId` overload of Azure Functions are removed (#2399).
- `TenancyOptions.RequireTenant` now defaults to `true`: a request without a tenant is rejected where tenancy is enabled (#2399).
