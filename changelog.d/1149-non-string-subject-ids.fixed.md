- **Non-string data subject ids (`Guid`, numeric ids, strongly-typed ids) are now resolved correctly instead of falling back to the authenticated caller** (#1149). `Encina.Compliance.DataSubjectRights.DefaultDataSubjectIdExtractor` and `Encina.Compliance.Consent.ConsentRequiredPipelineBehavior.ExtractSubjectId` only recognized `string`-typed subject-id properties; a matching property of any other type (e.g. a `Guid PatientId`) was silently ignored, and the extractor fell back to `IRequestContext.UserId` — the authenticated caller — instead of the real data subject. Both now accept a matching property of any convertible type (`string`, `Guid`, numeric types, `IFormattable`, or a type overriding `ToString()`), converted to a stable invariant string. The fallback to the caller now only happens when no matching property exists at all; a matching property whose value is `null` is treated as a missing subject (returns `null`), and a matching property of an unconvertible type is a configuration error (throws) rather than a silent fallback. `Encina.Compliance.GDPR`'s `DefaultLawfulBasisSubjectIdExtractor` does not share this pattern — it never inspects request properties — and needed no change.
