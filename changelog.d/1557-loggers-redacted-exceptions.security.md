- **Logger calls across the libraries no longer receive raw exceptions or EncinaError/exception messages** (#1557). Exceptions passed directly to logger calls go through `ForLogging()` (type and stack trace, never the message) and errors are logged by error code or exception type. Covers the compliance, security, messaging, transport, caching, Marten, EF Core, MongoDB, Cdc, AWS Lambda, Polly, resilience and Refit packages. Log templates that printed `{ErrorMessage}` now print `{ErrorCode}` or `{ExceptionType}`. This holds for exceptions and errors passed directly to logger calls and for the six local-variable sites this change fixed (Sanitization input and output encoding, Encryption, ABAC EEL precompilation); activity tags and status, and EncinaError messages built from exception messages, are tracked in #1591.
- **`ReadAuditLog.EntryLogFailed`, `QueryFailed` and `PurgeFailed` take an `errorCode` instead of an `errorMessage`** (#1557).
- **A static scan test (`LoggerExceptionLeakStaticScanTests`) fails the build when a logger call under `src/` passes a raw exception, a message or an exception rendered to text** (#1557).
- **Stored values no longer carry messages:** `AuditEntry.ErrorMessage` written by `AuditPipelineBehavior` holds the error code or exception type, CDC dead-letter entries hold the exception type, and secret audit entries hold the error code (#1557).
- **`Encina.Security.Secrets` logs an audit-store write failure as `AuditEntryStoreFailed` under EventId 5126** (previously `AuditEntryFailed`, 5135) (#1557).
