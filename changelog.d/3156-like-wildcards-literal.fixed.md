- ADO.NET and Dapper repositories (SqlServer, PostgreSQL, MySQL): a specification's `Contains`, `StartsWith` and `EndsWith` now match their value literally, as EF Core and MongoDB already did. The `SpecificationSqlBuilder` escapes the `LIKE` wildcards `%` and `_` (and `[` on SQL Server) in the value and adds `ESCAPE '!'`, so `Contains("50%")` no longer matches "500" (#3156).
- ADO.NET and Dapper repositories (SqlServer): a `LIKE` pattern over SQL Server's 8,000-byte limit (4,000 characters, counting the escapes and the `%` wrappers) is rejected before the query runs, like other untranslatable specifications, instead of failing on the server with a generic error. The error gives the pattern's length and the limit, not the search value (#3156).
