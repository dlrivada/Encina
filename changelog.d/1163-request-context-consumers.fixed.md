- Fixed about 30 call sites that resolved an unregistered `IRequestContext` from DI and always got `null`. They now read the ambient context through `IRequestContextAccessor` (registered by `AddEncina()` and by every messaging/repository provider package), matching the pattern introduced by #1147. Affected: repository and sharding registrations in `Encina.ADO.*`, `Encina.Dapper.*` and `Encina.MongoDB`; `Encina.Security.ABAC`'s `PersistentPolicyAdministrationPoint`; `Encina.Security.Secrets`'s `AuditedSecretReaderDecorator`; and `Encina.Compliance.NIS2`'s `DefaultNIS2ComplianceValidator`.
- Fixed `SagaRunner` (`Encina.Messaging`), which failed to build from DI in every ADO.NET and Dapper package because it required an unregistered `IRequestContext`; it now depends on `IRequestContextAccessor` and resolves the current context (or a fresh one) at the start of each run.
