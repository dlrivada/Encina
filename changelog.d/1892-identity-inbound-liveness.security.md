- **An explicit context can no longer change the identity over an inbound chain** (#1892). With an inbound request (anonymous included), an `External` restored message or a connection marker anywhere in the flow, an explicit context passed to `Send`, `Publish` or `Stream` whose authenticated identity differs from the ambient one is refused with `encina.identity.scope_conflict` and logs EventId 167 with the error code only, like `RunAsServiceAsync` without `IdentityScopeOptions.AllowOverInbound`; anonymous explicit contexts and contexts with the ambient identity are still accepted, and the opt-in scope remains the way to run as another identity.
- **An ended identity scope reads as anonymous everywhere** (#1892). `RequestContext.Identity` returns `RequestIdentity.Anonymous` once the scope that issued the identity has ended, on the context and on every copy of it, so a stream behavior that kept its context, a fire-and-forget dispatch whose gates run later, or any other gate, handler or extractor reading `context.Identity` sees an ended scope as anonymous and denies; identities built without a scope (`Encina.Testing` builders) are unchanged. `RequestContextAccessor.RequestContext` now refuses (throws `InvalidOperationException`) a context whose scope has ended.
