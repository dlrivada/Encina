- **Health checks in compliance and security modules no longer expose EncinaError.Message or exception text** (#1538). DataSubjectRightsHealthCheck (Encina.Compliance.DataSubjectRights) and fifteen other health checks in Encina.Compliance (AIAct, Attestation, BreachNotification, ProcessorAgreements, GDPR, NIS2) and Encina.Security (ABAC, AntiTampering, Audit, Encryption, PII, Sanitization, Secrets) now record only the EncinaError code (or `"encina.unknown"` if absent) or the exception type name, not the message text. This prevents database error details, operational strings and other sensitive data from reaching `HealthCheckResult` descriptions, data dictionaries or exception objects, which are often exposed via unauthenticated `/health` endpoints or monitoring dashboards with broader access than application logs. The existing rule, applied to logging (#1499) and DPIA health checks, is now consistently enforced across all compliance and security health checks.
