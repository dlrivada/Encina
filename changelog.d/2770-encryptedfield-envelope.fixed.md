- **Encina.Audit.Marten: unreadable encrypted audit fields fail typed instead of leaking** (#2770). `EncryptedField` no longer throws raw `ArgumentException`/`InvalidOperationException` out of the audit projections, and no longer returns a raw envelope as plaintext. An unreadable envelope (tampered, wrong key or sizes, malformed, or an unmarked value) now throws `EncryptedFieldDecryptionException` with a fixed message, the code `audit.marten.encrypted_field_unreadable` and an `EncryptedFieldDecryptionFailureReason`. Marten's async daemon pauses that shard until an operator resolves it.
- **Encina.Audit.Marten: `[SHREDDED]` only for lawful erasure, `[EXPIRED]` for retention** (#2770). A key destroyed with an `ErasureReference` (request id, request date, actor) reads `[SHREDDED]`. A key destroyed with a `RetentionReference` (policy `audit-retention:<ISO 8601 RetentionPeriod>`, actor `system`, written by both stores' `PurgeEntriesAsync` and by auto-purge) reads `[EXPIRED]` (`MartenOperationAuditOptions.ExpiredPlaceholder`, `IsExpired` on both read models), and the shard keeps running, also on rebuild. A key destroyed with neither reference, or with a marker carrying both, fails with `EncryptedFieldDecryptionException` (reason `KeyDestroyedWithoutErasureRecord`) and pauses the shard.
- **Encina.Audit.Marten: `ITemporalKeyProvider.DestroyKeysBeforeAsync` takes a key destruction reference** (#2770). The new optional `KeyDestructionReference? reference = null` parameter sits before the `CancellationToken`. `KeyDestructionReference` is a closed record: `ErasureReference` or `RetentionReference` (policy id, cutoff, execution time, actor); one destruction carries exactly one. This is a breaking change for callers that pass the cancellation token positionally.
- **Encina.Audit.Marten: async projections pause on unprojectable events instead of skipping them** (#2770). The Audit.Marten async projections now pause the shard when an audit event cannot be projected, instead of Marten's default of skipping it. Encina no longer changes those store-wide Marten flags (SkipApplyErrors, SkipSerializationErrors, RebuildErrors). At startup the audit projections now fail to start (clear message, host stops) when the application left them skipping (Marten's default), unless the application sets them to false itself or opts out with `MartenOperationAuditOptions.AllowSkippedProjectionErrors` (logged at startup, event 2590). A key with no active key and no destroyed marker no longer claims the daemon will retry it.
- Breaking for applications that left Marten's projection error flags at their default: the host now fails at startup (set the four flags to false, or opt out with `AllowSkippedProjectionErrors`).
- **Encina.Audit.Marten: `MartenOperationAuditOptions.RetentionPolicyId`** (#2770). Default `null`; it names the approved retention policy recorded in the retention marker of purged keys. When unset the policy id stays `audit-retention:<ISO 8601 RetentionPeriod>`.
