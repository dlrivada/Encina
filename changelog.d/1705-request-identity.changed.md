- `IRequestContext` carries the caller identity as `IRequestContext.Identity` (`RequestIdentity`: kind Anonymous/User/Service, user id, principal, roles, permissions) and gains `CausationId`; `context.UserId` is now a C# 14 extension property that projects `Identity.UserId`, so a context can never report a user id that differs from the identity the gates authorized (#1705).
- One claim map for the whole stack: `RequestIdentityOptions` (`UserIdClaimTypes` default `sub`, NameIdentifier, Entra object id; role, permission and tenant claim lists) registered by `AddEncinaRequestIdentity()`, which `AddEncina` calls; an authenticated principal without a user-id claim, with a reserved `service:` subject or with conflicting authenticated identities maps to the anonymous identity and logs a warning (EventIds 162-164) (#1705).
- Breaking: `IRequestContext.WithUserId`, `RequestContext.Create(string)` and the `userId` parameter of `RequestContext.CreateForTest` are removed; `RequestContext.CreateAnonymousAt(DateTimeOffset, ...)` is the public production factory and `CreateForTest` is anonymous-only. Tests build authenticated contexts with `Encina.Testing.Identity` (`TestRequestContext.For(TestIdentity.User(...))`) (#1705).
- An explicit context passed to `Send`, `Publish` or `Stream` whose authenticated identity differs from an ambient user identity is refused with `encina.identity.scope_conflict`; every such identity swap logs Warning 165 with identity kinds only. Dispatch activities carry `encina.identity.kind` (anonymous, user or service), never the user id (#1705).
- Interim until the next #1705 phase: `UseEncinaContext()` creates an anonymous request context (the claim mapping moves to the identity scope factory), so HTTP requests carry no user id until that phase lands (#1705).
