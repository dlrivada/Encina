- `IRequestContext` carries the caller identity as `IRequestContext.Identity` (`RequestIdentity`: kind Anonymous/User/Service, user id, principal, roles, permissions) and gains `CausationId`; `context.UserId` is now a C# 14 extension property that projects `Identity.UserId`, so a context can never report a user id that differs from the identity the gates authorized (#1705).
- One claim map for the whole stack: `RequestIdentityOptions` (`UserIdClaimTypes` default `sub`, NameIdentifier, Entra object id; role, permission and tenant claim lists) registered by `AddEncinaRequestIdentity()`, which `AddEncina` calls; an authenticated principal without a user-id claim, with a reserved `service:` subject or with conflicting authenticated identities maps to the anonymous identity and logs a warning (EventIds 162-164) (#1705).
- Breaking: `IRequestContext.WithUserId`, `RequestContext.Create(string)` and the `userId` parameter of `RequestContext.CreateForTest` are removed; `RequestContext.CreateAnonymousAt(DateTimeOffset, ...)` is the public factory for anonymous contexts at a given time, `RequestContext.Create()` also remains public and `CreateForTest` is anonymous-only. Tests build authenticated contexts with `Encina.Testing.Identity` (`TestRequestContext.For(TestIdentity.User(...))`) (#1705).
- An explicit context passed to `Send`, `Publish` or `Stream`, or a context set through `RequestContextAccessor.RequestContext`, whose authenticated identity (kind, user id, roles or permissions) differs from an ambient user identity is refused: the dispatch returns `encina.identity.scope_conflict` and the setter throws `InvalidOperationException`; every accepted or refused change of authenticated identity logs Warning 165 with identity kinds only (a refusal over an inbound chain logs EventId 167 with the error code, #1892). An explicit context is checked and dispatched as one immutable snapshot. The `Encina.Send` and `Encina.Stream` activities carry `encina.identity.kind` (anonymous, user or service), never the user id (#1705).
- `VaryByUser` query caching fails closed: a request whose identity is not an authenticated user bypasses the cache (no read, no write; Debug EventId 3512 with the identity kind only) instead of sharing one cache key across callers, and `DefaultCacheKeyGenerator.GenerateKey` and the default key of `CacheConfiguration<TRequest>.GenerateKey` (no custom `KeyGenerator`) throw `InvalidOperationException` for such a request (#1705).
- `ReadAuditOptions.ExcludeSystemAccess` skips only reads made under a service identity; anonymous and user reads are always audited (#1705).
- `RequestIdentity` hardening: a user id containing an invisible Unicode format character (such as U+200B or U+202E) is rejected; `HasClaim` answers from the claims frozen when the identity was created, so a principal mutated later changes nothing; `PersistedRequestIdentity.ToString()` prints the identity kind only (#1705).
