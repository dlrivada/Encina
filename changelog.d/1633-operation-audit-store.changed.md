- Rename the operation audit store to its ADR-036 names, without aliases: `IAuditStore` -> `IOperationAuditStore`, `AuditEntry` -> `OperationAuditEntry`, `AuditQuery` -> `OperationAuditQuery`, `AuditOptions` -> `OperationAuditOptions`, the table `SecurityAuditEntries` -> `OperationAuditEntries`, the flag `UseSecurityAuditStore` -> `UseOperationAuditStore` (`MessagingConfiguration` and `EncinaMongoDbOptions`), the MongoDB collection property and default (`OperationAuditEntries`, `operation_audit_entries`), and every store, Marten event, projection, read model, option, health check, retention service, factory and EF/Mongo entity that carried the old names (#1633).
- Register `IOperationAuditStore` for ADO.NET (SQL Server, PostgreSQL, MySQL), Dapper (SQL Server, PostgreSQL, MySQL) and MongoDB when `UseOperationAuditStore` is set; the database store wins over the in-memory default in any registration order and never replaces a store the application registered itself (#1633).
- Add the `028_CreateOperationAuditEntriesTable.sql` script to the six relational provider packages and to their `000_CreateAllTables.sql` (#1633).
- Resolve the operation audit store per purge run (`OperationAuditRetentionService`) and per audit write (the audited secret decorators) through `IServiceScopeFactory`, so a scoped database store works with those singleton services; their constructors take an `IServiceScopeFactory` instead of the store (#1633).
- Inject `TimeProvider` (optional, defaults to the system clock) into `AuditPipelineBehavior` and the three audited secret decorators instead of reading the system clock (#1633).
- Register the EF Core operation audit store with `TryAdd` semantics like the other providers, and let a database provider replace the in-memory default even when the OpenTelemetry instrumentation wrapped it (`OperationAuditStoreRegistration.RemoveInMemoryDefault`, `IDecoratedServiceFactory`) (#1633).
- Store the PostgreSQL operation audit `TimestampUtc` as `TIMESTAMPTZ`; the ADO.NET, Dapper and MongoDB stores apply `MinDuration` and `MaxDuration` before paging (page and total count are those of the filtered set), the Dapper stores pass the cancellation token to Dapper, and MongoDB creates the operation audit collection indexes (#1633).
- On-disk names changed with the rename: the Marten event type, the read-model document table and the EF Core table (`OperationAuditEntryRecordedEvent`, `OperationAuditEntryReadModel`, `OperationAuditEntries`); pre-1.0 there is no migration (#1633).
- AuditPipelineBehavior writes operation audit entries on a best-effort basis (a failed write is logged, never fails the request) until #1869 defines the guaranteed-audit contract.
- Duration-only operation audit queries (MinDuration/MaxDuration without other filters) load the filtered set and apply the duration in memory until #1873 moves the filter into the store.
