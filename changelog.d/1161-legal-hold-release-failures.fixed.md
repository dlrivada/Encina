- **`LiftHoldAsync` reports release failures and fails closed** (#1161). `ILegalHoldService.LiftHoldAsync` ignored the result of releasing each retention record and swallowed exceptions, so a record could stay `UnderLegalHold` forever while the call reported success; and an error while checking for other active holds was treated as "no other hold", releasing records another hold still protected. Now every record is attempted, the ones that fail stay held and the call returns `retention.hold_release_incomplete` with their ids under `failedRecordIds` (EventId 8588 per record); an error in the other-holds check releases nothing and returns the same error (EventId 8589); the other-holds check excludes the hold being lifted, so a lagging read model cannot keep records held. Calling `LiftHoldAsync` again for a hold that is already lifted no longer fails with an invalid state transition: it retries the release of the records still held (EventId 8590) and returns success once they are all released.
