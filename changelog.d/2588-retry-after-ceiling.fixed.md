- A `Retry-After` above a configurable ceiling no longer parks a message for decades: `RecoverabilityOptions.MaxRetryAfter` and `OutboxOptions.MaxRetryAfter` (default 24 hours, must be above zero; `TimeSpan.MaxValue` means no ceiling) bound it. Up to the ceiling the next attempt still waits at least the header; above it `RecoverabilityPipelineBehavior`, `DelayedRetryProcessor` and the outbox schedule nothing and dead-letter the message with the new error code `recoverability.retry_after_exceeds_ceiling` (`RecoverabilityErrorCodes.RetryAfterExceedsCeiling`), log a warning (EventIds 5454, 5455, 5456) and count `encina.retry.skipped_total` with the new reason `retry_after_exceeds_ceiling` (`RetryMetrics.ReasonRetryAfterExceedsCeiling`) (#2588).
