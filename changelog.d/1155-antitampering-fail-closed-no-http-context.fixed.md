- `HMACValidationPipelineBehavior` now fails closed (rejects the request) when a `[RequireSignature]` request has no `HttpContext` available, instead of silently passing it through. Opt out explicitly via `AntiTamperingOptions.SkipWhenNoHttpContext` or the per-request `RequireSignatureAttribute.WhenNoHttpContext` (#1155).
- `RequireSignatureAttribute.SkipWhenNoHttpContext` (bool) is replaced by `WhenNoHttpContext` (`HttpContextRequirement`: `Inherit` / `Reject` / `Skip`, default `Inherit`). An explicit attribute value always wins over the global `AntiTamperingOptions.SkipWhenNoHttpContext` switch, so a request type can force strict validation even when the global option skips, or opt into the skip even when it does not (#1155).
- The no-`HttpContext` rejection now goes through the same `Fail()` path as every other HMAC validation failure, so activity status and metrics are recorded consistently regardless of which switch caused the skip or rejection (#1155).
