- ABAC runs on the request identity (#1705): `ABACPipelineBehavior` reads the caller from `IRequestContext.Identity` and no longer takes `ISecurityContextAccessor`; `AddEncinaABAC` registers the request identity model itself. An anonymous caller is denied in `Block` and `Warn` mode with the shared code `encina.authorization.unauthenticated` (detail `gate = abac`), replacing `abac.missing_context` (`ABACErrors.MissingContext` is replaced by `ABACErrors.UnauthenticatedCaller`).
- `IAttributeProvider.GetSubjectAttributesAsync` takes the caller's `RequestIdentity` instead of a user id string, and the PEP always adds the built-in subject attributes `subject-id` and `identity-kind` (`ABACSubjectAttributes`), so a policy (a Subject attribute designator with that attribute id) or an EEL condition can tell users from declared service identities.
- The persistent PAP attributes each change to the authenticated caller (a user or a declared service identity) and records the audit metadata `actor` as `user` or `service`; its `IRequestContextAccessor` constructor argument is required. Startup policy seeding runs under the built-in service identity `service:encina.abac.policy-seeding` instead of the removed system-actor scope.
- EventId 9085 (Warning) is logged once at startup when ABAC enforcement is `Disabled`; EventId 9096 is now the seeding summary with the seeded and total counts.
