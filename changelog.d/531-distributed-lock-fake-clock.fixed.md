- The lock providers `InMemoryDistributedLockProvider`, `Encina.DistributedLock.Redis` `RedisDistributedLockProvider`, `Encina.Caching.Memory` `MemoryDistributedLockProvider` and `Encina.Caching.Redis` `RedisDistributedLockProvider` wait between retries on the injected `TimeProvider` instead of the wall clock, so a test clock drives the whole wait and a frozen `FakeTimeProvider` no longer makes `TryAcquireAsync` spin forever; the retry delay is never under 1 ms (#531).
- `TryAcquireAsync` of these providers always attempts the lock once, so a zero `wait` takes a free lock instead of returning `null`, and the last retry is shortened to the remaining wait (#531).
- `InMemoryDistributedLockProvider` and `MemoryDistributedLockProvider` remove expired and released entries with compare-and-remove, so they only delete the exact entry they read; `InMemoryDistributedLockProvider` lock handles report `AcquiredAtUtc`/`ExpiresAtUtc` as `DateTimeKind.Utc` (#531).
- Both Redis lock handles log a failed release at Warning (exception type only, EventIds 3754 and 3615) instead of swallowing it silently (#531).
