- Keyset pagination follows the sort direction of the keyset property on every provider (ADO.NET and Dapper for SqlServer, PostgreSQL and MySQL, EF Core and MongoDB): when the specification orders the keyset property descending, the next page is filtered with `<` instead of `>`, so it holds the smaller keys instead of the wrong rows or none. The direction comes from the new `IsKeysetDescending` extension property on `IQuerySpecification<T>` (#3154).
- Keyset pagination now requires the keyset property to be the primary ordering (`ApplyOrderBy` or `ApplyOrderByDescending`). A specification ordered by another property first, or with the keyset property only in a `ThenBy`/`ThenByDescending`, is rejected with `NotSupportedException` on every page, the first one included, instead of silently skipping or repeating rows; the repositories surface it as they surface other unsupported specifications. A specification with no ordering keeps the ascending filter (#3154).
