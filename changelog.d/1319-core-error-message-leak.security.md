- **Core error message sanitization prevents leaks to OpenTelemetry and structured logs** (#1319). The request/notification handling pipeline no longer interpolates `EncinaError.Message` or raw exception messages into log message templates or activity tags. `Log.RequestFailed` and `Log.NotificationHandlerFailure` now include the request/notification type, error code/reason and (for RequestFailed) the exception object itself via the `Exception` parameter for structured logging, not string-interpolated. `EncinaErrorExtensions.GetEncinaCode` fallback changed from `error.Message` to the fixed literal `"Encina.unknown"`. Sharding diagnostics and log classes (`ShardingMediator`, `ShardingPipeline`, `ActivityPipelineBehavior`, `RequestFailureLogger`) were updated to follow the same pattern, preventing personal data in `EncinaError` messages from reaching logs, activity spans or health checks.
