- `[RequirePolicy]` and `[RequireCondition]` on ABAC requests are now enforced as documented (#1634): each named top-level policy set or standalone policy is evaluated on its own through the new `IPolicyDecisionPoint.EvaluatePolicyAsync` (a policy nested inside a policy set is not found by its own name, so its parent's enabled flag, target, combining algorithm and obligations cannot be bypassed: name the parent set); attributes combine as AND/OR groups (`AllMustPass`); a required policy that returns NotApplicable denies; a missing policy denies with `abac.policy_not_found`; conditions run per request against `user`, `resource`, `environment` and `action` (resource attributes now come from the request instead of an empty value); a false condition denies with `abac.condition_not_met`; errors are Indeterminate and deny in every enforcement mode (`Warn` relaxes only definite denials: a Deny, a required policy that is NotApplicable or not found, a false condition); policies and conditions combine with AND. `ABACOptions.DefaultNotApplicableEffect` (no longer read by anything), the `abac.evaluation.not_applicable` metric and log EventIds 9006 and 9007 are removed. `ABACOptions.FailOnMissingObligationHandler` is removed too: nothing read it, and a mandatory obligation without a handler always denies.
- A throwing obligation or advice handler (from `CanHandle` or `HandleAsync`) no longer escapes `ObligationExecutor`: it is reported as `abac.obligation_handler_exception` (a mandatory obligation denies, an advice is skipped), without the exception message text; cancellation still propagates.
- `ABACPipelineBehavior` now takes an `EELCompiler` constructor parameter to evaluate `[RequireCondition]` expressions.
