- `[RequirePolicy]` and `[RequireCondition]` on ABAC requests are now enforced as documented (#1634): each named policy is evaluated on its own through the new `IPolicyDecisionPoint.EvaluatePolicyAsync`; attributes combine as AND/OR groups (`AllMustPass`); a required policy that returns NotApplicable denies; a missing policy denies with `abac.policy_not_found`; conditions run per request against `user`, `resource`, `environment` and `action` (resource attributes now come from the request instead of an empty value); a false condition denies with `abac.condition_not_met`; errors are Indeterminate and deny; policies and conditions combine with AND. `ABACOptions.DefaultNotApplicableEffect` (no longer read by anything), the `abac.evaluation.not_applicable` metric and log EventIds 9006 and 9007 are removed.
- A throwing obligation or advice handler no longer escapes `ObligationExecutor`: it is reported as `abac.obligation_handler_exception` (a mandatory obligation denies, an advice is skipped), without the exception message text; cancellation still propagates.
- `ABACPipelineBehavior` now takes an `EELCompiler` constructor parameter to evaluate `[RequireCondition]` expressions.
