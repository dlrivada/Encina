- **Error category contract on `EncinaError`** (#3419, #3545). Every error can now carry a protocol-neutral `ErrorCategory` set where it is created, through the new overloads `EncinaErrors.Create(code, category, message, ...)` and `EncinaErrors.FromException(code, category, exception, ...)`, and read with `error.GetCategory()`. The 14 categories (`Internal`, `Validation`, `InvalidRequest`, `Unauthenticated`, `Forbidden`, `NotFound`, `Conflict`, `AlreadyExists`, `FailedPrecondition`, `RateLimited`, `Unavailable`, `Timeout`, `UpstreamFailure`, `Cancelled`) and their HTTP, gRPC and GraphQL statuses are fixed by ADR-062. `EncinaErrorMetadataKeys.RetryAfter` and `EncinaErrorMetadataKeys.AuthenticateChallenge` name the details that hosts turn into `Retry-After` and `WWW-Authenticate`. An error without a code is `Internal`; until the staged migration ends, an error created without a category gets the category its code text implied before.
