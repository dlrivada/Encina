- EF Core security audit stores (`AuditStoreEF`, `ReadAuditStoreEF`) now work on PostgreSQL: the filtered indexes of `AuditEntryEntityConfiguration` and `ReadAuditEntryEntityConfiguration` quote their column (`"UserId" IS NOT NULL`), so creating the schema no longer fails with `column "userid" does not exist`; write failures keep the underlying exception in the returned `EncinaError`.
- `PurgeEntriesAsync` on both EF Core audit stores now also catches the raw provider `DbException` that `ExecuteDeleteAsync` can throw (it bypasses EF Core's `DbUpdateException` wrapper), returning the same `Left` shape as the write path instead of letting the exception escape (#1128).
- `EncinaError` messages built from EF Core audit store failures no longer include the provider's exception message text, which can embed column values (e.g. SQL Server 2628 "Truncated value: '...'"); they now report only the root cause's exception type and, when it is a `DbException`, its `SqlState` or `ErrorCode` as a provider error identifier. The full exception is still attached to the error via `EncinaError.Exception`.
