- **Pipeline behaviors now receive the caller's user, tenant and idempotency key** (#1147). `IEncina.Send`, `Publish` and `Stream` used to build an empty `IRequestContext` for every dispatch, so authorization, consent, data-subject-rights, lawful-basis, query-cache, idempotency and audit behaviors always saw `UserId == null` and `TenantId == null`, even behind `EncinaContextMiddleware`. The pipeline context is now taken from an ambient `IRequestContextAccessor` when one is set, and a fresh context (correlation id from `Activity.Current`) is created only when there is none.

  - `IRequestContextAccessor` and its `AsyncLocal`-backed `RequestContextAccessor` moved from `Encina.AspNetCore` into `Encina` core (namespace `Encina`) and are registered by `AddEncina`. `EncinaContextMiddleware` fills the core accessor; the `Encina.AspNetCore` copies are gone.
  - New explicit overloads `IEncina.Send(request, IRequestContext context, ct)`, `Publish(notification, context, ct)` and `Stream(request, context, ct)` for entry points without an ambient context (background jobs, webhooks, message consumers). The explicit context wins over the ambient one. `FakeEncina` implements them.
  - While a request, notification or stream is dispatched, its context is the ambient one, so nested `Send` calls, notification handlers and EF Core interceptors observe the same context; the previous value is restored afterwards, so concurrent or unrelated calls never see it.
  - The EF Core audit, soft-delete and query-cache interceptors read the core accessor directly instead of locating `Encina.AspNetCore` through reflection, and `Encina.Tenancy` no longer references `Encina.AspNetCore`.
