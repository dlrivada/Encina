- **Pipeline behaviors now receive the caller's user, tenant and idempotency key** (#1147). `IEncina.Send`, `Publish` and `Stream` used to build an empty `IRequestContext` for every dispatch, so authorization, consent, data-subject-rights, lawful-basis, query-cache, idempotency and audit behaviors always saw `UserId == null` and `TenantId == null`, even behind `EncinaContextMiddleware`. The pipeline context is now taken from an ambient `IRequestContextAccessor` when one is set, and a fresh context (correlation id from `Activity.Current`) is created only when there is none.

  - `IRequestContextAccessor` and its `AsyncLocal`-backed `RequestContextAccessor` moved from `Encina.AspNetCore` into `Encina` core (namespace `Encina`) and are registered by `AddEncina`. `EncinaContextMiddleware` fills the core accessor; the `Encina.AspNetCore` copies are gone.
  - New explicit overloads `IEncina.Send(request, IRequestContext context, ct)`, `Publish(notification, context, ct)` and `Stream(request, context, ct)` for entry points without an ambient context (background jobs, webhooks, message consumers). The explicit context wins over the ambient one. `FakeEncina` implements them.
  - While a request, notification or stream is dispatched, its context is the ambient one, so its behaviors, its handler and EF Core interceptors observe it; the previous value is restored afterwards (also after an exception, a cancellation or an abandoned stream), so concurrent or unrelated calls never see it.
  - Only the entry-point dispatch carries the idempotency key. A `Send`, `Publish` or `Stream` issued while another dispatch runs (from a handler, a notification or domain-event handler) gets a derived context with the same correlation id, user, tenant and metadata, its own `Timestamp` (from the `TimeProvider` now accepted by `Encina`), and no `IdempotencyKey`, so nested idempotent requests no longer collide with the outer one in `InboxPipelineBehavior` or `DistributedIdempotencyPipelineBehavior`. Both behaviors let a nested request without a key run (new `IRequestContext.IsNestedDispatch()`); an explicit context is used as-is.
  - `TenantResolutionMiddleware` creates the ambient context (tenant plus correlation id) when no earlier middleware established one, instead of dropping the resolved tenant.
  - `DelayedRetryProcessor` dispatched every retry through a cast of the returned `ValueTask` to `Task`, so each retry failed with an `InvalidCastException`; it and `DeadLetterManager` replay now send through a typed helper and treat a `Left` outcome as a failure (the dead-letter replay used to report it as a success).
  - The EF Core audit, soft-delete and query-cache interceptors read the core accessor directly (and prefer it over a DI-registered `IRequestContext`) instead of locating `Encina.AspNetCore` through reflection, and `Encina.Tenancy` no longer references `Encina.AspNetCore`.
