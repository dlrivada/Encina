- **Hangfire no longer persists the handler's response by default, and job failure logs no longer include the error message** (#1173). `HangfireRequestJobAdapter.ExecuteAsync` (the method `EnqueueRequest`, `ScheduleRequestWithDelay` and `ScheduleRequestAt` enqueue) now returns `Task` instead of `Task<TResponse>`, so Hangfire's job storage has nothing from the response to serialize; applications that need the response can opt in explicitly with `ExecuteAndReturnResultAsync` (still `Task<TResponse>`, still throwing `EncinaJobFailedException`/`EncinaJobPermanentFailureException` on failure) / `EnqueueRequestWithResult`, documented as safe only for responses known not to carry personal or health data. Failure logs in `Encina.Hangfire` and `Encina.Quartz` (the `RequestJobFailed`/`NotificationJobFailed` log lines) now carry only the `EncinaError` error code and its classification, not the full error message, which for compliance modules (Consent, DSR) can embed a data-subject id. Quartz's `JobExecutionException` message already carried only the code and classification (#1159); Quartz does not retry failed jobs. Only `EnqueueRequest` has a response opt-in (`EnqueueRequestWithResult`); the delayed, scheduled and recurring helpers always discard the response.
