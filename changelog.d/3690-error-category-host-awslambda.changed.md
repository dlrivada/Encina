- `Encina.AwsLambda`: the API Gateway response helpers (`ToApiGatewayResponse`, `ToProblemDetailsResponse`, `ToCreatedResponse`, `ToNoContentResponse`, `ToHttpApiResponse`) now read the `ErrorCategory` of the error and the core `ErrorCategoryHttp` table instead of parsing the error code; the code-suffix rules are removed and the host no longer parses codes at all. An error created without a category still gets one from the legacy inference of core until #3740 removes it. An explicit status override still passes through, also outside the core table (for example 418, with the title `An error occurred`) (#3690, part of #2913).
- `Encina.AwsLambda`: new statuses and problem titles from the category table: 429 `Too Many Requests`, 499 `Client Closed Request`, 502 `Bad Gateway`, 503 `Service Unavailable` and 504 `Gateway Timeout`; an overridden status such as 422 now gets its reason phrase (`Unprocessable Entity`) instead of `An error occurred`.
- `Encina.AwsLambda`: `Retry-After` is written for 429 and 503 errors that carry a retry delay, and `WWW-Authenticate` (default `Bearer`) for every 401, in both the REST API and the HTTP API v2 responses.
- `Encina.AwsLambda`: the tenancy errors `tenancy.tenant_mismatch` and `tenancy.invalid_tenant_claim` are `Forbidden` and answer 403 instead of 500.
- `Encina.AwsLambda`: a cancellation of the EventBridge processing delegate is no longer reported as `eventbridge.processing_failed` (500); it returns the new error code `eventbridge.processing_cancelled` with category `Cancelled` (499).
- `Encina.AwsLambda`: the EventBridge `eventbridge.detail_null` and `eventbridge.deserialization_failed` errors and the SQS `sqs.deserialization_failed` error are `InvalidRequest` (400); `eventbridge.processing_failed` is `Internal` (500).
