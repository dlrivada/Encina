- Query-cache and cache-provider log entries no longer contain the caller's user id or tenant id. Cache keys and key patterns are logged with their `t:` and `u:` segments redacted (`t:***`, `u:***`) through the new `CacheKeyRedactor` in `Encina.Caching`; the real key is still used for the cache itself. Tenant and user ids placed in a generated key now have `:` escaped as `%3A` (and `%` as `%25`) so a segment is always one part. The pub/sub providers (Memory, Redis and therefore Valkey, Dragonfly, Garnet, KeyDB) no longer log the published payload, and a subscribed pattern is logged redacted. Affects EventIds 3500, 3501, 3503, 3508-3511 (`Encina.Caching`), 3560 and 3610 (pub/sub), the key logs of the Memory, Hybrid and Redis cache providers and the scatter-gather executor, which now also logs when it stores or skips a result (#1953).
