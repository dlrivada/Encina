- **Encina.Compliance.LawfulBasis health check no longer leaks EncinaError.Message or raw exception messages in health-check results** (#1461). `LawfulBasisHealthCheck` now records only the error code (via `EncinaError.GetCode()`, falling back to `"encina.unknown"`) in its two warning paths from `GetAllRegistrationsAsync` and `GetPendingLIAReviewsAsync`, never the raw error message. Its two `catch (Exception ex)` blocks now record only the exception type name via `ex.GetType().Name`, never `ex.Message`. The first `catch` block also stopped passing the raw exception object into `HealthCheckResult.Degraded`'s `exception:` parameter and now sets `data["exception_type"]` instead. Additionally, `DefaultLawfulBasisService`'s `RegisterAsync` and `CreateLIAAsync` argument-validation logging no longer passes `ex.Message` as a redundant log template argument. This is the health-check sibling of #1435 (which fixed the same defect class in validation pipeline logging).
