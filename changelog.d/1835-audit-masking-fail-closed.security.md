- The audit module no longer stores raw personal data when PII masking fails: `IOperationAuditEntryFactory.Create` now returns `Either<EncinaError, OperationAuditEntry>`, `DefaultOperationAuditEntryFactory` returns the `audit.masking_failed` error (carrying only the exception type, never its message) and builds no entry, and `AuditPipelineBehavior` propagates it under the default fail-closed mode (best effort logs it) (#1835).
- `DefaultSensitiveDataRedactor` throws instead of returning the unmasked request or text when serialization or parsing fails, and masks the JSON form directly, so sensitive-named non-string properties no longer break hashing (#1835).
- `AddEncinaAudit` no longer registers a default pass-through `IPiiMasker`: the host fails at startup when no masker is registered, unless the application sets `OperationAuditOptions.AllowUnmaskedPayloads = true` in the configure action (registers `NullPiiMasker` and logs a warning at every start). The payload path now also runs custom maskers (#1835).
- A masking failure is logged with the error code and the cause exception type (EventId 5012) and counted on the new `Encina.OperationAudit` meter (`operation_audit.masking_failures.total`, tags `error_code` and `request_type`) in both failure modes; fatal exceptions are no longer turned into audit errors (#1835).
