- Persistent dead letter queue on the 10 database providers: ADO.NET, Dapper and EF Core on SQL Server, PostgreSQL and MySQL, plus MongoDB (#583). Enable it with `UseDeadLetterQueue = true`; each relational provider ships its `029_CreateDeadLetterMessagesTable.sql` schema script.
- The EF Core dead letter mapping is `DeadLetterMessageConfiguration`; applying it requires the filter-column collation argument so that the source pattern and message id columns compare the same way on every provider (#583).
- Dead letter capture is idempotent by `(SourcePattern, SourceMessageId)`, the queue carries a tenant column, and replay is an atomic claim bounded by `ReplayClaimTimeout` so a crashed replay cannot leave a message locked forever (#583).
- Dead letter operations emit the `encina.dlq.*` counters and the `Encina.Messaging.DeadLetter` activity source; tags carry the error code only, never the tenant or the message text (#583).
- The `IDeadLetterStore` / `IDeadLetterMessage` contract was reshaped (#583): paging is oldest-first; `AddAsync`, `MarkAsReplayedAsync` and `DeleteAsync` return `bool`; `TryClaimForReplayAsync`, `DeleteManyAsync` and `GetCountAsync` are new; the message exposes `ErrorCode` instead of the error text.
