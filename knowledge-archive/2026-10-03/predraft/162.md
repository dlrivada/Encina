## Decisions
- To create a new package named `Encina.Testing.Testcontainers` for Docker-based integration testing (Source: issue body "Proposed Solution" and "Affected Packages").
- To implement pre-configured fixtures for SQL Server, PostgreSQL, MySQL, MongoDB, and Redis (Source: issue body "Proposed Solution" and "Acceptance Criteria").
- To provide a static factory class `EncinaContainers` for quick container creation and customization (Source: issue body "Proposed Solution").
- To integrate the containers with the existing `EncinaFixture` via `EncinaIntegrationFixture<TContainer>` (Source: issue body "Proposed Solution").
- To position this as the first foundational package for the v0.11.0 Testing Infrastructure milestone (Source: comment by dlrivada).
- To add the package for Docker integration tests (Source: commit 711675dc message).

## Rejected alternatives
- In-memory databases only (SQLite/EF InMemory), as behavior differs from real databases and misses SQL dialect issues (Source: issue body "Alternatives Considered").
- Shared test database, due to test interference and difficulty in parallelization (Source: issue body "Alternatives Considered").
- Manual Docker setup, as it is more error-prone and difficult for CI/CD (Source: issue body "Alternatives Considered").

## Rules and lessons
- Integration tests should use real database instances via Docker for isolation and reproducibility rather than in-memory fakes (Source: issue body "Motivation").
- Public APIs must have XML documentation (Source: issue body "Acceptance Criteria").
- Unit test coverage should target at least 85% (Source: issue body "Acceptance Criteria").
