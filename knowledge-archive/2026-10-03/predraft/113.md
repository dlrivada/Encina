## Decisions
- Implement automatic health check registration for all infrastructure providers when configured (Source: Issue body, "Proposed Solution").
- Provide an opt-out mechanism via `config.RegisterHealthChecks = false` (Source: Issue body, "Implementation Details"; Comment by dlrivada, "Implementación parcial completada").
- Make health check timeout and tags configurable (Source: Issue body, "Implementation Details").
- Use specific tags for health checks (`db`, `messaging`, `cache`) (Source: Issue body, "Implementation Details").
- Define a base class `DatabaseHealthCheck` and options class `ProviderHealthCheckOptions` in `Encina.Messaging` to standardize implementation (Source: Comment by dlrivada, "Implementación parcial completada").
- Treat Redis client compatibility to include Valkey, KeyDB, Dragonfly, and Garnet under a single health check implementation (Source: Issue body, "Providers to Support").
- Update READMEs for all affected packages with health check documentation (Source: Issue body, "Acceptance Criteria"; Comment by dlrivada, "Documentación Completada").
- Close issue only after resolving dependency #116 (EF Core PropertyTests compilation) (Source: Comment by dlrivada, "Actualización Final - Issue #116 Resuelta").

## Rejected alternatives
- none

## Rules and lessons
- Health checks must be automatically registered to provide out-of-the-box observability without manual wiring (Source: Issue body, "Motivation").
- Cloud-based providers (Azure Service Bus, Amazon SQS) are exempt from integration tests due to the lack of viable local emulators (Source: Issue body, "Exhaustive Implementation Status", note 4).
- In-process providers (SQLite, SignalR) are exempt from container-based integration tests (Source: Issue body, "Exhaustive Implementation Status", notes 2 and 5).
- Property tests for EF Core were blocked by pre-existing errors in `Generators.cs` related to removed messaging types, which required a separate issue (#116) for resolution (Source: Issue body, "Exhaustive Implementation Status", note 3).
- Documentation updates are a required acceptance criterion for feature closure (Source: Comment by dlrivada, "Documentación Completada").
