## Decisions
- **Delete obsolete test files** (`tests/Encina.EntityFrameworkCore.PropertyTests/Generators.cs` and `tests/Encina.EntityFrameworkCore.PropertyTests/Outbox/OutboxStoreEFFsCheckTests.cs`): The files relied on FsCheck 2.x API (`Arb.From()`, `Prop.ForAll()`, `.ToProperty()`) which was incompatible with the project's current FsCheck 3.x dependency, and the types referenced had moved namespaces. Rewriting was deemed unnecessary in favor of removal (Source: Comment by dlrivada).
- **Fix namespace ambiguity in remaining tests**: Added explicit alias `using SagaStatus = Encina.EntityFrameworkCore.Sagas.SagaStatus;` in `SagaStoreEFPropertyTests.cs` to resolve conflicts now that types reside in `Encina.EntityFrameworkCore.*` rather than `Encina.Messaging.*` (Source: Comment by dlrivada).
- **Retain modern property tests**: The following files using `[Fact]` and `[Property]` attributes were verified to compile and run successfully and were kept:
  - `Health/EntityFrameworkCoreHealthCheckPropertyTests.cs`
  - `Outbox/OutboxStoreEFPropertyTests.cs`
  - `Inbox/InboxStoreEFPropertyTests.cs`
  - `Sagas/SagaStoreEFPropertyTests.cs`
  - `Scheduling/ScheduledMessageStoreEFPropertyTests.cs` (Source: Comment by dlrivada).

## Rejected alternatives
- **Rewriting the obsolete FsCheck 2.x tests**: Rejected because the comment notes "serían necesarios reescribirlos completamente" (would need to be completely rewritten) and the decision was made to delete them instead (Source: Comment by dlrivada).
- **Updating `using` statements in the obsolete files**: Rejected implicitly by the decision to delete the files entirely rather than fix the namespace references, likely due to the additional incompatibility with the FsCheck version (Source: Comment by dlrivada vs. Issue Body proposal).

## Rules and lessons
- **FsCheck Version Compatibility**: The Encina test suite uses FsCheck 3.x. Code using FsCheck 2.x APIs (e.g., `Arb.From()`, `Prop.ForAll()`, `.ToProperty()`) is incompatible and should not be retained if obsolete (Source: Comment by dlrivada).
- **Namespace Migration for EF Core Entities**: Messaging-related entity types (`OutboxMessage`, `InboxMessage`, `SagaState`, `ScheduledMessage`, `SagaStatus`) have been moved from `Encina.Messaging` to `Encina.EntityFrameworkCore.*`. New code or tests must reference the new namespace locations (Source: Comment by dlrivada).
- **Alias for Ambiguous Types**: When types like `SagaStatus` exist in multiple contexts or cause ambiguity, explicit `using` aliases should be used in test files (Source: Comment by dlrivada).

## Candidate destinations
- **docs**: Document the migration of messaging entity types from `Encina.Messaging` to `Encina.EntityFrameworkCore` to prevent future compile errors in new code/tests.
- **reviewer-checklist**: Verify that property tests use FsCheck 3.x compatible APIs (e.g., `[Property]` attribute with `FsCheck` package) rather than legacy 2.x methods like `Prop.ForAll`.
- **regression-test**: Ensure that `Encina.EntityFrameworkCore.PropertyTests` project continues to compile without referencing deleted files or old namespaces.
