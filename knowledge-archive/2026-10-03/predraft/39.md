## Decisions
- Implement a recoverability pipeline with immediate retries (in-memory) and delayed retries (persistent/scheduled), distinguishing transient errors from permanent failures. (Source: issue body)
- Configuration is handled via `RecoverabilityOptions`, including settings for immediate/delayed retries, backoff, and jitter. (Source: comment by dlrivada)
- Error classification uses `IErrorClassifier` and `DefaultErrorClassifier` to categorize errors as Transient, Permanent, or Unknown based on exception type, HTTP status, and message patterns. (Source: comment by dlrivada)
- Delayed retries are abstracted via `IDelayedRetryScheduler`, `IDelayedRetryStore`, and `IDelayedRetryMessage`, with implementations `DelayedRetryScheduler` and `DelayedRetryProcessor`. (Source: comment by dlrivada)
- Dead letter queue (DLQ) integration is achieved through an `OnPermanentFailure` callback and `FailedMessage` records. (Source: comment by dlrivada)
- Jitter support is included to prevent the "thundering herd" problem. (Source: comment by dlrivada)
- The feature is opt-in via `MessagingConfiguration.UseRecoverability = true`. (Source: comment by dlrivada)
- Default retry intervals for delayed retries are 30s, 5m, 30m, and 2h. (Source: comment by dlrivada)
- Documentation updates were made to CHANGELOG.md, ROADMAP.md, docs/history/2025-12.md, and Encina.Messaging/README.md. (Source: comment by dlrivada)

## Rejected alternatives
- none

## Rules and lessons
- Distinguish between transient errors (retryable) and permanent failures (send to DLQ) for predictable error handling in distributed systems. (Source: issue body)
- Use jitter in retry backoff mechanisms to prevent thundering herd scenarios. (Source: comment by dlrivada)
- Integration and property-based tests are deferred to Phase 3 (Issues #117, #118, #119) and are blocked until `IDelayedRetryStore` provider implementation is complete. (Source: comment by dlrivada)
