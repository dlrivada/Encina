## Decisions
- Implement the bulkhead isolation pattern using Polly to limit concurrent executions and queue excess requests (Source: issue body).
- Use `SemaphoreSlim` for the core implementation of concurrency limiting (Source: comment by dlrivada, "BulkheadManager.cs - SemaphoreSlim-based implementation").
- Support global configuration (`MaxConcurrency`, `MaxQueuedActions`) and per-handler configuration via `ForHandler<T>` (Source: issue body).
- Implement via pipeline behavior (`BulkheadPipelineBehavior`) rather than standalone service registration only, integrating with Encina's existing pipeline architecture (Source: comment by dlrivada, new files list).
- Add metrics for bulkhead usage (Source: issue body implementation tasks, comment by dlrivada mentioning `BulkheadMetrics` in property tests).

## Rejected alternatives
- none

## Rules and lessons
- Bulkhead limits must be configurable both globally and per-handler type to allow fine-grained control over critical paths like payment processing (Source: issue body proposed solution).
- Excess requests must be queued with configurable limits rather than dropped immediately, to prevent immediate failure under transient load (Source: issue body).
- Pre-existing integration test issues should be tracked separately rather than blocking the delivery of the new feature (Source: comment by dlrivada, "tracked in #120").
- New Polly-based resilience patterns require comprehensive testing including unit, property, guard, contract, integration, and benchmark tests (Source: comment by dlrivada test summary).

## Candidate destinations
- docs: Document the new `AddEncinaBulkhead` API and per-handler configuration for users (Source: issue body implementation tasks "Add documentation").
- regression-test: Ensure bulkhead concurrency limits and queue behavior are covered by load/stress tests to validate isolation under pressure (Source: issue body test matrix "Load Tests - Yes").
- spec-invariant: Concurrency limits must never be exceeded per handler type, and queued requests must respect `MaxQueuedActions` (Source: issue body acceptance criteria).
