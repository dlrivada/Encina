## Description

**Configure branch protection rules** for the main branch to ensure code quality and review requirements.

## Component Affected

Repository settings: Settings > Branches > Branch protection rules for `main`.

## Current Behavior

No branch protection rules are configured. Direct pushes to `main` are allowed, no review or CI checks are required before merging.

## Expected Behavior

- Code quality ensured through required PR reviews before merging
- CI/CD enforcement: all checks pass before merge
- Force pushes and direct commits to main blocked
- Consistent contribution workflow enforced

### Rules to Configure

| Rule | Setting | Rationale |
|------|---------|-----------|
| Require PR reviews | 1 reviewer | All changes reviewed |
| Require status checks | CI workflow | Tests must pass |
| Require up-to-date branch | Enabled | No merge conflicts |
| Require signed commits | Optional | Enhanced security |
| Restrict who can push | Maintainers | Prevent accidents |
| Require linear history | Optional | Cleaner git history |

## Impact

All contributors are affected. Without branch protection, bugs can be introduced directly to `main` without review, and CI checks can be bypassed.

## Proposed Solution

### Tasks

- [ ] Go to Settings > Branches
- [ ] Add branch protection rule for `main`
- [ ] Configure required checks
- [ ] Set review requirements
- [ ] Document in CONTRIBUTING.md

### Alternatives Considered

1. **No branch protection**: Allow direct pushes. Risky, no review process, easier to introduce bugs.
2. **Require multiple reviewers**: Require 2+ reviewers. Too restrictive for single-maintainer project initially.
3. **Require all checks**: Require every CI check to pass. Too rigid, some checks may be optional.

### Acceptance Criteria

- [ ] Branch protection enabled
- [ ] Required checks configured
- [ ] Direct pushes prevented
- [ ] Documented in CONTRIBUTING.md
