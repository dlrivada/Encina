## Summary

Implement the Routing Slip pattern for dynamic message routing through multiple processing steps.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Medium
- **Complexity**: Medium

The Routing Slip pattern (an Enterprise Integration Pattern) enables dynamic, multi-step message processing where each step can modify the route at runtime. Unlike sagas which define steps upfront, routing slips allow steps to add, remove, or reorder subsequent steps based on processing results, with built-in compensation for rollback on failure.

## Proposed Solution

- Dynamic route definition via `RoutingSlipBuilder`
- Step execution with compensation logic
- Route modification mid-flight (add/remove steps dynamically)
- Completion tracking and notification

```csharp
var routingSlip = new RoutingSlipBuilder()
    .AddStep<ValidateOrder>()
    .AddStep<ProcessPayment>()
    .AddStep<ReserveInventory>()
    .AddStep<ShipOrder>()
    .OnCompletion<NotifyCustomer>()
    .Build();

await _encina.Execute(routingSlip, new OrderData(orderId, items));

// Each step can modify the slip
public class ProcessPaymentStep : IRoutingSlipStep<OrderData>
{
    public async Task<RoutingSlipResult> Execute(
        OrderData data,
        RoutingSlipContext context)
    {
        var result = await _paymentService.Process(data.OrderId);

        if (result.RequiresManualReview)
        {
            // Add a new step dynamically
            context.AddStep<ManualReviewStep>();
        }

        return RoutingSlipResult.Continue(data with { PaymentId = result.Id });
    }

    public async Task Compensate(OrderData data, RoutingSlipContext context)
    {
        await _paymentService.Refund(data.PaymentId);
    }
}
```

## Summary
Added the Routing Slip enterprise integration pattern to `Encina.Messaging` for dynamic message routing with compensation support.

## Features
- `RoutingSlipBuilder` fluent API for inline step definition
- Dynamic route modification via `RoutingSlipContext`:
  - `AddStep()`, `AddStepNext()`, `InsertStep()`, `RemoveStepAt()`, `ClearRemainingSteps()`
- Automatic compensation in reverse order on failure
- Configurable via `RoutingSlipOptions`
- Full ROP error handling with `Either<EncinaError, TData>`
- High-performance logging with `LoggerMessage` (EventIds 400-415)

## Key Differences from Saga Pattern
| Aspect | Saga | Routing Slip |
|--------|------|--------------|
| Route | Fixed at build time | Dynamic during execution |
| Step Modification | Not possible | Full control via context |
| Use Case | Predefined workflows | Adaptive workflows |
