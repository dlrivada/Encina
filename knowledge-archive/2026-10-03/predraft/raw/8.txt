## Description

Several PropertyTests in `Encina.Dapper.Sqlite.PropertyTests` are failing due to missing database tables.

## Location

- **File(s)**: `tests/Encina.Dapper.Sqlite.PropertyTests/TransactionPipelineBehaviorPropertyTests.cs`, `tests/Encina.Dapper.Sqlite.PropertyTests/Scheduling/ScheduledMessageStoreDapperPropertyTests.cs`
- **Package(s)**: Encina.Dapper.Sqlite

## Current Behavior

Tests fail with SQLite errors:

```
Microsoft.Data.Sqlite.SqliteException : SQLite Error 1: 'no such table: OutboxMessages'.
Microsoft.Data.Sqlite.SqliteException : SQLite Error 1: 'no such table: ScheduledMessages'.
```

### Failing Tests

- `TransactionPipelineBehaviorPropertyTests.ConnectionState_DoesNotAffectBehavior`
- `TransactionPipelineBehaviorPropertyTests.Behavior_IsIdempotent`
- `ScheduledMessageStoreDapperPropertyTests.Reschedule_UpdatesDueStatus`
- `ScheduledMessageStoreDapperPropertyTests.Reschedule_AlwaysResetsRetryFields`

## Expected Behavior

All PropertyTests should pass after properly initializing the in-memory SQLite database with the required schema.

## Root Cause

The PropertyTests are not properly initializing the in-memory SQLite database with the required schema before running tests.

## Proposed Fix

1. Add proper test fixture that creates the required tables before tests run
2. Or use a shared database initialization helper
