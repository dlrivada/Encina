## Summary

Create distributed lock abstractions for coordinating access to shared resources.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Low
- **Complexity**: Medium

In distributed systems, multiple instances of a service may attempt to access or modify the same shared resource concurrently. A distributed lock abstraction provides a provider-agnostic interface for mutual exclusion, enabling safe coordination across service instances with automatic timeout and release semantics.

## Proposed Solution

- Provider-agnostic lock interface (`IDistributedLock`)
- Redis lock provider (Redlock algorithm)
- SQL Server lock provider (`sp_getapplock`)
- Timeout and auto-release mechanisms

```csharp
public interface IDistributedLock
{
    ValueTask<IAsyncDisposable?> TryAcquireAsync(
        string lockKey,
        TimeSpan timeout,
        CancellationToken ct = default);
}

// Usage
await using var lock = await _distributedLock.TryAcquireAsync(
    $"order:{orderId}",
    TimeSpan.FromSeconds(30));

if (lock is null)
{
    return Either<EncinaError, Unit>.Left(
        new EncinaError("lock.timeout", "Could not acquire lock"));
}
```
