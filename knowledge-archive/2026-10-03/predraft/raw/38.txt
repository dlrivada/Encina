## Summary

Implement saga timeout functionality using the `RequestTimeout<T>()` pattern for handling saga step timeouts.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Critical
- **Complexity**: Medium

Long-running sagas need timeout mechanisms to handle cases where expected messages never arrive (e.g., payment service down). Without timeouts, sagas can hang indefinitely, blocking business processes and consuming resources.

## Proposed Solution

### Features

- Timeout configuration per saga step
- Automatic timeout message dispatch
- Timeout handlers in saga
- Configurable retry behavior on timeout

### Proposed API

```csharp
public class OrderSaga : Saga<OrderSagaState>
{
    public override void ConfigureHowToFindSaga(SagaPropertyMapper<OrderSagaState> mapper)
    {
        mapper.MapSaga(saga => saga.OrderId)
              .ToMessage<StartOrder>(msg => msg.OrderId);
    }

    public async Task Handle(StartOrder message, ISagaContext context)
    {
        // Request timeout after 5 minutes
        context.RequestTimeout<PaymentTimeout>(TimeSpan.FromMinutes(5));

        await context.Send(new ProcessPayment(message.OrderId));
    }

    public async Task Timeout(PaymentTimeout timeout, ISagaContext context)
    {
        // Handle timeout - compensation logic
        await context.Publish(new OrderCancelled(Data.OrderId, "Payment timeout"));
        MarkAsComplete();
    }
}
```
