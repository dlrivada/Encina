## Summary

Implement the Content-Based Router pattern for routing messages based on content inspection.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Low
- **Complexity**: Medium

The Content-Based Router pattern (an Enterprise Integration Pattern) inspects message content and routes it to the appropriate handler based on configurable rules. This enables scenarios like routing high-value orders to specialized handlers, international orders to region-specific processing, or hazardous materials to compliance workflows, all without the sender needing to know about routing logic.

## Proposed Solution

- Content-based routing rules with predicate expressions
- Multiple destination support
- Default route handling for unmatched messages
- Route caching for performance optimization

```csharp
services.AddEncinaContentRouter<Order>(config =>
{
    config.When(o => o.Total > 10000)
          .RouteTo<HighValueOrderHandler>();

    config.When(o => o.IsInternational)
          .RouteTo<InternationalOrderHandler>();

    config.When(o => o.Items.Any(i => i.IsHazardous))
          .RouteTo<HazardousMaterialsHandler>();

    config.Default<StandardOrderHandler>();
});

// Usage
var result = await _encina.Route(order);
```

## Summary
- Created  interface with  methods returning 
- Implemented  fluent API for defining routing rules:
  - `When(condition)` / `When(name, condition)` for conditional routes
  - `RouteTo(handler)` with sync/async overloads
  - `WithPriority(int)` for route ordering
  - `WithMetadata(key, value)` for route metadata
  - `Default(handler)` for fallback handling
- Added `ContentRouterOptions` with `ThrowOnNoMatch`, `AllowMultipleMatches`, `EvaluateInParallel`
- Integrated with DI via `MessagingConfiguration.UseContentRouter = true`
