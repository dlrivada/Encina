ISSUE #113: [FEATURE] Automatic health checks per infrastructure provider
closed_at: 12/26/2025 09:57:14
labels: enhancement, area-health-checks

BODY:
## Summary

When the user configures an Encina infrastructure provider, a connectivity health check for that provider should be automatically registered.

## Motivation

Infrastructure providers (databases, message brokers, caching) need automatic health monitoring. By registering health checks at configuration time, users get observability out-of-the-box without manual wiring.

## Proposed Solution

### Expected Behavior

```csharp
// When configuring Dapper with PostgreSQL
services.AddEncinaDapper<PostgreSqlConnection>(config => {
    config.UseOutbox = true;
});

// Automatically registered:
// - OutboxHealthCheck (messaging pattern)
// - PostgreSqlHealthCheck (DB connectivity)
```

### Implementation Details

1. Each provider package (e.g., `Encina.Dapper.PostgreSQL`) must:
   - Reference the corresponding health check package
   - Automatically register the health check when the provider is configured
   - Use appropriate tags (`db`, `messaging`, `cache`)

2. The user can disable automatic registration:
   ```csharp
   config.RegisterHealthChecks = false;
   ```

3. Health checks must be configurable:
   ```csharp
   config.HealthCheckTimeout = TimeSpan.FromSeconds(5);
   config.HealthCheckTags = ["custom-tag"];
   ```

None documented.
