## Summary

Implement a recoverability pipeline with immediate and delayed retry capabilities for message processing.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: High
- **Complexity**: Medium

Message processing failures are inevitable in distributed systems. A structured recoverability pipeline distinguishes between transient errors (worth retrying) and permanent failures (send to DLQ), providing predictable error handling behavior.

## Proposed Solution

### Features

- Immediate retries (in-memory, fast)
- Delayed retries (persistent, scheduled)
- Configurable retry policies
- Error categorization (transient vs permanent)
- Dead letter handling

### Proposed API

```csharp
services.AddEncinaRecoverability(config =>
{
    config.ImmediateRetries = 3;
    config.DelayedRetries = new[]
    {
        TimeSpan.FromSeconds(30),
        TimeSpan.FromMinutes(5),
        TimeSpan.FromMinutes(30)
    };
    config.OnPermanentFailure = msg => /* DLQ handling */;
});
```

The Recoverability Pipeline has been fully implemented with the following components:

### Core Components
- `RecoverabilityOptions` - Configuration (immediate/delayed retries, backoff, jitter)
