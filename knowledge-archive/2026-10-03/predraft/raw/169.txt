BODY:
## Summary

Add **specialized test helpers** for each messaging pattern (Outbox, Inbox, Saga, Scheduling) to Encina.Testing, providing Given/When/Then style testing utilities.

## Motivation

- **Pattern-specific needs**: Each messaging pattern has unique testing requirements
- **Current gap**: AggregateTestBase covers Event Sourcing, but messaging lacks similar utilities
- **Reduced boilerplate**: Pre-built helpers for common testing scenarios
- **Consistency**: Standard approach to testing messaging patterns

## Proposed Solution

### Outbox Test Helper

```csharp
public class OutboxTestHelper : IAsyncDisposable
{
    public async Task<IReadOnlyList<OutboxMessage>> CaptureMessages(Func<Task> action);
    public async Task ProcessPendingMessages();
    public void VerifyMessagePublished<TEvent>(Action<TEvent>? validator = null);
    public void VerifyNoMessagesPublished();
}
```

### Inbox Test Helper

```csharp
public class InboxTestHelper
{
    public async Task<bool> SimulateMessage(Guid messageId, Func<Task> handler);
    public async Task VerifyProcessedOnce(Guid messageId);
    public async Task VerifyDuplicateRejected(Guid messageId);
}
```

### Saga Test Helper

```csharp
public abstract class SagaTestBase<TSaga, TData>
{
    protected void GivenSagaStarted(TData initialData);
    protected void GivenSagaAtStep(string stepName, TData data);
    protected void WhenStepCompletes(string stepName);
    protected void WhenStepFails(string stepName, string error);
    protected void WhenCompensationStarts();
    protected void ThenSagaStatus(SagaStatus expected);
    protected void ThenCurrentStep(string expectedStep);
    protected void ThenSagaData(Action<TData> validator);
    protected void ThenCompensationStarted();
}
```

### Scheduling Test Helper

```csharp
public class SchedulingTestHelper
{
    public async Task<Guid> ScheduleMessage<TRequest>(TRequest request, TimeSpan delay);
    public async Task<IReadOnlyList<ScheduledMessage>> AdvanceTimeAndGetDue(TimeSpan amount);
    public void VerifyCronNextExecution(string cron, DateTime expected);
}
```

## Alternatives Considered

1. **Generic test utilities only**: Providing only base EncinaFixture without pattern-specific helpers. Requires more boilerplate, harder to test messaging patterns correctly.

2. **Separate packages per pattern**: Creating Encina.Testing.Outbox, Encina.Testing.Saga, etc. Too fragmented, most users need all patterns together.

3. **Mocking-only approach**: Providing only mocks without test helpers. Misses integration testing scenarios, harder to verify actual behavior.
