## Summary

Implement modular monolith support with module interfaces and runtime discovery.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Medium
- **Complexity**: Low

Modular monoliths allow teams to develop and maintain independent modules within a single deployable unit. An `IModule` interface with a registry provides a standardized way to define module boundaries, register module-specific services, and manage module lifecycle (startup/shutdown hooks), enabling a clean path toward eventual microservice extraction.

## Proposed Solution

- `IModule` interface for module definition
- `IModuleRegistry` for runtime discovery
- Module lifecycle hooks (`OnStart`/`OnStop`)
- Module-scoped service registration

```csharp
public interface IModule
{
    string Name { get; }
    void ConfigureServices(IServiceCollection services);
}

public interface IModuleLifecycle : IModule
{
    Task OnStartAsync(CancellationToken ct);
    Task OnStopAsync(CancellationToken ct);
}

// Module implementation
public class OrderModule : IModuleLifecycle
{
    public string Name => "Orders";

    public void ConfigureServices(IServiceCollection services)
    {
        services.AddScoped<IOrderRepository, OrderRepository>();
        // Module-specific handlers registered automatically
    }

    public Task OnStartAsync(CancellationToken ct) => Task.CompletedTask;
    public Task OnStopAsync(CancellationToken ct) => Task.CompletedTask;
}

// Registration
services.AddEncinaModules(config =>
{
    config.AddModule<OrderModule>();
    config.AddModule<PaymentModule>();
    config.AddModule<ShippingModule>();
});
```
