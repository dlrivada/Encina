## Summary

Create a testing package with fixtures and fluent assertions for testing Encina-based applications.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Critical
- **Complexity**: Medium

Testing Encina-based applications currently requires significant manual setup. A dedicated testing package with fixtures, in-memory transport, and fluent assertions reduces friction and improves test quality. This is critical for user adoption.

## Proposed Solution

### Features

- `EncinaFixture` for test setup
- Fluent API for test configuration
- In-memory transport for testing
- Handler mocking utilities
- Behavior assertion helpers

### Proposed API

```csharp
// Test fixture
public class OrderTests : IClassFixture<EncinaFixture>
{
    private readonly EncinaFixture _fixture;

    public OrderTests(EncinaFixture fixture)
    {
        _fixture = fixture;
    }

    [Fact]
    public async Task CreateOrder_ShouldSucceed()
    {
        // Arrange
        var encina = _fixture.CreateEncina(config =>
        {
            config.AddHandler<CreateOrderHandler>();
            config.AddValidator<CreateOrderValidator>();
        });

        // Act
        var result = await encina.Send(new CreateOrder(Guid.NewGuid(), items));

        // Assert
        result.ShouldBeSuccess();
        result.ShouldHaveValue<OrderId>(id => id.Value != Guid.Empty);
    }
}
```
