## Description

The integration tests in `Encina.Polly.IntegrationTests` have several pre-existing issues that were discovered during the Bulkhead Isolation implementation (#53).

### Failing Tests

1. `RetryPolicy_EndToEnd_SuccessOnSecondAttempt` - Retry behavior doesn't properly retry on failure (returns Left immediately)
2. `CircuitBreaker_EndToEnd_OpensAfterFailures` - Throws `ResultIsNullException` from Encina core logging
3. `Bulkhead_EndToEnd_RejectsWhenFull` - Throws `ResultIsNullException` from Encina core logging

  - `Encina.Polly.IntegrationTests`

## Current Behavior

- `RetryPolicy_EndToEnd_SuccessOnSecondAttempt` returns Left immediately instead of retrying on failure.
- `CircuitBreaker_EndToEnd_OpensAfterFailures` and `Bulkhead_EndToEnd_RejectsWhenFull` throw `ResultIsNullException` from Encina core logging.

## Expected Behavior

- Retry policy should retry on failure and succeed on the second attempt.
- Circuit breaker and bulkhead tests should complete without `ResultIsNullException`.

## Root Cause

The `ResultIsNullException` appears to originate from `Encina.Encina.LogSendOutcomeCore` in `src/Encina/Core/Encina.cs:line 85`.

This happens when:
1. A pipeline behavior returns an error (Left) before the handler executes
2. The logging mechanism tries to log the outcome but receives a null result

## Proposed Fix

1. Fix the null result handling in `LogSendOutcomeCore` to gracefully handle cases where a pipeline behavior returns Left before the handler executes
2. Review the retry pipeline behavior to ensure it properly retries on failure instead of returning Left immediately
3. Ensure integration test pipeline setup correctly wires Polly behaviors

COMMENT by dlrivada:
Fixed! The issue was in `LogSendOutcomeCore` method in `src/Encina/Core/Encina.cs`.

## Root Cause
LanguageExt's `Match` method doesn't allow null return values, but the code was returning `null` for the `None` case:

```csharp
// Before (broken):
var exception = effectiveError.Exception.Match(
    Some: ex => (Exception?)ex,
    None: () => null);  // ÔØî Match doesn't allow null
```

## Fix
Changed to `MatchUnsafe` which allows null return values:

```csharp
// After (fixed):
var exception = effectiveError.Exception.MatchUnsafe(
    Some: ex => (Exception?)ex,
    None: () => (Exception?)null);  // Ô£à MatchUnsafe allows null
```
