BODY:
## Summary

Add **Verify snapshot testing integration** to `Encina.Testing` for approval-based testing of complex responses, with automatic serialization and data scrubbing.

## Motivation

- **Complex responses**: Snapshot testing ideal for complex Either<EncinaError, T> responses
- **Automatic comparison**: Serialization and diff handling built-in
- **Data scrubbing**: Non-deterministic values (GUIDs, dates) handled automatically
- **Diff tools**: IDE integration for easy review

## Proposed Solution

### EncinaVerifyExtensions

```csharp
public static class EncinaVerifyExtensions
{
    public static SettingsTask VerifyEither<T>(this Either<EncinaError, T> result);

    public static SettingsTask VerifyValidation(this ValidationResult result);

    public static SettingsTask VerifyOutboxMessage(this OutboxMessage message);

    public static SettingsTask VerifyEncinaErrors(this IEnumerable<EncinaError> errors);
}
```

### EncinaVerifySettings

```csharp
public static class EncinaVerifySettings
{
    [ModuleInitializer]
    public static void Initialize()
    {
        VerifierSettings.ScrubInlineGuids();
        VerifierSettings.AddExtraSettings(settings =>
        {
            settings.Converters.Add(new EitherConverter());
            settings.Converters.Add(new EncinaErrorConverter());
        });
    }
}
```

### Usage Example

```csharp
public class CreateOrderHandlerTests
{
    [Fact]
    public async Task Handle_ValidOrder_ShouldReturnExpectedResponse()
    {
        var result = await _encina.Send(new CreateOrderCommand
        {
            CustomerId = "cust-123",
            Items = new[] { new OrderItem("SKU-001", 2) }
        });

        await result.VerifyEither();
    }

    [Fact]
    public async Task Handle_InvalidOrder_ShouldReturnValidationErrors()
    {
        var result = await _encina.Send(new CreateOrderCommand { });

        var error = result.ShouldBeValidationError();
        await error.VerifyEncinaErrors();
    }
}
```

## Alternatives Considered

1. **Manual assertion for complex objects**: Writing assertions for each property. Tedious, error-prone, hard to maintain for complex responses.

2. **JSON comparison without Verify**: Custom JSON serialization and comparison. Reinvents Verify functionality, misses scrubbing features.

3. **Approval Tests library**: Using ApprovalTests instead of Verify. Verify has better .NET integration and is more actively maintained.
