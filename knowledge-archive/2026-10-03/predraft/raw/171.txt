## Summary

Add **TUnit framework support** to Encina.Testing for modern, source-generated testing with NativeAOT compatibility and significantly faster test execution.

## Motivation

- **Source-generated tests**: No reflection for test discovery
- **Performance**: 10-200x faster test execution than traditional frameworks
- **NativeAOT support**: Critical for Encina Source Generators and trimming
- **Modern .NET**: Built on Microsoft.Testing.Platform
- **Parallel execution**: Default parallelization for faster CI/CD

## Proposed Solution

### New Package: Encina.Testing.TUnit

```csharp
// TUnit-compatible fixture
public class EncinaTUnitFixture : IAsyncInitializer, IAsyncDisposable
{
    private ServiceProvider? _serviceProvider;

    public async Task InitializeAsync()
    {
        var services = new ServiceCollection();
        ConfigureServices(services);
        _serviceProvider = services.BuildServiceProvider();
    }

    protected virtual void ConfigureServices(IServiceCollection services)
    {
        services.AddEncina(config =>
        {
            config.RegisterServicesFromAssemblyContaining<EncinaTUnitFixture>();
        });
    }

    public IEncina CreateEncina() => _serviceProvider!.GetRequiredService<IEncina>();

    public async ValueTask DisposeAsync()
    {
        if (_serviceProvider != null)
            await _serviceProvider.DisposeAsync();
    }
}

// Attribute for Encina tests (works with TUnit source generator)
[AttributeUsage(AttributeTargets.Class)]
public class EncinaTestAttribute : Attribute { }

// Either assertions for TUnit
public static class TUnitEitherAssertions
{
    public static async Task ShouldBeSuccess<TLeft, TRight>(
        this Either<TLeft, TRight> either)
    {
        await Assert.That(either.IsRight).IsTrue();
    }

    public static async Task ShouldBeError<TLeft, TRight>(
        this Either<TLeft, TRight> either)
    {
        await Assert.That(either.IsLeft).IsTrue();
    }

    public static async Task<TRight> AndReturn<TLeft, TRight>(
        this Either<TLeft, TRight> either)
    {
        await either.ShouldBeSuccess();
        return either.Match(Left: _ => default!, Right: v => v);
    }
}
```

### Usage Example

```csharp
[EncinaTest]
public class OrderHandlerTests
{
    private readonly EncinaTUnitFixture _fixture = new();

    [Before(Test)]
    public async Task Setup() => await _fixture.InitializeAsync();

    [After(Test)]
    public async Task Cleanup() => await _fixture.DisposeAsync();

    [Test]
    public async Task CreateOrder_ShouldSucceed()
    {
        var encina = _fixture.CreateEncina();
        var result = await encina.Send(new CreateOrderCommand { CustomerId = "123" });

        await result.ShouldBeSuccess();
        var order = await result.AndReturn();
        await Assert.That(order.Id).IsNotEqualTo(Guid.Empty);
    }
}
```

## Alternatives Considered

1. **xUnit only**: Continue with xUnit exclusively. Misses NativeAOT compatibility and performance benefits of source-generated tests.

2. **NUnit adapter**: Adding NUnit support instead of TUnit. NUnit still uses reflection, doesn't provide NativeAOT benefits.

3. **Custom test framework**: Building our own source-generated framework. Massive effort, TUnit already solves this well.
