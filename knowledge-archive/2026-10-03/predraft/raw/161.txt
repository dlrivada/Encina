## Summary

Add **test data generation utilities** to `Encina.Testing` using Bogus and AutoBogus libraries for realistic, reproducible test data generation.

## Motivation

- **Realistic data**: Names, emails, addresses instead of "test1", "test2"
- **Reproducibility**: Seed-based generation for deterministic tests
- **Automatic population**: AutoBogus fills properties automatically
- **Reduced boilerplate**: Less manual test data setup code

## Proposed Solution

### New Package: `Encina.Testing.DataGeneration`

```csharp
// Base faker with Encina-specific conventions
public class EncinaFaker<T> : AutoFaker<T>
{
    public EncinaFaker()
    {
        // Auto-configure common Encina types
        RuleFor(x => x.CorrelationId, f => f.Random.Guid());
        RuleFor(x => x.CreatedAtUtc, f => f.Date.Recent().ToUniversalTime());
    }
}

// Pre-built fakers for messaging entities
public class OutboxMessageFaker : EncinaFaker<OutboxMessage> { }
public class InboxMessageFaker : EncinaFaker<InboxMessage> { }
public class SagaStateFaker : EncinaFaker<SagaState> { }
public class ScheduledMessageFaker : EncinaFaker<ScheduledMessage> { }

// Request/Command/Query fakers with fluent customization
public class RequestFaker<TRequest> : EncinaFaker<TRequest>
    where TRequest : IRequest<TResponse> { }
```

### Usage Example

```csharp
var faker = new OutboxMessageFaker()
    .UseSeed(12345) // Reproducible
    .RuleFor(x => x.RequestType, "OrderCreated");

var messages = faker.Generate(100);
```

## Alternatives Considered

1. **AutoFixture only**: Using AutoFixture without Bogus. Less realistic data, harder to customize specific fields.

2. **Manual builders only**: Continuing with manual test data builders. More boilerplate, less realistic data.

3. **Static test data**: Using hardcoded test data files. Inflexible, hard to generate variations.
