## Summary

Implement enhanced Dead Letter Queue handling across all messaging providers with unified abstractions, replay, and monitoring.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Medium
- **Complexity**: Medium

Failed messages need a consistent, inspectable destination across all transport providers. Enhanced DLQ handling allows operations teams to inspect failed messages, replay them after fixes, and monitor DLQ health for alerting.

## Proposed Solution

### Features

- Unified DLQ abstraction
- Message inspection and replay
- DLQ monitoring
- Automatic poison message detection
- Manual and automatic replay

### Proposed API

```csharp
services.AddEncinaDeadLetterQueue(config =>
{
    config.MaxRetries = 5;
    config.RetentionPeriod = TimeSpan.FromDays(7);
    config.EnableAutoReplay = false;
    config.OnDeadLetter = async msg =>
    {
        // Custom handling, alerting, etc.
    };
});

// Manual replay
var dlqManager = serviceProvider.GetRequiredService<IDeadLetterManager>();
await dlqManager.ReplayAsync(messageId);
await dlqManager.ReplayAllAsync(filter: m => m.CreatedAt > DateTime.UtcNow.AddHours(-1));
```
