## Description

**Increase branch coverage to >=80%** to ensure all conditional paths are tested.

- **Complete testing**: Branch coverage ensures all decision paths are exercised
- **Edge case coverage**: Untested branches often contain bugs
- **Error handling verification**: Error paths need testing too
- **Quality confidence**: Higher branch coverage means fewer surprises

### Focus Areas

1. **Conditional logic in pipeline behaviors** - Pre-processor conditions, post-processor error handling, behavior chain logic
2. **Error handling branches** - Exception catch blocks, error result paths, fallback logic
3. **Configuration validation** - Required option checks, invalid configuration handling
4. **Guard clauses** - Null checks, range validation, state validation

### Example Uncovered Branch

```csharp
public async Task<Either<Error, T>> HandleAsync(ICommand<T> command)
{
    if (command == null)  // <- Branch 1: Need test with null
        return new ValidationError("Command required");

    var result = await _handler.HandleAsync(command);

    if (result.IsLeft)    // <- Branch 2: Need test that produces error
        return result;

    return result;        // <- Branch 3: Success path (likely covered)
}
```

COMMENT by dlrivada:
Closing: this target comes from the old single-percentage coverage model. Encina now measures coverage per flag (unit, guard, contract, property, integration) against the per-package targets in .github/coverage-manifest/, computed by .github/scripts/coverage-report.cs and shown on the coverage dashboard. Mutation score is tracked per file with no project-wide target (docs/testing/mutation-measurement-methodology.md). Gaps against those targets are tracked as [TEST] issues per package.
