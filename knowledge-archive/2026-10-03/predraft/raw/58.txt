## Summary

Implement module-scoped pipeline behaviors that only apply to handlers within a specific module.

## Motivation

- **Phase**: 2 - Functionality
- **Priority**: Low
- **Complexity**: Medium

In a modular monolith, different modules have different cross-cutting concerns. For example, an Orders module may need audit logging while a Notifications module does not. Module-scoped behaviors allow each module to define its own pipeline behaviors without affecting handlers in other modules, and optionally override global behaviors.

## Proposed Solution

- Behaviors scoped to a specific module
- Module-specific validation, logging, and telemetry
- Ability to override global behaviors at the module level

```csharp
public class OrderModule : IModule
{
    public string Name => "Orders";

    public void ConfigureServices(IServiceCollection services)
    {
        // Module-specific behavior
        services.AddEncinaModuleBehavior<OrderModule, OrderAuditBehavior>();
    }
}

// Behavior only runs for handlers in OrderModule
public class OrderAuditBehavior<TRequest, TResponse>
    : IModulePipelineBehavior<OrderModule, TRequest, TResponse>
{
    public async ValueTask<Either<EncinaError, TResponse>> Handle(...)
    {
        _auditLog.Log($"Order operation: {typeof(TRequest).Name}");
        return await next();
    }
}
```

COMMENT by dlrivada:
Implemented module-scoped pipeline behaviors. See CHANGELOG.md for full details.

### Summary
- **IModulePipelineBehavior<TModule, TRequest, TResponse>** - Interface for module-specific behaviors
- **ModuleBehaviorAdapter** - Wraps module behaviors and filters execution by module ownership
- **IModuleHandlerRegistry** - Maps handler types to their owning modules via assembly association
- Request context extensions: GetModuleName(), WithModuleName(), IsInModule()
- DI extensions: AddEncinaModuleBehavior<>() with optional ServiceLifetime

### Usage
```csharp
// Define a module-specific behavior
public class OrderAuditBehavior : IModulePipelineBehavior<OrderModule, CreateOrderRequest, string>
{
    public async ValueTask<Either<EncinaError, string>> Handle(
        CreateOrderRequest request,
        IRequestContext context,
        RequestHandlerCallback<string> nextStep,
        CancellationToken cancellationToken)
    {
        // This only executes for handlers in OrderModule
        Log("Order operation started");
        var result = await nextStep();
        Log("Order operation completed");
        return result;
    }
}

// Register
services.AddEncinaModules(config => config.AddModule(new OrderModule()));
services.AddEncinaModuleBehavior<OrderModule, CreateOrderRequest, string, OrderAuditBehavior>();
```
