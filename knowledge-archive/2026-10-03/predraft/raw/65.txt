## Description

**Increase line coverage to >=85%** across all packages to ensure comprehensive test coverage.

- **Bug prevention**: Untested code often contains bugs
- **Refactoring safety**: High coverage enables confident refactoring
- **Documentation**: Tests document expected behavior
- **Quality gate**: Coverage thresholds prevent quality regression

### Common Uncovered Areas

| Area | Typical Reason | Solution |
|------|---------------|----------|
| Error paths | Focus on happy path | Add error case tests |
| Edge cases | Miss boundary conditions | Add boundary tests |
| Constructors | Tested indirectly | Add explicit tests |
| Configuration | Complex setup | Use test builders |

COMMENT by dlrivada:
Closing: this target comes from the old single-percentage coverage model. Encina now measures coverage per flag (unit, guard, contract, property, integration) against the per-package targets in .github/coverage-manifest/, computed by .github/scripts/coverage-report.cs and shown on the coverage dashboard. Mutation score is tracked per file with no project-wide target (docs/testing/mutation-measurement-methodology.md). Gaps against those targets are tracked as [TEST] issues per package.
