## Summary

Add **ArchUnitNET integration** to `Encina.Testing` with pre-defined architectural rules for Encina applications, enabling automated architecture compliance verification.

## Motivation

- **Automated verification**: Enforce architecture rules in CI/CD
- **CQRS/Clean Architecture**: Pre-built rules for common patterns
- **Dependency violations**: Detect layer violations automatically
- **Continuous compliance**: Architecture rules as code

## Proposed Solution

### New Package: `Encina.Testing.Architecture`

```csharp
public static class EncinaArchitectureRules
{
    // CQRS Rules
    public static IArchRule CommandsMustNotReturnVoid();
    public static IArchRule QueriesMustNotModifyState();
    public static IArchRule HandlersMustNotDependOnControllers();

    // Layered Architecture Rules
    public static IArchRule DomainMustNotDependOnInfrastructure();

    // Messaging Rules
    public static IArchRule SagasMustInheritFromSagaBase();
    public static IArchRule NotificationsMustBeImmutable();

    // Pipeline Rules
    public static IArchRule BehaviorsMustImplementCorrectInterface();
}
```

### EncinaArchitectureTestBase

```csharp
public abstract class EncinaArchitectureTestBase
{
    protected abstract Assembly ApplicationAssembly { get; }

    protected Architecture Architecture =>
        new ArchLoader()
            .LoadAssemblies(ApplicationAssembly)
            .Build();

    [Fact]
    public void Application_ShouldFollowEncinaRules()
    {
        Architecture.CheckEncinaRules();
    }
}
```

### Usage Example

```csharp
public class MyAppArchitectureTests : EncinaArchitectureTestBase
{
    protected override Assembly ApplicationAssembly =>
        typeof(CreateOrderHandler).Assembly;

    [Fact]
    public void Handlers_ShouldNotDependOnControllers()
    {
        EncinaArchitectureRules.HandlersMustNotDependOnControllers()
            .Check(Architecture);
    }

    [Fact]
    public void Domain_ShouldNotDependOnInfrastructure()
    {
        EncinaArchitectureRules.DomainMustNotDependOnInfrastructure()
            .Check(Architecture);
    }
}
```

## Alternatives Considered

1. **NetArchTest only**: Using NetArchTest instead of ArchUnitNET. ArchUnitNET has better rule composition and more active maintenance.

2. **Manual code review for architecture**: Reviewing architecture manually. Not scalable, error-prone, misses violations.

3. **Custom reflection-based checks**: Building custom architecture checks. Reinvents existing solutions, more maintenance burden.
