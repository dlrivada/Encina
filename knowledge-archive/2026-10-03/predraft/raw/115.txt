## Summary

Create detailed documentation on how to combine Encina health checks with the existing `AspNetCore.HealthChecks.*` packages.

## Motivation

Users need guidance on how Encina's pattern-level health checks (outbox, inbox, saga) complement infrastructure-level health checks from the `AspNetCore.HealthChecks.*` ecosystem. Without clear documentation, users may duplicate health check coverage or miss important monitoring gaps.

## Proposed Solution

### 1. Integration Guide

- Explain the difference between pattern health checks (Encina) vs infrastructure health checks (`AspNetCore.HealthChecks.*`)
- Examples of combined configuration
- Best practices for tags and organization

### 2. Examples by Scenario

#### Typical Microservice
```csharp
builder.Services.AddHealthChecks()
    // Encina: messaging patterns
    .AddEncinaHealthChecks(sp)

    // Infrastructure: database
    .AddNpgSql(connectionString, tags: ["db", "critical"])

    // Infrastructure: cache
    .AddRedis(redisConnection, tags: ["cache"])

    // Infrastructure: message broker
    .AddRabbitMQ(rabbitUri, tags: ["messaging"]);
```

#### Modular Monolith
```csharp
builder.Services.AddHealthChecks()
    .AddEncinaHealthChecks(sp)
    .AddEncinaModuleHealthChecks(sp);  // Per module
```
