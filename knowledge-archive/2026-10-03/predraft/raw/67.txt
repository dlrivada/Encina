## Description

**Increase mutation score to >=95%** using Stryker mutation testing to ensure test effectiveness.

- **Test quality**: Mutation score measures test effectiveness, not just coverage
- **Bug detection**: Higher mutation score means tests catch more real bugs
- **Assertion strength**: Identifies tests with weak assertions
- **Confidence**: High mutation score provides confidence in test suite

### What Mutation Testing Does

1. **Creates mutants**: Small code changes (e.g., `>` to `>=`, `true` to `false`)
2. **Runs tests**: Execute tests against each mutant
3. **Kills mutants**: Good tests fail when code is mutated
4. **Scores**: Killed mutants / Total mutants = Score

### Common Surviving Mutants

| Mutation | Solution |
|----------|----------|
| Boundary changes (`>` to `>=`) | Add boundary tests |
| Boolean inversions | Assert both true and false paths |
| Null returns | Assert non-null explicitly |
| Arithmetic changes (`+` to `-`) | Verify calculations |

### Example Fix

```csharp
// Original
public bool IsOverLimit(int count) => count > 100;

// Test that kills boundary mutant (> to >=)
[Theory]
[InlineData(99, false)]
[InlineData(100, false)]  // This kills the >= mutant
[InlineData(101, true)]
public void IsOverLimit_BoundaryValues(int count, bool expected)
{
    Assert.Equal(expected, IsOverLimit(count));
}
```

COMMENT by dlrivada:
Closing: this target comes from the old single-percentage coverage model. Encina now measures coverage per flag (unit, guard, contract, property, integration) against the per-package targets in .github/coverage-manifest/, computed by .github/scripts/coverage-report.cs and shown on the coverage dashboard. Mutation score is tracked per file with no project-wide target (docs/testing/mutation-measurement-methodology.md). Gaps against those targets are tracked as [TEST] issues per package.
