## Decisions
- Adopted a hybrid Jekyll + DocFX architecture where Jekyll handles narrative documentation and DocFX generates the API reference from XML comments. (source: comment by dlrivada)
- Restored `docs/docfx.json` scoped specifically to API metadata and HTML generation, excluding narrative content. (source: comment by dlrivada)
- Configured DocFX to output to `docs/api/` and excluded this directory from Jekyll processing in `docs/_config.yml` to prevent conflicts. (source: comment by dlrivada)
- Implemented a CI pipeline in `.github/workflows/docs.yml` that builds the solution, generates DocFX metadata and HTML, and merges the output into the Jekyll `_site/api/` directory before deployment. (source: comment by dlrivada)
- Added security hardening to restrict Pages deployment to the `main` branch and limit OIDC permissions to the specific deploy job. (source: comment by dlrivada)
- Created a human-written landing page at `docs/_api-landing/index.md` to serve as the entry point for the API reference. (source: comment by dlrivada)

## Rejected alternatives
- Manual API documentation writing was rejected as time-consuming and prone to becoming outdated. (source: issue body)
- Relying solely on Swagger/OpenAPI was rejected as it only covers HTTP endpoints, not the broader library API. (source: issue body)
- Using Jekyll alone was rejected as insufficient for documenting 112 packages and hundreds of public types. (source: comment by dlrivada)
- Using DocFX alone was rejected as it would sacrifice the existing `just-the-docs` narrative user experience. (source: comment by dlrivada)
- Global search integration (e.g., Algolia) was rejected as out of scope due to complexity. (source: comment by dlrivada)

## Rules and lessons
- Documentation tools with overlapping concerns must have disjoint scopes and explicit exclusion configurations to prevent conflicts. (source: comment by dlrivada)
- CI/CD pipelines for documentation must handle the merging of multiple generation tools' outputs into a single deployable artifact. (source: comment by dlrivada)
- Deploy jobs for public sites must be restricted to the main branch to prevent feature branches from overwriting production content. (source: comment by dlrivada)
- Intermediate build artifacts (like DocFX intermediates) should be ignored by version control. (source: comment by dlrivada)

## Candidate destinations
