## Decisions
- Decided to create a 5-minute quickstart guide with specific file location `docs/quickstart.md` to ensure fast onboarding and immediate value for users (source: issue body).
- Decided to use a specific 5-step flow: Install package, Configure services, Create a command (record), Create a handler, Send and handle result with `Either` pattern (source: issue body).
- Decided that all 12 transversal functions are N/A because the feature is documentation only with no runtime code (source: issue body Cross-Cutting Integration table).
- Decided to include an introduction and philosophy page (PR #1175) and link it to the quickstart (source: linked PRs/commits).
- Decided to establish distinct top-level navigation order and a verified next step in the tutorials docs (source: commit d282c82b/94da5d6e).
- Decided to add `encina-docs` skill and `docs-writer`/`docs-reviewer` agents for documentation processes (source: PR #1179).
- Decided to allow read-only git clone in the worker publish hook (source: PR #1178).

## Rejected alternatives
- Comprehensive getting started: rejected because it would take too long and lose users (source: issue body).
- Video quickstart: rejected because it is less accessible and code cannot be copy-pasted (source: issue body).
- Interactive tutorial (.NET Interactive notebook): rejected because it requires additional setup (source: issue body).

## Rules and lessons
- Documentation features must be evaluated against all 12 transversal functions, even if marked N/A (source: issue body Cross-Cutting Integration Rule).
- Quickstart guides must be tested from scratch to ensure all code samples work when copy-pasted (source: issue body Tasks).
- Documentation should have a distinct top-level navigation order to avoid confusion (source: commit d282c82b/94da5d6e).
- Documentation work can require infra changes (like git clone permissions) and agent/skill definitions (source: PR #1178, PR #1179).
