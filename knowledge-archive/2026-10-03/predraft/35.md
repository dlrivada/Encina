## Decisions
- Define `IEncinaHealthCheck` interface and associated abstractions in `Encina.Messaging/Health/` to support microservices readiness (Source: issue body, comment by dlrivada).
- Implement specific health checks for Outbox, Inbox, Saga, and Scheduling (Source: comment by dlrivada).
- Integrate with ASP.NET Core `IHealthCheck` via `EncinaHealthCheckAdapter`, `CompositeEncinaHealthCheck`, and `HealthCheckBuilderExtensions` in `Encina.AspNetCore/Health/` (Source: comment by dlrivada).
- Scope initial delivery to messaging/saga health checks rather than all infrastructure providers listed in the issue, deferring infrastructure provider health checks to follow-up issues #113, #114, and #115 (Source: comment by dlrivada).

## Rejected alternatives
- none

## Rules and lessons
- Health check implementations should be separated into `Encina.Messaging` for domain logic and `Encina.AspNetCore` for framework integration (Source: comment by dlrivada file paths).
- Infrastructure-specific health checks (database, transport, cache) are tracked as separate issues to manage complexity (Source: comment by dlrivada referencing #113, #114, #115).

## Candidate destinations
- docs: Documentation for integration with AspNetCore.HealthChecks.* is needed (Source: issue body "Add documentation" and comment by dlrivada referencing #115).
- regression-test: 52 unit tests were added for health check logic (Source: comment by dlrivada).
