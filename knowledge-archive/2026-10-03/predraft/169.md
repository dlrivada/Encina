## Decisions
- To implement specialized test helpers for Outbox, Inbox, Saga, and Scheduling patterns within the `Encina.Testing` package to reduce boilerplate and ensure consistency (source: issue body).
- To structure the Saga tests using an abstract base class `SagaTestBase<TSaga, TData>` with Given/When/Then methods (source: issue body).
- To implement the feature as part of the v0.11.0 Testing Infrastructure milestone (source: comment by dlrivada).
- To close the issue upon the commit `9d887cbb` titled "feat(testing): add Messaging Pattern Test Helpers" (source: input commit).

## Rejected alternatives
- Generic test utilities only (providing only base `EncinaFixture`), rejected due to increased boilerplate and difficulty in testing messaging patterns correctly (source: issue body).
- Separate packages per pattern (e.g., `Encina.Testing.Outbox`), rejected due to fragmentation and the fact that most users need all patterns together (source: issue body).
- Mocking-only approach, rejected because it misses integration testing scenarios and makes verifying actual behavior harder (source: issue body).

## Rules and lessons
- Specific messaging patterns require specialized test helpers rather than generic fixtures to handle unique testing requirements effectively (source: issue body).
- Test helpers should follow a Given/When/Then style for consistency across different patterns (source: issue body).
