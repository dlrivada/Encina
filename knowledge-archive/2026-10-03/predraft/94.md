## Decisions
- Create a SECURITY.md file with content including supported versions, reporting instructions (emphasizing private channels), response timeline, and disclosure policy (issue body).

## Rejected alternatives
- **No security policy**: Rejected as unprofessional and potentially discouraging responsible disclosure (issue body).
- **Public issue reporting only**: Rejected as it exposes vulnerabilities before a fix is in place (issue body).
- **Bug bounty program**: Rejected as overkill for a pre-1.0 open source project (issue body).

## Rules and lessons
- **Cross-Cutting Integration Rule**: Per CLAUDE.md, every new feature must be evaluated against all 12 transversal functions. For documentation files with no runtime impact, these are marked as N/A (issue body).
- **Security Reporting Channel**: Security vulnerabilities must not be reported via public GitHub issues; a secure channel (email or GitHub Security Advisories) is required (issue body).
