## Decisions
- Implement Verify snapshot testing integration in `Encina.Testing` (Source: Issue body).
- Provide static helpers for verification of Either results, ValidationResults, Outbox messages, and EncinaErrors (Source: Issue body, Comment by dlrivada).
- Include specific helper methods: `PrepareEither`, `ExtractSuccess`, `ExtractError`, `PrepareUncommittedEvents`, `PrepareOutboxMessages`, `PrepareInboxMessages`, `PrepareSagaState`, `PrepareScheduledMessages`, `PrepareDeadLetterMessages` (Source: Comment by dlrivada).
- Implement `EncinaVerifySettings.Initialize()` with automatic scrubbing for timestamps, GUIDs, and stack traces (Source: Issue body, Comment by dlrivada).
- Create custom `EncinaErrorConverter` for clean snapshots (Source: Issue body, Comment by dlrivada).
- Place tests in `tests/Encina.Testing.Verify.Tests/` (Source: Comment by dlrivada).

## Rejected alternatives
- Manual assertion for complex objects: Rejected as tedious, error-prone, and hard to maintain (Source: Issue body).
- JSON comparison without Verify: Rejected as it reinvents Verify functionality and misses scrubbing features (Source: Issue body).
- ApprovalTests library: Rejected in favor of Verify due to better .NET integration and active maintenance (Source: Issue body).

## Rules and lessons
- Use `[ModuleInitializer]` or `Initialize()` methods to configure Verify settings (scrubbing, converters) globally for the testing package (Source: Issue body).
- Snapshot testing is preferred over manual assertions for complex response types like `Either<EncinaError, T>` to ensure automatic diff handling and data scrubbing (Source: Issue body).

## Candidate destinations
- docs: Document the usage of `EncinaVerify` helpers and the automatic scrubbing behavior for developers writing tests.
- regression-test: Ensure the custom converters and scrubbing settings work correctly across different Verify versions.
