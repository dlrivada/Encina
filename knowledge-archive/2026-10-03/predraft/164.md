## Decisions
- Create a new package `Encina.Testing.WireMock` to provide WireMock.NET integration for `Encina.Testing` (Source: Issue body, Proposed Solution)
- Implement `EncinaWireMockFixture` as an `IAsyncLifetime` class with helpers for setup and verification (Source: Issue body, Proposed Solution)
- Implement `EncinaRefitMockFixture<TClient>` for specific Refit client testing, extending the base fixture (Source: Issue body, Proposed Solution)
- Include fault simulation capabilities such as delay and timeout (Source: Issue body, Motivation and Additional Context)
- Include request verification methods to confirm API calls were made (Source: Issue body, Proposed Solution and Acceptance Criteria)
- Implement additional Refit-specific stubs (`StubGet`, `StubPost`, etc.) and error/delay simulation in `EncinaRefitMockFixture<TApiClient>` (Source: Comment by dlrivada, "Extended Implementation Complete")
- Implement `WebhookTestingExtensions` for Outbox pattern webhook testing, including setup and verification methods (Source: Comment by dlrivada, "Extended Implementation Complete")
- Achieve test coverage with 147 tests including unit, fault simulation, sequence, and guard clause tests (Source: Comment by dlrivada, "Test Coverage")

## Rejected alternatives
- **HttpMessageHandler mocking**: Rejected because it is less flexible and harder to simulate complex scenarios (Source: Issue body, Alternatives Considered)
- **Real test servers**: Rejected because it requires more infrastructure, is slower, and makes fault simulation harder (Source: Issue body, Alternatives Considered)
- **MockHttp library**: Rejected because it is less powerful and does not support advanced matching or fault simulation (Source: Issue body, Alternatives Considered)

## Rules and lessons
- For testing external HTTP APIs in Encina, use WireMock.NET integration via the new `Encina.Testing.WireMock` package rather than manual `HttpMessageHandler` mocking or real servers (Source: Issue body, Alternatives Considered)
- The `Encina.Testing.WireMock` package is designated as the foundational package for the v0.11.0 Testing Infrastructure milestone (Source: Comment by dlrivada, first comment)

## Candidate destinations
