## Decisions
- Implement a CLI tool for scaffolding Encina projects and components using System.CommandLine 2.0.1 and Spectre.Console (Source: comment by dlrivada).
- Implement commands `encina new`, `encina generate`, and `encina add` covering project templates (api, worker, console), code generation (handler, query, saga, notification), and package addition (caching, database, transport, validation, resilience, observability) (Source: comment by dlrivada).
- Create `Encina.Cli` as a new dotnet tool package (Source: issue body).
- Include 65 tests comprising 21 unit tests and 44 guard tests (Source: comment by dlrivada).
- Update CHANGELOG.md, ROADMAP.md, and docs/history/2025-12.md (Source: comment by dlrivada).
- Use commit b02647b3 to close the issue (Source: input commit reference).

## Rules and lessons
- New feature packages require both unit and guard test suites (Source: comment by dlrivada mentioning 21 unit + 44 guard tests).
- CLI tools should document changes in CHANGELOG.md, ROADMAP.md, and historical docs (Source: comment by dlrivada).
- CLI scaffolding tools are considered higher complexity but lower priority than testing libraries (Source: issue body).
