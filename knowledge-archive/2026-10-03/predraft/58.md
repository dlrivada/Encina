## Decisions
- Implemented `IModulePipelineBehavior<TModule, TRequest, TResponse>` interface for module-specific behaviors (source: comment by dlrivada).
- Created `ModuleBehaviorAdapter` to wrap module behaviors and filter execution by module ownership (source: comment by dlrivada).
- Created `IModuleHandlerRegistry` to map handler types to their owning modules via assembly association (source: comment by dlrivada).
- Added request context extensions: `GetModuleName()`, `WithModuleName()`, `IsInModule()` (source: comment by dlrivada).
- Added DI extension `AddEncinaModuleBehavior<>()` with optional `ServiceLifetime` (source: comment by dlrivada).
- Module registration via `services.AddEncinaModules(config => config.AddModule(new OrderModule()))` (source: comment by dlrivada).
- Achieved 100 passing module-related unit tests (source: comment by dlrivada).

## Rejected alternatives
- none

## Rules and lessons
- Module behaviors must only run for handlers within the specific module; filtering is handled by `ModuleBehaviorAdapter` (source: issue body / comment by dlrivada).
- No performance impact on non-module handlers is an acceptance criterion (source: issue body).
- `IModule` interface dependency (#57) is a prerequisite for this feature (source: issue body).
