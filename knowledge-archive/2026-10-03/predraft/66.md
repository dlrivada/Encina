## Decisions
- The issue was closed because the target (single 80% branch coverage) was obsolete; Encina now uses a per-flag coverage model (unit, guard, contract, property, integration) with per-package targets defined in `.github/coverage-manifest/`. (source: comment by dlrivada)
- Coverage is computed by `.github/scripts/coverage-report.cs` and displayed on the coverage dashboard. (source: comment by dlrivada)
- Mutation score is tracked per file with no project-wide target, documented in `docs/testing/mutation-measurement-methodology.md`. (source: comment by dlrivada)
- Gaps against current targets are tracked as separate [TEST] issues per package. (source: comment by dlrivada)
- Hand-typed quality and inventory figures were removed from README, ROADMAP, and architecture pages. (source: linked PR #1300)

## Rejected alternatives
- The old single-percentage branch coverage model was rejected in favor of the per-flag, per-package coverage model. (source: comment by dlrivada)

## Rules and lessons
- Coverage targets must be defined per flag and per package, not as a single global percentage. (source: comment by dlrivada)
- Hand-typed quality metrics in documentation should be removed to prevent drift; use automated tooling (`.github/scripts/coverage-report.cs`) instead. (source: linked PR #1300)
- Coverage gaps should be tracked as granular per-package issues rather than one monolithic issue. (source: comment by dlrivada)
