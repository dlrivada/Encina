## Decisions
- To create three specific reusable GitHub Actions workflow templates: `encina-test.yml` (basic tests, coverage, cross-platform), `encina-matrix.yml` (multi-OS, multi-DB, parallel), and `encina-full-ci.yml` (build, pack, unit, integration, architecture, optional mutation tests). (Source: issue body)
- To target .NET 10 for the workflow templates. (Source: issue body, example YAML snippet)
- To use GitHub Actions service containers (specifically SQL Server 2022) for database dependencies in the basic test workflow. (Source: issue body)
- To classify this work under "Other: Documentation / CI templates" rather than a specific code package. (Source: issue body, Affected Packages section)
- To implement the feature via the commit `1bf19f96` with the message "feat(ci): add reusable CI/CD workflow templates". (Source: input commit data)

## Rejected alternatives
- **Azure DevOps pipelines only**: Rejected because GitHub Actions has broader adoption and most Encina users are on GitHub. (Source: issue body, Alternatives Considered)
- **No templates**: Rejected due to inconsistent practices, repeated effort, and potential for errors among users. (Source: issue body, Alternatives Considered)
- **Docker Compose for all services**: Rejected because it was deemed more complex to set up and harder to configure in GitHub Actions compared to service containers. (Source: issue body, Alternatives Considered)

## Rules and lessons
- GitHub Actions is the preferred CI/CD platform for Encina due to user adoption. (Source: issue body, Alternatives Considered)
- Service containers in GitHub Actions are preferred over Docker Compose for simpler configuration in the context of Encina's CI templates. (Source: issue body, Alternatives Considered)
- The v0.11.0 Testing Infrastructure milestone begins with foundational CI/CD workflow templates. (Source: comment by dlrivada)
