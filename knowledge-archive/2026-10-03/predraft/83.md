## Decisions
- The documentation structure was defined to include `overview.md`, `entityframeworkcore.md`, `dapper.md`, `ado.md`, and `mongodb.md` under `docs/database/` (Source: issue body).
- All 12 transversal functions (Caching, OpenTelemetry, Structured Logging, Health Checks, Validation, Resilience, Distributed Locks, Transactions, Idempotency, Multi-Tenancy, Module Isolation, Audit Trail) were marked as N/A because the task involves documentation only and no runtime code changes (Source: issue body).
- The implementation was delivered via PR #1264, which explains 10 database providers and adds a reference matrix (Source: linked PR #1264, commit fb073c68, commit 82ade4c6, commit 426dc596, commit b84e76f3).
- The closure of the issue was recorded in `PROJECT-HISTORY` via PR #1305, which folds issues closed since 2026-09-22 (Source: linked PR #1305).

## Rejected alternatives
- **Per-package README only**: Rejected because documentation would be scattered across packages, making comparison difficult (Source: issue body).
- **Single massive document**: Rejected because placing all 13 providers in one file would be too long and overwhelming (Source: issue body).
- **Video tutorials only**: Rejected because they are not searchable and harder to reference for specific configurations (Source: issue body).

## Rules and lessons
- Documentation tasks must still undergo the Cross-Cutting Integration Rule evaluation, even if all transversal functions are marked N/A (Source: issue body).
- Documentation should include SQL dialect differences (parameters, LIMIT, Boolean types) to aid provider selection (Source: issue body).
- Historical records of closed issues should be updated in `PROJECT-HISTORY` (Source: PR #1305).
