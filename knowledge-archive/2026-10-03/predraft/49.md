## Decisions
- Implemented TryGetValue-before-GetOrAdd pattern in RequestDispatcher and NotificationDispatcher to avoid delegate allocation on cache hits. (Source: Comment by dlrivada)
- Added a static cache for GetRequestKind results to avoid repeated IsAssignableFrom calls. (Source: Comment by dlrivada)
- Added new benchmarks (CacheOptimizationBenchmarks.cs) to compare raw cache access and full pipeline cache hit scenarios. (Source: Comment by dlrivada)
- Optimization is positioned as a stepping stone toward future Source Generator work. (Source: Issue Body)

## Rejected alternatives
- Source generators instead of runtime reflection: Rejected for this issue as it is a larger effort; current optimization is a prerequisite. (Source: Issue Body)
- Frozen collections (.NET 8+): Rejected due to the requirement to validate that all registrations are truly immutable. (Source: Issue Body)
- No optimization (status quo): Rejected because it leaves performance on the table for demanding workloads. (Source: Issue Body)

## Rules and lessons
- GetOrAdd always allocates the factory delegate even on cache hits; TryGetValue should be attempted first to avoid allocation on the hot path. (Source: Comment by dlrivada)
- Reflection calls like IsAssignableFrom should be cached statically if the result is deterministic for a type. (Source: Comment by dlrivada)
- Performance optimizations in internal dispatch pipelines require micro-benchmarks for before/after comparison. (Source: Issue Body)
