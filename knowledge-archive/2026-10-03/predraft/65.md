## Decisions
- The goal of a single global line coverage target of >=85% was rejected because it relies on an outdated "single-percentage coverage model" (source: comment by dlrivada).
- The coverage strategy was shifted to measuring coverage per test flag (unit, guard, contract, property, integration) against specific per-package targets located in `.github/coverage-manifest/` (source: comment by dlrivada).
- Coverage computation is handled by `.github/scripts/coverage-report.cs` and displayed on a coverage dashboard (source: comment by dlrivada).
- Mutation score tracking is now managed per file without a project-wide target (source: comment by dlrivada).
- Future coverage gaps are to be tracked as individual `[TEST]` issues per package rather than one global issue (source: comment by dlrivada).
- Documentation cleanup to remove hand-typed quality figures was performed via PR #1300 (source: linked PR #1300).

## Rejected alternatives
- Maintaining a single global line coverage percentage as a quality gate (rejected due to being an old model, source: comment by dlrivada).

## Rules and lessons
- Coverage targets must be defined per package and per test type (flag) in `.github/coverage-manifest/` rather than as a global metric (source: comment by dlrivada).
- Mutation testing should be tracked per file, not as a project-wide aggregate (source: comment by dlrivada).
- Avoid hard-coding quality metrics in documentation; they should be dynamically computed or removed to prevent staleness (source: linked PR #1300 title).

## Candidate destinations
- spec-invariant: The requirement that coverage must be measured per flag and per package as defined in the manifest is a core architectural constraint.
- coverage-manifest: The issue confirms the existence and necessity of the `.github/coverage-manifest/` directory structure for defining targets.
- docs: The removal of hand-typed figures implies a documentation policy against static metrics, which may need to be explicitly stated in contributor docs.
- none: The specific 85% target is obsolete, so it should not be preserved as a current rule.
