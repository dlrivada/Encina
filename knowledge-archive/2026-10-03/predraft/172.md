- The issue scope was defined to include `stryker-config.json`, `scripts/run-stryker.cs`, a GitHub Actions workflow, baseline documentation, helper attributes, and local run documentation. (Source: issue body)

## Rejected alternatives
- Relying solely on line/branch coverage, as it does not verify that test assertions validate behavior. (Source: issue body)
- Manual code review for test quality, as it is time-consuming, subjective, and not scalable. (Source: issue body)
- Using PITest, as it is Java-only and not applicable to .NET projects. (Source: issue body)

## Rules and lessons
- Mutation testing is a complementary check to coverage, ensuring tests actually catch bugs rather than just achieving line coverage. (Source: issue body)
- Standard configuration ignores non-essential mutations (e.g., `String`, `ToString`, `GetHashCode`, `Equals`) to reduce noise. (Source: issue body)
