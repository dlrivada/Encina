## Decisions
- Integrate the **Respawn** library into `Encina.Testing` (specifically the `Encina.Testing.Testcontainers` package) to provide intelligent database cleanup between integration tests (source: issue body).
- Implement an `EncinaRespawner` static factory class with pre-configured options for Encina-specific tables (source: issue body "Proposed Solution").
- Implement a `DatabaseIntegrationTestBase` abstract class implementing `IAsyncLifetime` to manage the Respawn lifecycle (source: issue body "Proposed Solution").
- Exclude system schemas (`sys`, `information_schema`, `pg_catalog`) and specific tables (`__EFMigrationsHistory`, `SchemaVersions`) from reset operations (source: issue body code snippet).
- Provide specific factory methods for `Encina.Messaging` to optionally preserve `OutboxMessages` and `InboxMessages` (source: issue body code snippet).
- The implementation was delivered via commit `35307ee8` titled "feat(testing): add DatabaseIntegrationTestBase for Respawn integration" (source: input commit).

## Rejected alternatives
- **Truncate with FK disable**: Rejected due to slower performance, requirement to re-enable foreign keys, and potential for constraint issues (source: issue body "Alternatives Considered").
- **Database recreate per test**: Rejected due to very slow performance, especially when involving migrations (source: issue body "Alternatives Considered").
- **Transaction rollback**: Rejected because it does not work for all scenarios and can hide bugs (source: issue body "Alternatives Considered").

## Rules and lessons
- Use Respawn for database reset in integration tests as it is significantly faster (cited as 3x) and correctly handles foreign key dependencies compared to truncation (source: issue body "Motivation").
- Preserve migration history tables (`__EFMigrationsHistory`, `SchemaVersions`) during test resets to ensure migration state integrity (source: issue body "Proposed Solution").
- Allow specific business tables (like messaging Outbox/Inbox) to be preserved based on test requirements to maintain isolation where appropriate (source: issue body "Proposed Solution").
