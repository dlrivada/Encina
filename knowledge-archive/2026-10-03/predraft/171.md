## Decisions
- Create a new package `Encina.Testing.TUnit` to support TUnit framework integration (source: issue body, "Affected Packages" section).
- Implement `EncinaTUnitFixture` as a TUnit-compatible fixture implementing `IAsyncInitializer` and `IAsyncDisposable` to manage `IServiceProvider` lifecycle (source: issue body, "Proposed Solution").
- Implement `TUnitEitherAssertions` static class with extension methods `ShouldBeSuccess`, `ShouldBeError`, and `AndReturn` for `Either<TLeft, TRight>` (source: issue body, "Proposed Solution").
- Introduce `EncinaTestAttribute` for marking Encina test classes (source: issue body, "Proposed Solution").
- Target NativeAOT compatibility and source-generated tests for performance improvements (10-200x faster) (source: issue body, "Motivation").
- This is the first foundational package for the v0.11.0 Testing Infrastructure milestone (source: comment by dlrivada).

## Rejected alternatives
- Continue with xUnit only (misses NativeAOT compatibility and performance benefits) (source: issue body, "Alternatives Considered").
- Add NUnit adapter (NUnit still uses reflection, doesn't provide NativeAOT benefits) (source: issue body, "Alternatives Considered").
- Build custom source-generated framework (massive effort, TUnit already solves this) (source: issue body, "Alternatives Considered").

## Rules and lessons
- New testing framework packages should target NativeAOT compatibility to align with Encina Source Generators and trimming requirements (source: issue body, "Motivation").
- Testing infrastructure milestones (v0.11.0) should prioritize foundational packages that enable modern, source-generated testing (source: comment by dlrivada).
- Unit tests for new packages must achieve >=85% coverage (source: issue body, "Acceptance Criteria").
