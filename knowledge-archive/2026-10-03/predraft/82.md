## Decisions
- Documentation for core concepts (handlers, pipeline behaviors, notifications) was to be structured into separate files under `docs/fundamentals/` (`encina-pattern.md`, `handlers.md`, `pipeline-behaviors.md`, `notifications.md`) (Source: issue body, Proposed Solution).
- The implementation was to cover specific aspects of pipeline behaviors (pre/post-processor, ordering, custom) and notifications (publishing, multiple handlers, execution modes, error handling) (Source: issue body, Content sections).
- All code examples provided in the documentation were required to compile and work (Source: issue body, Acceptance Criteria).
- The documentation was part of Phase 5 Exit Criteria (Source: issue body, References).
- The feature was evaluated against the 12 transversal functions, with all marked as N/A because it is documentation only with no runtime code changes (Source: issue body, Cross-Cutting Integration table).
- PR #1263 was merged to explain the request pipeline, add the pipeline-behavior how-to and reference, fulfilling the issue (Source: linked PR #1263 title and state).

- Video-only tutorials were rejected as not searchable and harder to reference (Source: issue body, Alternatives Considered).
- XML documentation only was rejected as it lacks conceptual explanations (Source: issue body, Alternatives Considered).
