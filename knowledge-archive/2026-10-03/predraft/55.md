## Decisions
- Create a provider-agnostic `IDistributedLock` interface for mutual exclusion in distributed systems (Source: Issue Body)
- Implement Redis lock provider using the Redlock algorithm (Source: Issue Body)
- Implement SQL Server lock provider using `sp_getapplock` (Source: Issue Body)
- Include timeout and auto-release mechanisms (Source: Issue Body)
- Create a new package `Encina.DistributedLock` along with provider-specific packages (Source: Issue Body)
- Use `ValueTask<IAsyncDisposable?>` for `TryAcquireAsync` return type, allowing null on failure to indicate lock acquisition timeout (Source: Issue Body Code Example)
- Require 85%+ test coverage (Source: Issue Body Acceptance Criteria)
- Implement the distributed lock abstractions (Source: Commit 7e50983e "feat(distributedlock): add distributed lock abstractions (Fixes #55)")

## Rejected alternatives
- none

## Rules and lessons
- Use provider-agnostic interfaces for distributed infrastructure concerns to maintain flexibility (Source: Issue Body Motivation)
- Implement auto-release semantics to prevent deadlocks in distributed systems (Source: Issue Body Proposed Solution)
- Use `Either` types or similar error handling patterns for lock acquisition failures to provide explicit error codes like "lock.timeout" (Source: Issue Body Code Example)
- Follow standard testing practices including unit, integration, load, and guard tests for critical infrastructure components (Source: Issue Body Test Matrix)
