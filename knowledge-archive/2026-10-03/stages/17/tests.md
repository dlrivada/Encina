## Lessons for the pipeline

- For a SPIKE issue whose only diff is a deletion commit, "measure the archivist's scope list" resolves almost entirely to "confirm there is nothing to measure": the deleted package has no source and (verified via `git log --all --diff-filter=A -- "tests/*<Package>*"`) never had a test project in this repository's reachable history, and the "kept" package the archivist lists for context was not touched by the issue's diff at all (verified via `git show --stat <sha> -- <package-path> tests`). The one useful test-stage action left is a narrow, test-name-filtered coverage run of exactly the files the archivist named as the kept implementation — not a full per-flag package run — to confirm the kept strategy's own tests exist, pass and are not vacuous, without duplicating the eventual audit of whichever issue actually wrote that package.
- Two independently-verified pairs of duplicate guard-test classes (`Infrastructure\<Package>\*GuardTests.cs` next to a newer `<Package>\<Feature>\*GuardTests.cs`) turned up as a side effect of confirming the "kept" strategy's tests aren't vacuous. Worth checking for this same folder-doubling pattern whenever a future stage reads a package's guard tests — it is exactly the shape the active Test Consolidation plan is meant to catch, and it was cheap to find once the file list from a targeted `Glob` was in hand.
