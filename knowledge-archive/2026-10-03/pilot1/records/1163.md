## Summary

Roughly 28 call sites across sharding registration, audited secret decorators, NIS2 compliance validation, ABAC policy administration, saga and routing-slip runners resolved `IRequestContext` directly from the DI container — a type that is never registered, so every one of them silently got `null` instead of the real ambient request context. Fixed by PR #1284, switching every consumer to `IRequestContextAccessor`, with new DI-registration regression tests. The fix correctly and consistently touched all applicable database providers (ADO/Dapper/EFCore ×3 each, MongoDB). The main gap: no architecture test exists to structurally prevent the same silent-null pattern from recurring for `IRequestContext` or any other ambient-context type — a concrete, cheap follow-up (see findings).
