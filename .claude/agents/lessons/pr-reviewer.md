# Lessons for pr-reviewer

Each lesson names the pull request whose review taught it; the lesson is about reviewing, not about that PR's change.

- (2026-09-27, review of PR #1459, #1460) Read post-PR file contents from the PR's worktree or `FETCH_HEAD`, never from the main checkout: main does not have the PR's changes yet, so a "missing" symbol there is not a finding. (read post-PR files from the worktree or FETCH_HEAD)
- (2026-09-27, review of PR #1507) A worktree may be based one merge behind `origin/main`; before calling something in the worktree a finding, check `git merge-base <branch> origin/main` and `gh pr diff <n>` — an already-fixed file can look broken in a stale worktree while the real PR diff excludes it. (check the merge base and gh pr diff before reporting a worktree-only finding)
- (2026-09-27, review of PR #1462, #1465) A knowledge record under `docs/knowledge/issues/` in an open PR is required by SPEC-003 REQ-031, not scope creep; its `prs`/`linked_prs` are filled by the orchestrator after the PR opens. (knowledge records in open PRs are expected)
- (2026-09-27, review of PR #1462, #1498) For a leak or rename PR, grep every log-message method name and parameter name repo-wide, including methods with no caller: a dead overload or duplicate log class with a stale `errorMessage` parameter is a trap for the next contributor. (grep log-method and parameter names repo-wide, dead ones included)
- (2026-09-27, review of PR #1495) When a PR deletes a `src/` file, check `.github/coverage-manifest/<Package>.json` for an entry that still names it; no CI gate catches a stale entry yet (#1497). (check the coverage manifest when a src file is deleted)
- (2026-09-27, review of PR #1496) You are read-only: never try a red/green check by editing source to revert a fix (enforce-path-ownership blocks it, correctly). Trace statically and say so; the orchestrator asks the issue-worker, who owns the worktree, for the red/green proof. (never edit source for red/green; trace statically)
- (2026-09-27, review of PR #1500) Independently re-grep any "I grepped and nothing else was missed" claim in the PR, especially across extract-method refactors where a call site moves to a new method name. (re-grep the PR's own completeness claims)
- (2026-09-27, review of PR #1502) When a fix removes a capability to make a failure structurally impossible instead of adding the instruction the issue proposed, say so explicitly rather than silently marking the criterion met; for a tools-allowlist PR, grep for a standalone (non-OR'd) tool-name hook matcher to see whether the other tool's path is still guarded. (name mechanism substitutions; grep for standalone tool matchers)
- (2026-09-27, review of PR #1508) A PR that changes a blocking gate (crap-gate, coverage, link check) gets an adversarial fixture: build a small input that tries to make a real violation escape (here an unsequenced changed line inside a closure nested in a complex method) and run the PR's script against it. When a rule picks one candidate among several, ask what happens to the discarded ones. (build an escape fixture for every gate PR; check discarded candidates)
- (2026-09-27, review of PR #1522) When a mock-signalled TaskCompletionSource replaces a `Task.Delay`, check that `Returns(...)` and `When(...).Do(...)` are both configured (NSubstitute composes them), that the TCS uses `RunContinuationsAsynchronously`, and that a "nothing happens" test is deterministic by construction (for example `ExecuteAsync` returning before any await), not by timing. (verify TCS-based waits and deterministic negative tests)
- (2026-11-20, plan-batch-2b plan PRs #4074-#4078, #4049-#4053) In a plan that registers an EventId range, the Zone column of the registry's "registered ranges" table must be `historical` below 10000 (`reserved-pre-zone` is only a Blocks-table status, and `EventIdRegistryAgreementTests.CheckZone` requires it); count `eventid-block-registry.md` in the PR file list and require the reserved row to be split (registered sub-range plus the remainder kept reserved). (check registry Zone vs Blocks status and count the registry file)
- (2026-11-20, plan PRs #4085, #4125) Compare every per-flag target number a plan quotes with the real package manifest, and grep `CollectionDefinition` before accepting a claim that a reusable collection exists. (compare targets with the real manifest; grep for the collection)
- (2026-11-20, plan PR #4125) Check the design for interface and DI correctness: "assign the id once" needs an id parameter in the interface; each split PR must register the services it introduces; a composite registered under its member type creates a DI cycle; a dead-letter MULTI/EXEC across Redis cluster slots needs a hash tag. (check interface shape, per-PR registration, DI cycles and cluster slots)
- (2026-11-20, plan PRs, process) Never rebase a pushed branch and never force-push; a fix is a new commit on top of the pushed head (branch `-ff`), pushed fast-forward only after a one-file check. (fast-forward pushes only)
- (2026-11-24, plan PRs #4260-#4266) Re-check every Settled or Trivial row against every option of every Dilemma, and never accept one that rests on a sibling or still-pending Dilemma; read the text of any cited ADR rule (for example ADR-062 R3) instead of trusting the citation. (re-check Settled rows against all Dilemma options; read the cited rule)
- (2026-11-24, plan PRs #4260-#4266) A target set in PR N needs the tests that reach it in PR N; a whole-file guard target of 90 is unreachable when guard tests only reach argument checks (measured 15.3%). (targets need tests in the same PR; guard targets are low)
- (2026-11-24, plan PRs #4260-#4266) Count the `ServiceCollectionExtensions`, manifest, `PublicAPI` and `.csproj` files a PR touches against its stated file list and the 15-file limit, and let sibling-plan EventId reservations beat the registry table when they conflict. (count the wiring files; sibling reservations win)
- (2026-11-24, plan PRs #4260-#4266) Generated code shown in a plan must be legal C#, and an unconditional upsert into a side registry needs a key space disjoint from the other writers. (generated code must compile; disjoint keys for shared upserts)
- (2026-11-25, plan PRs #4175, #4261, #4262, #4266) A delta that adds a Dilemma requires re-checking the pros and cons of the other Dilemmas; `AuditInterceptor` swallows post-commit failures, so audit-store plans claiming the writer fails closed are false; an "unchanged" target must quote the real manifest numbers (per-file entries may not exist); also check counts such as "seven manifests" (six, EF Core shared) and justification wording such as "rest of file" versus "package target". (re-check Dilemmas after a delta; verify audit fail-closed claims, manifest numbers and counts)
